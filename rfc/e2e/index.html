Why the three parts work together

Three questions every agent number must answer

  1. Which version and rules? Replayable context

    Search ranks candidates; files describe knowledge. Together they add a validated publication and a Catalog pin to the version BigQuery serves.

  2. Whose access, right now? Explainable access

    Permission to discover does not explain permission to retrieve. Here the restricted requester’s own account was checked at every step, and again after revocation.

  3. Did the approved calculation run? Verifiable execution

    A declared calculation does not show it ran. The consumer checked the SDK receipt linking job, calculation and result before release.

OKF alone supplies the declaration; Knowledge Catalog alone, discovery; an ungoverned agent, neither this publication contract nor this receipt check. With BigQuery publishing and the enforcing consumer, the recorded path answered all three questions once. An architectural comparison from the RFC, not a benchmark.

  • Knowledge Catalog pointed the requester to exactly that version.
  • Release happened only with a verified receipt.
  • Revocation held against three later routes.

Technical limits (named, not waived)

  • Graph: retrieval and access ran on relational SQL over the published tables, not BigQuery Graph / GQL; access inside graph queries is still open.
  • Attestation: the SDK example’s own verifier with a requester-held key; no independent attester. The receipt’s publication ID is the SDK’s label, not the BigQuery publication ID.
  • Revision: the publication ID is content-addressed from the pinned source, so this run deployed the same ID the long-lived spike dataset holds into a fresh run-owned dataset: a new deployment, not a new revision of the knowledge.
  • Cross-service protocol (Detailed RFC §05): simplified to one owned dataset with active_publication; no sync_id staging, deployment_heads, *_current views or Catalog lag SLO.
  • Access setup: the harness grants the requester Catalog viewer and dataset reads for the run and removes them to revoke; the hidden-rule case uses an injected legacy seed on the long-lived _rls copy, not a Catalog discovery.
  • Cache: Catalog concept seeds disable the retrieval cache, so cached replay after revocation was not exercised.
  • Sample: n = 1, synthetic data, no cost or latency benchmark. Earlier runs stay as recorded: e2e-20260915t070643z-9ddaf35f (consume-only, report) and e2e-20260915t065449z-98e21004 (E2E_BROKEN).
