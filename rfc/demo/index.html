Walkthrough

Four beats on the live page: Observe → Adapt → Project → Consume. ADK model gemini-3.8-flash. Fixture data, no live GCP.

What is real here, and what is not
  • Real: the Phase 0 authored fixture and its golden identities (copied from okf-phase0-mvp/); the PROFILE.md hashing rules, ported to JavaScript and cross-checked against the golden vectors and an independent Python re-derivation; the derived bundle you can read file by file in beat 2.
  • Synthetic, labelled: the BQAA trace (shaped like agent_events rows, never written to a table); the Catalog entries and BigQuery rows in beat 3 (client-side projection views, no kcmd write, no DML); the ADK transcript in beat 4 (fixture replay of a gemini-3.8-flash agent, no model call).
  • Honest by construction: the receipt verdict is UNVERIFIABLE with reason phase0_no_execution_or_integrity_proof. Nothing was executed, so nothing is attested. The Phase 4 ATTESTED shape is shown beside it and marked non-normative.
  • Never emitted on agent-facing payloads: concept_version_id, bundle paths, principal, SQL / query text, parameter values, raw destination table names. Beat 4 asserts this against the tool JSON at render time.
Run it locally

Static files, no build. From the repo root: python3 -m http.server 8000 then open http://localhost:8000/rfc/demo/. Regenerate the derived bundle with node rfc/demo/tools/build-derived.mjs and verify with python3 rfc/demo/tools/derived_vectors.py. See README.md.
