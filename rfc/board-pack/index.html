Illustrative scenario · invented company, people & numbers

The board pack says 118%.
Retention is 96%.

8:55 a.m. Maya Chen, VP of Finance at subscription software company Alder, opens the board pack for a $4 million plan to expand sales to existing customers. The meeting starts in five minutes. Her agent calls 118% retention “verified.” An analyst spots new customers in the calculation. Revenue from existing customers fell 4%.

Maya pulls the slide. Three questions go unanswered. The agent found Finance’s definition but missed the accompanying rule: count revenue only from customers there at the start. It reused a total-ARR query; Maya cannot trace the policy allowing this agent to use that asset. And no execution receipt connects the query, the declared retention calculation and the reported result.

Why BigQuery · proposed runtime · RFC, not built

What BigQuery adds to the story.

Knowledge Catalog (KC) discovers and governs. Open Knowledge Format (OKF) authors the graph.

01 Replayable context

Same retention definition, cohort rule and declared computation.

KC + OKF

KC discovers; OKF authors the graph. Similarity ranks candidates; it does not pin linked context. The retriever assembles it.

+ BQ runtime

Host the OKF projection. Pin a publication; use explicit SQL or bounded walks. Fix query, parameters, fact versions, access scope and ordering → same selected context and shape.

Vector search can be deterministic. Replayable context does not promise identical LLM answers.

02 Explainable access

Maya can trace why this agent could use the total-ARR asset.

KC + OKF

Custom-entry access uses an EntryGroup boundary today. Per-node policy evaluation is separate.

+ BQ runtime

Join identity ↔ policy ↔ projected assets. Bind the requesting user/agent to the execution identity. Enforce access along the retrieval path; record which nodes were returned to whom under which policy.

Access metadata needs enforcement. Keep source permissions current; metadata access does not grant file access.

03 Verifiable execution

Maya can check whether the board number used the retention calculation.

KC + OKF

Finding the definition and its computation declaration does not prove the calculation ran.

+ BQ runtime

Run retention; validate a job ↔ context ↔ result receipt against the declared computation. A substituted query or missing evidence leaves the number unproven.

A job ID alone does not validate the computation. Demo receipts remain UNVERIFIABLE.

The graph can be the first BigQuery workload. Land the OKF projection and version the facts retrieval needs. No existing revenue warehouse is required.

Technical designRFC proposal

Proposed integration, not an implemented runtime. The OKF bundle stays authoritative; BigQuery hosts a publication’s node/edge projection and versioned facts. The graph can be the first workload, but it must enter BigQuery before retrieval can run there.

Retrieve a fixed context

Start at Finance’s retention definition. Follow its authored links to the cohort rule and computation declaration using explicit SQL or bounded walks. Fix publication, query, parameters and fact versions; define traversal bounds, tie-breaking, output schema and ordering. Avoid volatile functions and unversioned inputs. Record these inputs and returned node IDs in a retrieval receipt. This explains context selection; it does not prove retention was computed or promise identical LLM answers.

Evaluate current access

Authenticate the requesting user or agent and bind that identity to the execution identity. Join identity, policy and projected assets; enforce current permissions along the retrieval path. Record the policy version and nodes returned for that requester. A publication pin never bypasses current authorization. Metadata visibility does not grant file access, and a shared service account alone cannot identify Maya’s agent.

Validate the calculation

Run retention separately. Bind the BigQuery job, executed query and parameters, input versions, pinned context and result in a computation receipt. Validate that execution against the declared retention calculation: the total-ARR substitution must fail that check. A retrieval receipt or job ID alone is insufficient. Missing evidence leaves the number unproven; existing demo computation attesters are stubs and receipts remain UNVERIFIABLE.

BigQuery turns the OKF graph into replayable context for agents—with explainable access and evidence that the declared computation ran.
