Illustrative scenario · invented company, people & numbers

The board pack says 118%.
Retention is 96%.

8:55 a.m. Maya Chen, VP of Finance at subscription software company Alder, opens the board pack for a $4 million plan to expand sales to existing customers. The meeting starts in five minutes. Her agent calls 118% retention “verified.” An analyst spots new customers in the calculation. Revenue from existing customers fell 4%.

Maya pulls the slide. Three questions go unanswered. The agent found Finance’s definition but missed the accompanying rule: count revenue only from customers there at the start. It reused a total-ARR query; Maya cannot trace the policy allowing this agent to use that asset. And no execution receipt connects the query, the declared retention calculation and the reported result.

Why BigQuery · proposed runtime · early experiments

What BigQuery adds to the story.

Knowledge Catalog (KC) discovers and governs. Open Knowledge Format (OKF) authors the graph.

Especially strong when the facts an agent needs already live in BigQuery on Enterprise or Enterprise Plus capacity, within a latency, freshness, concurrency and cost budget the customer has agreed to. What works today: recorded examples of a graph walk that finds linked rules, and of a receipt that ties a query to its result. What we still need to prove: those pieces running as one connected path on real cohort data. That is the pilot’s job.

01 Replayable context

Same retention definition, cohort rule and declared computation.

KC + OKF

KC discovers; OKF authors the graph. Similarity ranks candidates; it does not pin linked context. The retriever assembles it.

+ BQ runtime

Host the OKF projection. Pin a publication; use explicit SQL or bounded walks. Fix query, parameters, fact versions, access scope and ordering → same selected context and shape.

Vector search can be deterministic. Replayable context does not promise identical LLM answers. See the recorded graph walk: retrieval works in the tested cases; access checks and speed benchmarks are still to come.

02 Explainable access

Maya can trace why this agent could use the total-ARR asset.

KC + OKF

Custom-entry access uses an EntryGroup boundary today. Per-node policy evaluation is separate.

+ BQ runtime

Join identity ↔ policy ↔ projected assets. Bind the requesting user/agent to the execution identity. Enforce access along the retrieval path; record which nodes were returned to whom under which policy.

Access metadata needs enforcement. Keep source permissions current; metadata access does not grant file access. The access checks in the graph experiment are not finished yet.

03 Verifiable execution

Maya can check whether the board number used the retention calculation.

KC + OKF

Finding the definition and its computation declaration does not prove the calculation ran.

+ BQ runtime

Run retention; validate a job ↔ context ↔ result receipt against the declared computation. A substituted query or missing evidence leaves the number unproven.

A job ID alone is not enough. See the recorded receipt check: one worked example ties the query, its inputs and its result together and withholds the number when they do not match. The wider demo does not have that check yet.

Graph walks need Enterprise or Enterprise Plus capacity. A projected graph can be the first workload there once its inputs are loaded, but the strongest case is a customer whose facts are already in BigQuery. Ordinary SQL and vector retrieval also run on-demand.

Technical designProposed integration · early experiments

This is a proposed integration, not a product. The OKF bundle stays the authored source; BigQuery would host a publication’s node and edge projection plus versioned facts. Two recorded experiments exist as separate pieces, both run on invented gross-margin data for a company called Acme: a graph walk that retrieves linked rules, and a receipt check that ties a query to its result. Nothing has yet run as one connected path from catalog discovery to a checked result.

Retrieve a fixed context

Start at Finance’s retention definition. Follow its authored links to the cohort rule and computation declaration using explicit SQL or bounded walks. Fix publication, query, parameters and fact versions; define traversal bounds, tie-breaking, output schema and ordering. Avoid volatile functions and unversioned inputs. Record these inputs and returned node IDs in a retrieval receipt. This explains context selection; it does not prove retention was computed or promise identical LLM answers.

The recorded graph walk ran on a measured Enterprise reservation. Starting from a retired definition, it followed two links to the sanctioned SQL, produced an impact list that matched a plain relational cross-check, and handled placeholder, ambiguous and out-of-scope entries on a deliberately awkward test bundle (Acme’s own backlog had no placeholders). It used generally available vector search plus graph queries. Its report counts this as demonstrated retrieval only: the SQL it returned was found, not run. Graph-native semantic search is a separately labeled Preview option, not the route we tested. Pinning a source is not yet a working live catalog discovery integration. Code and README for the graph walk.

Evaluate current access

Authenticate the requesting user or agent and bind that identity to the execution identity. Join identity, policy and projected assets; enforce current permissions along the retrieval path. Record the policy version and nodes returned for that requester. A publication pin never bypasses current authorization. Metadata visibility does not grant file access, and a shared service account alone cannot identify Maya’s agent.

The graph experiment’s access checks are unfinished. Per-requester authorization and publication consistency were only partly tested, tests with two different requesters could not run, we could not confirm that no hidden identifiers leak, and protection across mixed publications is not proven live (open items in the graph walk report). Those gaps are separate from the receipt check’s own caller-binding and revocation tests, which cover one job’s owner and dataset grant, not per-node graph authorization.

Validate the calculation

Run retention separately. Bind the BigQuery job, executed query and parameters, input versions, pinned context and result in a computation receipt. Validate that execution against the declared retention calculation: the total-ARR substitution must fail that check. A retrieval receipt or job ID alone is insufficient. Missing evidence leaves the number unproven.

The recorded receipt check used a BigQuery job owned by the caller, read the job and its result back from BigQuery itself, verified them in a fresh process, and let a consumer release the result only after the check passed. Wrong-query, wrong-parameter, tampered, replayed and missing-evidence cases released nothing (see the case records). It ran under the requester’s own delegation, with a locally held signing key and one small invented gross-margin fixture. An independent verifier, portable signatures and general accounting correctness are not demonstrated. A passed check is an evidence verdict for that example, not a product-readiness claim. The wider demo’s computation checks are still placeholders, so its receipts cannot be verified yet.

Where the evidence stands

Both experiments are merged into their repositories and were reviewed. The receipt check is example code and tests, with no change to the underlying library; the reviewer’s approval note discloses that the same reviewer also wrote the final fix. The graph walk’s speed benchmarks have not run yet (0 of 9 cells), and the Enterprise reservation was recorded as torn down, which is not an audit of every pending job or fixture resource. Evidence labels per comparison. No customer has yet agreed an operating budget. The broader Knowledge Catalog serving-tier case is judged more modest than the scoped case above.

We will call the connected path proven only after one chain runs end to end: catalog discovery, pinned publication, governed retrieval, computation delegated by the caller, a receipt bound to the result, and a consumer that enforces it, plus tests for publication consistency, denied intermediate nodes, revocation before cached replay and unauthorized output. Two merged experiments alone do not clear that bar. Receipt work should not wait for the graph benchmark. We reassess the opportunity at the 2026-09-19 checkpoint. It narrows if budgets or Enterprise cost prove unacceptable, if simpler retrieval meets the need, if semantics, authorization or publication guarantees fail, or if result evidence cannot be bound and enforced. Platform boundaries: BigQuery editions, graph placement.

The proposed BigQuery runtime would turn the OKF graph into replayable context for agents—with explainable access and evidence that the declared computation ran.
