Illustrative scenario · invented company, people & numbers

The board pack says 118%.
Retention is 96%.

8:55 a.m. Maya Chen, VP of Finance at subscription software company Alder, opens the board pack for a $4 million plan to expand sales to existing customers. The meeting starts in five minutes. Her agent calls 118% retention “verified.” An analyst spots new customers in the calculation. Revenue from existing customers fell 4%.

Maya pulls the slide. Three questions go unanswered. The agent found Finance’s definition but missed the accompanying rule: count revenue only from customers there at the start. It reused a total-ARR query; Maya cannot trace the policy allowing this agent to use that asset. And no execution receipt connects the query, the declared retention calculation and the reported result.

Why BigQuery · proposed runtime · merged spike evidence

What BigQuery adds to the story.

Knowledge Catalog (KC) discovers and governs. Open Knowledge Format (OKF) authors the graph.

Opportunity HIGH (scoped): analytical agents whose relevant facts already live in BigQuery, on Enterprise or Enterprise Plus, within customer-accepted latency, freshness, concurrency and cost budgets. That operating envelope is not yet accepted. Combined delivery LOW: the connected path remains unproven. Receipts MODERATE: one merged example only.

01 Replayable context

Same retention definition, cohort rule and declared computation.

KC + OKF

KC discovers; OKF authors the graph. Similarity ranks candidates; it does not pin linked context. The retriever assembles it.

+ BQ runtime

Host the OKF projection. Pin a publication; use explicit SQL or bounded walks. Fix query, parameters, fact versions, access scope and ordering → same selected context and shape.

Vector search can be deterministic. Replayable context does not promise identical LLM answers. Graph spike: tested retrieval demonstrated; governance and benchmarks incomplete.

02 Explainable access

Maya can trace why this agent could use the total-ARR asset.

KC + OKF

Custom-entry access uses an EntryGroup boundary today. Per-node policy evaluation is separate.

+ BQ runtime

Join identity ↔ policy ↔ projected assets. Bind the requesting user/agent to the execution identity. Enforce access along the retrieval path; record which nodes were returned to whom under which policy.

Access metadata needs enforcement. Keep source permissions current; metadata access does not grant file access. Graph spike governance evidence is partial.

03 Verifiable execution

Maya can check whether the board number used the retention calculation.

KC + OKF

Finding the definition and its computation declaration does not prove the calculation ran.

+ BQ runtime

Run retention; validate a job ↔ context ↔ result receipt against the declared computation. A substituted query or missing evidence leaves the number unproven.

A job ID alone is insufficient. Receipt example: MODERATE for this slice; recorded VERIFIED path with enforced consumption (merged SDK PR 479). Full-demo attesters are still stubs; the full demo’s receipts remain UNVERIFIABLE.

GQL needs Enterprise or Enterprise Plus. A projected graph can be the first workload there after its inputs are loaded; that empty-project route is outside the scoped opportunity above. Ordinary SQL and vector retrieval also run on-demand.

Technical designProposed integration · spike evidence

Proposed integration with spike evidence, not a product. The OKF bundle stays authoritative; BigQuery would host a publication’s node/edge projection and versioned facts. Two merged Acme experiments exist as separate implementations: a graph retrieval spike and a receipt example. No live connected KC-to-result path has run, and neither experiment is a product claim.

Retrieve a fixed context

Start at Finance’s retention definition. Follow its authored links to the cohort rule and computation declaration using explicit SQL or bounded walks. Fix publication, query, parameters and fact versions; define traversal bounds, tie-breaking, output schema and ordering. Avoid volatile functions and unversioned inputs. Record these inputs and returned node IDs in a retrieval receipt. This explains context selection; it does not prove retention was computed or promise identical LLM answers.

The graph spike ran on a measured Enterprise reservation and demonstrated Acme’s deprecated-anchor two-hop retrieval to the sanctioned SQL, impact analysis matching the relational oracle, and stub, ambiguity and scope-isolation handling on a negative fixture (Acme’s own stub backlog is empty), using GA VECTOR_SEARCH plus GQL; its report rates those passed retrieval gates MODERATE for demonstrated retrieval only. Returned sanctioned SQL carries NOT_EXECUTED semantics: retrieval evidence, not proof the calculation ran. Graph-native semantic search is a separately labeled Preview option, not the demonstrated route. A source pin is not a working live KC discovery integration. Source: merged site PR 28 (spike code and README).

Evaluate current access

Authenticate the requesting user or agent and bind that identity to the execution identity. Join identity, policy and projected assets; enforce current permissions along the retrieval path. Record the policy version and nodes returned for that requester. A publication pin never bypasses current authorization. Metadata visibility does not grant file access, and a shared service account alone cannot identify Maya’s agent.

Graph spike governance is partial: G6 authorization and G7 publication consistency remain PARTIAL, distinct-principal graph tests are BLOCKED, no-hidden-identifier evidence is INCONCLUSIVE and mixed-publication protection is not proven live (graph spike open gates). These graph gaps are separate from the receipt example’s own caller-binding and revocation checks, which cover one job’s owner and dataset grant, not per-node graph authorization.

Validate the calculation

Run retention separately. Bind the BigQuery job, executed query and parameters, input versions, pinned context and result in a computation receipt. Validate that execution against the declared retention calculation: the total-ARR substitution must fail that check. A retrieval receipt or job ID alone is insufficient. Missing evidence leaves the number unproven.

The merged receipt example recorded a caller-owned BigQuery job, authoritative job and result reads, fresh-process verification and consumer-enforced release; wrong-query, wrong-parameter, tampered, replayed and missing-evidence cases released nothing (live case records). It uses the requester’s delegation, local HMAC custody and a narrow synthetic gross-margin fixture: an independent verifier principal, portable signatures and general accounting correctness are not demonstrated. VERIFIED is an evidence verdict, not ATTESTED, GA or product readiness. Full-demo computation attesters remain stubs and full-demo receipts remain UNVERIFIABLE.
