Illustrative scenario · invented company, people & numbers

The board pack says 118%.
Retention is 96%.

8:55 a.m. Maya Chen, VP of Finance at subscription software company Alder, has five minutes before the board decides on a $4 million plan to expand sales to existing customers. Her agent calls 118% retention “verified.” Revenue from those customers actually fell 4%.

An analyst catches it. Maya pulls the slide. The agent cited Finance’s definition but reused a total-ARR query. New business made a shrinking customer base look like growth.

Why BigQuery · proposed runtime · RFC, not built

A definition lookup isn’t a computation receipt.

Catalog alone can find the approved definition. It doesn’t run Maya’s calculation or bind the answer to a query job. Alder already keeps its revenue data in BigQuery, alongside query jobs and data access controls.

Knowledge Catalog

Find the definition.

Discover Finance’s approved retention metric: follow the customers present at the start of the quarter. Exclude new customers.

Open Knowledge Format (OKF)

Pin the instructions.

Author the definition, declared query and parameters in an OKF bundle. The runtime pins one revision for Maya’s run, so later edits don’t change the context it used.

BigQuery

Run it. Account for it.

Run the declared query against Alder’s revenue tables. Bind job + pinned context + quarter parameters + result in a computation receipt.

Trace the answer to the agent and the identity that ran the job. Use IAM to separate who can publish context, run the query and read the evidence.

No execution evidence → “unproven.” Finding the right definition is not proof that the calculation used it.

Find it in Catalog. Run it in BigQuery. Bring the receipt.

One ask of the BigQuery VP

Sponsor one retention pilot with a Finance owner.

Test this quarter’s 96% with a pinned definition, a receipt and an accountable agent. Remove the execution evidence: the answer must stay unproven.
