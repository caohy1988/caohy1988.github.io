OceanBase Agentbase vs BigQuery Agent Analytics: a deep dive

For Haiyuan Cao, TL of Google BigQuery Agent Analytics, before meeting OceanBase CTO Yang Chuanhui (杨传辉, “Charlie Yang”).

01 / Read this first

  • Agentbase is a full agent backend, not just another trace viewer. It combines BaaS, knowledge, long-term memory, a managed ReAct runtime, gateways and AgentOps inside one account → organization → project governance model; OceanLake places it in the Agent Runtime layer.1,2,6
  • The direct BQAA overlap is substantial. AgentOps accepts OTLP/HTTP and Langfuse-compatible batches, models ten observation types, and adds scores, prompts, datasets, metrics, annotation queues and low-score root-cause analysis.7,8,9,10
  • Our judgement: this is a credible suite-level threat, not yet a demonstrated BQAA-scale analytics win. Integrated procurement and private deployment matter, but the public material does not establish AgentOps’ physical trace engine, arbitrary SQL over traces, business-table joins, throughput SLOs or list pricing.3,7,8,21
  • BQAA’s sharpest distinction is business-context analysis, not merely “traces in SQL.” BQAA explicitly supports arbitrary BigQuery SQL and a worked business-table join; Databricks already offers direct SQL over Unity Catalog Delta traces, and Snowflake offers SQL table functions over immutable observability events, so the generic warehouse claim is no longer unique.41,56,62
  • OpenTelemetry is both the exposure and the partnership opening. Agentbase documents `gen_ai.*` mapping while BQAA’s documented producers use Storage Write API rather than a native OTLP endpoint. A lossless OTel GenAI → `agent_events` bridge would let customers keep instrumentation and add BigQuery analytics.7,8,41,42,66
  • The production story is meaningful but vendor-reported. An OceanBase engineering talk describes one Ant application at about 10 TB of traces/day and 3–6 PB/year; the launch release says Afu evaluation setup fell from days to minutes. Neither proves that the current Agentbase product carries that volume, and no independent benchmark was found.32,33,38
  • For the meeting, press on four things: the actual trace store and SQL contract; full OTel/ATIF interoperability and export; what is product versus Ant-built in the Afu story; and deployment, pricing and version compatibility. The goal should be a concrete interop path, not only a competitive scorecard.

02 / Product and stack

2. What Agentbase is and where it sits

Agentbase calls itself “enterprise-grade agent backend infrastructure” (企业级 Agent 后端基础设施). Its pitch is to combine knowledge, memory, enterprise-data access, an application backend and run-time evaluation while preserving a customer’s existing orchestration. Its shortest positioning statement is “不替代客户 Agent 平台，补齐生产后端” — “we do not replace the customer’s agent platform; we complete the production backend.”1 The more detailed manual describes one control and governance tree spanning traditional BaaS and agent infrastructure.6

OceanLake gives that product a wider home. Its four layers are DataPilot for data intelligence, Agentbase for agent runtime, Ontos for business semantics, and a data/compute foundation of OceanLake Core, Compute, DataStudio and object storage.2 The 24 November launch headline was OceanLake plus open-source OceanSeek; Agentbase was not separately named in the English launch release or TechNode’s launch report, so it is better read as an existing product repositioned inside OceanLake than as a same-day debut.19,33,34

Do not collapse the names. OceanSeek is a distributed, storage/compute-separated AI database; seekdb is an embedded or server search/state database; PowerContext is a context and memory service whose documented storage choices include SQLite, OceanBase and seekdb. Agentbase’s native Memory and hosted PowerContext are mutually exclusive in one Runtime configuration. These are adjacent answers to agent state, not one product with three names.13,23,24,25

03 / Capability deep dives

3. Capabilities in depth

3.1 AgentOps observability

Ingestion is dual-channel and asynchronous. `POST /v1/observability/ingestion` accepts 1–100 Langfuse-model events per request (`trace-create`, observation create/update and `score-create` families). It returns 200 when all events are accepted and 207 Multi-Status with per-event successes/errors when any are rejected; the outer event ID is the retry idempotency key.7 `POST /v1/observability/otel/v1/traces` accepts OTLP/HTTP JSON or protobuf, optionally gzipped, capped at 4,718,592 bytes raw and decompressed. It is not OTLP/gRPC, and even HTTP 200 requires checking `errors[]` rather than assuming standard OTLP `partialSuccess` behavior.7 Acceptance is not persistence: clients are told to read back with bounded polling, and the FAQ says queue-full or retry-exhausted export can lose events.7,8

The published `gen_ai.*` mapping is real but incomplete. The manual names `gen_ai.system`, `gen_ai.request.model` and `gen_ai.usage.*` as mappings into GENERATION and TOOL observations; the API also recognizes `gen_ai.tool.call_id` and `gen_ai.tool.call.id` for tool linkage.7,8 No complete attribute→field table or pinned semantic-convention version appears in the Chinese or English references reviewed, so unknown-attribute preservation and full coverage must stay open.

The data model is broader than a span tree. Session groups traces; Trace contains Observations linked by `parentObservationId`; User aggregates traces, token use, estimated cost and score distributions. Scores can be NUMERIC, CATEGORICAL or BOOLEAN and come from EVAL, ANNOTATION or API. Prompt versions and labels, Datasets, Metrics and Reports are first-class surfaces.7,8 The ten observation types are `GENERATION`, `TOOL`, `AGENT`, `SPAN`, `EVENT`, `RETRIEVER`, `EMBEDDING`, `CHAIN`, `EVALUATOR` and `GUARDRAIL`.8

ATIF-v1.8 is derived, not uploaded. Trace detail returns `{trace, observations, trajectory}`; the server asynchronously extracts and persists an Agent Trajectory Interchange Format v1.8 trajectory from stored evidence, returning `null` until it is ready. Tool correlation requires matching IDs in the model’s `tool_calls`, the TOOL observation and the subsequent tool-role model message.7,9 Section 4 separates that confirmed behavior from the inferred identity with Harbor’s public ATIF specification.

APIs, metrics and retention. The main API reference declares 23 endpoints across ingestion, entity queries, scores/RCA, eval/MCP/prompt resolution, metrics, logs and status; datasets, annotation queues and 2.12 report/trace-analysis additions are documented separately, so “23” is not a total for every observability operation.7,9,11 Metrics include P50/P95/P99 latency, token use, model cost and quality trends; reports cover 24 hours, 7 days, 30 days or custom windows up to 30 days.8,12 Retention defaults to unlimited, accepts 3–36,500 days, covers traces, observations, scores, analysis artifacts and media, and runs through daily background cleanup with optimistic revision checks.8

The BQAA-relevant boundary

The public surface is Console + REST metrics/reports/APIs. The docs call for a high-performance trace store but do not name its physical engine or offer arbitrary customer SQL over AgentOps traces. OceanSeek’s SQL and ForkDB features do not prove an AgentOps SQL surface.7,8,22

3.2 Evaluation, datasets, human annotation and RCA

Four task families. General evaluation covers traces, selected observations, sessions and dataset runs with built-in trilingual templates for correctness, faithfulness, hallucination, RAG query quality, context relevance, SQL semantic equivalence and intent following; custom Prompt, Program or Agent judges are supported. Memory evaluation targets ten pipeline stages. Parsing and chunking each contribute 50% to document-quality scoring. Index-quality evaluation independently scores GraphRAG, RAPTOR and LLM Wiki outputs from 0 to 1.10

Evidence controls are unusually concrete. Index evaluation uses rule checks over all records and deterministic stratified sampling (30 per capability by default), then a separate Grounding Review against frozen source text. Agent judges can bind up to eight immutable Evaluation Skills; the judge receives only read-only `skills_list`/`skill_view`, limited to 256 KiB per read, 512 KiB total and eight tool steps.10

The production-to-regression loop is first-class. A trace, observation or low-score result can become a dataset item; bulk `from-score` preview deduplicates before import. Dataset run items link the static item to produced traces/observations and scores, and Agent Runtime runs freeze configuration at admission.11,15 For managed RAG answer-accuracy evaluation, `datasetEvidence` uses an independent-domain HMAC to freeze the question, reference answer, trace and retrieval fingerprints; the dataset FAQ explicitly warns not to generalize that signed snapshot to every evaluation type.11

Human review and RCA. Annotation queues bind score configs and assigned members; “claim next” issues a five-minute exclusive lease, and queue scores carry a separate `queueId`.9 Numeric scores at `normalizedValue <= 0.5` can trigger RCA. Rule-based diagnosis is the zero-model-cost default; optional model attribution has a 300-second timeout and 24 KB evidence budget, emits confirmed/probable/possible confidence, and never automatically changes production configuration.10

3.3 Memory

Native Memory requires OceanBase Shared V2 table mode and a project-specific physical table group. Records carry content, type, `recordKind` (fact/conversation/action), scope and an optimistic-lock version; immutable Sources support provenance and idempotency, while Profiles provide user portraits.13 Writes can be deterministic (`infer=false`) or asynchronous pipeline inference (`infer=true`), including image and PDF inputs from project Storage.

Recall combines OceanBase dense vectors, DashScope sparse vectors, full-text keywords and an entity-relation graph under a token budget. Contexts & Dreaming builds L2 topic/episode/state and L3 overview layers; Evolution distills experiences and skills; custom pipelines, audit, Memory traces, forgetting and project pause/delete/purge complete the lifecycle.13 In Agent Runtime, native Memory and hosted PowerContext are strictly mutually exclusive; Knowledge Search can remain enabled with either.13,15

3.4 Knowledge base

The KB ingests uploads, bound Storage buckets and incremental Yuque spaces. Parsers are `text`, `vlm` and `mineru`; chunkers are `general`, `title`, `smart`, `regex` and `faq`. Search modes are hybrid, vector and full text, with optional reranking and derived GraphRAG, RAPTOR and LLM Wiki indexes.14 Lexicons support synonyms, expansions and stop words, with different behavior when bound to a KB versus the agent.

Ingestion is asynchronous (202): readers must check both job and document readiness and match `activeGeneration` to the ingestion generation. Versioned publish/seal/rollback separates drafts from the active KB. Runtime can attach up to ten KBs in the console.14,15

3.5 Sandbox, replay and Fork Database

Three related mechanisms must not be conflated. Agentbase’s architecture lists an isolated execution Sandbox for code, and its self-improvement loop validates candidate strategies in a sandbox.4,5 AgentOps can execute dataset runs against Agent Runtime or a custom remote endpoint, preserving run configuration and produced evidence.11,15 OceanSeek separately provides copy-on-write Fork Table/Database: a shared baseline, isolated writes, and discard or merge paths for safe experiments.22,23

Not confirmed: that every Agentbase Dataset Run automatically receives a ForkDB branch, or that replay is deterministic across code, model output, tool responses, memory and database state. An OceanBase engineering talk says internal requirements were end-to-end evaluation setup within five minutes and the data layer within one; it reports forks of thousands of tables in milliseconds to seconds and multi-terabyte forks in about seconds. Those are vendor claims, not a published benchmark or proof of the Agentbase integration.32

3.6 Agent Runtime, gateway, MCP and skills

Agent Runtime manages a multi-step ReAct loop bounded by `max_steps` and `max_duration_ms`. Its object model is Project → Config → Thread → Run → Message; a Run freezes its config hash, only one unfinished Run may occupy a Thread (`409 THREAD_BUSY`), and messages use `message_seq` cursors.15 Submission returns 202 and continues if the browser closes; AG-UI SSE supports `Last-Event-ID` resume and idempotent deduplication. Client tools pause a run at `WAITING_CLIENT_TOOL`, then resume through `/tool-messages`.15,16

A project API key plus explicit `userId` isolates external users, but the key must stay in the trusted backend because it can act for any user in the project. Skills are ZIP/TAR packages with `SKILL.md`, at most 10 MiB; they are read as text, do not execute code and do not grant tool permissions. AI Gateway tools validate input schemas and, for client-tool results, optional output schemas.15,16

The LLM Gateway handles model providers; the separate AI Gateway handles gateways, targets, tools, consumers, policies, MCP and A2A and is off by default. In 2.12.0, AI Gateway model inference, logical models, deployment/discovery and standard model-management APIs are unavailable; model calls should use LLM Gateway. Automatic redaction, prompt-injection blocking and semantic response caching are also not guaranteed in that release.6,17

3.7 BaaS and governance

The application backend includes authentication and sessions, relational/document data with row-level permissions, file/object storage, functions, site hosting, messaging and multimodal moderation.5,6 The resource tree is Account → Organization → Project, with Project as the boundary for data, keys, service switches, table mode, region and quotas. Console developers and project end users are separate identity planes; server API keys can bypass row-level checks within their scopes, while client user credentials remain constrained by row and object permissions.5,18

Controlled enterprise-data access is part of the product pitch, including identity-aware and audited querying without moving business data into a new application DB.1 That should not be confused with arbitrary SQL access to AgentOps telemetry: the BaaS SQL Proxy and business database surface are separate from the observability API.6,7,18

04 / Architecture and implementation

4. Architecture and implementation evidence

Confidence labels apply to the proposition in the first column, not to every fact in the evidence column. For example, a public Langfuse fork is confirmed; the claim that Agentbase runs that fork is not.

CONFIRMED — Langfuse-compatible contract

Event names, fields, metrics and configuration

The API says the data plane is compatible with the Langfuse data model and ingestion contract; the metrics endpoint accepts a Langfuse metrics query object. The admin defaults include `_APP_LANGFUSE_ENABLED` for `agentops.enabled` and `AGENTOPS_LANGFUSE_ENABLED` for Runtime export.7,8

What this proves: a deliberate Langfuse compatibility strategy, not a coincidental resemblance.

UNCONFIRMED — the actual Langfuse engine

A public fork exists, but its Agentbase role is not established

`oceanbase/langfuse` is a real upstream fork whose customized README describes ClickHouse AMT optimization, deployment changes and a RAGFlow-on-OceanBase evaluation bridge.28 Collector inspection found its default branch at `powerrag-langfuse-v3.103.0`; the public docs and package evidence refer to deploying Langfuse but do not identify this repository as Agentbase’s production engine.7,28,29

Do not infer: embedded ClickHouse, the fork’s exact version in production, or upstream migration policy.

CONFIRMED at protocol/SDK level; INFERRED at source level — Appwrite

Headers, generator and compatibility cap

Official examples use `X-Appwrite-Project`, `X-Appwrite-Key`, JWT/session and admin mode. Official SDKs negotiate `X-AppBase-SDK: true` and `X-Appwrite-Response-Format: 2.12.0`; native Appwrite-compatible clients have a separate default 1.9.0 cap.6,7,18 The Python guide explicitly warns not to substitute the open-source `appwrite` package because it lacks Agentbase surfaces, and the public Node artifact identifies Appwrite’s custom SDK generator.18,29

What remains inference: the exact server-side fork and upstream commit. No public `oceanbase/appwrite` repository was found in the code-evidence pack.

CONFIRMED — SDK packaging; UNCONFIRMED — one PyPI artifact

Public npm, ZIP-only documented Python, and a naming discrepancy

The documented Node/Web/Console packages are `agentbase-*-sdk@2.12.0`; the Python 2.12.0 server and console wheels are documented as release-ZIP installs, not PyPI, requiring Python 3.9+, `requests` and `pydantic>=2,<3`.18,29 Yet PyPI serves `agentbase-python-sdk` 15.5.0, uploaded 2 September 2026, with Agentbase Team metadata and no project links.30 Whether that artifact is an official legacy line, stale package or something else is unconfirmed.

CONFIRMED — OceanBase uses ATIF-v1.8; INFERRED — Harbor identity

Agent Trajectory Interchange Format

OceanBase expands ATIF as Agent Trajectory Interchange Format v1.8, derives it server-side, requires `trajectory.schema_version=ATIF-v1.8` with nonempty `steps`, and normalizes text, image, audio and tool evidence.7,9 Harbor’s active April 2026 RFC defines the same name and current version, the same `schema_version`/`steps` shape, tool-call result IDs, subagent trajectories and v1.8 audio parts.31

High-confidence inference: this is Harbor’s ATIF family. OceanBase’s docs do not cite Harbor or declare conformance, so full schema compatibility and governance remain unconfirmed.

UNCONFIRMED — physical trace layout and ForkDB wiring

Product architecture stops at “high-performance trace storage”

AgentOps docs describe unified authentication/control plus a high-performance trace store and asynchronous evaluation engine, but not the store’s engine, table layout or SQL exposure.8 OceanSeek independently documents ForkDB, while Agentbase independently documents Runtime dataset replay; no reviewed source says the two are automatically coupled.11,22

CONFIRMED — version skew at fetch time

Docs, package tags and the live service are not one version

The docs catalog offers 2.8.0–2.12.0 and marks 2.9.0 default.19 Collector checks observed the live health endpoint reporting 2.13.0 and npm’s `latest` tag at 2.11.2 while a `release-2.12.0` tag existed.20,29 This is a compatibility question for the CTO, not evidence that any one version is broken.

05 / Delivery and commercial model

5. Deployment, open source and pricing

Deployment is documented; its boundaries are not

The official “Understand Agentbase” page explicitly supports cloud-hosted service and private deployment for data-residency and independently controlled environments.3 The hosted production API is `https://appbuild.oceanbase.com/v1`, with a separate SIT endpoint and web console.40 A Project binds a physical region, but the public deployment guide says region is usually `default` and provides no region catalogue.6,40 Minimum private topology, BYOC, customer-managed keys, SLA, GA date and regional residency commitments are unconfirmed.

OceanLake has a separate availability ambiguity: TechNode reports cloud or private deployment with selectable layers, while the Chinese launch report says the engine was already used by offline customers and a cloud version was “coming soon.” The safer conclusion is not to equate the OceanLake launch with cloud GA, and not to transfer OceanBase’s company-wide cloud footprint to Agentbase.33,34,36

Open source: open substrate, unconfirmed Agentbase boundary

  • OceanSeek: Apache-2.0; public README, code tree, build guide, Docker/Kubernetes paths and S3-compatible object-storage requirements are available.23
  • seekdb and PowerContext: also public Apache-2.0 projects. PowerContext is the successor to PowerMem, not the same thing as either database.24,25,26
  • Agentbase itself: no official Agentbase server repository or open-source license was found in the reviewed product docs and OceanBase GitHub organization sweep. That is an unconfirmed licensing/open-core boundary, not proof that no release is planned.1,6,23
  • SDKs: JavaScript packages are publicly inspectable on npm. Documented Python, Java and Go 2.12.0 distributions use release ZIPs rather than their normal public registries; the Python package’s release-host contents could not be inspected in the code pack after connection timeouts.18,29,68

Pricing: quote-led, with no public unit economics

The product page offers trial and solution-consultation calls to action, not an Agentbase SKU or price per project, trace, token, seat or instance.1 The order page exposes Catalog → Quote → PreCheck → Create rather than a public rate card; the docs pack also observed its notice that cashier, payment, fulfillment and metering were not open.21 No free-tier quota, private-deployment minimum or price/retention curve was confirmed. This makes cost a meeting question, not a basis for claiming Agentbase is cheaper or more expensive than BQAA.

08 / BQAA strategy

8. Threats and opportunities for BQAA

Threats to take seriously

  1. Suite compression. Agentbase bundles the backend, memory, knowledge, runtime, evaluation and governance that a customer otherwise assembles around BQAA.1,6,13,15 Procurement can prefer one control plane to a plugin plus warehouse plus custom workflows, even if BQAA has the stronger analytical surface.
  2. Instrumentation neutrality. Agentbase, Langfuse, LangSmith, MLflow and TruLens all document OTel-oriented paths.7,45,52,56,62 BQAA’s documented Storage Write API producers can look like a second instrumentation project when a customer has already standardized on OTel.41,42
  3. Lower Langfuse migration friction. Agentbase speaks a Langfuse-compatible event and metrics model, giving existing Langfuse users familiar entities and APIs.7,45 BQAA’s event-row schema requires explicit producer and consumer mappings.
  4. A more closed quality loop. Agentbase joins annotation, low-score RCA, datasets, Runtime replay, Memory evaluation and knowledge-index evaluation.9,10,11 BQAA’s rich judges and eval suites can feel lower-level if the bad-case → dataset → replay → release path is not equally guided.41,43
  5. Private deployment plus open database substrate. Agentbase officially supports private environments, while OceanSeek, seekdb and PowerContext are Apache-2.0.3,23,24,25 That is a strong answer in data-residency, on-premises and China/Southeast Asia financial settings where a BigQuery-only architecture may not be acceptable.
  6. Warehouse-native differentiation is narrowing. Databricks stores traces as governed Delta tables with direct SQL; Snowflake stores immutable traces/scores with SQL functions.56,61,62 “Our traces are queryable” is becoming table stakes.
  7. Trust and cost narrative can cut both ways. Agentbase’s quote-only pricing and version skew are weaknesses, but BQAA’s Storage Write, query, storage, GCS, AI-judge and optional compute charges also make total cost harder to explain.19,20,21,42,44 Competitors already publish simple unit prices.48,54

Opportunities BQAA can act on

  1. Ship an OTel GenAI compatibility bridge. Build a collector/exporter from OpenTelemetry GenAI conventions—and, where useful, OpenInference—into canonical `agent_events`.41,42,66 Preserve unknown attributes, parent links, source provenance and delivery gaps rather than flattening everything into a few model fields. This directly answers Agentbase, Langfuse, LangSmith, MLflow and TruLens portability.45,52,56,62
  2. Make ATIF and Langfuse mappings a neutral interchange layer. Publish tested converters for Langfuse events and ATIF-v1.8 into `agent_events`, with loss reports and conformance fixtures.9,31,43,45 BQAA’s existing idempotent LangSmith export is a useful proof that export can be an anti-lock-in feature rather than a concession.43
  3. Propose an Agentbase partnership, not only a rivalry. A supported Agentbase/ATIF → BigQuery export, OTel fan-out recipe or ADK integration would let OceanBase keep runtime, memory and private deployment while BQAA provides cross-domain analytics.3,9,15,41 This is the most concrete meeting ask.
  4. Lead with business-outcome joins. Productize governed recipes for revenue, conversion, retention, support cost, fraud and task completion, building on BQAA’s explicit order-value example and job-label spend attribution.41,43 The message should be “connect agent decisions to business consequences,” not “we also have SQL.”
  5. Package the quality loop as one workflow. Combine BQAA’s existing judges, golden suites, trajectory matching, drift detection and eval-suite lifecycle into guided bad-case → dataset → judge → replay → release flows.41,43 Agentbase’s annotation/RCA and Memory/index-specific evaluations are concrete feature references.10,11
  6. Define a warehouse-native evaluation-branch contract. Package isolated evaluation datasets, frozen business-data versions, replay manifests and promotion/rollback results while clearly distinguishing data snapshots from live model and tool execution. OceanSeek’s ForkDB shows the user value; it does not need to become a claim that BigQuery and OceanSeek have identical mechanics.22,43
  7. Turn memory into an evaluated data product. Add memory precision/recall, staleness, contradiction and business-outcome measures to BQAA’s long-horizon memory and context graph.41,43 Agentbase’s ten-stage Memory evaluation shows that “memory exists” is not the same as “memory works.”10
  8. Publish reference TCO and reliability dashboards. Use SDK job labels to expose write, storage, query, GCS, judging and retention costs next to delivery/drop metrics.42,43 A buyer should be able to compare a 30-day and one-year workload without a bespoke cost study.
  9. Use the market validation. OceanBase is arguing that agent traces, memory, evaluation and business data belong near the database; Databricks and Snowflake are making similar warehouse-native moves.2,56,61 That validates BQAA’s direction and gives it permission to be the open, cross-framework analytical layer rather than another full runtime.

09 / CTO meeting

9. 12 questions for Charlie Yang

  1. Where exactly do AgentOps Trace, Observation and Score rows live, and can customers query them with SQL and join business tables?Why it matters: this decides whether Agentbase is an observability console or an analytical data platform, and whether BQAA’s open-schema advantage is real.7,8
  2. Which OTel GenAI semantic-convention version is pinned, where is the full attribute→field mapping, and what happens to unknown attributes? Is OTLP gRPC, logs or metrics ingestion planned?Why it matters: lossy mapping breaks cross-system debugging and any shared instrumentation strategy.7,8,66
  3. Is production AgentOps powered by the public `oceanbase/langfuse` fork, another Langfuse build, or a separate implementation? What is the upstream sync and schema-migration policy?Why it matters: “compatible API” and “maintained internal engine” carry very different operational risks.28,29
  4. Will you publish an ATIF-v1.8 conformance statement and exporter, including mappings to OTel GenAI, ADK events and BQAA’s `agent_events`?Why it matters: ATIF could become the cleanest joint interoperability surface rather than another proprietary trace view.9,31,43
  5. What are the ingestion lag, drop-rate, backpressure, replay and read-after-write objectives?Why it matters: accepted is not persisted and queue/retry loss is documented, so evaluation and billing need measurable completeness, not just HTTP 200.7,8
  6. For Afu and the roughly 10 TB/day trace workload, which parts are Agentbase, OceanBase/OceanSeek, AI Vision or Ant-built? What is counted, retained and queried each day?Why it matters: it turns an impressive scale story into a defensible reference architecture and cost model.32,33,38
  7. How are LLM judges calibrated against the annotation queues, and do dataset comparisons include sample sizes, confidence intervals and judge–human agreement?Why it matters: frozen evidence and low-score RCA are useful only if score differences and diagnoses are statistically trustworthy.9,10,11
  8. Does a Dataset Run automatically receive a Fork Database, and what does replay freeze—model parameters, tool responses, knowledge versions, memory and DB state?Why it matters: this distinguishes a strong branch primitive from end-to-end reproducible evaluation with safe side effects.11,22
  9. What is the strategic boundary among native Memory, hosted PowerContext, PowerMem’s successor, seekdb and OceanSeek?Why it matters: customers need one memory/state recommendation and a migration path, not four overlapping stories.13,23,24,25,26

  11. What is the supported compatibility version, GA status, private-deployment minimum, region catalogue and commercial unit?Why it matters: docs 2.9.0 default/2.12.0, npm `latest` 2.11.2 and live 2.13.0 are not an integration contract, and quote-only pricing prevents TCO comparison.19,20,21,29
  12. Would OceanBase jointly support ADK/A2A/LangGraph integration, OTLP fan-out to BigQuery, or an Agentbase/ATIF → BigQuery exporter?Why it matters: a yes creates a practical partnership: Agentbase for runtime and private execution, BQAA for open business analytics.9,15,41
