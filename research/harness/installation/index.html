Reviewers

  • Seats (resolved 2026-10-20): code PRs the Opus seat implemented get Astra alone; docs, drafts and other seats’ code keep Astra + Fable blind dual review; a Fable-authored PR in a two-seat lane (a doc or draft) keeps the 09-16 fallback — Kimi (or Muse) as second blind reviewer for that PR only; a code PR the Fable coding seat authored is Opus-implemented and gets Astra alone. When Fable is limited, Sol 6.1 takes Fable’s place as the second blind docs reviewer (Haiyuan 2026-10-20 10:50 PT). Implementer ≠ reviewer on the same PR, always. reviewer rule
  • Method: each reviewer is blind to the other (PR + intent/spec/plan only), attempts disproof with 2–3 named rejection criteria, and ends with exactly one VERDICT: … @ <head sha> line — UNPARSED never counts. disproof · verdict line
  • Rounds: re-reviews read only the new diff and never re-raise findings; P0/P1 introduced by the change block; Pre-existing never blocks; three fix rounds, then escalate to Haiyuan (2026-10-20 02:39 PT). converging re-reviews · round breaker
  • Public posts: a GitHub review is posted only when a seat has a P0/P1 introduced by the change (from 2026-10-19 14:08 PT; BQAA SDK #534 posts all findings). blockers only
  • Approved by Haiyuan 2026-10-20: three review-depth tiers by consequence; complementary seat focus. Proposed, not built yet: an Astra reviewer eval. depth tiers

Gates

  • Human gates: merge, production, send/publish, spend, delete non-junk, permissions = Haiyuan, always (GREEN/YELLOW/RED); an approval is re-checked — item unchanged, authority current — right before the action runs (approval re-check). Standing approvals on record: Collection’s Field Brief publish blanket; Manage’s Lab + playbook publish blanket (promotion ladder).
  • Decision queue: irreversible asks and judgment calls wait in one queue file, checked daily on the 09:09 sweep; one re-raise at 3 days (decision queue).
  • Jev gates: active — intake, pre_browser, pre_retry, pre_research, pre_tool (confidence floor 0.55; pre_tool never authorizes send/pay/merge); shadow-only — research_check, completion_check, and worth_running (narrowed 2026-09-27 to retries and one-off launches). Shadow → active needs Three-Run Proof + a replay check + beating the constant baseline (gates · baseline).
  • Launch gates (Mac): tmux + streaming + ~540s watchdog; spawn-ok probes before any launch after Mac trouble; hold long launches below 15 GB free; a stale run resumes only after the old process is confirmed gone, else parked — enforced since 2026-10-20 12:16 PT by the installed ownership guard (attempt ID + workspace per launch, only the current attempt publishes through grok-attempt-publish, restart refused unless the old process is proven dead; sessions launched before the install are parked, never killed) (§8 launch standards · resume safety).
  • Done gates: code decides done; done receipts carry VERIFIED + NOT VERIFIED; negative claims need a lookup that worked; a new check must be seen failing once (code decides done · check can fail).
  • Review gates: see reviewers above — dual LGTM is agent-complete, never shipped; merge only by Haiyuan.
  • Kill machinery: every routine has a pre-written kill condition and a receipt line; Monday kill review proposes pauses/deletes to Haiyuan; runs an outage prevented count as skip (kill conditions · kill review).

Which of these controls is enforced, report-only, manual or proposed — one row each — is tracked in the main page’s controls inventory (73 rules paired with enforcers, checked 2026-10-20).
