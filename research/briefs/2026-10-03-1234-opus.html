  • Industry NEW (1): LangGraph.js @langchain/langgraph 1.4.19 and @langchain/langgraph-sdk 1.12.1 (GitHub releases 18:38Z, npm 18:39Z). This is the only stable product release in the window. It is a patch release. I rank it because it fixes silent state-read and state-write bugs, the bar the 0634 brief set for LangGraph #8548.
  • Empty subgraph state: reading a subgraph's state returned every DeltaChannel as [] while plain channels were correct. Reads now use the checkpointer the parent resolved. Hydrating a written DeltaChannel without a checkpointer now throws instead of returning empty.
  • Lost updates: for a checkpointer: true subgraph, getState(config, { subgraphs: true }) returned values: {}, and updateState from the subgraph task's config was silently lost. Both are fixed.
  • Resume re-fired the interrupt: resuming from a subgraph checkpoint returned by getState re-fired the interrupt instead of applying the answer. Fixed.
  • SDK changes: the protocol SSE transport no longer retries on 4xx (except 408 and 429), and errors keep the HTTP status and body. After stop() cancels a run mid-turn, useStream reconciles against the persisted thread state, so messages that were never checkpointed no longer stay visible.
  • Python is behind: the Python counterparts (#8538, merged Oct 2; #8548, merged Oct 3 12:56Z) are still unreleased. PyPI langgraph is still 1.2.12, from Sep 21.
  • Academy NEW (3). All three are full PDF reads from the Fri Oct 2 listing. The 0634 brief screened them by abstract and named them as strong candidates for a later slot; none was carded.
  • BudgetSchemaBench (2610.00092, Megagon Labs, COLM 2026 workshop): schema context for data agents over an 80-database, 597-table catalog.
    • With lexical retrieval, raising the schema budget from 2.5% to 50% of the catalog lifts execution accuracy +18 pp. With dense retrieval the lift is only +3 pp.
    • With the needed tables removed, 94.6% of the "correct" answers name a removed table exactly. The model rebuilt the missing schema from memory.
  • The Delegation Danger Band (2610.00041, PayPal AI): a sub-agent that inherits a parent's superseded note.
    • The mid-sized model (Qwen3-1.7B) does worse than a fresh fork, by −0.19.
    • When the stale note arrives without the current note beside it, every model follows it, including 4B and 8B (reliance 0.90 / 0.94).
    • A curated handoff beats full inheritance on all three datasets.
  • A Verifier Can Leak the Answer (2610.00126, Blossom AI): an exact solver and a greedy one "agreed" in 12/12 cases only because the probes had already revealed the planted fault (9/9).
    • The fix is a verifier that abstains unless it has eligible, comparable evidence.
    • A preregistered heldout produced 0/20 false admissions (95% upper bound 0.139).
    • Caveat: the agent is a simulator policy, not an LLM.
  • The theme: all three papers show that an agent record can mislead unless it says what the agent was given:
  • how much schema was in budget, and whether the answer could have come from memory;
  • which inherited notes the child saw, and whether a current note sat next to the stale one;
  • whether the verifier's probe already encoded the answer.
  • For BQAA: log the inputs of each step, not just its outputs: schema-context budget and recall, inherited-context provenance, and the verifier's eligibility state.

I1 (NEW). LangGraph.js 1.4.19 / SDK 1.12.1: subgraph state reads stop coming back empty, subgraph updates stop being lost, and SDK streams stop retrying 4xx

  • What shipped (Oct 3, 18:38Z, GitHub releases; npm 18:39–18:40Z):
  • @langchain/langgraph 1.4.19, @langchain/langgraph-sdk 1.12.1;
  • @langchain/react, vue, svelte and angular 1.2.1 (dependency bumps only);
  • @langchain/langgraph-api, -cli and -ui 1.5.2 (dependency bumps; "no changes" for -ui).
  • Core fix (#2906, merged Oct 2 15:19Z, released now):
  • Empty reads. getState, getStateHistory and updateState resolved the checkpointer in a way that came out undefined for subgraphs. So getState(config, { subgraphs: true }) showed delta: [] beside correct plain channels.
    • Only reads were affected; bulkUpdateState already hydrated correctly, so no bad state was written back.
  • Wrong namespace for checkpointer: true subgraphs. Their runs store checkpoints under a namespace without task ids, but the state methods looked under name:<task_id>. As a result, getState returned values: {} and updateState from the subgraph task's config was silently lost. Runs and all three state methods now share one namespace rule.
  • Replay re-fired the interrupt. Returning the real subgraph checkpoint exposed a resume bug that also affects default subgraphs. Replaying from a subgraph checkpoint and then resuming re-fired the interrupt instead of applying the resume value.
  • Checkpointer flags are now enforced:
    • a checkpointer: false graph no longer writes state through a checkpointer lent via config;
    • a checkpointer: true graph used as a root fails state methods with the run's error rather than a TypeError.
  • Cost (PR table): root reads are unchanged. A subgraph read adds one history lookup, matching a root read.
  • SDK fixes in 1.12.1:
  • #2918: the protocol SSE transport stops retrying stream/events on 4xx (except 408/429), keeps the HTTP status and body text on errors, and resets the reconnect counter after each successful connect. Idle reconnects no longer use up maxReconnectAttempts.
  • #2882: after stop() cancels a run mid-turn, useStream reconciles its buffer against persisted thread state. Messages that were never checkpointed no longer stay visible.
  • Why BQAA cares:
  • Anything that reads LangGraph state for analytics, such as time-travel debugging, HITL audit or state diffs, could have recorded empty subgraph channels or lost subgraph edits as if they were real.
  • Before this release, an empty DeltaChannel in a subgraph snapshot from LangGraph.js is suspect, not evidence of an empty channel.
  • Readers of LangGraph checkpoints should key on the library version. Python LangGraph has the same fixes merged (#8538, #8548) but not released (PyPI langgraph 1.2.12, Sep 21).
  • Bar note: this is a patch release and is ranked for state-history correctness, not new capability. The 0634 brief set the same bar for LangGraph #8548. No LangGraph card exists in the catalog (grepped). I propose this card as the parent for the Python release when it ships.

Academy

A1 (NEW). BudgetSchemaBench: how much catalog schema a data agent gets, and what it answers from memory when the needed tables are missing (arXiv 2610.00092)

Full PDF read (11 pages, including Appendix A). Chen Shen, Megagon Labs. Accepted at the COLM 2026 Workshop on Context Beyond the Window. cs.CL. Submitted Sep 8; it first appeared in the Fri Oct 2 listing.

  • Setup (§3, Table 2):
  • Catalog: the pooled BIRD dev+train union, 80 databases, 597 tables, 127,560 tokens (cl100k). 24.5% of tables have a base-name collision with a table in another database.
  • Budgets: the schema payload is capped at 2.5 / 10 / 25 / 50% of the catalog (3.2k to 63.8k tokens). Tables are packed whole, in retriever-rank order.
  • Questions: the 1,279-question held-out complement.
  • Three regimes: end-to-end retrieval; frozen-gold (the needed tables are guaranteed); and a probe that removes the needed tables.
  • Labels are derived mechanically from gold SQL (no human or LLM annotation).
  • Source-namespace contract: a result-equivalent answer read from the wrong database counts as an error, with lineage checked by sqlglot parse.
  • Results:
  • Budget matters when retrieval is coverage-limited (Table 3):
    • Primary solver gpt-5.4-mini, lexical retrieval: execution accuracy goes 0.38 to 0.55 as recall goes 0.60 to 0.90 (Δ +0.18, CI [0.15, 0.20]).
    • Dense retrieval already has recall 0.92 at the smallest budget, so the gain is only Δ +0.03.
    • gpt-4o-mini: +0.09 lexical, about zero dense.
  • Memorization floor (§4): with the needed tables removed, the solver still answers 4–19% correctly. Of the 1,236 predictions counted correct, 94.6% (1,169) name a removed table by its exact name. That is consistent with rebuilding the absent schema from what the model learned in training (15/15 sampled flags confirmed by hand).
  • Representation barely matters once the needed tables are in context (Table 4): raw DDL, enriched (with column descriptions) and hybrid differ by at most 0.02. No contrast survives Holm correction, and the widest paired CI is ±0.04.
  • The lineage contract changed the classification of only 2 of 797 sampled result-correct predictions (0.3%).
  • Off-family replication (Table 5): DeepSeek-V4-Flash reproduces all three patterns, with the same lexical Δ of +0.18.
  • Limitations (stated):
  • One BIRD snapshot. BIRD's gold SQL carries known annotation noise.
  • Only 11 source databases in the clustered bootstrap.
  • Single decode at temperature 1.
  • Representation-aware retrieval is out of scope.
  • The memorization floor is not separated from generic schema-name priors; there is no identifier-randomization control yet.
  • The dense retriever is near-saturated, so the catalog may understate how hard schema selection is.
  • Why BQAA cares:
  • This is the BigQuery data-agent setting: a large catalog, schema that does not fit, and a retriever that picks tables.
  • The schema-context budget and table recall for each step drive accuracy more than serialization format. They belong in the agent's trace.
  • A correct answer can come from training memory of a public schema rather than the schema the agent was shown. Logging which tables were in context lets an analyst flag "answered about a table it was never given".
  • "Right result, wrong source database" needs a lineage check, not a result match.

A2 (NEW). The Delegation Danger Band: mid-capability sub-agents over-trust inherited stale state, and every model follows a stale note that arrives alone (arXiv 2610.00041)

Full PDF read (16 pages, including appendices A–J). Jundong Hu and Shekar Ramachandran, PayPal AI. cs.MA. Submitted Sep 3; it first appeared in the Fri Oct 2 listing.

  • Setup (§3): a parent forks a child under one of three inheritance policies:
  • RESET: fork fresh, base evidence only.
  • SELECTIVE: a curated handoff of the base evidence plus the useful current conclusion.
  • FULL@d: an implicit fork that also carries d copies of a superseded conclusion, with d = 1 to 32.
  • Solvable without the notes: every task can be solved from the base evidence alone, so any loss is reliance on stale state.
  • Models: Qwen3 0.6B / 1.7B / 4B / 8B (plus 14B), with Llama-3.x as a cross-family check.
  • Tasks: two synthetic primitives (summation, counting) plus MuSiQue and HotpotQA. Scoring is judge-free closed-set matching.
  • Results:
  • Deference falls with capability (§4): the slope of stale-reliance against clean accuracy is negative on all four task families, and every CI excludes zero (Spearman −0.80 to −0.91).
  • But harm is band-shaped (§5, Table 1):
    • Only Qwen3-1.7B falls significantly below its fresh-fork baseline: Δ(32) = −0.19 [−0.25, −0.12].
    • 4B, 8B and 14B stay positive (+0.15 / +0.13 / +0.20), and 0.6B is near zero.
    • 1.7B is a significant local minimum against both of its neighbours.
  • Stale meaning causes it (Table 5): at 1.7B, matched-length neutral filler (+0.33) and 32 copies of the right answer (+0.36) both help, while stale notes harm (−0.15).
  • The strong models are not immune (Appendix G): with base evidence plus a stale note and no current note, every model follows the stale note.
    • Reliance is 0.69 / 0.97 / 0.90 / 0.94.
    • 4B and 8B accuracy drops by 0.75 and 0.78.
    • Strong-model robustness in FULL comes from comparing two notes, not from recomputing.
  • A live fork reproduces it (Table 8): when the parent writes the stale note itself and the child inherits it through a full-context copy, 1.7B is harmed from dose 1 (Δ(32) = −0.43).
  • What works (§6, Table 2): curated handoff beats full inheritance on all three datasets (+0.211 synthetic, +0.104 MuSiQue, +0.068 HotpotQA).
    • A capability-threshold router helps on synthetic (+0.048) but hurts MuSiQue (−0.054).
    • No observable router transfers in leave-one-dataset-out testing (Appendix J, Table 9).
    • Turning on thinking at 1.7B does not remove the effect (−0.17 versus −0.15).
  • Limitations (stated):
  • Small open models only (≤14B; 14B on the synthetic core only).
  • On the real datasets, no model enters the band at default difficulty; the band evidence comes from the matched-difficulty sweep and the Llama replication.
  • The harm needs the stale note to be recent; placed at the start of context, it disappears.
  • The live fork runs in the authors' harness, not a production runtime.
  • Why BQAA cares:
  • Sub-agent spans should record what context the child inherited: full, curated or fresh, plus whether a superseded note was present and whether a current note sat beside it.
  • The most dangerous case for every model size is a stale note without its correction. That is detectable from inheritance provenance and invisible from the child's output alone.
  • Pairs with Causal Recovery Eval (2610.00372, carded at 0634): both say to score delegation and retry choices against a counterfactual, not by average success.

A3 (NEW). A Verifier Can Leak the Answer: audit evidence eligibility and non-revelation before comparing optimizers (arXiv 2610.00126)

Full PDF read (7 pages). Peiying Zhu and Sidi Chang, Blossom AI. cs.CR. Submitted Sep 9; it first appeared in the Fri Oct 2 listing.

  • Setup (§3):
  • A trace debugger watches a closed-loop decision agent in a simulator (24 policy components, 3 demand regimes, 72 regime-component units) and tries to localize a planted fault from aggregate traces.
  • It turns discrepancies into conflict sets and solves them with exact minimum hitting set or a greedy method.
  • Caveat: the agent is a fitted policy, not an LLM.
  • The failure (§4, Table 1):
  • Exact and greedy returned identical answers in 12/12 development cases and recovered the planted fault in 9/12.
  • An audit found why: the exact-anchor predicates produced the planted pair in 9/9 cases. After those anchors were removed, a single-component hard probe still produced it in 9/9.
  • 0/9 cases had any ambiguity left after propagation. The optimizer was correct, but the verifier had already disclosed the answer.
  • The fix (§5): a support-gated verification contract.
  • State sequence: REFERENCE_ABSTAIN → RUNTIME_ABSTAIN → SIGNAL_ELIGIBLE → DETECTED / NOT_DETECTED.
  • Reference gate: a clean reference map must show the component was exercised (support ≥12 in ≥14 of 15 partitions).
  • Runtime gate: reference and current streams must have matched support in the same partitions.
  • Detection: only then may a pre-fixed signal rule (z ≥ 1.50) fire.
  • Separate verdicts: execution, safety and structure each get their own label, with no combined PASS.
  • Preregistered heldout (§6–7, Table 2):
  • Scale: 1,440 cases and 21,600 partition rows; all 56 independent validation checks passed.
  • Admission: the reference gate admitted 55/72 units, and the runtime gate admitted 54 of those 55.
  • False admission: 0/20 represented components (one-sided 95% upper bound 0.1391, inside the frozen 0.20 rule).
  • Traffic predicts detection: affected clean traffic predicts detection better than the share of cells edited, by 0.126 nats per row, CI [0.059, 0.192].
  • Limitations (stated):
  • One simulator and one policy family; not an LLM agent.
  • The heldout does not confirm fault localization.
  • About 20 component clusters, and the family-sufficiency margin is thin (0.0034 nats).
  • The "refresh" endpoint is a smoke test only.
  • Why BQAA cares:
  • An eval pipeline that converts traces into predicates and then scores them can be deterministic and still leak the answer through how its probes are scoped.
  • For BQAA's eval and diagnosis tables, the states "not testable here" (abstain) and "verifier is non-revealing" should be first-class columns, separate from "detected".
  • Coverage should be indexed by actual traffic through the component, not by the size of the injected change.

  • tag: Academy · title: The Delegation Danger Band: sub-agents over-trust inherited stale state
  • arXiv: 2610.00041 · https://arxiv.org/abs/2610.00041
  • card: When a forked sub-agent inherits a superseded parent note, mid-capability Qwen3-1.7B does 0.19 worse than a fresh fork, while 4B–14B stay robust because they compare the stale note with the current one. Curated handoff beats full inheritance on all three datasets, and no capability router transfers across datasets (full PDF read).
