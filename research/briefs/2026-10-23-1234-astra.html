A reliable score needs a denominator and an evidence boundary. promptfoo now reports repeated-test instability while withholding confidence intervals contaminated by cache reuse. Opik exposes failed score records excluded from aggregates and separates a request to stop an experiment from its actual completion. These are shipped changes to evaluation behavior, not admissions of the underlying PRs. promptfoo 0.125.0, Opik 2.2.119, October 23.

The other two updates affect what a trace can establish. Langfuse separates requested skill loads from available and loaded skills, and retains execution issues alongside stored transcripts. Langfuse 4.69.0, Agno 3.1.10, October 23.

Progress — promptfoo 0.125.0 makes repeated evaluation and trace selection explicit

Target catalog item id: promptfoo-0-123-1-openai-agents-api-portable-mcp-schemas.

Primary: 0.125.0 release, stable, October 23 15:32:01 UTC / 08:32:01 PT; npm 15:56:53 UTC, under latest.

Repeated evaluations now group results by test, expanded variables, provider and prompt, exposing pass/fail/error counts and cache reuse through results.repeatStability. Pass rates exclude errors. Wilson 95% intervals are omitted when target or grader responses were cached, or when no scored rows exist; independent runs with a fixed success probability remain an assumption even without cache hits. Shared conversation history and changing external state can violate it. The release includes the follow-up that recognizes cached graders inside nested/mixed grading aggregates. Repeat reporting, nested grader-cache accounting.

Trace count, duration and error assertions can now select spans by exact attribute matches as well as names. All supplied attributes must match; missing attributes do not. Duration percentiles and error percentages use the selected spans. When an operation is required, pair those assertions with a minimum count: a latency check alone does not establish that the operation happened. Released trace filters.

BQAA inference: store the cohort definition, scored/error counts, target-cache and grader-cache flags beside each stability statistic. Preserve an explicit “required operation absent” result rather than letting an empty selection look healthy. This is one product update; the release's other assertion types, safe mode and dependency changes are not additional cards.

Progress — Opik 2.2.119 makes experiment completion and omitted scores inspectable

Target catalog item id: opik-2-2-99-triggered-alerts-aws-eventbridge-mcp-instructions-deferred-tools-server-breakdown-row.

Primary: 2.2.119 release, stable, October 23 11:21:50 UTC / 04:21:50 PT; PyPI 11:16:55 UTC, unyanked. Same-window 2.2.118 is grouped here, not ranked separately.

Regular-dataset playground runs execute on the server, cover the dataset subject to active filters, and survive navigation or closing the tab. Explicit Stop cancels queued work; a provider call already in progress may still return a result. Per-variant state, failures and finished_at distinguish cancellation requests from the end of result production. Released execution behavior.

A recorded outcome keyed by stream-entry ID prevents a later redelivery from calling the provider and counting completion again. This is not general exactly-once execution: the implementation notes explicitly retain reruns when a pod dies during the provider call before recording an outcome; in-progress leases and additional finish/admission recovery remain follow-up work. Redelivery behavior and remaining limits.

Python ScoreStatistics.failed_count now reports failed score records excluded from survivor statistics, and the statistics table gains a Failed column. A single trial may produce several records under one metric name, so len(values) + failed_count counts score records, not necessarily trials. All-failed metrics still disappear from the returned aggregate dictionary, with a warning; consumers must not infer that every configured metric has an aggregate row. Released aggregate contract.

BQAA inference: retain requested, queued, attempted, recorded and drained states separately. Model metric coverage from explicit records and configured metrics, not just rows that survived aggregation. Hosted deployment and independent reproduction were not verified.

Progress — Langfuse 4.69.0 separates skill requests and execution issues from conversation text

Target catalog item id: langfuse-v4-61-0-v4-63-0-skills-gateway-keys-experiment-filters.

Primary: v4.69.0, stable/latest, October 23 14:03:13 UTC / 07:03:13 PT. This advances 4.68.0; its score-provenance exports are not re-Progressed.

The generation preview separates requested from unrequested skills and shows distinct requested paths. It derives requests from output tool calls, excludes malformed or ambiguous matches, and explicitly does not equate a request with a successful load. Separate available-skill and loaded-skill filters reach the trace sidebar and Users trace surfaces; Sessions are outside that filter change. Requested-load display, available/loaded filters.

The release also adds an assembly wrapper returning the transcript plus execution issues: ERROR observations and WARNING observations with a status message, including observations that emit no conversation messages. Issue records retain observation/trace identity, level, name, time and the first 1,000 status-message characters. They are stored as an optional V1 field; old objects read as an empty issue list. The author-described scope requires a transcript and does not pass these issues to the Topics summary model. Released storage/assembly scope.

BQAA inference: keep available, requested and observed-loaded states distinct. An empty issue array in an older object is not evidence that execution was error-free. Version the collection path, and verify which downstream evaluator actually receives the issue records before claiming better diagnosis.

Progress — Agno 3.1.10 retains larger traces and changes the meaning of Company ownership

Target catalog item id: agno-3-1-0-agentos-rbac-audit-log-per-user-filesystem-mcp-tools-opt-in.

Primary: v3.1.10, stable/latest, October 23 13:10:30 UTC / 06:10:30 PT; PyPI 13:11:21 UTC, unyanked.

Agno-created tracing providers now use OpenInference's 10,000 span-attribute default when neither relevant OpenTelemetry count limit is set, addressing eviction under the generic 128-attribute default. Explicit limits, their precedence and caller-installed providers are preserved. This increases retention capacity; it does not make tracing unbounded or guarantee complete capture. Released tracing change.

Company writes move from creator-ownership checks to resource scopes; user_id remains creator attribution. The change is breaking for deployments relying on user isolation to prevent members changing one another's Company records. Task-run ownership checks remain distinct. A Routine edited by another member can retain its creator identity while scheduled execution uses the editor's saved authorization; manual triggering of auto-accept routines checks the acceptance grantor. Released authorization scope.

BQAA inference: preserve creator, acting principal, authorization grant and effective scopes as separate dimensions. Attribute-count limits and producer version should accompany trace completeness checks. Neither a richer trace nor a creator ID establishes authorization correctness.

NEW — Post-Audit Mirage: Identifiability Limits of Offline Agent Verification — arXiv:2610.31130

Full PDF read — 17 pages. Submitted October 22. The useful contribution is an executable observation boundary: 272 safe/harmful lifecycle pairs × 50 rounds yield 13,600 byte-identical paired public inputs, opposite protected truth, and identical paired decisions from nine public-only diagnostic procedures (§§3–4). The theorem applies a standard indistinguishability argument; it is not evidence that those nine procedures are generally poor or equivalent.

Fresh group-labelled outcomes can resolve the declared group-harm question, but the difficulty sweep is the planning-relevant result. Of 18 controlled settings, the Hoeffding confidence-sequence monitor meets the prespecified qualification rule in 4, versus 9 for the beta-binomial confidence sequence, within 20,000 attempted observations (Table 7, Appendix D). At that final look, the primary monitor remains undecided for 70.0% of safe and 69.9% of harmful streams across the equally weighted controlled grid (Table 3). These are synthetic-grid results, not production error rates or formal sample-complexity estimates.

The guarantee requires independent, fixed-rate binary outcomes within declared groups, outcome-independent missingness and a stable target (§3, Appendix C). Unobserved groups cannot pass. Declared collection violations produce unsupported; undeclared bias is not automatically detected. The monitor addresses specified group harm, not complete deployment safety. The fixed panel's success and zero observed false-safe lifecycles do not establish zero risk (§4).

BQAA inference: add explicit cannot_determine and unsupported states to evidence-dependent analyses, with the missing group/outcome and collection assumptions attached. More trace replay can audit calculations; it cannot reconstruct an outcome that was never observed. Preserve the distinction between “need more observations” and “this collection design cannot answer the question.”

NEW — The Cost of Saying Hello: Handshake Overhead in AI Agent Communication Protocols — arXiv:2610.30151

Full PDF read — 15 pages. Submitted August 12; eligibility here is the Friday listing and the prior brief's unread-lead exception. Official SDKs contact minimal anonymous echo counterparts, with 50 measured runs per main cell, on one Apple-silicon machine (§4).

Table 2 reports median cold task-ready times under an emulated 50 ms RTT of 230 ms for legacy MCP, 122 ms for modern MCP, 61.0 ms for A2A and 62.1 ms for ACP. These are not end-to-end agent latency measurements. The userspace relay delays chunks; legacy SSE responses incur extra chunk delays, and TCP/TLS setup is excluded (§§4.5, 5.1). Preserve those qualifications rather than selling the ratios as universal protocol speedups.

The token accounting is independently useful. Replicating captured capability entries to 200 entries produces 15,618 MCP, 4,891 A2A and 21,405 ACP metadata tokens (Table 5). This is a constructed inventory sweep using o200k_base, not measured provider billing or real 200-tool server traffic. Content differs across protocols, including schemas versus shorter skill descriptions. The advertised warm-reconnect gains depend on caching policy: the modern MCP experiment supplies an explicit one-hour public TTL and distinguishes default revalidation from era pinning (§§4.2, 5.2). Authentication and live language-model negotiation are outside scope (§7).

BQAA inference: measure discovery, capability listing, readiness and useful execution separately. Record protocol/SDK version, cache policy, inventory size and whether metadata actually entered model context. HTTP metadata transfer is not automatically a billed model input, and cache reuse requires an explicit validity policy. No production savings estimate follows from this paper alone.

TL;DRs for BQAA

  • Opik: distinguish a recorded outcome from an attempted call, and failed score records from absent aggregate rows.
  • Langfuse: available, requested and loaded skills are different facts; old empty issue arrays do not prove clean execution.
  • Agno: keep creator identity separate from effective authority, and treat attribute retention as a configured limit.
  • Post-Audit Mirage: say whether more data could answer the question or the collection assumptions are unsupported.
  • Handshake overhead: account for setup phases and metadata context separately from useful execution and billed usage.
