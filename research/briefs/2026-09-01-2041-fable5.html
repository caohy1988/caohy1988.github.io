3. Parsing the Stream: A Live Trace Model for Long-Horizon Agents and Their Observers (arXiv 2609.01466, submitted Sep 1)

Egor Pakhomov and Erik Nijkamp. Code is released as SalesforceAIResearch/tracelab with a companion dataset on Hugging Face, so this is Salesforce AI Research. 22 pages.

The thesis is one sentence from the abstract: "A long-horizon agent's trace outgrows both of its consumers: the human observer monitoring the run, and the agent itself, whose bounded context the trace must be folded back into." Their answer is "an append-only event ledger folded incrementally into typed run state and compiled into per-consumer views." The ledger is the source of truth; the fold is deterministic; the views are compiled, not prompted.

Observer-side result, with an LLM reader as proxy for a human: the compiled view answered monitoring questions with "approximately 14x and 15x fewer input tokens" and "at 5-7x lower cost" than a budget-capped single read of the raw trace, at accuracy "0.85-0.87 versus 0.48." They flag that the questions were co-designed with the view schema and say only the token and cost reduction, "conditional on schema coverage," should transfer. Agent-side, on 120-link sequential tasks, per-step state maintenance succeeded 30/30 where full-context prompting managed 8/30; a plain scratchpad matched the fold's accuracy at lower cost, so the fold's remaining edge is "deterministic auditability and serving the observer from the same state." They derive eleven candidate requirements for trace folding from observed failures and show a task family where folding stops helping.

The wrong belief to kill: an observer product should summarize traces with a model. This paper's evidence points the other way: fold events into typed state deterministically, then let the model read the state.

TL;DR for BQAA. This is an outside argument for the named-loop and typed-state columns: an append-only event table plus a deterministic fold into per-run state is what an observer reads well, and the paper puts a rough 14x token reduction on doing it that way. The "schema coverage" caveat is the coverage matrix in academic clothing. Read the eleven requirements against the state-and-loop columns; the code is public.

4. EDGE: Error Dependency Graph-Guided Multi-Error Attribution in Multi-Agent LLM Systems (arXiv 2609.01360, submitted Sep 1)

Jun Hou, Priya Pitre, Yi Fang, Xuan Wang. Accepted to EMNLP 2026.

Premise: "LLM agent failures often contain multiple related errors rather than a single mistake." Existing attribution picks one agent, step, or root cause. EDGE builds an error dependency graph from observed error events, validates a causal subset by counterfactual rollout, and uses the graph to guide a two-stage LLM judge. Evaluated on TRAIL and MAST, the two public agent-trace failure benchmarks; the abstract says it "improves category-level multi-error attribution across most evaluated models and settings."

TL;DR for BQAA. Third paper in two days to treat forensics as attribution over a multi-error graph rather than a single root cause. The product implication is unchanged and now better sourced: an error row needs a parent-error pointer, or the attribution tooling everyone is building will have to reconstruct dependencies from timestamps.

5. Cheap Verifiers, Large Blind Spots (arXiv 2609.01345, submitted Sep 1)

Dushyant Rajput. Studies cascades where a cheap model answers and a stronger model verifies, then the cheap model is fine-tuned on rejections. Four findings, but one matters here: "the cascade's own dashboard, every metric computed through the verifier, reads a flat 3% error while true delivered error swings up to 32%: the system is blind to its own degradation by construction." Conclusion: "the reliability of a self-improving cascade cannot be read from any metric computed through its own verifier."

TL;DR for BQAA. Any quality metric BQAA reports that is computed by the same judge the agent uses to route or self-correct is structurally uninformative. The eval schema should record which model produced a verdict so that analysts can exclude in-loop judges from quality dashboards.

6. Three more, one line each

  • SAGE: State-Grounded, Abstention-Aware Evaluation of Task-Oriented Dialogue Agents (2609.00434). Compiles a workflow spec plus per-turn state diff into atomic criteria, routes them through symbolic and encoder verifiers that abstain rather than guess, and emits "a turn-level decision with an evidence trace." Decides 81–91% of criteria with no paid LLM call. Another vote for state deltas as the eval substrate.
  • Invalidation Contracts for Cross-Episode Agent Memory (2609.00243). Version stamps and cacheability hints on cached recovery suggestions so agents evict stale fixes without trial and error. Notable for the finding that identical bytes get 100% first-try compliance on one model and 11% or below on another. Memory rows want a version stamp.
  • The Irreversibility Budget (2609.00275). Fleet-level cumulative account of residual value-at-risk per principal, charged per effect at a trusted runtime. Per-effect gates admitted overdraws "up to 48 times the tenant's risk limit" in their study. An analytics question, not a spec one: can a fleet's irreversible effects be summed from the event table.
