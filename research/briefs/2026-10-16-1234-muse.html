Agno v3.1.4 — sandboxed harness agents: whole Claude/Codex processes run in per-session computers with verified, transactional checkpoints; durable queue extends to factory and db-backed components

  • What shipped: GH Release v3.1.4 published 2026-10-16T13:35:06Z (stable; full body read by me via gh api). Prior card is v3.1.3 (durable external-agent sessions); this ranks NEW on the sandbox execution surface, the same bar v3.1.3 cleared.
  • The execution contract is the story: ClaudeAgent(id="coder", db=PostgresDb(...), sandbox=DockerSandbox("agno-sandbox:local", network="isolated")) is the whole setup — no new classes. Each turn claims the session through a lease row (<session_table>_sandbox_bindings), starts compute restored from the session's last committed checkpoint (workspace plus the harness's own conversation files), runs the turn, then captures and verifies a new checkpoint and publishes the run row and recovery point in one transaction. A cancelled or failed turn publishes nothing and the previous checkpoint stays the recovery point. Crucially, the turn passes the native conversation id (Claude session id, Codex thread id) committed with the last checkpoint, and a restore that lost it fails with native_state_missing before the model runs — no silent fresh conversation masquerading as a continuation. Host-only settings (cwd, retries, env, native option objects) are rejected by name at construction; require_native_resume and strict_persistence are new options on BaseExternalAgent.
  • Two providers, one contract: DockerSandbox runs containers as UID 1000 with read-only image filesystem, dropped capabilities, no privilege escalation, CPU/memory/process limits, bounded tmpfs, no host or Docker-socket mounts, networking defaulting to none (isolated = managed bridge, inter-container traffic off), commands never auto-retried, and pause/resume via the kernel freezer. AgentCoreSandbox implements the same contract on Bedrock AgentCore Runtime (one Firecracker microVM per sandbox generation, idempotent create via derived session id, incarnation-fenced operations so a stale handle can never act on a later claim). The breaking-adjacent rename is handled honestly: CodexAgent(sandbox="read-only") becomes sandbox_mode, old form kept with a DeprecationWarning.
  • Durable queue completes its spread: background runs on components-API, version-pinned, and AgentFactory/TeamFactory/WorkflowFactory submissions now ride the durable queue instead of dropping to a detached task on the accepting replica; the accepting endpoint stamps a resolution scope (source, owner, version, trusted claims, factory input) on the ticket and the worker replays it at claim time. A factory that reads ctx.request on the worker fails the run with a message naming the fix — the live request cannot ride the ticket, and the system says so instead of failing obscurely.
  • Why it matters for BQAA: this is the first mainstream framework release where checkpoint verification is part of the run record's semantics: a run either committed (run row + recovery point, atomically) or it did not exist. That gives analytics a clean durability boundary to join on — sandboxed runs should carry sandbox provider, generation/incarnation, checkpoint commit status, and native-resume verification outcome, because "the agent continued the conversation" is now a checked claim (native_state_missing failures are a new, countable failure class) rather than an assumption. Compare Cline Cloud sessions (0034 brief): hosted execution is converging, and execution locus + checkpoint provenance are becoming required dimensions, not metadata garnish.

Langfuse v4.61.0–v4.63.0 — skills become first-class, versioned, usage-measured trace objects (public v4 preview); AI-gateway keys split from org keys; experiments get unified filter targeting

  • Skills graduate from span decoration to product object: v4.61 adds a dedicated skills tab on trace details (#18872), traces for selected skill versions (#18893), and getting-started onboarding (#18891); v4.63 adds a skill usage-metrics tab (#18947), improved browsing/editing (#18940), and exposes skill management as a public v4 preview (#18948). Read together: a skill now has versions, an attributable trace population per version, and usage metrics — the minimum needed to answer "did skill v7 change outcomes vs v6?" from the observability product itself rather than by reconstructing it from span attributes downstream.
  • Gateway and experiment plumbing moves with it: v4.63 separates AI Gateway keys from organization API keys (#18936) — gateway traffic gets its own credential/revocation domain — attributes gateway errors by origin and measures gateway overhead (#18919), and unifies per-experiment filter targeting (#17944), so experiment cohorts are defined one way. v4.61 routes gateway models by connection slug with per-connection model controls (#18628, #18642) and unifies manual trace processing with topic generation (#18840). v4.62 is mostly fixes (ClickHouse query-AST CTE resolution #18865, OTEL metadata decoding for SDK v5/v6 exports #18911, usage normalization robustness #18302) plus audit-log change events staged beside the Postgres audit log (#18769) — recorded here as part of the train, not as rank reasons.   • Why it matters for BQAA: skill-version-keyed trace populations are exactly the unit warehouse skill analytics keeps having to synthesize. If Langfuse emitters now carry skill id + version as first-class dimensions, BQAA ingests should preserve them as such (not bury them in attribute maps) so skill A/B and regression questions stay answerable after export. The gateway key split likewise changes credential-scope joins: gateway-originated usage will arrive under a different key domain than org API usage from v4.63 on.

Six-week EV

  • Sandboxed harness execution becomes a framework feature, not deployment glue. Agno's sandbox= (this brief), Cline Cloud sessions (0034), and Qwen's managed agents converge: within six weeks, expect every serious harness wrapper to offer an isolated-execution option, and expect the differentiator to be checkpoint semantics — Agno's publish-nothing-unless-verified rule is the bar others will be measured against. Analytics schemas should add execution locus, sandbox provider/generation, and checkpoint-commit outcome now, while the population is small.
  • Skills get their own analytics plane. Langfuse's versioned skills with per-version trace populations and usage metrics (this brief) plus Opik persisting repo skills/instruction files on trace identities (this brief, Progress) say the observability vendors have decided skills are a queryable entity. BQAA should expect skill id/version join requests and preserve those fields first-class on ingest rather than flattening them into attributes.
  • Score completeness becomes the quiet eval-integrity frontier. Braintrust's every-failed-row scoring fix (this brief) rhymes with DIB-Bench/AgentEval (0034): the failures that matter are the ones where the record looks complete but isn't — unscored failed rows, unverified restores, unbound evidence. Products that make completeness checkable (counts that must reconcile) will win the postmortems.
