Industry

Industry commentary: Josh Rosen, "System One Models Revisited: Two Months In"

INDUSTRY COMMENTARY (an analysis post, not a product launch). Josh Rosen (@JoshARosen), X Article, 2026-11-17. Source: https://x.com/JoshARosen/status/2122694429580443684

What it is. Rosen describes System One models as answering predefined questions (yes/no, pick an option, rubric score) with probabilities, "often in a single forward pass", without generating text.

Rosen's main points.

  1. Harness decisions. He writes that developers use these models for model routing, tool selection, permissions and task completion. "Early results are mixed": encouraging on some tool selection, "poor zero-shot performance on model routing".
  2. Validation. Checking an agent's claimed result against acceptance criteria and evidence; scoring execution traces against rubrics.
  3. Cascades. Uncertain decisions escalate to an LLM or a human. He argues confidence must be "calibrated against actual outcomes", notes accuracy "can deteriorate when options are reordered", and warns that too many escalations "can eliminate much of the expected savings".

Confirmed on primary pages. TypeSafe announced Jev on Sep 15. Then came Cloudflare's Clef (Oct 1) and Clairic preview (Oct 19); Liquid AI's d1 (Oct 5) and d1.2 (Nov 16); OpenAI's Decisions API (beta Oct 6, generally available Oct 22); Microsoft-Decision-1 (Oct 9), supporting "rubric-based grading of AI responses and agent actions"; and Google's Gemini Decisions API (Nov 11), for "tool selection, policy checks, model routing, and context grading".

Judge and verifier examples.

  • Foreman (MIT-licensed) supervises coding agents with Jev or OpenAI's Decisions API: yes/no probability checks such as requirements_satisfied and tests_sufficient feed a deterministic Python arbiter. Its README says assessment accuracy "is unproven for this use case and the semantic scores need calibration".
  • Jev Agent Completion Verifier and AI Agent Evaluation are pages on self-described independent guide sites, not TypeSafe's. One checks each acceptance criterion against observed evidence; the other grades a tool trace for completion, policy compliance and quality. Both show illustrative values; the verifier's are "invented to show branching, not measured results".

Already carded. OpenAI Decisions API public beta. arXiv 2610.02267, "Fast Models, Slow Evidence", the independent evaluation Rosen links: neither model beats chance on zero-shot model routing, and the author's own audit cut a reported 23.9% saving to 4.3% once an omitted pre-screen cost was counted.

Why it matters for BQAA/ADK. Writer's reading: a decision call that judges, verifies or routes is itself something to evaluate. Does the record keep the question, option order, evidence, probability and threshold behind each action? Was the verdict later compared with what actually happened? Does a savings figure count the gate's own cost and escalation rate?
