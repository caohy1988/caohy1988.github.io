Read this first

The three reserve papers all hold up on full read, and together they are one argument: report agent scores with their structure attached, or stop reporting them.

The hierarchical reliability framework (2611.19614) separates execution noise from task heterogeneity and shows the common pooled standard error understates uncertainty by ~2.93x in its worked example (0.02502 pooled vs 0.07329 hierarchical on the same 100x20 matrix, §3.2.1); on Thinkingbox, reinforcement fine-tuning lifts mean pass rate significantly while pass@5/pass@20 coverage differences have 95% CIs that include zero — it made solvable tasks more consistent without expanding coverage (§4.1, Table 1). DetourBench (2611.20844) replaces authored reference paths with a search-proved minimum: on eight tasks every model succeeds on every repeat yet conditional attainment still spreads 0.074–0.190 (Table 6), and deleting one signpost sentence drops view use by 63 points and success by 41 across 160 pairs (Table 1, §5.1). SilentGuard (2611.20595) finds silent failures in 11 of 15 public research APIs (overcounts to 691x, Table 8) and shows model-facing fixes — checklists, reviewers, judges, warnings — leave ~70–74% of answers wrong because agents report flagged counts anyway in 77.4% of flagged runs, while harness withholding of values that fail an exact invariant cuts wrong answers to 1.7% with no clean-task loss (Tables 2–3).

NEW 1 — AWS Agent Registry: custom metadata schemas for governed agent/MCP/skill records

Primary: AWS ML Blog, "Govern and discover records with common metadata in AWS Agent Registry" (2026-11-17T20:31Z feed timestamp, stable): https://aws.amazon.com/blogs/machine-learning/govern-and-discover-records-with-common-metadata-in-aws-agent-registry/. Not in live catalog (grep agent registry / custom metadata: no Agent Registry card).

Custom metadata schemas are "now available" in AWS Agent Registry: an administrator defines organization-wide key–value fields (business unit, owner, risk class, environment), applies the schema to a registry, and every record — agent, MCP server, skill or custom record — must carry validated values. Records with unknown/missing/invalid fields get a ValidationException; records saved with no custom metadata are held as NON_COMPLIANT and cannot be submitted for approval. Approvers review against validated values (EventBridge can trigger an approval function), and discovery APIs can filter records by these attributes. The worked example is a governed registry publishing a read-only payments-ledger MCP server enriched from existing security/inventory systems before approval.

BQAA read: governed agent inventory is the join key analytics needs. A vendor-side schema gate that blocks unclassified agents/tools at publish time is the registry analogue of BQAA's trace-side governance; trace exports that carry the same validated owner/risk/environment fields join cleanly to cost, quality and incident views.

NEW 1 — A Hierarchical Statistical Framework for Evaluating Agent Reliability — abs

Full PDF read (28 pages via pdftotext in chunks: abstract, §§1–5, Eq. (18)/(30)/(33), Figs. 1–11, Table 1, references, Appendices A–D incl. derivations and sample-size analysis; methods/results/conclusion included). Reserve promotion from 0034. Not in live catalog (grep 2611.19614: 0 hits).

Milletari & Kundu (Microsoft) organize evaluation as scenarios > instances > samples and derive how uncertainty propagates upward: scenario-level variance is the sum of a between-task term (task-heterogeneity tau²/M, untouched by more runs per task) and a within-task sampling term (Eq. 18). The worked toy (M=20 tasks, N=100 runs, Uniform(0,1) true probabilities) makes the failure mode concrete: identical data and identical mean (0.4825 at N=M=20) give hierarchical SE 0.07329 vs pooled SE 0.02502 — flattening repeats into fake tasks understates error ~2.93x, and the pooled SE keeps shrinking with N while the honest one plateaus on having only 20 tasks (§3.2.1, Fig. 5). They give exact finite-sample sampling variances for the unbiased pass@k (Eq. 30) and pass^k (Eq. 33, via subset-overlap/U-statistics), prove the plug-in p^k estimator is upward-biased for k>1 (App. C), and warn that plugging in observed rates yields estimated SE=0 at 0/N or N/N without proving certainty. Thinkingbox case study (5 scenarios, 98–104 instances each; base vs RL fine-tuned Qwen-3.8-27B): per-scenario mean-pass-rate gaps +0.039±0.008 to +0.145±0.012 (Table 1), but overall pass@5/pass@20 gap 95% CIs include zero while pass^k reliability rises — training sharpened already-solvable tasks rather than expanding coverage (§4.1, Fig. 10). Limits stated by the authors: binary outcomes for the metric formulas, tasks modeled as i.i.d. draws (deliberately selected suites may need another model), and no run budget fixes an unrepresentative task mix (§3.1); normal-approximation intervals need care on small sets (App. D).

BQAA read: BQAA dashboards should store per-instance attempt counts and propagate both variance terms; any "model A beats B by 2 points" claim from pooled repeats is exactly the 2.93x error shown here. Report pass@1 (typical), pass@k (coverage under retries) and pass^k (repeatable success) as three different questions, each with its own error bar.

NEW 2 — DetourBench: Trajectory-Level Evaluation of Interactive Agents with Exact Minimum-Action Bounds — abs

Full PDF read (15 pages in chunks: abstract, §§1–6, Tables 1–8, Figs. 1–3, Appendices A–I incl. selection audits, necessity audits, per-task results and oracle-cost timing; limitations in §6). Reserve promotion from 0034. Not in live catalog (grep 2611.20844: 0 hits).

DetourBench constrains each task to a finite, partially observable transition system where discovered resources stay globally addressable, so exhaustive BFS computes the exact full-information minimum charged accesses L_o with a replayable witness, plus exact residual work R_T from any recoverable terminal state; irreversible wrong commitments get no finite residual rather than a fake distance (§3.2–3.4). Success, conditional attainment (L_o/C on successes), residual progress and normalized detour are reported separately. Two results matter. Controlled pair (§5.1, Table 1; 40 Currency pairs, 960 episodes): removing one seed sentence that names an already-available view drops view use by 63 points, success by 41 points, and adds 2.9 out-of-scope reads per episode; on 176 both-arm-success pairs attainment falls 0.763→0.637 (delta −0.126, 95% cluster-bootstrap CI [−0.156, −0.099]). Integrated suite (§5.2–5.5, Table 2; 25 tasks x 5 endpoints x 3 repeats = 375 episodes): success 58.7–96.0% orders models one way, conditional attainment 0.803–0.890 another (lowest-success GLM still beats two models on attainment); eight tasks are solved by everyone every time yet attainment spreads 0.074–0.190, widest on task 3 where best/worst models both have RSR=0.000 (no repeats/invalid calls) but differ 17.0 vs 21.7 mean accesses (Table 4). Of 99 failures, 95 exhaust the 1.5x budget a median of 3 accesses from the goal (47 within 2), with duplicates/invalids only 7.6% of charged steps (§3.5). Stated limits (§6): model-informed screening (not prevalence), three repeats, the omniscient oracle does not net out lookalike-selection advantage, and semantic necessity is executed as content counterfactuals for only 4 of 25 tasks (structural removal audit: 309/314 oracle-route nodes load-bearing, App. C).

BQAA read: trajectory analytics need a reference cost that is proved, not authored. Where a workflow graph is knowable, store charged accesses against a computed minimum and split failures into one-step-short, budget-exhausted-far, and irreversibly committed — three different fixes that a binary score records identically.

NEW 3 — Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures (SilentGuard) — abs

Full PDF read (25 pages in chunks: abstract, §§1–6, Tables 1–31, Figs. 1–7, Appendices A–K incl. benchmark construction, per-model/per-fault results, cost, fine-tuning, cutoff sensitivity and the preregistered prediction log 26/39 held; limitations in §5.4/§6 area and App. K). Reserve promotion from 0034. Not in live catalog (grep 2611.20595: 0 hits).

A silent API failure is an HTTP 200 whose body does not answer the request sent. Probing 15 public research APIs found 11 with at least one silent fault: 10 return the unfiltered count for a plausibly misnamed filter (overcounts 2x–691x, Table 8/Fig. 3), 6 of 14 testable silently cap over-limit pages, 3 silently drop typo'd filter values (§5.1, Table 11). The controlled core (AgentOrchBench, 36 count tasks, 7 open models, exact grading) separates three ingredients. Evidence: a judge without extra queries leaves 71.7% wrong as advice and 70.8% even when blocking, because a self-consistent wrong count shows nothing. Permission: warned agents still report the flagged count in 77.4% (judge-flagged) / 64.4% (warned) of runs despite confidence dropping 1.00→0.43; adding "you may answer cannot-be-determined" cuts wrong to 18.2% but ranges 0–59% by model. Enforcement: SilentGuard checks every result in the harness (count identity N(F)+N(F<k and not C_k)=N(F<k) via its own extra queries, list membership, spec/parameter check, learned contracts; re-check once, withhold on exact-check failure, warn on learned-check failure) and leaves 1.7% wrong at most across models (per-model max 3.7%, Table 19) with clean accuracy unchanged (84.9% vs 84.9%); frontier models go 70.2%→0.5% (Table 5). Honest debits: it abstains rather than recovers (correct under faults falls 16.4%→2.4%; 67% coverage at 3.3% risk under a 25% fault rate, Fig. 2); on six post-freeze fault types wrong falls only 61.1%→24.5% (Table 6); auto-repair beats it on designed faults but ships 49 wrong answers marked "verified" on unseen faults; blind retry wins on faults that clear in 1–2 calls (ToolMaze 60.4% vs 47.6%) while repeating write actions 2.36x/run; self-consistent lies defeat any check built from the API's own answers (<=2.8% caught, Table 30); filters inside query strings evade the spec check (21.3% wrong remains on real APIs, uneven 38.6% pre-freeze vs 7.4% later APIs).

BQAA read: this is the harness-side twin of trace-side verification: judge/warning layers in BQAA pipelines should be assumed advisory until proven otherwise. Cheap exact identities (partition counts summing, returned rows satisfying the filter, parameters inside the published spec) belong in the tool-call path with withholding authority; "verified" must never label an auto-repair the check cannot confirm.
