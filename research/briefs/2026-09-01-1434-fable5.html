Industry

1. OTel GenAI conventions moved on main, not on the releases tab (Aug 20, Aug 27, Aug 31)

The releases page of semantic-conventions-genai is still empty, and that is what the standing check has been reading. The main branch tells a different story. Three merged PRs, all verified on their PR pages:

  • #440 (merged Aug 20). New span and event attributes for token usage broken down by modality and cache: gen_ai.usage.cache_write.input_tokens, and text, image, and audio splits for input, output, and cache-read tokens. Stated motivation: near-precise cost per inference operation. Tools, video, and document tokens deliberately skipped for now.
  • #469 (merged Aug 27). Removes cache_read and cache_write token attributes from the internal invoke_agent span. The reasoning is the useful part: an agent span accumulates usage over a call tree that may mix models with different cache semantics and pricing, so a cache breakdown at that level "is not interpretable on its own." Consumers should sum from the inference spans. Total tokens stay on the agent span; whether that is right is tracked separately.
  • #363 (merged Aug 31, 5:15 PM PT). Deprecates gen_ai.output.messages[].finish_reason in favor of gen_ai.response.finish_reasons. The array is positional by generation, and a position that started generating but never reached a terminal reason is reported as error rather than shifting later values left. If inference never starts, the attribute stays unset. The PR explicitly calls finish reasons "response metadata used for incident triage, evaluation, and dashboards."

The wrong belief to kill: the GenAI conventions are frozen because there is no tagged release. The registry is being edited weekly, and #469 is a design ruling about where cost attribution is allowed to live. Judgment: this is the most BQAA-relevant OTel movement in weeks, and we were not looking at the right page.

TL;DR for BQAA. Cost and cache columns should be first-class on model-call events and derived by aggregation on agent-level rows, never stored as independent agent-level facts. That matches #469 and avoids the "uninterpretable rollup" problem the spec just named. Finish reason as a positional array with an error placeholder is a cheap, spec-blessed fault signal worth mapping into the fault-edge design. Standing check should read the main-branch changelog fragments, not the releases tab.

2. Phoenix server 20.5.0 — replayed corpus, SQL over MCP, reasoning-token prices (Sep 1, 1:33 PM PT)

Shipped just before the 1335 as-of and not in that brief. Three items of substance, each verified on its PR page.

A replay sidecar for realistic session data (#15614). A new datagen server subcommand continuously replays a recorded trace corpus into Phoenix. It fetches a content-addressed archive from a public GCS bucket with no credentials, composes sessions so each one samples a single application archetype and domain and never mixes applications mid-session, replays with fresh trace, span, and session IDs, shifted timestamps, token and duration jitter, and a fat-tail slow-span outlier on a small fraction of traces, then exports over OTLP HTTP. The corpus-generation tooling and deployment docs are still open PRs, so the runtime shipped ahead of the corpus.

An analytics SQL surface for agents (#15580 plus the mcp/sql tree). Phoenix's MCP server exposes describeSqlSchema and executeSql: read-only SQL against allowlisted telemetry, dataset, and experiment tables, with the schema rendered as DDL because the consumer is a model. The hardening PR is instructive about the cost of building this yourself: an admission bypass where SELECT user FROM spans, (SELECT 1) q returned the database role, an unqualified subquery column bound to the outer table and silently returning the wrong latency, JSON paths the rewriter rendered invalid, and fractional seconds dropped from timestamp subtraction. That is what a hand-rolled SQL gate over a Postgres store looks like after one round of review.

Reasoning tokens priced separately (#15164). The cost manifest now carries LiteLLM's reasoning-token rate. Before this, any reasoning token fell back to the output rate; one model was over-billed 2.67x, and reasoning now shows as its own cost line rather than folding into output.

Also in the release: PXI can search and file GitHub issues using a per-user token that never enters a tool argument or span, keyset pagination on trace listing, and the session-level PII evaluator from 1335 now wired into the server.

The wrong belief to kill: observability vendors ship dashboards and a client SDK, and SQL is the warehouse's job. Phoenix is putting a SQL surface in front of agents and paying the security tax to do it. Judgment: peer, and the strongest external validation of the "queryable store is the product" thesis this week.

TL;DR for BQAA. Our SQL-over-MCP story is BigQuery's own MCP with IAM and row-level security doing what Phoenix's allowlist and sqlglot rewriter do by hand; that is a positioning paragraph, not code. The public replay corpus is worth a look as demo data next to AgentLogs once the corpus tooling PR merges. Reasoning-token pricing joins cached tokens as a "does the ADK plugin emit it separately" check.

3. Reasoning tokens as a metric, three vendors in five days (Aug 27–Sep 1)

Small thread, same direction as item 2's manifest fix. Braintrust JS SDK 3.29.0 (Aug 28) records Anthropic thinking tokens and LangChain reasoning tokens as metrics, and preserves all OpenAI streaming choices in instrumentation output. Braintrust Python 0.35.0 (Aug 27) fixed LiteLLM prompt-caching metrics. Phoenix priced reasoning tokens separately (item 2). The wrong belief to kill: tokens are input plus output. The industry is settling on at least four buckets per call: input, output, cache read or write, and reasoning, with modality splits arriving via OTel #440. Judgment: convergent, low drama, and it sets the column list customers will expect.

TL;DR for BQAA. Extend the 0849 cached-token check to reasoning tokens: what the ADK plugin emits for Gemini thinking, and whether the schema has a place for it that is not "output."
