Ecdysis — NEW rank: diagnose harness failures in batches, not one task at a time

Ecdysis: Efficient and Effective Training of Runtime Harnesses for LLM Agents, Ruiqing Yue, Yu Cui, Zhuoyu Sun, Sicheng Pan, Xianhong Xue, Tingyu Li, Ting Li, Wenzhuo Zhu, Yi Chen, Yifei Liu, Baohan Huang, Zhe Cui, Haibin Zhang, Cong Zuo (CAS Chengdu / UCAS / BIT / BJUT / Tsinghua Yangtze Delta Institute). v1 2026-09-10 15:09Z (08:09 PT — submitted ~4.5h pre-window, announced in the Thursday cycle inside the window). Full PDF read including appendix tables. (PDF)

Argues that iterative harness evolution overfits to single failure instances and conflates model deficiencies with harness deficiencies. Ecdysis aggregates failure evidence across a batch of task instances before editing, and its Failure-Driven Collaborative Refinement (Analyst/Critic/Engineer roles plus a Moderator) explicitly separates model-specific accommodation from systematic harness-level repair — the authors' manual analysis shows the model-accommodation ratio of edits dropping from 60.0% (self-evolution baseline) to 45.5%. Headline numbers, precisely scoped: the 1.84× speedup is vs the Self-Evolution baseline on τ²-Airline only (4,403s vs 8,121s; other cells are 1.30× Retail, 1.03× AgentBench); the +18.56% is a relative average-accuracy gain over that same baseline (58.67% → 69.56% across 5 models × 3 datasets), not percentage points. Code released (github.com/cuiyu-ai/Ecdysis, public-release PR merged in-window Sep 12).

Mandatory qualifications: tiny evaluation — 20 train + 20 test tasks per subset, 3 trials (60 trajectories per cell); harnesses evolved only with Qwen3-8B then reused on four other models; all FDCR roles and the coding agent run DeepSeek-V4-Pro at temperature 0; single evolution run per method, no seeds, no significance tests, and some cells regress or tie. The baseline is the authors' own reconstruction of instance-level evolution; no comparison to other published harness-training systems. "Up to 1.84×" is one benchmark cell.

BQAA/ADK application — editorial proposal: when an ADK agent fails a workflow, the instinct is a reactive prompt patch tuned to that instance — Ecdysis's 60%→45.5% accommodation ratio quantifies how much of that patching is model-coddling rather than harness repair. A BQAA harness-improvement loop should aggregate failure evidence across a batch of runs before any edit lands, and report what fraction of edits are model-specific accommodations.

AgentZip — NEW rank: compress sandbox memory while the LLM is thinking

AgentZip: Memory Compression for High-Fanout Agent Sandboxes, Mengming Li, Ceyu Xu (equal contribution), Qijun Zhang, Jiangnan Yu, Xiangfeng Sun, Haohui Mai, Zhiyao Xie (HKUST). v1 2026-09-10 09:25Z (02:25 PT — pre-window submission, Thursday-cycle announcement in-window). Full PDF read. (PDF)

High-fanout agent execution (one workload spawning dozens of concurrent sandbox sessions) is memory-bound, and generic OS compression misses two agent-specific opportunities: pages across non-identical sandboxes are similar (shared template, shared cohort), and every sandbox has long idle windows while its LLM generates. AgentZip exploits both — template-delta plus cohort-dictionary compression, compression work aligned to LLM inference wait periods so it never interferes with foreground tool execution, and restore-time prefetching (stride, cohort-temporal, tool-hotset) replacing compression-time page selection. Results: sandbox-owned memory reduced by up to 8.7× vs 2.1× for the best Linux configuration (KSM+zswap), with slowdown cut from 3.1× to 1.40×.

Mandatory qualifications: "8.7×" is the Rollout workload's best case (88.6% average saving); on the GAF workload the saving is 64.3% (~2.8×) and AgentZip's latency there (1.468×) is worse than both zswap (1.118×) and KSM+zswap (1.159×) — the win is memory, not latency, on that workload. Only two baselines, both Linux-generic. Workloads are emulated: R2E-Gym traces replayed with recorded think times (DeepSeek-V4-generated), 16 concurrent Rollout trajectories — not live production traffic, and the whole scheme depends on LLM idle windows existing. Single host, built on Zeroboot/KVM-Firecracker snapshots; no artifact release mentioned.

BQAA/ADK application — editorial proposal: parallel evaluation rollouts over BigQuery are exactly the high-fanout case, and LLM-generation waits are exactly when an orchestrator can do expensive maintenance for free. The transferable idea is not the compressor — it is treating inference wait as a schedulable resource for infrastructure work (compression here; cache refresh, compaction, or audit scans are equally eligible).

Verbalized confidence compatibility shift — NEW rank: the logprob preference is a GPT-only finding now

Rethinking Verbalized Confidence for LLM-as-a-Judge: A Compatibility Shift on Post-2025 Proprietary Models, Yu-Chung Hsiao (Cisco Systems). v1 2026-09-10 02:17Z (Sep 9, 19:17 PT — pre-window submission, Thursday-cycle announcement in-window). Full PDF read including all supplementary tables and prompt templates. (PDF)

Evaluates up to 18 LLMs across SummEval, AggreFact (2,700 items), and HelpSteer2 (800 items) and documents a compatibility shift: the established preference for token log-probabilities (G-Eval-style) over verbalized confidence inverts on post-2025 proprietary models. With two additions — an overconfidence advisory prompt and self-debate scaffolding — verbalized confidence beats logprob-based scoring on calibration, score spread, and subjectivity robustness (e.g., Sonnet 4.5 on AggreFact: AECE 8.9%→3.8%, spread 75.8%→89.6%; SummEval dimension-level ∆slope −0.143, p < 10⁻⁴; 67/90 model-task cells favor the proposed method, p = 1.9×10⁻⁶). The generation effect flips sign: pre-2025 models −1.8pp balanced accuracy vs post-2025 +0.7pp.

Mandatory qualifications — the headline needs its scope: the logprob-vs-verbalized comparison is GPT-family only (gpt-4o, gpt-4.1, gpt-5.2, gpt-5.4) — Claude never returned logprobs and Gemini dropped them at 3.x Pro, so "the consensus breaks on post-2025 models" is shown only where logprobs still exist. Single-author preprint, no limitations section at all, no code/data release. Subjectivity-robustness is a meta-regression of Kendall τb against inter-annotator agreement, not direct accuracy; aggregate balanced-accuracy deltas are modest (1–3pp). Several evaluated models (gpt-5.4, sonnet-4.6, gemini-3.1-pro) are not independently reproducible without vendor access.

BQAA/ADK application — editorial proposal: for BQAA's judge pipelines, the actionable finding is cheap: an overconfidence advisory plus self-debate scaffolding on verbalized confidence is a prompt-only change that outperforms logprob scoring on modern judges and works on judges with no logprob access at all. Stop treating logprob availability as a judge-selection requirement; calibration-test the advisory prompt on your own rubric instead.

Noise fabricates judge bias — NEW rank: typos manufacture failures your judges never found

When Noise Fabricates Bias: The Fragility of LLM-as-a-Judge Bias Measurement under Noisy Text, DongHyun Ryu, Jaehyeok Lee, YeongJun Hwang, JinYeong Bak (Sungkyunkwan University). v1 2026-09-10 04:14Z (Sep 9, 21:14 PT — pre-window submission, Thursday-cycle announcement in-window). Full PDF read including appendices and limitations. (PDF)

Subjects 3,822 responses (42 CLEAR-Bias-derived templates × 91 demographic name pairs, 7 bias categories) to 5 realistic noise conditions (typos, informal register, punctuation, colloquialisms, combined) across 4 judges (Llama-3.1-8B, Qwen3-8B, Gemma-4-12B-it, GPT-5.4). The degradation is asymmetric: surface noise flips neutral judgments to biased/failing far more than the reverse. The 120× figure, precisely: under typo noise at intensity 0.3, Llama-3.1-8B fabricates 240 biased verdicts vs erasing 2 (240:2, binomial p < 0.001). Scope honestly — that is one judge/noise/intensity cell: at full intensity the ratio drops to 50×, and other judges at the same cell run 5.6× (Qwen3), 3.4× (Gemma), 1.3× (GPT-5.4). Distortion is "purest" at mild, realistic noise: at severe corruption, judges start erasing bias verdicts instead.

Mandatory qualifications: the metric is self-baseline flip (stability under noise), not correctness or stereotype alignment — a "fabricated" bias verdict is a None→directional flip, and whether the new label is actually stereotype-aligned is unverified (unknowable for several axes, the authors concede). No human study confirming noise preserves meaning; input text is model-generated, not authentic user text; 3,822 items derive from only 42 templates; English-only, single source benchmark. GPT-5.4 is nearly immune here (1.3×), so "judges are fragile" distributes very unevenly.

BQAA/ADK application — editorial proposal: production judges reading real user logs will meet typos, shorthand, and messy SQL formatting — and mild noise is exactly where fabrication is purest. Before BQAA reports judge-derived failure or bias rates over production traffic, run a noise-stability audit on the judge at realistic corruption levels, and report the None→directional flip rate beside every failure-rate dashboard. A judge with a 5%+ fabrication asymmetry is manufacturing incidents.

SearchAtlas — NEW rank: parse the trajectory into an evidence graph before you judge it

SearchAtlas: Analyzing Agentic Search Strategies via Evidential Query Graphs, Jiacheng Sang, Mengyuan Li (equal contribution), Sanxing Chen, Yukun Huang, Yu Feng, Bhuwan Dhingra (Duke / UPenn). Date correction: v1 is 2026-09-09 23:09Z (Sep 9, 16:09 PT), not the pack's September 10 — it missed Wednesday's submission cutoff and was announced in the Thursday, September 10 cycle, which is in-window. Full PDF read. (PDF)

Converts unstructured search-agent trajectories into Evidential Query Graphs — DAGs of evidence propagation from queries through intermediate steps to the final answer. Automated graph construction achieves macro edge F1 0.860 against 100 human-adjudicated canonical DAGs, stable across four attribution LLMs (0.814–0.860). Over 1,350 trajectories from five agents (WebSailor-v1-32B, MiroThinker-v1-30B, Tongyi DeepResearch, two TYDP variants) on BrowseComp/WebWalker-Hard/DeepSearchQA, the graphs expose three process failures invisible to outcome-only accuracy: fragmented answer support, question constraints that never reach the final answer, and unverified parametric knowledge entering the response. The combined diagnostics predict task errors (macro ROC-AUC 0.840–0.856 per agent) significantly better than GPT-5.2 judging raw trajectories (positive-class recall 0.750 vs 0.475). Code: github.com/DukeNLP/SearchAtlas.

Mandatory qualifications: closed-answer, English, deep-search tasks only — open-ended, non-English, and multimodal settings untested. Attribution is LLM-based with nontrivial per-DAG inference cost, and both the constructors and the comparison judges are LLMs (circularity partially, not fully, addressed). Regime misclassification adds metric noise; the method recovers only what the trajectory log surfaces — a silent tool side effect leaves no graph edge. Single annotation round with adjudication on the 100-graph gold set.

BQAA/ADK application — editorial proposal: this is the missing middle layer between raw trace and verdict. BQAA trajectory analysis today has outcome labels and raw spans; an evidential DAG over a multi-step analytics run (which intermediate result supports which conclusion; which user constraint reached the final answer) turns "the agent got it wrong" into a localizable edge failure. Constraint-grounding coverage — did every filter in the user's question reach the final SQL? — is directly implementable over BQAA traces.

Bayesian backward reasoning — NEW rank: an orthogonal anchor for multi-agent disagreement

When Agents Disagree: Bayesian Backward Reasoning as a Label-Free Anchor for Multi-Agent Collective Decision-Making, Ken Chen, Wei Wang, Sachith Seneviratne, Hansani Weeratunge, Saman Halgamuge (University of Melbourne / SLIIT). v1 2026-09-10 15:27Z (08:27 PT — pre-window submission, Thursday-cycle announcement in-window). Full PDF read. (PDF)

Multi-agent ensembles fail because forward aggregators (voting, electoral rules, LLM-as-judge) compound shared errors — every agent factorizes evidence-to-label the same way. This paper constructs a reverse posterior via Bayesian backward reasoning (label-to-evidence likelihood inversion), giving an orthogonal factorization, then ranks agents by Jensen-Shannon divergence between their forward posterior and the reverse anchor (three operators: MinJS hard selection, FwdJS soft reweighting, LogLin fusion). On DDXPlus across five backbones, LogLin beats the best forward-only electoral rule by +1.2–4.7pp on the subset where agents disagree; errors between forward agents and the reverse anchor collide less often (π = 0.196–0.413 vs 0.594–0.765 for a second forward agent).

Mandatory qualifications — read before quoting: single dataset, single domain — DDXPlus is a synthetic medical-diagnosis benchmark with a closed 49-label set, and the method explicitly requires a finite label space (inapplicable to open-ended generation, by the authors' own statement). The "five agents" are five prompting strategies on one backbone per experiment, not heterogeneous models. No significance tests, CIs, or seeds anywhere. Aggregate gains are thin (~0.5–1.5pp on the full set; the story lives on the Disagree subset). The reverse posterior is the weakest standalone predictor in the study — it earns its place purely as a decorrelation anchor, at the cost of one extra generative inversion per case.

BQAA/ADK application — editorial proposal: read this beside the 0634 brief's VP-CONTROL card: that study showed evidence-lineage independence beats model count for commit gates; this one shows a factorization-inverted anchor decorrelates errors even with a shared backbone and shared evidence. For BQAA multi-reviewer setups over closed-label decisions (pass/fail gates, category classification), a backward-reasoning reviewer is a cheap orthogonal vote. For open-ended analytics answers, the method does not transfer as published.
