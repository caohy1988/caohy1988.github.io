NEW

1. Cloudflare personal-agent analytics + per-agent access policies (launched Nov 4). Primary: Cloudflare blog, "See the agents, set the terms: new visibility and control for personal agents", datePublished 2026-11-04T14:00:00Z, fetched in full (HTTP 200). Facts as stated there: (i) Security Analytics' Bot Analysis chart gains a Personal Assistants category alongside Verified Bot / Likely Human / Likely Automated / Automated, selectable to isolate personal-agent traffic over time, backed by Cloudflare's verified bot directory; (ii) a Top Statistics Personal Assistants widget lists which agents visit a site and how many requests each sends, and filtering on one agent propagates to the other widgets (paths requested, status codes received, source networks) — i.e., whether an agent is logging in, reading product pages, reaching checkout, or erroring; (iii) for sites on Account Abuse Protection (stated early access), a population view shows which personal agents are active across users and how many accounts use them, every login/sign-up event shows whether a personal agent made it and which one, and accounts can be filtered by agent events; (iv) access control becomes per-agent: under the renamed AI Crawler and Agent access policies, an overall Agents policy plus a per-supported-agent choice of Allow (do not block) / Block on pages with ads / Block, settable at zone onboarding or in Security Settings; Search and Training bot policies are unchanged. Stated next work (not shipped): privacy-aware ways to carry user context through an agent, help sites assess reputation, and establish accountability. Scope honesty: this is edge traffic analytics over HTTP requests by third-party personal agents — no traces, spans, evals, or warehouse storage are involved, identification covers "supported" agents in Cloudflare's directory, and the account-linkage layer sits behind an early-access product. It is ranked because it is a material, dated, GA analytics launch that establishes agent identity + behavior + outcome as a measured, policy-priced traffic class on a major platform — the demand-side mirror of first-party agent analytics. BQAA read: expect customers to ask how their agents appear to counterparties (identified? allowed? erroring at checkout?) and to want first-party trace records joinable against such external observations; no build is implied this week.
