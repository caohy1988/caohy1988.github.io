Read this first

  • Evaluation cost is now a measured design trade-off, not merely advice to use a smaller judge. Arize reports code-first checks, trace trimming and cascades that cut cost 20x or more in several vendor-run tasks while retaining or improving task-specific accuracy. Do not generalize those results into a universal judge ranking.
  • Two AWS releases expose useful agent-control primitives. The Agent Toolkit skill uses workload traces to estimate distributed-KV-cache fit before spending, while AWS Quick combines deterministic multi-agent flows with detect-only guardrails, approval boundaries and group agent-hour limits.
  • The Academy cards share one primitive: evidence that can be audited after the answer. LEDGER scores the evidence sent to the model as well as the answer; Anchor and Check replays a pure reconciliation decision from stored samples; Sightline attaches a calibrated miss rate to input-output data-flow summaries. None establishes unattended-production safety.

1. Arize measures code checks, trimming and cascades for lower-cost evaluation

2026-11-21T01:22:44Z (page datePublished 2026-11-20T17:22:44-08:00), stable. Measured vendor study, not method-only advice.

  • On 890 Berkeley Function Calling Leaderboard tool calls, a schema check settled 38% for free before an LLM judge. Arize reports cost falling from $2.17 to $1.34 per 1,000 and accuracy moving from 96.4% to 96.5%.
  • On 199 expert-labelled AgentRewardBench traces, code trimming reduced cost 20x–24x across four judges and improved balanced accuracy for each. For one judge, the reported comparison is 56.0% at $154.84 for full traces versus 70.0% at $6.58 for trimmed traces; this is a task-specific result, not a general accuracy multiplier.
  • On the RAGTruth hallucination task, a decision-model-first cascade escalated 8% of cases to a large judge and scored 86.8% at $1.40 per 1,000, against 84.9% at $14.53 for the large judge alone. A separate code-plus-judge result shows why structural checks should settle only the cases they can actually decide.
  • Boundary: these are Arize's own experiments and prices, with no independent rerun here. Sampling, trimming, judge choice and escalation thresholds need validation on the customer's eval and labels; the post itself warns that a result on its data is only a hypothesis for another workload.

2. AWS Agent Toolkit adds a distributed-KV-cache evaluation and setup skill

2026-11-21T00:14:26Z, stable.

  • The Agent Toolkit for AWS skill lets a coding agent diagnose cold-prefill latency, estimate fit, size and price a shared ElastiCache tier, configure LMCache for vLLM or SGLang, and troubleshoot transfers. It checks fit before creating infrastructure and stops when expected savings do not cover cache cost.
  • KVTrace records vLLM/SGLang cache events and replays block hashes and token counts offline against candidate cache sizes; it does not record token IDs or prompt text. Sensitive workloads can supply an anonymize-key file, and tenants that share a cache need a tenant ID in the KV hash.
  • The guided flow starts with read-only fleet inspection, seeks explicit approval for high-impact operations, and checks that two cache-loaded runs produce the same output before production. That correctness check matters because healthy hit counters alone do not establish a compatible layout.
  • Boundary: the post separately quotes up to 40% lower inference cost and 80% lower TTFT for the underlying distributed-cache architecture. Those are not measured outcomes of this new agent skill, and freed GPU time becomes a dollar saving only if capacity or served traffic changes.

3. AWS Quick combines multi-agent flows, prompt guardrails and group agent-hour limits

2026-11-21T01:06:42Z, stable.

  • Quick's conversational Flows now orchestrate agents, skills, tools and structured data with deterministic calculation/check steps, longer runs and larger data volumes. Multi-agent orchestration lets specialized agents work in parallel and combines their contributions; work can continue after the browser tab closes.
  • New prompt guardrails in preview filter denied topics/words, detect prompt attacks and protect selected personal-information types. Administrators can test in detect-only mode before enforcement. Group controls add permissions and agent-hour limits, while connector write actions still require user permission.
  • Boundary: this is a product-capability launch, not a measured orchestration-quality or guardrail-accuracy result. The customer fourfold data-use and 80-hours-per-month anecdotes are not treated as controlled evaluation evidence.

Academy

1. LEDGER: Auditable Agent Memory Under Change — arXiv:2611.20927

Full PDF read: all 11 pages via pdftotext -layout, including architecture, evaluation, results, threats to validity, conclusion and references. Key evidence: Tables V–VIII and §§III–VII.

LEDGER has an LLM propose facts while explicit rules decide supersession, source trust, validity intervals and deletion; LEDGER+EP adds raw-turn retrieval and scrubs those turns on deletion. On the authors' synthetic coding-agent workload, fallback mode answers 94.3% on development seeds and 91.1% on five held-out seeds, versus 82.1% and 83.3% for full replay (Tables V–VI). More importantly for analytics, development-seed evidence contains a forbidden stale/future/contaminated value in 16 of 512 probes for fallback mode versus 249 for full replay; description-only deletion sent no deleted value in the evaluated LEDGER probes.

On a 210-question LongMemEval subset, LEDGER+EP augment and full replay both score 74.8%, with 1,087 versus 108,447 injected tokens (Table VII). The paired 95% difference interval of −6.2 to +6.2 points does not establish equivalence. The coding workload is synthetic and built by the authors, held-out seeds shrink the lead, and no downstream coding task is measured. Deletion guarantees also depend on extraction/routing and do not cover every missed-value phrasing, earlier snapshots, response caches or run logs (§§III-E, V-H, VII).

2. Anchor and Check: Deterministic Cross-Prompt, Cross-Model Reconciliation for Auditable LLM Decisions — arXiv:2611.25818

Full PDF read: all 20 pages via pdftotext -layout, including the method, matched/cross-model comparisons, operational results, limitations and Appendices A–F. Key evidence: Tables 2–8 and §§5.7, 6–7.

The contract commits a greedy anchor, checks it through an alternate prompt and another model family, and lets a pure function emit five outcomes; only Agree is automated. Across 48,000 model-item evaluations on six tasks and eight models, anchor+alternate+peer reaches 0.852 AUROC versus 0.829 for single-model semantic entropy over 10 samples, at 29% of that baseline's cost (Table 2). Against equal-budget cross-model pipelines, however, differences from pooled entropy over three and five samples are +0.4 [−0.5, +1.2] and +0.1 [−0.8, +1.0] points: no superiority or equivalence claim is justified (Table 3).

Under the strict three-call Agree gate, 70.1% of items are automated at 5.4% error among automated items; 84.0% of errors go to review, but 16% of all errors are still acted on (Table 8). Stored samples, model/prompt/decoding provenance, decision key, equality-rule version, outcome and action replay the pure reconciler exactly. The hosted generations themselves are not reproducible: repeated anchors change 7.7% of items and the three-call gate flips 5.2% (§5.7). Shared-wrong-answer coupling, comparable checker strength, staffed review queues and untested structured/date key types remain deployment limits (§7).

3. Sightline: Calibrated Data-Flow Summaries for LLM-Integrated Applications — arXiv:2611.26221

Full PDF read: all 28 pages via pdftotext -layout, including the Lean-mechanized theory, calibration, six evaluation questions, threats to validity, data-availability statement and references. Key evidence: Tables 3–6 and §§3–6.

Sightline uses one teacher-forced pass to read per-head attention for recorded prompt placeholders, learns which reads are uses, and applies split-conformal calibration over repository families. On 2,103 unseen repository families and four models it reaches 81.1–86.7 Macro-F1 (Table 3). At a calibrated 1% true-flow miss level per call site it prunes 43.9–65.6% of spurious flows, 1.6–2.6 times the best baseline; calibration on another collection still prunes 43.8–60.1% (Table 5).

An open surrogate reads models treated as closed within −4.2 to +3.2 Macro-F1 points of self-reading (Table 6). In a 120-turn AgentDojo client, it removes 50.0% of label creep and lets none of 34 attack calls through the tested integrity policy (§5.7). These results do not make attention a complete causal explanation or a production security guarantee: runtime values are reconstructed rather than observed in production, labels come from LLM/author procedures, baselines are author-implemented, and the miss bound assumes exchangeable deployment and calibration clusters (§6).

Six-week EV

  • Evidence-packet memory ledger (high EV, 2–4 weeks). Store slot, value, source event, trust, valid interval, deletion/tombstone and raw-turn scrub state. Score evidence and final answers separately for stale, future, contaminated and deleted values; test description-only deletion and explicitly inventory snapshots, caches and logs that deletion does not reach.
  • Replayable automation-gate record (high EV, 2–4 weeks). Version the decision key and equality rule; retain anchor/check model, prompt, decoding, raw samples, outcome, confidence and action. Publish risk–coverage, residual errors acted on, gate flips and review-queue latency rather than treating agreement as correctness.
  • Calibrated input-output lineage shadow (high EV, 4–6 weeks). Join placeholder/span IDs to output and tool-call records, surrogate/readout versions, calibration cohort, threshold and α. Measure missed true flows, pruned non-flows, transfer across repositories/models and online overhead before using summaries for enforcement.
  • Eval cost-quality registry (high EV, 1–3 weeks). For each evaluator record scope, raw/trimmed tokens, code-check settlements, judge/model/effort/cutoff, cascade band, escalation share, sample size, accuracy and cost per 1,000. Compare code-first, trimming and cheaper-judge variants on held-out customer labels before rollout.
  • Cache-fit and correctness evidence (medium-high EV, 2–4 weeks). Keep prompt text out of cache-fit traces; store block hashes, token counts, hit-rate scenarios, prompt-length cutover, cache size/price and predicted versus measured L2 share. Pair reuse metrics with output-equivalence checks and tenant-isolation IDs.
  • Multi-agent governance events (medium-high EV, 3–5 weeks). Normalize flow/agent/skill/tool IDs, deterministic checks, per-agent contributions, connector write approvals, detect-only versus enforced guardrails and group agent-hour limits. Report completed outcome and denied/held work separately from raw agent hours.

TL;DRs for BQAA

  • Arize eval-cost study: put code settlement, input trimming, judge choice and escalation rate beside accuracy and cost in every evaluator report; validate the trade-off on customer labels.
  • AWS KV-cache skill: cache-fit analytics should use privacy-preserving workload traces and an output-correctness gate, not hit rate or modeled GPU savings alone.
  • AWS Quick: deterministic flow checks, detect-only guardrails, write approvals and agent-hour limits are useful governance events to normalize across agent platforms.
  • Vercel AI SDK: continuous voice/agent sessions need lifecycle events and final usage joined to the same session, with experimental-API version pinned.
  • LEDGER: answer accuracy can hide polluted or deleted evidence; audit the evidence packet itself and track deletion coverage beyond the primary store.
  • Anchor and Check: store enough provenance to replay the gate, but dashboard residual acted-on errors and generation-driven gate flips alongside automation rate.
  • Sightline: calibrated lineage is useful only with its calibration population, miss rate, surrogate model and distribution-shift evidence attached.
