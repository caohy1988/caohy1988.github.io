Industry

1. ADK main: transfer_reason lands on EventActions (Sep 1, 4:42 PM PT, unreleased)

Commit 22ab4d8 on adk-python main merges community PR #6590, opened Aug 4 by an outside contributor. The problem it names is agent ping-pong: the built-in transfer tool carried only the target agent name, so a receiving agent could not tell why it had been handed control and would transfer straight back, sometimes indefinitely.

What actually merged differs from what was proposed. The PR asked for a required transfer_reason argument on every transfer. The merged version makes it optional on the function, and TransferToAgentTool only exposes it in the tool declaration when constructed with include_transfer_reason=True, default False. When the flag is off, the parameter is stripped from the declaration and the docstring the model sees is a version with no mention of it. When on, the reason is a free-text string with no enum constraint, and agent_name remains the only required parameter.

On the event side, EventActions gains transfer_reason: Optional[str], populated from the tool call when non-empty. The A2A converter test was extended so a peer-supplied transferReason is dropped along with the other peer-supplied actions; a remote agent cannot inject a reason into the caller's session any more than it can inject a transfer.

Other main-branch commits after 1634 are minor: the paused-task turn fix and resumable-node checkpoint fix noted at 1634 landed, plus hyphenated column names in the BigQuery tools and test-only changes.

The wrong belief to kill: agent transfer is a one-column fact, source agent to target agent. As of today's main it is a two-column fact, and the second column is model-authored prose.

TL;DR for BQAA. When this ships, transfer rows can carry a model-written reason string. Treat it as content for redaction purposes, not as a label: it is free text the model produced, and it is the first EventActions field that is neither an identifier nor a delta. Coverage matrix gets one line; the forensics story gets a better one, because a reason chain across a hop sequence is exactly what you read when diagnosing a transfer loop.

The author says it will not touch state.changed and will rebase if #507 lands first. So the real LangGraph producer is moving to the instrumentation repo, not the conventions repo.

The wrong belief to kill: #445 is converging. It is shrinking to the parts the author can defend, and the one identity it had, thread id as execution id, was just withdrawn. The question 1634 raised, what a resumed run is joined on, is more open tonight than it was this morning.

TL;DR for BQAA. The producer contract should state its own join key for pause and resume and not wait for this thread. ADK's invocation_id across a confirmation pause is a concrete answer; OTel currently has none. Cite #445 as the reason the contract needs to say this, not as something to align to.
