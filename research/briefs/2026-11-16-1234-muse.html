Read this first

Two reserve papers clear the bar and both are about the same operational question: what can you actually trust about an agent you did not tune?

The finance-agent case study (2611.17939) measures run-to-run drift first and only then judges diagnosis and intervention against that noise: seven identical runs span 105–123 of 149 rubric criteria, and under a pre-written rule a cost change to 0.34× baseline is real while a +14-point dev accuracy gain is indistinguishable from zero on held-out questions. Its transferable protocol — freeze a split, replicate the baseline, write the promotion rule against measured drift, classify failures by owner of the remedy — is directly usable for BQAA evaluation gates.

LeBet (2611.17662) learns an interpretable OR-of-AND runtime monitor whose learning objective is derived from sufficient conditions for valid intervention, then intervenes by a fixed betting statistic with finite-sample, training-conditional false-positive and detection guarantees (Theorem 5) without i.i.d. trajectories or a split calibration set. On SWE-bench Lite it saves 34.46% of tokens at a 13.64% empirical false-positive rate (Table 1). The empirical win is modest (29.59% detection); the guarantee structure is the contribution.

NEW 1 — Can You Trust Your Finance Agent? Drift, Diagnosis and Auditable Intervention on One Shipped Financial Research Agent — abs

Full PDF read (9 pages, whole paper incl. §§1–8, Tables 1–11, Fig. 1–2 and Appendices A–E). Not in live catalog (grep 2611.17939: 0 hits).

The paper audits the shipped Vals Finance Agent Benchmark v2 reference agent without tuning it, on an 18/9 dev/test split frozen before analysis (§2, Table 1). Four measured claims matter for BQAA:

  1. The score is a draw (§3, Table 2). Seven identical runs pass 105–123 of 149 rubric criteria (12 points of pass rate); 15–28 criteria flip between consecutive runs and the bill varies by up to 17% (twin ratios 0.830–1.038). Per-question cost ratios run 0.16×–5.43×, so a median/geometric-mean gate can approve a change that raises the bill 11% (§3).
  2. Who owns the fix (§4, Tables 3–5). Under a frozen owner-of-the-remedy projection (Table 3, Rule M), the 20 failed test trajectories split policy 13 / tool 3 / data 0 / model 4 (Table 4; model 5 under sensitivity reading B). The same question fails under different layers across replicas (Table 5), and data=0 is by construction, not evidence retrieval never failed (§4.3).
  3. Diagnosis is corroborated on what, loose on where (§5, Table 6). Four blind readers from three model families name the same fault as the analyzer in 75/80 cases vs 112/120 reader–reader; decisive-event localisation within ±5 trace events is only 45/80 vs 84/120. The analyzer's own errors (over-claimed counterfactual, label instability on replay) are declared in §5.2 and Appendix C.
  4. Only the structural change survives the frozen test (§6, Tables 7–10). The cost winner costs 0.341× baseline (95% CI [0.216, 0.580], entirely below the 0.83 drift band) at pass rate within noise (Table 9), driven by moving nested retrieval to a cheaper model ($62.91 of $71.17 baseline was nested-LLM spend; §6.3). The accuracy winner's +14 dev points become +1.5 on held-out questions (CI [−5.3, +7.2], sign-flip p=0.74). Limits are explicit (§7.1): one agent, n=9 test questions, single judge family, no control arm — an anatomy and audit protocol, not a population estimate.

BQAA read: replicate baselines before promoting any config change; set promotion bars outside measured drift, not inside it; store owner-of-remedy labels (policy/tool/data/model) on failed trajectories so fixes route to the right team; treat per-question cost tails, not just totals, as a gate.

NEW 2 — Learn then Bet: Learning Interpretable Rules for Reliable Agent Intervention (LeBet) — abs

Full PDF read with one stated limit: main text §§1–11, Tables/Algorithms, Appendices A–K (notation, examples, experimental details, search, betting interpretation, lemmas and proofs of Propositions 2–3, Theorem 5, Lemma 6) and Supplement §§1–2 (Lean Challenge statements) read in full; Supplement §3 Lean Solution code listing (S-14–S-236) inventoried by theorem/lemma and tail-checked, not proof-checked line by line. Not in live catalog (grep 2611.17662: 0 hits).

LeBet learns an OR-of-AND monitor over prefix predicates by maximizing empirical separation (eq. 6) derived from sufficient conditions for valid intervention, then intervenes when a fixed betting evidence process crosses 1/α (Algorithm 1, eq. 2; §§4–5). Propositions 2–3 (§§5–6) link observed prefix averages to calibration and to false-intervention/detection bounds under average-conditional-mean conditions. Theorem 5 (§7) gives finite-sample PAC-style bounds on next-trajectory false intervention and missed detection conditional on the training sample, using the same trajectories for learning and calibration under finite within-class exchangeability (Assumption 1) and leave-one-out stability (Assumption 4) — no i.i.d. assumption and no data split. Rule learning uses stochastic local search guided by Boolean edit structure (Lemma 6, §8, Appendix D).

Empirics (§9, Table 1, Appendix C): Ministral 3 8B on all 300 SWE-bench Lite tasks (180 learn / 120 eval, d=5,356 predicates, window steps 50–500, α=0.01). The selected monitor (7 rules, 10 predicates, Appendix C.4; training gap 0.88−0.68=0.20) stops 29 failed and 3 successful eval trajectories: detection 29/98=29.59%, FPR 3/22=13.64%, token saving 34.46%, output precision 19/88=21.59% vs 22/120=18.33% without stopping. Case studies (Tables 6–9, Fig. 5) show a correctly stopped failure and a falsely stopped success with identical evidence curves (both cross at step 73) — the monitor is useful, not sharp. Formal statements are Lean-4-checked per the supplement (§1.4 contribution 4; Challenge/Solution via Comparator); this brief does not independently verify the Lean code.

BQAA read: for long-running ADK/BQAA agents, learn the intervention monitor against an explicit false-stop budget instead of hand-tuning turn limits; keep monitors as readable rule sets over trace predicates (repeated failed actions, tool errors, edit/test activity) so on-call can audit why a run was stopped, upgraded or handed to a stronger model; report detection and false-stop rates together — token saving alone overstates value.
