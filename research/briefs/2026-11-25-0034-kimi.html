Read this first

The durable signal is measurement design, not another model leaderboard. SecondChance replays natural agent errors from shared checkpoints and shows that task success can leave the original damage in place. A deployed enterprise RAG study runs every question ten times and finds an 18.5-point gap between finding the right page in any run and finding it in every run. ShellBench separates model, harness and rubric effects across 53,100 rollouts: average harness differences are small, model-by-harness interactions are not, and removing source/staleness criteria changes the harness ranking.

1. LangChain names LangSmith an “Agent Lake”: trace storage and outcomes feed search, evaluation and automated improvement

Primary: https://www.langchain.com/blog/the-agent-lake (published 2026-11-25T01:30:00Z, modified 01:32:21Z, in-window).

The post defines an Agent Lake as storage optimized for agent traces plus “intelligent compute” to query, analyze and learn from them. LangSmith’s version groups multi-turn traces into threads, joins outcomes such as feedback and merged PRs, and layers on online evaluators, natural-language AI Search, Insights clustering, and LangSmith Engine’s recurring-issue diagnosis and fix PRs. SmithTune fine-tunes a model on selected trajectories through Fireworks or Baseten and compares it with the base model in LangSmith. This is a product-platform launch and consolidation, not a claim that every component first shipped today.

Vendor-reported evidence needs the labels kept on. The post says Engine has analyzed more than 60 million production traces. Its SmithTune example reports 96 on an internal IssueBench subset for fine-tuned Kimi K3, versus 90 for the base model and 87 for GPT-5.6 Sol; no subset size, variance, cost or independent replication is given, so those numbers are directional only. The decision-model and AI Search claims likewise report no measured precision or end-to-end cost reduction in this post.

Why it ranks. It gives agent analytics a concrete data-and-compute architecture: traces and observed outcomes are the shared corpus, while evaluators, search, clustering, diagnosis and tuning are separable consumers. For BQAA, the useful distinction is trace ≠ outcome: join both, but preserve their cardinality and provenance rather than treating an LLM-generated proxy as observed impact. Catalog check: no existing Agent Lake or SmithTune item; NEW.

2. FastMCP 4.2.6 adds experimental client-side CodeMode, transport attributes on server spans, and durable typed events

Primary: https://github.com/prefecthq/fastmcp/releases/tag/v4.2.6 (published 2026-11-25T00:40:46Z, stable; PyPI upload 02:55:05Z, in-window).

The new CodeModeClient wraps a client or client group and exposes search, schema and execute meta-tools even when the remote servers do not implement CodeMode; one execute block can chain calls across servers. Server spans gain network.transport and, over HTTP, protocol name/version. The release also moves experimental events into fastmcp-events with Pydantic-model event types and optional Redis/Docket persistence across restarts and replicas. Authlib is removed as a dependency, so direct importers must declare it themselves.

Why it ranks. This is a material stable release, not a patch train: cross-server CodeMode changes the tool-execution surface, and the span attributes make transport analysis possible without inferring it from peer names. The CodeMode and events APIs are experimental, and no accuracy, latency or token-saving evaluation is reported. BQAA should trace the individual calls inside an execute block rather than record only one opaque meta-tool invocation, and treat transport attributes as request metadata, not proof of execution outcome. Catalog check: no existing FastMCP release card; NEW.

1. SecondChance: Benchmarking Reliable Error Recovery in AI Agents — https://arxiv.org/abs/2611.31586

Full PDF read: yes — entire 18-page PDF read via pdftotext in chunks, including benchmark construction, scoring, results, limitations, references, and all appendices.

Problem and method. SecondChance starts from natural errors in agents’ own τ²-bench, BFCL and AppWorld attempts, not injected tool failures (§§1, 3.1–3.2). It restores 129 shared checkpoints and resumes 12 models under four cumulative conditions: unaided, error notice, error location, and plan-assisted repair (Table 2). The main study has 5,760 continuations (§4.1). Complete recovery is deliberately stricter than task success: correction and protected state are required, with task success, policy/user-goal and disclosure requirements where applicable; durability and work are separate (§3.4, Appendix B). Fixability is established before evaluation: 57 demonstrated, 15 proven impossible, 57 unknown (§3.2).

Results to reuse. The best model completes only 16% unaided and 27% plan-assisted recoveries across the environments it runs (Table 3); these rates include impossible and unknown-fixability checkpoints. Plans add 10.0, 13.7 and 3.3 points of correction in τ², BFCL and AppWorld, but only 2.0, 6.8 and 2.1 points of complete recovery (Table 14). Most starkly, 40 of 84 successful AppWorld continuations leave the original error in place (§4.2), and 13 of 84 plan-assisted BFCL corrections are later undone (§4.7). Even on the 57 demonstrated-fix checkpoints, 12 are never corrected by any model, and the best model completes 54% in τ²/BFCL with a plan (§4.6). Limits are material: one run per main cell, 57 unknown-fixability checkpoints, only 27 checkpoints individually reviewed, no human validation of the acknowledgment measure, and possible familiarity with public tasks (Limitations).

BQAA takeaway. Do not mark a run healthy from final task status. Record error correction, protected-state preservation, disclosure, later reversion and task outcome as separate fields, with a fixability class and recovery cost. A successful SQL answer can coexist with an unrepaired side effect; BQAA’s evidence model should make that visible.

2. Agentic Systems Need Multi-Run Evaluation: A Study of Retrieval and Response Variability in a Deployed Enterprise RAG System — https://arxiv.org/abs/2611.31266

Full PDF read: yes — entire 10-page PDF read via pdftotext in chunks, including experimental setup, results, discussion, limitations, references, and divergence/continuation appendices. Version note: arXiv v1 is dated 2026-10-21; it appeared in this slot’s Wednesday listing and was absent from the live catalog, so this is a newly carded paper, not a claim that October 21 falls inside the industry window.

Problem and method. The authors run 739 product-documentation questions ten times each in one deployed agentic RAG system, holding model, tools, corpus and decoding fixed: 7,390 runs (§2). They distinguish per-run, any-run and every-run retrieval, compare answers on correctness/groundedness/comprehensiveness, and align traces to assign each non-equivalent response pair to its first divergent step. The attribution uses fixed unigram TF-cosine thresholds, including 0.40 for query content and 0.45 for reasoning (Appendix A).

Results to reuse. Ground-truth-page retrieval is 69.4% when any of ten runs may succeed, 50.9% when all ten must succeed, and 61.5% per run (§3). Retrieval accounts for 43.9% of 8,092 divergent pairs; the number of parallel searches at the first retrieval step alone accounts for 20.1% (Table 1). The agentic system gains 22.6 points of comprehensiveness over a non-agentic baseline but loses 12.8 points of groundedness and 1.9 of correctness with nearly equal retrieval hit rates (Table 2). Generation-only divergent pairs include 185 contradictory factual claims (Appendix Table 5). One system/domain, a GT-URL proxy, an unvalidated GPT-4o judge, fixed thresholds without sensitivity analysis, and possible infrastructure nondeterminism bound the claims (§6).

BQAA takeaway. A single execution is not a reliability estimate. Report any-run, every-run and per-run rates together, then store the first-divergence step and contradiction rate. For data agents, parallel retrieval-plan count is a first-class trace dimension, and more comprehensive answers must not silently trade away grounding.

3. ShellBench: What Matters More for AI Agents, Models, or Harness for Everyday Tasks — https://arxiv.org/abs/2611.32946

Full PDF read: yes — entire 17-page PDF read via pdftotext in chunks, including task construction, judging, experiments, limitations, references, full results, safety tables, and the worked task appendix.

Problem and method. ShellBench contains 100 everyday tasks derived from 10,456,576 opted-in personal-assistant queries, with realistic workspaces (median 188 files), competing sources, and all-or-nothing correctness and safety rubrics (§3, Table 3). Twelve models cross five harnesses and three effort levels produce 53,100 rollouts; 20 tasks are release-designated (§4.1). Ninety tasks use an agentic LLM judge and ten use code tests. Costs are estimated from recorded tokens and list prices, not provider bills (§4.2).

Results to reuse. The top three model means span only 1.1 points (62.5%, 61.9%, 61.4%), while harness means for the 11 shared models span 42.9–45.2 (Table 1). Across 55 configurations, model explains 95.7% of variance, harness 0.36%, and model×harness interaction/sampling 4.0%; restricting to the five strongest models changes that to 65.6% and 16.5% (§5.2), so “harness does not matter” is too strong. Mean Pass@1 is 44.4%, at-least-one-of-three 61.2%, and all-three 28.2% (§5.1). Safety fails in 15.7% of all rollouts, and 2,589 runs pass every correctness criterion while failing a safety requirement (§5.5, Fig. 7). Removing source and stale-information criteria moves Codex from fourth to first (Table 7). The LLM judge has 89.9% agreement on 278 sampled criterion decisions, not validated whole-task accuracy; only 20% of tasks are public, and harness prompt/tools/runtime are changed together (§§4.3, 6).

BQAA takeaway. Report model×harness interactions and rubric sensitivity beside every leaderboard. Preserve source-use and safety failures as separate outcome dimensions, and label token cost as estimated. A 2.3-point harness-average gap is not a universal harness ranking when the task’s evidence requirements can reorder it.

Six-week EV

  • Highest EV — recovery-aware run state (2611.31586): Add correction, protected-state, disclosure, durability and fixability to the run schema. This catches failures that success-only analytics structurally miss and gives BQAA a direct replay target.
  • High EV — repeated-run reliability as a standard metric (2611.31266 + 2611.32415 reserve): Budget repeated executions and report per-run/any-run/every-run plus first divergence. A single score is insufficient for nondeterministic retrieval and tool planning; the hazard paper is the next methodological read.
  • High EV — traces and outcomes as a shared analytical corpus (LangSmith Agent Lake): BQAA can separate storage from compute consumers while preserving trace↔outcome cardinality and evidence provenance. The adoption gate is measured judge/search/diagnosis quality and unit cost, not the “lake” label.
  • Medium-high EV — versioned, testable context (Google Knowledge Catalog): OKF bundles plus local validation and retrieval tests make context changes reviewable like code. Watch for actual retrieval-quality evaluations and publication/readback semantics before treating a bundle as authoritative.
  • Medium EV — attribution and telemetry hardening (ShellBench, Pydantic AI, Claude Code, LiteLLM, FastMCP): Pin and report harness/rubric state, isolate eval-event attributes from caller baggage, keep response content opt-in, and separate guardrail spend/audit trails. These are immediate schema and ingestion checks with low implementation cost.
