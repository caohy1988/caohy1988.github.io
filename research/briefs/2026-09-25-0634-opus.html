  • Every model call has usage.

NEW 1: OpenTelemetry Python GenAI instrumentations 1.2b0: cancellations become failures, each package reports under its own scope, gen_ai.conversation.id reaches nested spans, and agent and tool durations get their own metrics

Clocks: PyPI 16:36–16:38Z and GitHub releases 16:40:33–16:46:59Z on Thu Sep 24. The previous release was 1.1b0 on Aug 20. This is a late catch: it was published inside the 1234 Thu window, and no brief or pack reported it.

Packages:

  • The shared layer, opentelemetry-util-genai.
  • Model SDK instrumentations: Google GenAI, OpenAI, Anthropic, Bedrock, Portkey.
  • Agent framework instrumentations: OpenAI Agents, LangChain, LlamaIndex, DSPy, Agno, smolagents, Qwen-Agent.

Evidence: I read all 13 release notes, and the PR bodies of #520, #616, #632, #726 and #377. I also checked util-genai's source at the 1.2b0 tag.

  • Cancellation is now a failure (#520, #656).
  • Before, asyncio.CancelledError took the success path. In the PR's words, a cancelled operation "was exported with StatusCode.UNSET, no error.type, and a duration metric with no error dimension — indistinguishable from one that completed".
  • The PR adds that packages finalizing in their own except Exception: handler were "worse off": on cancellation "the span is never ended, so nothing is exported at all".
  • #656 closes that gap for OpenAI, Anthropic, Bedrock, Google GenAI, Portkey, Qwen-Agent and stream finalization.
  • Each package reports under its own instrumentation scope (#632).
  • Before, spans, metrics and logs from every package carried the scope opentelemetry.util.genai.handler. Now they carry, for example, opentelemetry.instrumentation.genai.openai.
  • get_telemetry_handler is deprecated.
  • The conversation id travels (#726, #474, #631).
  • gen_ai.conversation.id is held on the OTel Context. Inference, agent and workflow invocations read it at finish time, and nested invocations inherit it, so a chat span owned by a different instrumentation package picks it up.
  • OpenAI Agents maps RunConfig.group_id to it. LangChain resolves it from thread_id, session_id or conversation_id metadata. OpenAI Responses reads the conversation parameter.
  • The PR's tests keep the id off metric attributes.
  • Agent spans split into local and remote (#616).
  • In-process framework agents get SpanKind.INTERNAL and drop gen_ai.agent.id and the provider and server attributes. Remote agent services get CLIENT.
  • The OpenAI Agents, LangChain, LlamaIndex, DSPy, Agno, smolagents and Qwen-Agent instrumentations now record gen_ai.invoke_agent.duration and gen_ai.execute_tool.duration instead of gen_ai.client.operation.duration.
  • Usage fields (#613, #662, #674, #680):
  • cache_write_input_tokens replaces the deprecated cache_creation_input_tokens.
  • Per-modality (text, image, audio) token breakdowns are added.
  • OpenAI chat completions now record gen_ai.usage.cache_read.input_tokens and gen_ai.usage.reasoning.output_tokens.
  • Less content by default:
  • #377 (marked breaking): gen_ai.tool.definitions is no longer emitted when content capture is off.
  • #775: retrieval spans in LlamaIndex, LangChain and DSPy now keep document IDs and scores only, not text.
  • Silent coverage gaps closed (release notes):
  • Anthropic messages.stream() consumed via text_stream or get_final_message() "previously produced a span with request attributes only" (#654).
  • OpenAI async with_streaming_response calls recorded no response telemetry (#610).
  • LangChain never emitted streaming timing metrics (#482).
  • Failed Google Interactions streams left their spans open (#538).
  • New coverage:
  • First PyPI releases of the DSPy, Bedrock and LlamaIndex instrumentations; 1.2b0 is their only version.
  • Google GenAI adds time-to-first-chunk and time-per-output-chunk metrics and fetch_response spans.
  • Same stack, today:
  • OTel Python contrib v0.66b0 formally removes the anthropic, claude-agent-sdk, langchain and weaviate instrumentations from contrib (#4903); they now live in this repo.
  • OTel Python v1.45.0 lets attribute values be maps and mixed arrays (#5266).
  • Checked at the tag: util-genai 1.2b0 still serializes messages to JSON strings on spans (gen_ai_json_dumps(dicts) if for_span else dicts) and passes structured values only on log events. So span shape does not change yet.
  • Why it ranks as NEW: the catalog's otel-python-genai-* cards (Sep 1–2) are single merged PRs (#488, #494, #536, #537). None covers a release. This is the first release in five weeks, and it changes status, scope, metric names and the session join key across 13 Python instrumentations.
  • Caveats:
  • These are beta (b0) packages, and GenAI semconv is still "development".
  • A process that mixes 1.1b0 and 1.2b0 packages emits both scope names and both metric names.
  • gen_ai.conversation.id only appears where the framework supplies one.
  • TL;DR:
  • Join sessions on gen_ai.conversation.id from these producers.
  • Do not read status UNSET from pre-1.2b0 producers as success.
  • Alias the old and new scope and duration-metric names.
  • Store instrumentation scope and version on every span, so mixed fleets can be explained.

1. NEW rank: arXiv 2609.29429: Just Ask Jev: Reinforcement Learning for Calibrated Decisions as a Zero-Shot Detector of AI Alignment Failures (RLCDAlignBench)

Guo, Liu, L. Y. Zhang (Griffith); Deng (NTU); Li (UNSW); Zhao (independent); Wu (Deakin); Chen (George Mason); Y. Zhang (Wake Forest). Submitted 24 Sep 2026; under review at ICLR 2027. Code, data and cached answers are at sumleo/RLCDAlignBench (MIT; the repo exists, created Sep 24).

Full PDF read (50 pp): §1–6 and App. A–J (Tables 1–34, Figs. 1–7). I skimmed the references.

The idea: many alignment failures are relational. Sycophancy is defined against the user's belief, deception against the model's own belief, and injection against an instruction hidden in tool output. So the study varies what Jev is asked (wording and answer type) separately from what Jev sees (which fields of the interaction are in its input).

What they did:

  • The benchmark: 44 benchmarks and 10 failure types (sycophancy, jailbreaks, deception, prompt injection, hallucination, privacy violation, social bias, reward hacking, concealing uncertainty, power seeking), for 7,193 detection instances (Table 1).
  • Targets: five open 2–7B models (Qwen3.5-2B, Phi-4-mini, Gemma-2-2B, Llama-3.2-3B, Olmo-3-7B).
  • Labels: each benchmark's reference scorer (20 rules, 20 LLM judges, 4 multi-turn judges). Human labels exist for StrongREJECT (1,360 responses) and HarmBench validation (578).
  • Questions: one templated generic question per benchmark, asked as a yes/no (Noul), a pick (Choice) or a 3-level Score. Beside it, 15–40 targeted strategies, selected on one half of the items and scored on the other (20 splits) so that search does not inflate the result.
  • Context: 49 paired contrasts that add one field to what Jev sees. Each field is tagged deployable (a monitor could hold it) or label key (part of the label's definition).
  • Model and cost: every call resolved to jev-1.13.0 (collected Sep 23). 23,411 calls cost USD 2.27 in total.

Numbers:

  • Zero-shot ranking (§4.1, Table 6).
  • The generic Noul reaches a median AUROC of 0.886 [0.821, 0.952] over 31 benchmarks.
  • It beats the better of an in-domain TF-IDF classifier and response length on 25 of 31 benchmarks (+0.132).
  • The split-half targeted strategy reaches 0.911 over 38 benchmarks.
  • Wording barely matters (§4.2, Tables 5 and 8).
  • Targeted wording adds +0.006 [−0.004, +0.015] out of sample (24/1/11 wins/ties/losses, p = 0.055).
  • Choosing the best question on the evaluation data would overstate that by 0.008, which is more than the gain itself.
  • Keep answers soft (§4.2, Fig. 3, Table 4).
  • Reading the probability beats taking the top answer on 28 of 31 benchmarks for Choice and 29 of 31 for Score (Table 4).
  • Rubrics that threshold each answer at 0.5 before combining lose to one direct question on 9 of 10 benchmarks (median −0.137 AUROC).
  • What Jev sees decides detection (§4.3, Tables 10–12).
  • Deployable context missing from the state helped on only 1 of 4 benchmarks (the deceptive goal on DeceptionBench, +0.050).
  • The large gains come from label keys, such as PrivacyLens's secret list (0.79 → 0.95). Those gains measure the label's construct, not the failure.
  • Long trajectories lose AUROC only when the reference is missing (PrivacyLens −0.14).
  • Calibration and thresholds (§4.4, App. E, Tables 15–16).
  • Pooled, calibration is good (ECE 0.047). Per benchmark, the median ECE is 0.168 against 0.074 under perfect calibration, and 24 of 31 benchmarks exceed the null's 95th percentile.
  • The mean probability misses each benchmark's base rate by a median 0.125, while ranking stays strong. The median F1-optimal threshold is 0.35.
  • F1 is 0.706 at t = 0.5, 0.793 with a threshold fitted on 10 labeled items, and 0.822 with a cross-validated threshold. Label-free prior-shift correction makes it worse (0.571–0.690).
  • Route the unsure cases (§4.4, Fig. 6c; App. E). Keeping only the most confident half of decisions (largest |p − 0.5|) raises median accuracy from 0.793 to 0.933. On social bias, confidence is anti-informative (AUROC 0.355).
  • Against humans (§4.5, Tables 20 and 22).
  • On StrongREJECT, Jev's κ is 0.809 against the GPT-4o-mini reference scorer's 0.811, and its AUROC is 0.971 against 0.929.
  • On HarmBench validation, its κ with a single annotator is 0.748, against 0.736 between annotators.
  • Per generator it is worse on GPT-3.5 outputs: κ 0.668 against the scorer's 0.790, and no threshold closes that gap.
  • Label audit (App. F, Tables 25–26).
  • Jev's confident disagreements exposed label-changing defects in three benchmarks. Open-Prompt-Injection's label tracks the injected task's accuracy; SycophancyEval (answer)'s label is correctness; the SycophancyEval (feedback) judge is inconsistent.
  • The MACHIAVELLI labels cannot be observed from the state.
  • Two AbstentionBench judges agree at only κ 0.05.
  • Of the 311 items read one by one, 25.4% were Jev errors.
  • Cost (App. H, Table 32).
  • At list prices, one pass over 19 API-judged benchmarks costs $0.30 against $18.96 (62.9×).
  • Repriced conservatively (every judge at GPT-4o-mini, and Jev asked one question), Jev is 12.1× cheaper pooled and 3.3× at the median.
  • With the full question battery it is 6.0× pooled and 1.5× at the median, and the judge is cheaper on 5 benchmarks.
  • A call carries 11.4 questions on average, with a median latency of 0.31 s that does not grow with the number of questions.

Caveats I'd flag:

  • It tests one RLCD model version (jev-1.13.0), English only, 2–7B targets, and mostly scorer labels (11 of 38 usable benchmarks are validated).
  • Per-type medians rest on 1–6 benchmarks, so their CIs are wide. Six benchmarks are degenerate and excluded.
  • The label audit is one reader, with no second adjudicator.
  • The 63× figure leans on PrivacyLens and MASK, which are 62–65% of judge spend. Without them it is 35.1×.
  • The developer states no retention period for versioned model ids. The authors pin every result to cached answers.
  • The flip side is already in the catalog: JevOut (2609.30243) shows that exposed probabilities can be optimized against.

Why it ranks:

  • It is the first large, split-half-controlled test of Jev as a monitor for failure behavior, not as a rubric grader, and it includes a label audit.
  • Its instruments map onto what BQAA would compute over logged sessions: soft scores, per-dataset thresholds, confidence-based routing, and ablations of what the logged state contains.
  • It is distinct from the catalog's Jev-judge cards:
  • arxiv-2609-26550-jev-as-a-judge-accept-escalate: a cascade on grounded checks.
  • arxiv-2609-29769-jev-vs-llm-rubric-judges-correlated-errors: rubric panels.
  • arxiv-2609-26758-type-safe-is-not-error-free-option-name-flip: option-name flips.
  • This paper adds that detection quality is bounded by what the log contains.

TL;DR for BQAA:

  • Log each turn's relational reference: the user's stated belief, the system prompt or goal, and the tool output that carried an instruction. A response-only log cannot support sycophancy, deception or injection detection.
  • Store detector probabilities, not labels. Fit thresholds per evaluation set (10 labels recover most of the gap), and route the least-confident decisions to a judge or a human.
  • Record the judge model version (jev-1.13.0 vs jev-latest) with every score.
