  • the claim to its span and run;
  • the verdict to what the judge actually concluded;
  • the retry's effect to its counterfactual.

Academy

A1 (NEW). Guarded Commits: human approval as a ledger record that the commit step must check (arXiv 2610.00037)

Full PDF read (13 pages, including appendices A–C). Bindschaedler (MPI-SWS), Kossmann and Mohoney (MIT CSAIL), Liu (Purdue). cs.DB. Submitted Sep 2; it first appeared in the Fri Oct 2 listing.

  • Problem (§1–2):
  • Approvals usually live outside workflow state, as a UI click or an audit line. So nothing at commit time checks that every risky path crossed an approval gate, or that the approval covered this artifact under this policy.
  • In agent runtimes, the agent process often holds the merge or publish credential while the human reviews elsewhere. "Logs are not commit predicates."
  • The contract (§3, four conditions checked by a credential-confined commit adapter):
  1. Barrier coverage on the executed path. The runtime, not the LLM, emits an executed-path witness, which must match a validated plan path containing an eligible approval barrier.
  2. Policy and ledger-prefix pinning. The decision was made under the governance-policy version and ledger state pinned when the transaction started.
  3. Artifact identity. The artifact hash consumed by the action equals the one bound into the approval. For an EDIT, the triple (pre-hash, delta hash, post-hash) is bound.
  4. Safe reuse and automation. A cached decision is reused only on exact canonical-context match with fresh reviewer credentials. Reuse writes a new derived record pointing transitively to a non-derived human (or declared automation) root.
  • Evidence (§5, Tables 1–2):
  • Workloads: three public workloads totalling 271,035 traces: 33,056 agent-authored GitHub PRs (AIDev), 236,532 Wikimedia ContentTranslation sections, and 1,447 CoAuthor sessions.
  • Replay: reproduced recorded artifact hashes in 252,386 / 252,386 traces that had artifacts (artifact coverage 100% / 92.1% / 100%).
  • Plan validator: 0 false accepts and 0 false rejects on 999 synthetic DAGs with injected missing, wrong-kind and partial-coverage barriers.
  • Cache-only reuse: avoidance is 0.9% / 16.8% / 72.0%, and disagreement with recorded human decisions is 0.04% / 5.3% / 27.6%.
  • Adding the bypass rules: translation disagreement rises to 10.6%. The ledger attributes the added 5.20 pp of disagreement to one bypass rule, which added 8.21 pp of avoidance. That is roughly 63% conditional disagreement inside the bypassed cohort (§5.3).
  • Baseline table (Appendix A, Table 3): Claude Code / Cursor permission systems: none of the four clauses. GitHub branch protection plus the Copilot agent: partial path coverage and artifact binding only. BPM / Temporal-style engines: partial coverage and pinning.
  • Limitations (stated):
  • Evidence is trace reconstruction only. There is no deployed-pipeline baseline and no learned-deferral comparison.
  • Reviewer credentials are synthetic: a hashed 75/10/10/5 split.
  • The trusted base (transaction manager, validator, adapter, ledger) is assumed honest.
  • Disagreement is a proxy, not correctness.
  • Why BQAA cares: pairs directly with APEX (2610.01564, carded at 0034), where a skill-written "user approved" record hijacked agents 74% of the time. An approval row that does not carry artifact hash, policy version, ledger offset, executed-path id and a reuse pointer cannot distinguish a real approval from a forged or stale one.

A2 (NEW). Actions with Receipts: binding claims, evidence spans and execution into one replayable receipt (arXiv 2610.00327)

Full PDF read (35 pages, including appendices A–E). Hu et al., UCAS School of AI and CAS Institute of Information Engineering. cs.CR. Submitted Sep 29.

  • Problem (§1–2): a valid citation and a valid trace can each be well formed while being transplanted across claims, actions, runs or source versions. Nothing binds "the sentence the user saw" to "the execution that produced it" and "the exact span that supports it".
  • Mechanism (§3, "EC-Agent"):
  • Each claim gets an emission anchor: event index, field, offsets, SHA-256 of the claim.
  • Evidence references carry document, span, offsets, UTF-8 hash and quote.
  • A domain-separated digest covers the ordered event prefix through the answer.
  • A joint commitment covers all of the above plus the run manifest and source version / access state.
  • An integrity plane (deterministic) is kept separate from a pluggable support plane (lexical, conflict-aware guard, NLI, LLM judge or human).
  • Results:
  • Joint contract (Table 16): detects 1,275 / 1,280 cross-object substitutions (0.9961) at a 0.0031 false-rejection rate.
  • Baselines (Table 18):
    • citation + independent trace + shared run id detects only 0.2266 of claim transplants;
    • citation alone detects 0.1094;
    • trace alone detects 0.0312.
  • Ablation (Table 17): removing any one of the seven properties drops detection of its targeted attack to 0.0156–0.0625.
  • Structural validity is not support (Tables 19–20, 384 adjudicated pairs, κ = 0.834): certificate validity alone has false acceptance 0.9375.
    • The deterministic conflict-aware guard (numeric, entity, temporal and polarity atoms) reaches F1 0.8865 at false acceptance 0.0729, in 0.23 ms per pair.
    • A frozen LLM support judge reaches F1 0.8831 at false acceptance 0.1198, in 0.73 s and 294 tokens.
  • Cost and non-interference (Tables 27–28):
    • Receipt overhead is 1,876 bytes against an 11,243-byte trace (16.9% storage), with 0.47 ms online verification.
    • Receipt-on and receipt-off runs match exactly on event traces at 0.9986, and the task-success difference is 0.0000.
  • Limitations (stated and observed):
  • The integrity guarantee assumes a trusted runner and logger.
  • The 128-row fixed-corpus screen uses title-copied claims from HotpotQA.
  • The model-backed study (2,550 tasks × 3 seeds) does not name its model in the paper; it defers to a manifest.
  • The lexical rule accepts 16/16 lexical-adversarial claims by design.
  • Why BQAA cares:
  • Joining citations to traces by run id leaves claim transplants largely undetected (22.7% caught). The binding key needs to be claim hash + span hash + execution-prefix digest + source version.
  • The integrity/support split maps cleanly onto two columns, "is this record intact" and "does the evidence support it". BQAA should not let the first stand in for the second.

A3 (NEW). The First Token Is Not the Verdict: first-token judge readouts overstate position bias (arXiv 2610.00054)

Full PDF read (5 pages). Villuri, Shaik and Doboli, Stony Brook. NeurIPS 2026 JUDGe workshop. Submitted Sep 4; it first appeared in the Fri Oct 2 listing.

  • Setup (§2):
  • Judges: Qwen3-1.7B / 4B / 8B, Llama-3.1-8B-Instruct and Phi-3.5-mini, run on the full JudgeBench (620 pairs) and LLMBar (419 pairs).
  • Readouts compared: (a) a forced first-token read, the larger of the two verdict-token logits, which is what constrained decoding and restricted-likelihood harnesses produce; (b) generate-and-parse, up to 500 tokens with a 1,500-token retry.
  • Results:
  • Compliance (the judge leads with a verdict token in both orders) ranges from 0.506 to 1.000 (Table 1).
    • Changing only the verdict tokens (X/Y to 1/2) moves Qwen3-8B from 0.506 to 0.676.
    • Changing only the benchmark moves it from 0.506 to 1.000. Compliance cannot be borrowed from another study (§3).
  • When the judge has not committed, the forced read reflects slot position, not content (§4):
    • Of 924 non-compliant pairs, the forced read flips on 829 (89.7%) against 439 (47.5%) generated. The paired difference is +0.422, CI [+0.365, +0.467].
    • 827 of 829 locks are to the first slot. So first-token position-bias figures are upper bounds.
  • Accuracy barely moves: the readouts differ by under one point in seven of ten conditions, while flip rate differs by up to 0.220 (Table 1). The distortion hits judge audits, not judge users.
  • Second failure (§4): even a compliant first token disagrees with the judge's final reasoned verdict on 0–5.5% of pairs (Qwen3-4B 15/271; Phi-3.5-mini 14/257). This rate is uncorrelated with compliance (r = 0.01).
  • Cheap fix (§5): read the first token, and generate only where the judge did not lead with a verdict. This cuts generations by 85.5%, with fidelity of about 0.945–1.00.
  • Limitations:
  • Open-weight judges at 8B and below only.
  • The divergence is measurable only in Qwen3, because Llama and Phi are too compliant to analyse.
  • The parser is heuristic.
  • Why BQAA cares: any judge-based eval stored next to traces should record readout mode (constrained / logprob versus generated), verdict tokens, and the judge's compliance rate. Without those, a position-bias or judge-drift dashboard can show 40-point artefacts.

A4 (NEW). When Harnesses Lose the Signal: paired branches score recovery as rescue versus harm (arXiv 2610.00372)

Full PDF read (15 pages, including appendices A–B). Xiao et al., Beijing Normal University and Ke Holdings. cs.AI. Submitted Sep 30.

  • Method (§3):
  • Controlled errors: inject a stale (1- or 2-step) or missing observation at 25% of the trajectory.
  • Paired branches: at delay d, branch from the identical state and history into recovery and no-recovery runs.
  • Scoring: rescue (fail to success) and harm (success to fail) are counted separately. The net effect is rescue rate minus harm rate.
  • Setup: ALFWorld, Qwen3-14B, ReAct harness, greedy decoding.
  • Results:
  • Recovery can hurt healthy runs (§5.2): on the 93-task factual-success cohort, an immediate refresh on clean observations lowered success by 6.45 pp (CI [−11.83, −2.15]).
    • On stale observations the effect was +7.53 pp, but that CI crosses zero.
    • The stale-minus-clean difference is 13.98 pp (CI [2.15, 24.73]).
  • Averages hide churn (§5.2): in the full 106-task cohort, refresh produced 2 rescues / 6 harms on clean runs and 17 rescues / 10 harms on stale runs.
  • Mechanism (§5.3, Appendix A): a refresh that queries the environment but hides the returned content still rescues 8 of the 10 tasks that full refresh rescues. Effects: +10.45 pp ablated versus +13.43 pp full, at delay 4 under two-step stale observations. The benefit is not just "better data".
  • Selective router, CIR (§5.4, Table 1): on 300 held-out episodes, success rises from 70.33% to 73.33% (+3.00 pp, CI [0.67, 5.67]), with 11 rescues, 2 harms and 0 interventions on clean runs. The gain is +9.33 pp on two-step stale observations.
    • The margin over a rate-matched anomaly baseline is +1.00 pp, CI [−0.67, 2.67], which is not significant.
  • Limitations:
  • One model and one benchmark; 75 held-out tasks.
  • The router's edge over a plain anomaly detector is not significant.
  • Why BQAA cares: retries and "recovery" steps are usually scored by success-after-retry. This paper shows they should be scored as rescue count and harm count against a paired baseline. Even without replay, logging pre-retry state features plus outcome lets BQAA estimate harm on clean runs.

Six-week EV

  1. Approval records become structured, not events. Guarded Commits plus APEX (0034) plus Claude Code's tool_decision fixes (Sat 0034 Progress) all push toward approvals that carry artifact hash, policy version and path. Expect at least one framework to add an approval id plus artifact digest to its HITL spans within six weeks. A BQAA approval schema with those columns would be ahead of it.
  2. "Run id" stops being enough as a join key. Receipts shows run-id joins miss 77% of claim transplants. For BQAA's citation and grounding analytics, a content-hash join (claim hash, span hash) is the defensible design.
  3. Judge metadata becomes mandatory. Readout mode and compliance rate are cheap to record. Any BQAA eval table that stores judge verdicts without them cannot explain position-bias swings. This needs a schema change, not a research project.
  4. Retry analytics shift from success rate to rescue and harm. Frameworks are adding durable retry and recovery (Qwen Code's Runtime workers, LangGraph fork fixes). A "retry harm on otherwise-healthy runs" metric is a differentiated BQAA view.
  5. Checkpoint history correctness is a live bug class. LangGraph #8548 shows time-travel forks could silently mix branches. When it ships, BQAA readers of LangGraph checkpoints should flag pre-fix fork histories as suspect.

  • First Token Is Not the Verdict (2610.00054): first-token judge reads overstate position bias (89.7% versus 47.5% flips on uncommitted pairs) while accuracy barely moves. Store the readout mode and compliance rate with every judge score.
