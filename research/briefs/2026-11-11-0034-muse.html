NEW 1 — Comparative Analysis of Agent Evaluation Frameworks: Stability, Detection, and Discovery in Enterprise Analytics Agents — https://arxiv.org/abs/2611.14493

Full PDF read (pdftotext, entire paper: Sections 1–7, Tables 1–7, Figure 1, and Appendices A–K including per-agent detection tables, judge configurations, example cases, and variance analysis).

Zhang et al. (Amazon) run the comparison BQAA buyers actually face: three evaluation paradigms — Strands Evals (trace-based LLM judge over the full OpenTelemetry execution trace), PromptFoo (text-only LLM judge plus red-teaming), and Agenta (deterministic string heuristics) — over frozen execution traces of two retail supply-chain analytics agents (category demand forecasts; product inbound lead-time forecasts; 9 tools each, SQL over warehouse tables), across five requirements (groundedness, intent, accuracy, tool correctness, SQL correctness; Table 1). Phase 1 measures harness stability (20 cases/agent, 3 judge models × 5 repetitions, 5,605 evaluations): 35/36 configurations meet the ≤0.15 within-case-std threshold (Table 2), but decision consistency — whether repetitions agree on pass/fail — is only 82% for the trace judge and 92% for the text judge, which the authors correctly read as not reliable enough for automated CI/CD gating, only for aggregate development signal (Section 4.1, Table 3). Stability is a property of the (framework, judge-model) pair, not the model alone: the single unstable cell (Qwen3/style in Strands, 0.207, 20% consistency) is stable in PromptFoo.

Phase 2 is the core result (72 cases, 33 with at least one dimension failure, 28 of them SQL correctness; Tables 4–5, per-agent Tables 9–10). Aggregate detection: trace judge F1 0.896 (precision 88.2%, recall 90.9%, FPR 10.3%), text judge F1 0.716 (60.4% / 87.9% / 48.7%), deterministic F1 0.629 (45.8% / 100% / 100% — it flags everything). The gap is entirely on dimensions needing execution context: both LLM judges hit ~89% recall on SQL correctness where query text can be injected, but on tool correctness the trace judge detects 89% vs the text judge's 11%, and on groundedness 0% vs 52% FPR, because text-only input carries tool-result metadata rather than the data the agent referenced. Deterministic regex matches the LLM judges on structurally-detectable SQL errors on one agent (92.9% recall) and scores 0% on the other's semantic errors (missing partition-key strings) — hand-coded checks work only for anticipated patterns, at custom-development cost. Phase 3 (discovery; Tables 6–7, Appendix C) generates 40 functional + 90 adversarial cases and finds 24 novel failures with zero overlap by design and in fact: functional generation surfaces a systematic silent SQL bug (UPPER(SUBSTR(product_id, -1)) — negative indexing returns empty string in the target dialect, zero rows, agent reports "no data found"; 6 cases, high severity) plus retry storms and schema fabrication, while red-teaming surfaces schema-metadata leakage (10), storage-path exposure (5), system-prompt disclosure (4), and excessive agency under prompt injection (1). Evaluators also caught 9 failures the human labeler initially marked pass (syntactically valid, semantically wrong SQL partitions; inverted calibration interpretation); the footnote sensitivity check excluding those relabeled cases barely moves detection (precision 0.82 vs 0.86, recall 0.88 vs 0.91), so the ranking does not hinge on the revision circularity.

Why it matters for BQAA: this is direct evidence for trace-first eval storage. If BQAA keeps only prompts/final answers, customers get text-judge economics — same recall, ~5× the false alarms, and blindness to tool-selection and groundedness failures; if it keeps queryable OTel traces with tool inputs/outputs and generated SQL, the same judge models become precise enough for development gating and second-reviewer duty on silent semantic SQL errors. The prescribed operating model is two-framework (trace judge for function, red-team generator for disclosure/agency risks), with judge configurations validated per (framework, model) pair — and explicitly not per-case CI blocking at 82–92% decision consistency. Limits to carry on the card: two agents from one forecasting system in a research (not live production) setting, 72 labeled cases with a single primary domain labeler per agent (cross-review only on ambiguous cases), frozen traces only, and no test of whether scores track real agent improvements/regressions (the authors' own Future Work, Section 7). Card the information-access finding, the per-dimension gaps, and the discovery complementarity; do not transfer the absolute F1s to other agents.

NEW 2 — Dependable Long-Horizon LLM Agents: A Trajectory-Centered Empirical Study of Where Errors Enter and Which Controls Reach Them — https://arxiv.org/abs/2611.13254

Full PDF read (pdftotext, entire paper: Sections 1–6, Tables 1–6, Figures 1–2, threats to validity, and Appendices A–E including the dynamics/controls background, control-contract Table 10, evaluation protocol, and case analyses).

Wang et al. define an episode record — origin, affected invariants, dependency links, detections, responses, manifestations, each located by operational phase (P0 admit → P7 govern) and state domain (R1 compute → R6 organizational) — write it as a 38-field annotation protocol, and apply it to 95 failed runs (88 Who&When + 7 MAD outcome failures, six multi-agent systems), reading each trajectory in full (Sections 2–3). RQ1 (Tables 2–3, Figure 2a): faults enter mostly in execution/deliberation (P2 34 runs, P1 24) corrupting task/knowledge state (R2, 71/95); kinds are wrong decisions with adequate information (42%), fabrications (26%), and misintegrated observations (11%). Origins sit at a median 0.18 of run length with a median 0.67-of-run gap to the symptom; in 37/88 Who&When runs the episode origin precedes the corpus's human-labeled "decisive step" (median 3 steps earlier), typically because the plan/fact sheet already held the wrong assumption the decisive step merely acted on. RQ2 (Figure 2b) is the number to remember: in 68/95 runs (72%) the trajectory already contained an observation or message contradicting the error before failure — in 32 of them before the fault even entered — yet agents acted on it in only 7 runs (41 never mentioned, 19 acknowledged and continued). Something flagged a deviation in 29 runs (31%) and a response followed in 34, but not one response removed the deviated state (4 removed part); replans changed the next action and kept the contaminated belief. RQ3 (Table 4): the controls judged to reach episodes are independent judges reading the unused evidence (74% any-reach), admission-time task contracts (67%), environment re-verification of beliefs (43%), stall rules (40%), and provenance on stored facts (38%; most-direct control in 20 runs, mostly fabrications); restoring the agent's own pre-origin state would have sufficed in only 35/95 runs — in 56 the fault sat in plan/brief/stop-rule that a restore would replay. Symptom labels underdetermine all of this: each frequent MAST mode maps to 4–11 distinct origin cells and multiple origin kinds (Table 6), so a mode count cannot say where to intervene.

The harness finding deserves its own sentence because it is annotation-independent: a deterministic scan of all 184 raw Who&When trajectories finds a provider content-filter crash (HTTP 400 on the orchestrator's ledger call) followed by a harness-emitted FINAL ANSWER no agent produced in 26/58 hand-crafted runs (45%; 25 with fallback answers, 0/126 algorithm-generated), and the corpus attributes 21 of those 25 to an agent other than the orchestrator (Section 4.6). Attribution methods scored on that split are partly scored on harness output. Why it matters for BQAA: failure analytics need origin/propagation/evidence/response fields, harness-termination as a first-class disposition separate from agent error, and control-coverage reporting (which stored facts lack provenance, which beliefs were never re-checked against the environment) — symptom taxonomies and responsible-step labels alone will misdirect fixes toward downstream steps and checkpoint machinery that replays the fault. Limits, stated plainly in Section 5.1 and to be carried on the card: annotation was performed by an LLM (one instance per trace) with no human inter-annotator agreement reported — mitigations are step-anchored fields, schema validation, 59% within-one-step agreement with human decisive steps, and the annotation-free harness scan; the 96/203 sample is batch-selected (length-matched on Who&When, small/short-biased on MAD); both corpora are sandbox QA/programming with zero external side effects, so committed-effect recovery is unstudied; and "would have reached" is counterfactual judgment, not a measured intervention. Card the episode schema, the early-origin/unused-evidence/ineffective-response measurements, and the harness-denominator warning with the annotator caveat attached.

NEW 3 — Agent Benchmarks Stop Ranking Before They Run Out of Tasks — https://arxiv.org/abs/2611.13541

Full PDF read (pdftotext, entire paper: Sections 1–8, Tables 1–2, Figures 1–4, limitations, and references).

Dong et al. re-score released runs of eight agent benchmarks (plus a small Terminal-Bench re-run) and split "saturation" into two measurement failures. Failure A, the bit is too coarse (Section 3, Figure 2): grouping leaderboards into statistical tiers (step-down max-T, 5% family-wise false-split bound), today's SWE-bench Verified and Terminal-Bench 2.0 top tens each form a single tier (spreads 3.6 and 8.5 points; no neighbouring pair significant on any of the three leaderboards studied, though the test detects ~6.3 points at 80% power and the top ten jointly solve 91% of tasks — ranking exhausted, tasks not). Verifier error exceeds the gaps: strengthened tests reject 17.7% of the median SWE-bench agent's passing patches (agent-specific spread ~2 points vs 0.2–0.4-point neighbour gaps), and correcting verdicts reorders neighbours no more than deleting a random sixth of each agent's passes (8 reversals either way) — neighbour order is noise. Failure B, the bit is capped (Sections 4–6, Tables 1–2): binarizing ALE-Bench's contest score against the median human collapses three tiers into one (S=1.00) although 47.8% of runs beat that human, while an uncapped objective restores three (S=0.03); partial credit below the reference does not help, only credit above it does. Raising the bar cannot substitute: a contest-winner bar separates newer models only by scoring 89% of earlier models zero on every task, and per-task calibrated bars still tie the later top ten — each bar sees one ability band. The derived fix is a clipped log-ratio score (baseline 0, reference 1, above 1 allowed to clip 3; unit-invariance + additive composition force the log form), with cost metered separately and never blended (a quality–cost composite anti-correlates with human rating, τ −0.35, on the later cohort). The discarded signal is large where it exists: only 20% of Terminal-Bench 2.0 tasks even compute a thresholded quantity (Figure 3a; 0% in the SWE-bench/OSWorld/τ² samples), but in the 13-task re-run (4 models, 156 runs, ~$115) pass/fail-tied models differ 10.9× vs 1.3× in median speedup on an all-pass task, 69% of passing runs beat the reference solution, and tied top-ten agents differ 7.3× in median tokens and 5.5× in median dollars per run. Section 7 packages this as layered evaluation: hardened deterministic gate, anchored per-domain objective with frozen dated anchors, separate cost meter, lexicographic reporting (gate rate → objective → cost Pareto), LLM judges for authoring evaluators only, never runtime scoring.

Why it matters for BQAA: any agent leaderboard, regression gate, or customer-facing quality number built by thresholding a stored quantity (SQL runtime, result quality, contest/task metric) and discarding the quantity will first stop ranking, then invite a "harder version" that breaks comparability — only a third of flagship-card agentic results are even comparable to the same lab's previous flagship (Figure 1). The importable discipline: persist the graded quantity and per-run cost alongside the verdict, report tiers with intervals instead of integer ranks, freeze baseline/reference anchors with dates so versions link, and keep cost as its own axis. Limits (Section 8): per-agent verifier error exists only for SWE-bench Verified (strengthened tests taken as truth; false-fails only simulated), the sliding-bar result rests on ALE-Bench with partly reconstructed release dates (tiers unchanged on the 32 verifiable-date models), the margin does not help where the key still separates (MLE-bench) or badly-aggregated continuous scores (SWE-fficiency's harmonic mean resolves worst), the re-run's aggregate model separation is borderline at 3 trials/cell, and rubric-graded work with no scalar objective is out of scope. Card the two-failure diagnosis, the clipped-log-ratio + separate-cost prescription, and the tier-reporting discipline; do not card a universal "benchmarks are saturated" claim.

TL;DRs for BQAA

  • 2611.14493: Give the judge the trace, not the transcript — on enterprise analytics agents a trace judge hits F1 0.90 at 10% FPR vs a text judge's 49% FPR at matched recall, tool-correctness detection 89% vs 11%, and functional + red-team generators find disjoint failure sets (silent zero-row SQL vs schema/prompt leakage). Store full OTel traces with SQL and tool outputs or eval quality is capped by input, not model.
  • 2611.13254: Failures start early and the refutation is usually already in the trace — median fault origin 0.18 into the run, contradicting evidence present in 72% of failures and acted on in 7/68, zero responses removed the bad state, and 45% of one benchmark split ended in harness fallback answers misattributed to agents. Record origin/evidence/response and harness disposition; symptom labels and checkpoints alone misdirect fixes. (LLM-annotated; no human agreement reported — harness count is annotation-free.)
  • 2611.13541: Benchmarks run out of ranking before tasks — SWE-bench/Terminal-Bench top tens are single statistical tiers, verifier error (~18% of passes rejected on retest) swamps 0.2–0.4-point gaps, and pass/fail ties hide 10× quality and 5–7× cost spreads. Persist graded quantities + cost, report tiers and anchored objectives, never just raise the bar.
