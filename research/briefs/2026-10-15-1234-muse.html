Haystack 3.4.0 — ToolResultOffloadCompactor preserves tool results by reference; Python 3.10 dropped; page_number semantics unified

  • What shipped: GH Release v3.4.0 published 2026-10-15T09:26:37Z (stable; body read via gh api by me), PyPI haystack-ai 3.4.0 uploaded 2026-10-15T09:26:27Z (DSH 0232's direct read) — registry first by ~10 seconds, both clocks labeled. No prior Haystack framework card exists (the catalog's haystack item is the Enterprise Platform traces product), so this ranks NEW.
  • The capability: the experimental ToolResultOffloadCompactor, a strategy for CompactionHook, does not drop or summarize older tool results when compaction triggers. It writes them to a ToolResultStore (filesystem implementation shown in the release example) and leaves a reference in their place; the agent reads full output back on demand with a read tool scoped to the same store. Fresh results stay in context until compaction, so short runs pay nothing extra. Compaction — usually the moment trace evidence quietly disappears from the model's view — becomes an addressed, recoverable state transition.
  • Compatibility and data semantics: Python 3.15 is supported and 3.10 dropped (3.11 floor, matching Inspect's move the same day). page_number now means the page a chunk's text starts on in every splitter; form-feed edge cases are corrected, with explicit guidance to re-index affected documents — stored chunk metadata changes meaning at this version boundary, which is exactly the kind of silent semantic shift that corrupts longitudinal retrieval comparisons if unversioned.
  • Why it matters for BQAA: offloaded-by-reference tool results are a warehouse pattern arriving inside the agent loop. Runs built on this hook will contain references whose payloads live in a side store; ingest that captures only the transcript will hold pointers to evidence it cannot resolve. Schema room for offload references (store identity, path, read-back events) is the actionable item. The refusal-preservation merge collectors caught this morning (haystack #13262) is not claimed here — I did not verify its presence in the 3.4.0 body; see Unconfirmed.

AgentSafeEvo: Adversarial Co-Evolution for LLM Agent Safety

  • Full PDF read. v1 [cs.AI] 14 Oct 2026. Wang et al. (Shanghai AI Lab, Fudan, SJTU, Zhejiang). Code and HF collection linked in the paper (not audited by me).
  • The question: agent safety training against a fixed attack set freezes the attack distribution while the defender improves. Prior co-evolution work is language-level (jailbreak/response) or, for agents, refines injections inside supplied tasks (ARLAS). AgentSafeEvo asks whether task construction itself can co-evolve with safe task execution across attack types.
  • Method: an attacker–defender RL game over multi-turn tool interactions. The attacker (Qwen3-8B, SFT-initialized on a constructed dataset spanning 50 agent scenarios and ~7,000 tools, built from ~10K TOUCAN tasks transformed with adversarial structure) constructs adversarial tasks — user query plus tool-environment configuration — across six attack types; the defender (also Qwen3-8B) executes them; both update from safety/utility judgments by a Qwen3.8-27B reward model. Learnability-guided task weighting up-weights tasks with greater within-task defender-reward variance in both policies' updates.
  • Results: best mean performance across all four safety benchmarks (Table 1). Against Static-AT (frozen attacker, the strongest safety baseline): Agent-SafetyBench ASR 31.01% → 17.84%, MSB ASR 38.64% → 31.25% with NRP 40.64 → 46.00, AgentHarm harm score 30.00 → 6.53, AgentDojo utility-under-attack 61.43% → 66.52% at 6.18% ASR. General capability improves rather than trading off (Table 2): ALFWorld 30.89% → 43.72%, ToolHop 39.43% → 48.04%, BFCL-V3 essentially preserved (65.98% vs 66.13% base). Cross-stage evaluation on 100 held-out seeds shows both sides improving: the final attacker reaches 92.59% ASR against the base defender (vs 55.81% for the SFT attacker), while the final defender holds that same attacker to 49.82% (Figure 3a). The evolved attacker transfers to larger targets — ASR vs SFT attacker rises 43.7% → 80.7% on Llama3.3-70B and 12.3% → 22.5% on GPT-5 (Figure 3b). Ablations (Table 3) credit co-evolution itself (−8.10/−5.75 ASR points over defender-only) and shared weighting (one-sided weighting can beat it on single-benchmark ASR but loses on NRP and general accuracy).
  • Limits (from the paper's own reporting): I found no standalone Limitations section; the stated scope is single-agent tool use, with collaborative multi-agent risks (communication, delegation) named as future work. Both policies and all headline numbers are Qwen3-8B-scale; safety/utility rewards come from a single model judge; the cross-stage matrix rests on 100 seed instances.
  • Why it matters for BQAA: this prices adversarial-task corpora as versioned assets. If the attack distribution co-evolves with the defender, then a safety score is only interpretable against the attacker checkpoint that produced it — attacker identity/version and per-task learnability weights belong in the eval record alongside defender version, or longitudinal "ASR improved" claims are incomparable. The transfer result also means one lab's evolved attacker is a reusable probe of everyone else's agents: expect generated adversarial tasks to circulate like benchmarks do, with the same provenance needs.

RuleTrek: Benchmarking Agentic Rule Reasoning in Complex Scenarios

  • Full PDF read. v1 [cs.AI] 14 Oct 2026. Yuan, Yu, Xu et al. (CAS Institute of Automation, UCAS, BAAI).
  • The question: rule-reasoning benchmarks usually hand the model a few factual statements, which makes finding the applicable rules trivial. Real work — tax, procurement, security policy — distributes facts across files and rules across repositories with dependencies. RuleTrek measures whether agents can find the rules, not just apply them.
  • Method: a rule-grounded construction pipeline extracts structured rule graphs from real-world repositories, generates a sub-scenario per rule, then composes sub-scenarios along rule dependencies while verifying consistency and solvability at each step. The evaluation set holds 240 instances across six domains (taxation, PostgreSQL, cybersecurity, software policy, procurement, game rules; 30–48 per domain, Table 3), run in interactive multi-file workspaces. Three scored capabilities: Rule Identification (recover applicable rules + dependencies from original documents), Rule Deduction (apply provided verified rules to distributed facts), and End-to-End (both). Eleven frontier LLMs are evaluated.
  • Results: identification is the first wall — best average RI is 62.47% (GPT-6.1-Sol), with the weakest model at 33.35% (Table 2). Even handed the verified rule graph, best RD reaches only 60.43%; E2E spans 26.97–55.29%. Error analysis (Table 4) shows systematic misses: condition-specific controls overlooked beside general requirements (cybersecurity), supporting initialization rules missed (tax), and distinct rules with different applicability conditions merged (game). Difficulty scales with rule-graph size and depth.
  • Limits (stated by the authors): English-language repositories only; predefined, static rule/scenario repositories for reproducibility — dynamic environments where rules evolve over time are named as future extensions.
  • Why it matters for BQAA: the RI/RD/E2E split is a ready-made attribution schema for any rules-driven agent workload: a wrong answer decomposes into "never retrieved the governing rule" versus "retrieved it and still reasoned wrong," and RuleTrek shows the first failure dominates at the frontier. For trace analytics, that argues for recording which rule documents/spans an agent actually opened before its decision — retrieval provenance, not just final-answer scoring. It also complements this morning's AgentSafeEvo read: one paper prices the attacker's task distribution, the other prices the defender's rule coverage.

  3. id: arxiv-2610-19422-agentsafeevo-adversarial-coevolution-agent-safety
    • tag: Academy
    • title: AgentSafeEvo — adversarial task construction co-evolves with safe execution; ASR nearly halved vs static adversarial training, attacks transfer to larger models
    • arxiv: https://arxiv.org/abs/2610.19422
    • card text: Full PDF read. AgentSafeEvo co-trains an attacker that constructs adversarial agent tasks (50 scenarios, ~7,000 tools, six attack types) against a defender executing them, with learnability-guided task weighting from within-task reward variance. Against static adversarial training it cuts Agent-SafetyBench ASR from 31.01% to 17.84% and AgentHarm harm from 30.00 to 6.53 (Table 1) while raising ALFWorld accuracy to 43.72% (Table 2); the evolved attacker's tasks transfer to larger targets (Llama3.3-70B ASR 43.7%→80.7%, Figure 3b).
  4. id: arxiv-2610-19698-ruletrek-agentic-rule-reasoning-benchmark
    • tag: Academy
    • title: RuleTrek — agentic rule-reasoning benchmark over multi-file workspaces; rule identification caps at 62.47% across 11 frontier models
    • arxiv: https://arxiv.org/abs/2610.19698
    • card text: Full PDF read. RuleTrek builds 240 multi-file instances across six domains from extracted rule graphs and scores Rule Identification, Rule Deduction, and End-to-End reasoning separately. Eleven frontier models reach at best 62.47% RI and 60.43% RD, with E2E spanning 26.97–55.29% (Table 2); error analysis shows condition-specific and supporting rules systematically missed (Table 4).
