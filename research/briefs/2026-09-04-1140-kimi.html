Industry

1. Arize Phoenix v20.8.0 — server-side error-status and latency filters on the trace list endpoint; MiniMax provider integration. GitHub release, published 2026-09-04 (18:32:44 UTC / 11:32:44 PT). The substantive feature (#14037) moves error-status and latency filtering for the trace list from client/UI-side down into the server query endpoint, so filtered trace listings are evaluated at the data layer rather than after fetching. For a trace store at Phoenix's scale this is the difference between a UI convenience and an API contract other tooling can build on — schedulers, alerting loops, and external analytics can now ask for "error traces slower than X" without paging full result sets. The release also adds a MiniMax provider integration (#14310) for playground/eval model coverage, and bumps arize-phoenix-client to 3.4.0. Nothing in the release changes Phoenix's eval or experiment surfaces. Net: a small but real shift of trace-query capability from presentation to platform. TL;DR for BQAA: Watch the pattern, not the version — vendors keep pushing trace filtering (error status, latency) into the serving API; BQAA's trace-query surface should treat these as first-class pushed-down predicates, not UI-side refinements.
