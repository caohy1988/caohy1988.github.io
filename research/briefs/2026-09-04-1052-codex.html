Industry

1. Gemini Enterprise: GA agent latency and error-rate views distinguish thinking from the answer the user sees (September 3)

The dated release note says the two new Observability views are GA:

  • Latency: p50 and p95 for Time to First Token (TTFT), Time to First Answer (TTFA), and Time to Last Token (TTLT). TTFT includes the model’s thinking tokens; TTFA begins only with the answer itself. Latency can be compared by agent feature.
  • Error rate: request volume and failure rate grouped into OK, client error, server error, and canceled outcomes, with the underlying client/server codes.

The metrics documentation, last updated 2026-09-03 UTC, makes the product shape more concrete. The Observability tab applies to the Core Assistant, Workflow Builder agents, and Deep Research agents. It has Overview, Tools, Latency, and Error rate views. TTFA restarts when an agent calls a tool after it began interim narration, so the metric measures when the answer the user ultimately reads starts streaming. A feature table gives traffic share plus p50/p95 TTFT, TTFA, and TTLT for parametric interactions, media generation, web search, uploaded-file analysis, connectors, Canvas, skills, and other turns. Tool metrics include p95 duration, call and error counts by tool, and a “no tool called” rate. Error drill-down uses canonical gRPC codes such as INVALID_ARGUMENT and INTERNAL.

TL;DR for BQAA. Treat first_token_at and first_answer_at as different clocks. A reasoning token is evidence that work started, not evidence that the user received an answer; without token-class or stream-boundary data, BQAA should report TTFT as TTFT rather than relabeling it perceived latency. Add feature_kind/tool slices to the latency example queries, and keep both a coarse response class and a concrete status code. The “no tool called” rate is useful only when conditioned on tasks expected to call a tool; fleet-wide, it confounds correct parametric answers with routing failures. These are schema/docs notes, not roadmap items.

Six-week EV

Ranking unchanged. One compact observability note should move into the six-week docs/schema queue:

  • Separate latency clocks. Define TTFT as request-to-first-streamed-token, TTFA as request-to-first-user-visible answer token, and TTLT as request-to-final-token. Preserve enough stream/token-role timing to compute them; do not derive TTFA from span start/end. Document eligibility denominators because TTFT/TTFA exist only when the corresponding token exists.
  • Reset semantics need a decision. Gemini Enterprise restarts TTFA after a post-narration tool call. BQAA should state whether it measures the first answer fragment or the final answer segment and, ideally, retain both timestamps rather than silently choosing one.
  • Slice before aggregating. Include feature_kind and tool identity in latency examples; mixed traffic can hide a slow connector or make media generation distort the fleet p95.
  • Outcome taxonomy. Retain a stable response class (OK/client/server/canceled) beside the concrete status code. Keep “no tool called” as a task-conditioned diagnostic, not a universal error metric.

Everything else from 2134 and the morning brief remains unchanged: recorded span links, assistant-over-owned-trace-store positioning, judged-content modality, mechanism-plane gates, typed refusal/termination events, source-event references, failure-step pointers, and judge-instrument metadata.
