Google Gemini agent (Gemini at Work 2026): agent identity in logs, agent-attributed audit trail, per-project spend caps that pause the agent

Source: https://cloud.google.com/blog/products/ai-machine-learning/welcome-to-gemini-at-work-2026 (Oct 8, 2026; Thomas Kurian keynote, adapted)

  • What shipped: the Gemini agent, described as "a single, universal agent for work". It combines chat, autonomous objectives and code generation, and can run on a schedule or respond to events. It runs headless across web, desktop, the command line, Workspace, Microsoft 365 and Slack. Work "keeps running after you close your laptop". It creates temporary sub-agents, and "coworker agents" get their own @agents.company.com identities and storage. It orchestrates "Gemini family of models and Claude models from Anthropic today".
  • Telemetry and governance claims:
    • "every action Gemini takes is written to an audit trail and attributed to the agent rather than to a person";
    • the agent identity "is stamped into the logs" and carries into any VM the agent starts;
    • Agent Gateway enforces policy on all traffic, and Agent Sandbox gives each agent its own network boundary;
    • real-time spend caps in Cloud Billing pause "that project's agent", tracked per project for chargeback.
  • Data hooks: reporting skills are integrated with BigQuery and Knowledge Catalog. Saved reports re-run "without incurring token costs".
  • Not stated: GA or preview status for most items (only the Financial Services and Legal specializations are labelled preview). The post does not mention ADK, Agent Engine, A2A, tracing or evaluation, and it does not name the "observability tools".
  • Why it matters for BQAA: Google's own agent now treats agent identity as the attribution key for audit and spend. An agent-analytics event table needs the agent principal as a first-class column, separate from the human user, and it needs to join spend and pause events at project grain.

NEW — AgentTracer: Tracing Indirect Prompt Injection Attack through Fine-Grained Intention-Execution Alignment — https://arxiv.org/abs/2610.09935

Yao, Wu, Lin, Huang, Zhang, Nan (SYSU / HKUST), cs.SE, Oct 7. Full PDF read (pdftotext, all sections and tables).

  • Method:
    • Starts from one anomalous tool call and slices back to the nearest user request.
    • Extracts decision relations ⟨sources, operation, targets⟩ from the agent's reasoning records. It grounds them in successful tool calls, which builds an Intent-Driven Execution Graph (§4.1).
    • Checks each edge against a user-intent authorization space built from the request and an 11-class operation knowledge base, on action, target and constraint (Table 1, §4.2).
    • Walks misaligned edges backward. If the root is an ExternalResource node, it reports IPI, the injection point and the chain (§4.3).
  • Setup: 356 AgentDyn plus 936 InjecAgent attack logs, mixed into five months of Codex logs (1,800 requests, 9,000 background tool calls). That is ~3,000:1 noise (§5.1). Every LLM step uses deepseek-v4-flash.
  • Results:
    • Table 2: injection-point accuracy 93.33% / 95.00%, path precision 91.11% / 96.00% (AgentDyn / InjecAgent).
    • Table 3: AgentTracer 94% injection accuracy vs Codex-as-tracer 70%, OpenClaw 69% and AgentArmor 76%. Precision is 93.18% vs ~51% for the agent tracers.
    • Ablations (Table 4): a plain temporal graph drops injection accuracy 91 → 74 and coverage 90.3 → 58.5. Replacing structured alignment with a direct LLM judgment drops accuracy to 64.
    • Event-anchored pruning saves 31% time and 51% tokens (Table 5).
    • Benign false-positive rate is 3.52% of edges (13 of 369, §5.5).
  • Limits:
    • It needs reasoning records; black-box agents degrade toward the temporal-graph ablation (§6.1).
    • Some baselines were reimplemented from their papers.
    • Only one LLM backbone is used.
    • Cross-session (persistent) IPI is exploratory only: 45 cases, >85%, excluded from the formal results (§6.1).
    • Code-level injection is out of scope (§6.2).
  • For BQAA: this sets a schema requirement for forensics. You need the user request, the reasoning text, and tool records with result objects, all linked into one segment. Each tool result also needs an origin label (external vs. internal). A table ordered by timestamp alone gets the temporal-graph number, not the full one.

NEW — Conditional Accuracy Profiles: Diagnosing LLM Judges across Deployment Conditions — https://arxiv.org/abs/2610.09229

Li, Liu, Ruan, Hu, Yin, Li (UAlbany / WVU), cs.LG, Oct 6. Full PDF read (main text and Appendices A–C).

  • Method: CAP splits pairwise judge accuracy into eight conditions (Table 1):
    • factual, logical, scope-overclaim and scope-omission sensitivity;
    • style, length and position robustness, scored strictly: correct in both variants;
    • rationale quality.
      Each condition has bootstrap CIs and a per-benchmark coverage status: direct, approximate, augmented or unavailable (Table 2). The new JudgerEva-Standard has 2,092 planted-error items and 6,276 pairs with presentation variants (§3.2). It is used alongside five public benchmarks with seven judges.
  • Results:
    • On the judge-independent Hard-Constructed subset (Table 4, N=139), the best judge overall (Sonnet 4.5, 76.3%) scores 36.7% on omission. The two best omission judges (Llama-3.3-70B 56.7%, GPT-4o-mini 51.7%) are the third-weakest and weakest overall. Overall accuracy vs omission: Spearman ρ = −0.33.
    • Position-robustness rankings transfer across benchmarks (mean ρ = 0.87, §4.2). Under JudgeBench-Pro stress, position robustness shows the largest mean drop (30.7 pts). Claude Haiku 4.5 degrades 47.0 pts on average (Table 6).
  • Limits:
    • Pairwise judging only; extending CAP to scalar or rubric judges needs new condition definitions (§7).
    • The judges are older models (GPT-4o, Sonnet/Haiku 4.5, Gemini 2.5), so the profiles are point-in-time.
    • Errors are generated by GPT-4o; absolute values depend on the generator, though rankings transfer (App. I).
    • Rationale quality relies on an LLM evaluator: κ = 0.826 against one non-blinded annotator (App. C).
  • For BQAA: for judge scores in agent analytics, store per-condition slices (order-swap pairs, length variants, error type) next to the verdict. A single judge-accuracy number will hide the omission failure that matters most for policy and compliance checks.

Six-week EV

  • Agent principal becomes the join key. Google's Gemini agent attributes audit entries, logs and spend caps to the agent identity. Claude Code now links its telemetry request_id to the gateway audit log. Expect customers to ask BQAA to join agent events to cloud audit logs and billing by agent principal and request ID. Plan the columns now.
  • Decision calls show up in every trace. After today, Decisions-API calls will come from LiteLLM, LangChain, promptfoo, Langfuse evaluators and Codex Guardian. Typed answers with confidence and refusals need their own event shape: answer type, confidence, refusal flag, input-only cost. They do not fit as generic LLM spans.
  • Compaction as a record, not a rewrite. Agno's reversible CompactionRecord follows the same pattern as Codex rollout history and Claude Code transcripts. The model payload differs from stored history, and the difference is itself an auditable event. Analytics that replays "what the model saw" has to read compaction events.
  • Forensics needs reasoning records. AgentTracer only works with reasoning text and result-origin labels. Agent analytics that drop reasoning content for cost will not support injection forensics later. Consider a keep-for-N-days tier instead of dropping it.

TL;DRs for BQAA

  • Google Gemini agent: every action goes to an agent-attributed audit trail; per-project spend caps pause the agent. Model the agent principal as a first-class key.
  • OpenAI Decisions adoption day: LiteLLM stable, LangChain, promptfoo, Langfuse evals and Codex Guardian all shipped support today. Give decision events their own shape in the schema.
  • Codex 0.162.0: Guardian decision duration, denial-limit counts, tool-catalog size and multi-agent version are now in telemetry, and OTLP temporality is honored.
  • Claude Code 2.1.295: fail-closed hooks, and gateway request-id = telemetry request_id. You can now join client telemetry to gateway audit.
  • Agno 3.1.2: compaction never rewrites stored messages; each approval-required call gets its own approval record. Compaction and approvals are now separate auditable rows.
  • Langfuse 4.55.0: export can write directly to GCS with ADC, a short path into BigQuery for Langfuse users.
  • 2610.09935 AgentTracer: 94% injection-point accuracy, and only with reasoning records plus tool-result origin. Timestamp order alone scores 74%.
  • 2610.09229 CAP: the best judge overall can be the worst on omissions. Store per-condition judge slices, not one accuracy number.
