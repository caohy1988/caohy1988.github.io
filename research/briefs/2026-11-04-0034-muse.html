The Wednesday arXiv batch carries this slot, and its strongest paper is the most directly BQAA-shaped Academy result in weeks: an artifact-only audit of two public agent leaderboards finds four silent instrument errors — nested trace spans double-counted in the cost column, episodes never graded and stored as failures, grader replay actions written into archived agent trajectories, and re-grades that reorder rankings without erroring. Every one of those is a failure mode of a trace warehouse, not of a model.   • Rank 1 Academy — audit the instrument, not just the model. arXiv:2611.04399 re-derives HAL and τ²-bench from published artifacts (no agent run, no model called) and finds: a cost column that sums usage over wrapper and child spans carrying the same response — exactly 2× in 70 of 134 runs (Table 1; §3.1: one row listed at $149.98 vs a $74.99 root-span cost); a scaffold graded in only 51% of episodes vs 98% for its comparator, where grading the ungraded half closes a published 13-point gap to a tie (pooled 0.30 → 0.43, §3.2, Figure 1); grader gold-replay actions present in 68% of 2,334 archived trajectories (§3.3); and re-grades under new evaluator builds moving scores −7 to +2.5 points and, via a silent mode-check miss, collapsing four files by 59–82 points (§3.4). HAL's maintainers reproduced and disclosed all three HAL items within five weeks (§3.5) — and the archived numbers still stand. For BQAA this is a schema spec in negative: publish the graded fraction beside every score, aggregate cost from root spans (and print the all-span/root-span multiplier), tag every recorded action with its author (agent / simulator / grader), and pin evaluator build + task-data version on every stored score with a published re-grade diff (§5). If BQAA stores traces other people's leaderboards are computed from, these four fields are the difference between a record and a rumor. Full PDF read (all sections, Tables 1–2, Figure 1, Appendix A).
  • Rank 2 Academy — a diagnostic taxonomy for traces, with severity arithmetic. arXiv:2611.04507 (Cisco) defines 45 problem types across eight families (Table 4; full definitions with evidence requirements in Appendix A), separates realized defects / risk exposures / inefficiencies, groups occurrences into engineering issues ("Signals"), and scores severity by fixed tables (Tables 1–2) computed in code. On public benchmark executions the pipeline matches reference Signals at 91.43% F1 vs 73.69% for a one-pass control with the same model and taxonomy (Table 5). Read the limits before quoting the F1: reference labels were created by LLM judges under human oversight (§5), and the matcher credits component + problem-type agreement only — not evidence, severity calibration, or remediation correctness (§6.1, self-disclosed); remediations were never implemented or tested (§6.4). The cardable asset is the taxonomy + evidence-requirement discipline as a candidate diagnostics layer over BQAA trace tables, not the headline score. Full PDF read (all sections, Tables 1–6, Appendices A–B).
  • Rank 3 Academy — cross-provider judge replication is a screen, not a certificate. arXiv:2611.04090 preregistered four hypotheses, re-judged 4,000 human-voted arena battles with five judges from three providers, and reports against its own thresholds: H1 not supported — verdict agreement is low (median Cohen's κ = 0.22) and rank correlation with the human ranking spans τ = 0.17–0.89 depending on the judge (median 0.67 vs a 0.8 preregistered bar; Table 1, §4.2). Replicated conclusions from two low-cost cross-provider judges beat single-judge precision by +0.10 (Table 2) only by filtering out one poorly aligned judge, at a coverage cost down to 35% of comparisons; the two best judges share their one wrong conclusion. Judge choice dominates sample size: aligned judges stabilize at 25 verdicts per pair, others never converge on 26–70% of pairs (Table 3). Modest by the authors' own framing (nine systems, 23 conclusion pairs, single-vote human reference, one judge possibly confounded by a reasoning-off setting — §6 Limitations); ranked because it prices the exact validation move BQAA users make when they "check" a judge score with a second provider. Full PDF read (all sections, Tables 1–7, Appendices A–D).

NEW

1. Silent instrument errors in agent leaderboards — https://arxiv.org/abs/2611.04399 (cs.AI, v1 3 Nov 2026). Full PDF read — every part, including §3.1–3.5 case derivations, Table 1 (four-case summary), Table 2 (per-model accuracies), Figure 1, §5 checks, §8 Limitations, and Appendix A reproduction procedures; key numbers below cite their table/section. Method: re-derive two maintained public leaderboards (HAL; τ²-bench) from released artifacts only — decrypted trace archives, repository trajectories, changelogs — with HAL figures recomputed by independently written code (§3 head, Appendix A). Findings: (i) Cost double-count (§3.1): cost aggregation sums token usage over every trace span; where a wrapper span and its provider-client child carry the same response, usage counts twice — exactly 2× in 70 of 134 runs, 1× in 46 (Table 1), 44 of 94 matchable leaderboard rows carrying doubled cost; uneven by client path, so the cost–accuracy frontier itself changes shape. (ii) Ungraded episodes stored as failures (§3.2): the reward computes only on a formal episode ending; one scaffold's closing behavior rarely triggers it — graded fraction 51% vs 98% for the comparator; offline grading under the benchmark's own rule lifts pooled accuracy 0.30 → 0.43 and closes the published 13-point scaffold gap to a tie (write-required tasks alone: 0.28 → 0.33, so the gain is not an artifact of read-only golds). (iii) Grader actions inside agent trajectories (§3.3): the grader replays gold actions through the same environment list the archive stores as the agent's actions — grader-written actions in 68% of 2,334 records, including 58 records where the agent made no tool call yet the record shows the full gold sequence; stripping them raises replay-reward agreement from 70% to 92%. (iv) Re-grading is a new measurement (§3.4): an announced, correct evaluator fix reverses 4 of 136 pairwise orderings and moves one model ninth → tied-fifth; an unflagged criteria change flips 77 of 800 simulations in both directions (−7 to +2.5 points per model); a solo-mode check that misreads four files rebuilds the replay environment without user tools and collapses those scores by 59–82 points while printing no error (community fix open, unmerged). Disclosure receipt (§3.5): HAL maintainers reproduced all three HAL findings and added dated leaderboard disclosures within five weeks; archives unchanged. Prescriptions (§5): report graded fraction per cell; aggregate cost from root spans and publish the all-span/root-span multiplier; tag provenance (agent / simulator / grader) on every recorded action; pin evaluator build + task-data version per score and publish re-grade diffs (fail, don't warn, past a replay-mismatch threshold); ship machine-readable errata inside frozen archives. Limits (§8, as stated): two leaderboards; the "common elsewhere" claim rests on mechanism, not survey; offline re-grades stub the user simulator, so they test database/output criteria only. BQAA use: adopt the four §5 fields as ingest contract requirements — graded fraction, root-span cost basis + multiplier, per-action provenance, evaluator/version pin — before any stored score is treated as comparable across time.

2. Signals — continuous diagnostics of AI agents from traces — https://arxiv.org/abs/2611.04507 (cs.AI, v1 3 Nov 2026; Cisco). Full PDF read — every part, including §3 method, severity Tables 1–2 and worked example (§3.3), taxonomy Table 4, dataset §5, matching rules and results §6.1–6.4 (Table 5), and the complete Appendix A catalog of 45 definitions plus Appendix B illustration. System: sessions (one execution) → occurrences (problem instances, each requiring an applicable requirement plus violating evidence, §4.2) → Signals (occurrences grouped by the fix a developer would make, §3.2), each Signal carrying explanation, cited evidence, severity, remediation actions and validation checks. Taxonomy: 45 types in 8 families — instruction/specification (5), knowledge/retrieval (6), reasoning/output (8), tool/integration (8), orchestration/state (5), runtime/platform (3), safety/security/privacy (6), efficiency (4) (Table 4) — with boundaries drawn where evidence or remediation differs (invalid tool arguments vs invalid tool result vs valid result ignored). Severity: separate fixed-table scores for realized defects, risk exposures (consequence × reachability multiplier), and inefficiencies, combined by max, with scope counted in distinct affected sessions and denominators recorded (§3.3, Tables 1–2); the model judges semantic factors, code does the arithmetic. Results (§6, Table 5): occurrence matching 90.49% F1; Signal matching 91.43% F1 (92.90% precision / 90.01% recall) vs a one-pass direct-generation control at 73.69% F1 using the same model and full taxonomy (+21.79 precision, +13.56 recall); session-level detection 97.26%/97.47% precision/recall (§6.2); repeat-run session-presence agreement 97.0–98.5%, dropping to 74.2% when some telemetry is removed (§6.4) — a quiet warning that diagnostics degrade with trace completeness. Limits, all author-stated and load-bearing: reference labels were produced by LLM judges under human oversight (§5); the matcher credits same-session component + shared problem-type agreement among three ranked candidates and explicitly does not verify diagnosis wording, cited evidence, severity calibration, or fix correctness (§6.1, §7); taxonomy development was exposed to the same public benchmark families used for evaluation (§5, §6.3); remediations were not implemented or tested and no production cost/time saving is established (§6.4). BQAA use: the 45-type catalog with per-type evidence requirements is a ready-made candidate schema for a diagnostics view over stored traces (occurrence → issue grouping, affected-session denominators); treat the F1 as agreement-with-LLM-judge-labels, not field accuracy, until independently labeled traces exist.

3. Cross-provider judge replication does not stabilize system rankings (preregistered) — https://arxiv.org/abs/2611.04090 (cs.CL, v1 3 Nov 2026). Full PDF read — every part, including design §3 (sample construction, judging protocol, measures), preregistration deviations §3.6, results §4.1–4.6 (Tables 1–4), discussion §5, limitations §6, and Appendices A–D (filtering Table 5, settings Table 6, language splits Table 7). Design: 4,000 confirmation battles (single-turn, first vote, decisive votes only) over nine systems / 33 pairs; five judges from three providers, each battle judged in both response orders with a frozen prompt/parser; prompt, hypotheses and analysis code hashed before any confirmation response (§3.6 — two post-freeze deviations disclosed: the judge set was reduced from six to five after partial results were seen, and the majority-vote rule changed; neither enters the H1/H2 criteria as evaluated). Results against preregistered criteria: H1 not supported (§4.2, Table 1) — median verdict-level κ = 0.217 and median rank τ = 0.667 (range 0.17–0.89 across judges) vs the 0.8 stability threshold; even excluding the least-aligned judge post hoc, median τ = 0.778 still misses the bar; a five-judge majority (τ = 0.778) does not beat the best single judges. H2 supported narrowly (§4.3, Table 2) — replicated cross-provider conclusions average precision 0.902 vs 0.804 single-judge (Δ = +0.098, Holm-adjusted p = 0.002), but the mechanism is filtering: the two best-aligned judges are each right on 22/23 pairs and share their single wrong conclusion, while requiring agreement with the poorly aligned judge keeps 7/8 precision yet leaves a conclusion for only 35% of comparisons. H3 (§4.4, Table 3): aligned judges need no more verdicts than human votes (25/pair on 22 of 23 pairs); three judges fail to converge on 26%, 35% and 70% of pairs at up to 100 verdicts. H4 (§4.5): all three low-cost judges disagree with the human vote together on 15.8% of battles vs 3.5% under independence — with the authors' own caveat that a single voter per battle cannot separate shared judge bias from voter noise. Limits (§6): nine systems / 23 conclusion pairs; H2 rests on one judge whose poor alignment may reflect a reasoning-off setting rather than the model; human reference is preference, not correctness; one prompt, one verdict-resolution rule. BQAA use: when a second-provider judge "confirms" a system comparison, log it as a screen that can only veto a misaligned judge — agreement certifies nothing (the shared wrong conclusion), and the coverage cost (65% of comparisons left conclusion-less in the bad-judge pairing) belongs in the eval record beside the precision gain. Vendor note: judge model names appear in the paper's Table 1/6; this brief paraphrases by tier/provider count only, per standing rule.

  • Make the instrument fields part of the BQAA ingest contract (from Rank 1). None of these needs new modeling; all are schema + one division. This is the highest-EV schema change the last several briefs have pointed at, and it composes with the queued 2026-11-03-0034 items (judge input assurance, validity denominator) rather than displacing them.
