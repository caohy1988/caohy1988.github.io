  • Computer-routed Agent tasks now read the exact accepted Super Run and its newest correlated child run. Before, success was inferred when the entry disappeared from the active list.
  • Listener terminal errors carry the accepted client_message_ids and are emitted before idle, so an error can no longer be overtaken by the idle signal and lost.
  • A rejected tool continuation stays a failure. The PR says "elapsed time does not decide whether the task finished".
  • Failure strings now name the run, for example "Remote Super Run ${run.id} failed during ${code}: ${message}". Transient reads retry without resubmitting work.
  • #4647, "stop child sends from retaining parent runtimes" [LET-12939].
  • A continued child published by SendAgentMessage now carries claims_parent_runtime: false and the accepted send's super_run_id. The server can follow that exact send after the parent disconnects, and the idle parent can sleep.
  • Older servers ignore the new fields.

1. NEW rank: arXiv 2609.30290: Auditing and Repairing LLM-as-Judge Failures in a Production Text-to-SQL Pipeline

Liu, Wu, Fang (Santa Clara University / independent). cs.CL; v1 stamped 9 Sep 2026; 13 pages. Full PDF read.

What they did. SynCA is a production pipeline that generates question–SQL pairs over a 604,146-row, 43-column telecom-derived table. Its stages are:

  1. question generation
  2. three-model SQL consensus
  3. o1 debate
  4. a final gpt-4o-mini faithfulness judge that sees the schema, question, SQL, and a top-10-row result preview

Its output gates an analyst-assist tool (~30 daily users) and an eval harness (§1, §3). Analysts kept finding plausible queries the judge had rejected, so the authors measured the judge.

Key numbers:

  • Judge agreement with human gold (Table 2). Gold is two-author, with an independent annotator agreeing at κ = 0.85 (§4).
Judge Enriched 234-set κ Uniform 200 spot-check κ
gpt-4o-mini (production) 0.04 0.42
gpt-5.4-mini 0.63 0.67
Qwen3.6-27B 0.72 0.94
Claude Opus 4.7 0.71 0.93
  • The production judge's false-negative rate on human-FAITHFUL cases was 77.1%.
  • One mechanism dominates (§5, App. F). GRADE-HALLUCINATION covers 66% of the 148 false flags: the judge sees "E", "z" or "None" in the preview, recalls a canonical {A,B,C,D} set, and flags "invalid grades" the question never excluded.
  • The finer 7-class taxonomy only reached second-coder κ = 0.29, so the authors rely on the binary split.
  • Prompting only partly fixes it (Table 3). All four prompt variants flip the judge from over-flagging to under-flagging. Dropping the preview is best, at κ = 0.37; nothing reaches 0.72.
  • Ensembles need calibrated members (§6, Table 4).
  • Pairing the weak judge with gpt-5.4-mini lowers κ (AND 0.572 vs 0.631 alone). On their 154 disagreements the stronger judge was right 142–12.
  • Three strong judges with unanimity routing reach κ = 0.788 at 89.7% auto-coverage, with about 10% sent to humans.
  • Adding the weak fourth judge drops coverage to 29%.
  • A learned 14-feature GBM router does no better (+0.002 κ, App. K).
  • Cost (§8, App. D). Per 1,000 questions: self-hosted Qwen $0.10, gpt-4o-mini $0.40, Opus 4.7 $30.
  • Transfer (§7, Table 5). Run on BIRD-financial, the same recipe flags 23–27 of 106 expert gold SQLs (21.7–25.5%) as candidate gold bugs; a blind annotator confirmed 23 of 27 at κ = 0.86. Per-judge over-flag rates shift 2–4.7× across schemas.

Caveats (Limitations, App. B, App. J):

  • a single English telecom deployment over SQLite
  • headline gold is author-produced
  • the Qwen-vs-Opus head-to-head is underpowered (n = 96, McNemar p = 0.082)
  • the failure taxonomy was collapsed post hoc
  • Anthropic and Google judges have no dated snapshot IDs, so κ can drift
  • datasets are deferred; only code and pre-registration are released now

Why it matters for BQAA. The 1234 brief carded LLM judges running inside trace queries (LangWatch judge functions; the text-to-SQL AI-operator paper 2609.21133). This paper measures what happens once such a judge is deployed and nobody checks it: it drifts to chance on the hard cases.

Three things transfer:

  1. Store (judge model and snapshot, prompt version, input-view) with every verdict. "Saw the result preview" was the failure trigger here.
  2. Keep a small domain gold set and re-measure κ whenever the schema or snapshot changes.
  3. Before adding a judge to a panel, check the split of its disagreements with the others. One-sided (142–12) means the weaker judge is simply wrong and the panel gets worse; split (12–7) means the cases are genuinely hard and a panel can help.

TL;DR for BQAA: an LLM judge over SQL results should be treated as an uncalibrated instrument until measured against domain gold. The preview rows it sees can make it invent constraints.

2. NEW rank: arXiv 2609.30725: Analyzing and Mitigating Cost-Inefficient Behaviors in Coding Agents

Hu, Jiang, Liang, Dey, Wu, Tan (Purdue). cs.AI; v1 25 Sep 2026; 30 pages; under review. Full PDF read.

What they did.

  • Four configurations: Claude Code v2.1.169 with Sonnet 4.6 (Haiku 4.5 subagents), and Mini-SWE-Agent v2.3.0 with Sonnet 4.6, MiniMax-M3, or Qwen-3.5 Plus.
  • Each ran on 300 SWE-bench Verified tasks, giving 1,200 trajectories.
  • Every step gets one of 18 action labels, mostly by rules; an LLM fallback labeled 7.26% of steps (App. A.1.1).
  • Each flagged action is costed from its tokens (tiktoken o200k) at model prices, including the cache and input charges when its output is carried forward (App. A.1.2).
  • Mitigations were tested over 10k+ trajectories on held-out Verified-200 and SWE-bench Pro-100 tasks. Baselines were run three times to set noise floors (App. A.1.4).

The three behaviors (§3, Table 1):

  • Subsumed retrieval. A read whose content is fully covered by an earlier read. It hits 64.33–92.33% of tasks and 5.01–11.41% of cost.
  • In Claude Code, 50.15% of it is cross-agent: the main agent re-reads code a subagent already read, because subagents return summaries rather than code (Table 2).
  • Similar script generation. A new script with line-level Jaccard ≥ 0.60 against an earlier one. It hits up to 68% of tasks and up to 9.57% of cost, and is 5.9–10× more frequent in Mini-SWE-Agent.
  • Test re-execution. The same test ID rerun within a window with no new patch. It hits 49.67–83% of tasks and up to 5.39% of cost.

Together the three touch 79–98% of tasks and account for 6.86–22.75% of task cost.

Mitigations (§4, Tables 3–4, Fig. 6):

  • CodeGraph, a structure-aware retrieval MCP/CLI tool, is not a cost win.
  • In Claude Code it cut subsumed retrieval by more than 75%, yet cost rose 8.30% on Verified and 12.19% on Pro (robust).
  • Each CodeGraph call returns 8.2–16.6× more tokens than a normal read.
  • Haiku subagent calls fell to zero, shifting the same token volume onto Sonnet at 3× the price.
  • Under Mini-SWE-Agent, CodeGraph calls were stacked on top of ordinary retrieval, raising cost by up to 28.14%.
  • Agent-synthesized skills (23–41 low-level rules distilled from traces via Trace2Skill) cut cost by at most 22.32%. Once synthesis cost is amortized over the 300 tasks, only one robust reduction remains (App. Table 15).
  • Seven developer-written principles cut cost by 7.88–41.73% in six of eight settings, with one small Pass@1 drop (−1.50 pp). Examples: "reuse context, justify re-reads", "capture test output, filter don't rerun", "persist and revise scripts, no numbered variants".
  • Task-cost changes are amplified relative to behavior-attributed cost, with fitted slopes of 2.83 on Verified and 1.33 on Pro. Removing one wasteful action also removes the later cache reads and reasoning it triggers.

Caveats (§6, App. A.1.4):

  • SWE-bench only, four configurations
  • 15 of 24 mitigation cells are single runs judged against transferred noise floors
  • behavior-frequency metrics are noisy (mean CV 15.68%), so behavior deltas carry no robustness verdicts
  • detectors and thresholds are author-calibrated
  • Mini-SWE-Agent with Sonnet 4.6 relied on the LLM labeler for 31.17% of its steps

Why it matters for BQAA. All three detectors are pure trace analytics:

  • span-content containment against earlier retrieval spans
  • near-duplicate tool inputs
  • repeated test-tool calls with no intervening edit span

Per-action cost attribution needs tokens per tool output plus cache-carry accounting. The Claude Code finding needs parent/subagent linkage to separate cross-agent re-reads. This is a ready-made "waste report" query set over agent_events-style tables. The paper also shows why cost dashboards must check delegation shifts: a tool that reduces one behavior can silently move tokens from a cheap model onto an expensive one.

TL;DR for BQAA: three SQL-expressible trace detectors account for up to 22.75% of coding-agent spend. Fixes should be judged on end-to-end cost, not on the behavior count.
