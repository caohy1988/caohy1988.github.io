Academy

Monday, Aug 31 announced 190 cs.AI entries. Nine abstracts fetched; eight worth your time, four in depth.

1. DoCtOR — failure attribution becomes a repair target (EMNLP 2026, arXiv 2608.28264)

Wang, Huang, Liang, Li, Du, Pan. The standing thesis says attribution is overclaimed as a localization product (LongRCA: 24.1% exact step). This paper flips the use: instead of showing a human "step 14 is the culprit," it attributes the failure to a specific agent, generates a counterfactual corrected version of that agent's error step, and then runs reflection only on the responsible agent — so the other agents' memories don't get polluted with wrong lessons. That targeting is worth +22, +26, and +27 points of success rate over initial runs on HotPotQA, ChartQAPro, and Mind2Web, beating Reflexion, Retroformer, and COPPER. The wrong belief to kill cuts both ways: imperfect attribution isn't useless — agent-level (coarser than step-level) attribution is evidently good enough to direct repair — but these are short-horizon benchmarks, so don't read this as vindicating step-exact localization on real traces either. Judgment: peer evidence, and the best outside support yet for BQAA's schema choice of coarse attribution fields over span-level blame.

TL;DR for BQAA. This is the argument for fault_edge + fault_side (EV #7) written up by someone else: attribution at the agent/edge grain is actionable even when step-exact attribution isn't reliable. Ship the columns; cite this when someone asks for span-level blame instead.

2. Fidelity Is Not Enough — dispatch-level instrumentation catches silent fabrication (arXiv 2608.28439)

An agentic datasheet-extraction pipeline where outputs passed fidelity checks — extracted values matched sources — while one model never opened the datasheet: structured-output constraints silently disabled tool use and the model answered anyway, with fabricated source text. Only inspecting the logged tool calls (which tools were actually dispatched, not whether the answer looked right) exposed it. Their two diagnostics — a rule-based failure classifier and a silent-failure detector, both built purely on tool-call logs — detected all 50 planted faults with zero false positives across 207 fidelity-passing extractions. The wrong belief to kill: "if the answer matches the golden, the trajectory was fine." Judgment: strong support, near-verbatim, for the trajectory-verification thesis.

TL;DR for BQAA. This is EV #5 (trajectory_verified beside match_golden_qa: answer matched and required_tools observed OK) with an independent 50/50-at-zero-FP result behind it. The agent_events table already has the dispatch record; the check is a view, not a capture change. Raise #5's priority within its cost class.

3. CURA — certified runtime alarms from harness-visible telemetry only (arXiv 2608.27808)

An external monitor for computer-use agents that reads only what the harness already logs — no model internals, no extra LLM calls, no prompt changes — turns the trajectory into a sequential test, and fires a CUSUM alarm when the failure statistic drifts. Numbers: detects 42.3% of failures a median of 31 steps before termination; 0.828 AUROC retrospectively; online recall 0.41 vs 0.34 baseline at α=0.10; alarm-gated oversight recovered 23 of 70 failures. The wrong belief to kill: "certified" here bounds false alarms only — there is no detection-completeness guarantee, and 42.3% caught means most failures still run to the end. Judgment: peer evidence for the deterministic-detection lane; the certificate framing (bound the false-alarm rate, promise nothing about recall) is exactly the honest contract a warehouse-side detector should offer.

TL;DR for BQAA. Supports EV #1 as designed: deterministic session flags over agent_events with a non-decaying latch are the SQL version of "sequential test on harness-visible telemetry." Copy the contract language — BQAA flags should advertise a false-positive bound, not a recall claim. No new work item.

4. OBPE — out-of-band enforcement at the tool boundary (arXiv 2608.27646)

"If Agents Were Angels, No Governance Would Be Necessary." An HTTP proxy between the agent and its backends (Jira, ServiceNow in testing) that authorizes the typed operation and resource, narrows the query before the backend call, then filters or masks the response — Cedar policies, prototype released, simplified from a production system. Numbers: trace failures 57.6% → 0.2% across 3,621 trials against 20 adaptive red-team tasks and four models; task fulfillment drops 79.1% → 60.9%; net "safe-useful" completion +21.8 points. The wrong belief to kill: prompt-level guardrails are the enforcement layer — this paper's whole point is that enforcement lives at a trusted boundary the model can't talk its way past, and it costs real task fulfillment. Judgment: adjacent, not competitive. BQAA is the observer; OBPE is what the enforcer looks like, and its typed-operation authorization log is a natural upstream producer for an events table.

TL;DR for BQAA. Ignore as a build target — runtime guardrails stay on the do-not-start list. Keep as the reference answer when someone asks why BQAA doesn't enforce: enforcement belongs at a proxy like this, and its decisions land in the warehouse as rows, same as everything else.

5. VICT — verifier logs as the attribution substrate (arXiv 2608.28128) — brief

Credit assignment for long-horizon agent RL that skips learned critics and branch rollouts: it opens up the terminal verifier, exposes its "executable or evidence-backed atoms," and traces them back to the actions they depend on, redistributing advantage only along those dependency edges. ALFWorld/WebShop, matches fine-grained credit-assignment methods at much lower cost. Judgment: training-side, not a product threat — but a second Monday paper whose attribution substrate is structured verifier/tool logs, not model introspection. TL;DR for BQAA: ignore operationally; file as more evidence that the logged-events table is where attribution work is converging.

6. GOD — a control room over agent telemetry (EMNLP 2026 demo, arXiv 2608.27992) — brief

Browser-based "control room" for generative-agent societies: live intervention and spatial replay share one operator command model, driven by agent movements, messages, commands, and model calls. Their own acceptance numbers are ~93% (78/84 commanded-destination checks, 169/182 state answers). Judgment: distractor as a product — simulation-flavored, demo track — but it marks "replay any session from the event log" as table stakes for agent-observability UX. TL;DR for BQAA: no action; replay-from-agent_events is already implied by the schema, and this is the genre it would be judged against.

7. RealSWE — realistic prompts cost 6.4 points (arXiv 2608.27831) — brief

381 multi-variant task families where the underlying task is fixed and the information composition/style varies. Real user requests are problem-statement-only 88% of the time (vs 7% of benchmark problems) and casual 87% of the time (vs 94% formal in benchmarks); realistic phrasing costs coding agents 6.4 points of resolution on average. Judgment: eval-hygiene evidence, not a competitor. TL;DR for BQAA: worth a line in EvalBench docs — golden sets built from curated, formal task text will overstate production success; the 0.92 golden-matching threshold is measuring against a politer distribution than production traffic.

8. Text-to-SQL module costs — execution feedback is the only module that always pays (arXiv 2608.28432) — brief

17 pipeline configurations × 5 recurring modules × 4 backbones, scored on accuracy and token cost. The one paradigm whose benefit "holds universally at consistently low cost" is execution-feedback refinement; most other modules only pay off under specific backbones, and a mid-tier model with a good pipeline often beats a frontier model with none. Judgment: calendar-adjacent for the BigQuery data-agent surface rather than BQAA itself. TL;DR for BQAA: one implication — execution feedback is exactly what agent_events captures for SQL-writing agents, so the highest-value eval signal for data agents is already in the table.

Also noted, not catalogued: Logos (2608.28553), an agent harness where plugins are separate processes on a ROS-like bus and the only shared state is an append-only transcript — 80 kill/resume sessions with zero repeated effects. The append-only transcript as the recovery source of truth rhymes with the producer contract, but the abstract has no telemetry schema; and an empirical study of Claude Code plugin marketplaces (2608.28497), background only.
