1. Google Workspace MCP servers and CLI reach general availability, with Cloud Agent Gateway and a mandate away from REST for agents

Primary: https://cloud.google.com/blog/products/identity-security/deploying-agents-safely-in-your-enterprise/ (November 24, 2026; feed timestamp 2026-11-24T17:00:00Z, in-window).

What shipped, per the post. Workspace MCP servers are "now generally available" as dedicated remote servers for Gmail, Google Drive, Docs, Sheets, Slides, Calendar, Chat, and Tasks, with built-in permission and DLP checks, native human-in-the-loop confirmations for sensitive actions, rejection of non-agent OAuth clients, and Model Armor prompt-injection screening. The Workspace CLI is "now generally available for local agents, terminal workflows, and automation," with structured JSON outputs and scoped OAuth sign-in. Google Cloud Agent Gateway is presented as a protocol-native gateway for LLM, MCP, and A2A traffic that verifies Agent Identities against Agent Registry, enforces IAM policies and default-deny outbound rules, and screens requests with Model Armor. The post states that permissions, confirmations, prompt screening, and audit logging happen automatically on these paths, while traditional apps continue on existing REST APIs.

The policy change is the durable part. Under the new Workspace AI Tools Addendum, "AI agents must use Workspace MCP servers or the Workspace CLI rather than existing REST APIs," with technical enforcement beginning February 1, 2027. Every call is checked against Workspace permissions, DLP rules, and classification labels. Agents connecting to Workspace must use dedicated OAuth client IDs with least-privilege scopes; time-limited approvals are described as "coming soon" and usage quotas with billing beginning April 1, 2027. Explicit user confirmation is required before agents send email, change Drive sharing permissions, or make bulk edits. Workspace administrators can view, audit, and revoke AI agents in the admin console; on Google Cloud, Security Command Center, Agent Observability, Cloud Audit Logs, and Wiz are named as surfacing unusual behavior, and revoking a Cloud Agent Identity or OAuth grant stops access immediately.

Why it ranks. This is a product-level capability plus an enforceable migration deadline, not a patch train: agent traffic to mail and files gets a distinct identity, a policy check in the request path, human confirmation for high-impact actions, and an audit/revocation surface. For agent analytics, the measurable consequence is that Workspace agent actions become attributable to a dedicated client identity instead of being indistinguishable from ordinary API calls under a user token. The post reports scale context (Workspace APIs handling more than 2.8 trillion calls a month; more than 18 billion Drive API reads a day) but no evaluation numbers for the gateway itself; no measured block/allow accuracy is claimed here. Google ADK is not the subject of this card.

1. Know When to Abstain: Conformal Confidence Estimation for Text-to-SQL — https://arxiv.org/abs/2611.31190

Full PDF read: yes — entire PDF read via pdftotext in chunks, including methods, results, limitations, appendices, prompts, and tables.

Problem and method. Execution success is not correctness: a query can run and answer the wrong question. Correctness is defined against gold SQL (§3, Eq. 1), observable on labeled data and latent at deployment. The estimator separates generation from validation (§4, Fig. 1): a generator writes and executes SQL with verbalized confidence; a different critic validates the executed result and scores execution-grounded alignment (including reconstructing the question the result actually answers); logit and SQL-structural features are computed locally (41 features, Table 1 / Table 7); a Random Forest fuses them. Two calibration rules follow: a conformal p-value bounds false abstention (Proposition 1), and a Learn-then-Test threshold certifies that error among accepted queries stays below a user-chosen budget with probability 1−δ (Proposition 2) — only while deployment follows the calibration distribution.

Results to reuse. On Spider (GPT-OSS-120B generator, Gemma-4-31B critic), error without abstention is 22.6%; at a 15% risk budget (δ=0.1) a threshold is certified on all 10 resampled splits, accepting 52.4% of queries at 9.1% observed error (Table 3). In the controlled shared-generator comparison, AUARC is 89.5 vs. 81.2 for the strongest logit baseline and 82.1 for five-sample self-consistency (Table 4); the same two LLM calls without fusion score 78.9, so the gain is attributed to fusion, not extra calls. Ablations show LLM-derived signals carry most of the information and a logit-free variant retains most performance (§5.4, Tables 5–6) — relevant where APIs hide logits. The failure boundary is stated plainly: transferred zero-shot to BIRD, scores still rank (AUROC 0.72 vs. 0.79 in-domain) but the Spider-certified 15% threshold yields 30.1% observed risk (§5.6, Table 19); with 636 calibration queries a 10% budget is often uncertifiable, in which case the rule abstains on everything. Cost is two sequential LLM calls, about 2.4–4.3 s per query in their setup (Appendix G.9).

BQAA takeaway. For data agents, "the SQL executed" must never be the success metric. A separate-critic + calibrated-abstention gate gives an auditable contract: accept only under a stated risk budget, re-certify per schema/workload distribution, and treat cross-dataset transfer of thresholds as invalid by construction.

2. From Local Errors to System Failures: Modeling and Benchmarking Error Propagation in Multi-Agent LLM Systems — https://arxiv.org/abs/2611.31063

Full PDF read: yes — entire PDF read via pdftotext in chunks, including formulation, experiments, comparisons, appendices, and limitations.

Problem and method. Outcome-only evaluation cannot distinguish an agent that rejected bad input from one that amplified it to the same final label (§1). REPA compares reference and perturbed executions of the same instance, measures multi-channel discrepancies at each agent's inputs and outputs (factual, hallucination, source-faithfulness, task-irrelevance), and separately fits input-assembly and agent-processing maps with nonnegative ridge regression (§3, Fig. 1). Composing the frozen local maps along the executed DAG predicts endpoint susceptibility from the source measurement alone, without observing test-time intermediates or fine-tuning. ErrPropBench-10 extends coverage to seven knowledge domains plus three multi-hop QA sets (1,500 pairs; §4.1).

Results to reuse. Common exposure (same error to all agents sharing input) hurts far more than localized exposure: mean accuracy drops of 16–27 points vs. ~2–4 points across six workflows, and higher clean accuracy does not imply robustness (§4.3, Fig. 3). REPA predicts measured system responses with Spearman 0.84/0.85/0.83 across three Qwen backbones vs. at most 0.58 for direct source-to-endpoint regression (Table 1), and localizes a disabled node at 0.77 success vs. 0.43 for raw local differences with lower false positives (§4.4, Fig. 4). Guided placement matters: one-node prompt restoration chosen by REPA recovers accuracy near the healthy level under the same repair budget, and REPA-placed retrieval retains much of global retrieval's accuracy at 0.55–0.60 of its token cost (§4.5, Fig. 5). Cross-domain rank correlation averages 0.81 but magnitude error varies widely (MAE 0.02–0.49), so ordering is more trustworthy than size (§4.6, Appendix C.6). Limits are material: three Qwen checkpoints and six workflows only (Appendix E), and the archived forward-prediction observer protocol "was not fully label-blind" (Appendix D.2) — treat absolute magnitudes cautiously and reuse the paired-measurement design, not just the headline correlations.

BQAA takeaway. Trace analytics should store per-step input-assembled vs. agent-produced discrepancies, not only final success. With paired clean/perturbed runs, susceptibility becomes predictable before deployment and repair budget can be spent at the amplifying node instead of the noisiest-looking one.

3. Attributing Security Outcomes in LLM-Agent Evaluations: The Role of Content-Free State — https://arxiv.org/abs/2611.30259

Full PDF read: yes — entire PDF read via pdftotext in chunks, including threat model, TARE tests, experiments, discussion, limitations, and appendix tables.

Problem and method. ASR comparisons assume the agent, attack, or defense caused each verdict. The paper defines content-free state — hash seed, tool/evidence order, serving instance, failure mapping (Table 1) — and requires decision noninterference: state a claim does not mention must not change any verdict (§3.1). TARE declares that state, strips what can be stripped (per-case keyed order; a third "inconclusive" verdict for failed runs), measures the rest against a same-state rerun floor, and attributes an effect only if it exceeds a worst-case margin (Proposition 1 / Corollary 1); keyed averaging with randomization/matched tests then detects small effects honestly (§§3.3–3.4).

Results to reuse. On Agent Security Bench, same-seed reruns are identical for seven agents, yet changing the seed changes up to 17% of verdicts while ASR moves ≤5 points because flips cancel (§5.1, Table 5); the mechanism is traced to tool order through a Python set. Fixing order by sorting instead of reverse-sorting raises ASR by up to 18.8 points because attacker tools sort first (§5.2, Table 7) and re-ranks agents. Reordering identical gate evidence flips 17–91% of decisions for six of seven judges (most stable: 7%), with ALLOW↔BLOCK flips for the most stable judges (§5.3, Table 8) — the requester controls that order. Failed runs scored as "attack failed" include runs where every request was rejected and reported as ASR 0% (§5.4, Table 6). Across 18 defense combinations the margin test attributes only large effects, and 35–69% of stopped attacks in attributed drops end with no tool call at all — inaction counted as defense (§5.5, Table 9). Keyed order drives seed influence to zero for all seven agents (§6.1, Table 10); three keyed gate presentations cut contradictory decisions to 0–2% at 5–65% abstention (§6.4, Table 13). Scope is bounded: deepest evidence is one benchmark, influences are lower bounds from sampled state, and guarantees hold within a serving instance (§7.3).

BQAA takeaway. Every eval table needs a state column: declared seeds/orders/instance, a same-state rerun floor, inconclusive and tool-action rates beside every ASR, and effects reported against a measured influence margin. Pinning a seed buys reproducibility, not attribution.
