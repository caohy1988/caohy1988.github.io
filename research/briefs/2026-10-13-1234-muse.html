Cline SDK v0.0.93 + CLI v3.0.71 + VS Code v4.1.24 — plugin state machine, flat image tokens, scheduled runs that admit failure

  • What shipped: three stable trains in one day, all bodies read via gh api by me — sdk/sdk/v0.0.93 (08:26:52Z), cli-v3.0.71 (08:56:25Z; npm cline 3.0.71 at 08:57:00Z), and v4.1.24 (15:02:27Z; plus desktop-v0.0.46 at 15:03:59Z, body not separately read). The SDK/CLI pair carries the substance; v4.1.24 ports the token/compaction fixes to the extension.
  • Plugin observability: plugins load in-process through one registry per process (no node/bun runtime on PATH; CLINE_PLUGIN_MODE=sandbox keeps the subprocess). The registry wraps import/setup/hooks/tools/commands with timeouts and error capture and tracks each plugin's state (loading/ready/degraded/failed/disabled) with its last error. A failing plugin no longer silently drops its tools: session.create accepts a plugins policy and returns pluginIssues, the hub answers plugins.list|status|reload and broadcasts plugin.status_changed, cline config tools --json lists a plugin_failure entry, and an uncaught plugin error marks the plugin failed instead of shutting down the daemon. Each session gets its own copy of every plugin module.
  • Cost correctness: estimateRequestInputTokens no longer bills base64 image payloads at the text rate — a ~90 KB screenshot counted ~30k tokens, so a few images triggered auto-compaction far below budget. Each image now adds a flat ESTIMATED_TOKENS_PER_IMAGE (1600), and auto-compaction uses the resolved model's context window when the catalog entry lacks one.
  • Scheduled-run honesty: queued runs are claimed correctly under bun:sqlite (named parameters bound as NULL meant the hub never claimed a run and it sat pending with no error); a run whose agent turn ends in a provider error is recorded as failed with the error message, keeping usage and tool calls, instead of succeeding silently; superseded cron occurrences are cancelled instead of replaying every missed slot back to back.
  • Also: reasoning-off works on every provider (level-only Gemini models get a thinking level, not a rejected thinkingBudget; a request never carries both portable and native reasoning controls); Composio connector meta-tools register for signed-in sessions; .claude/skills is discovered; symlink rule files load; catalog grows 6,572 → 6,862 models.
  • Why it matters for BQAA: this is the harness-side version of the trace-store correctness wave — extension points and background runs getting explicit state machines and failure records. "The run report keeps usage and tool calls on failure" is exactly the property cost audits need from autonomous schedulers; flat image-token accounting is a reminder that token estimates drive compaction behavior and belong in the trace. Prior Cline card is v4.1.22 (Sep 30); this is a distinct capability wave, ranked NEW.

Cloudflare Agents 0.28.1 + @cloudflare/codemode 0.5.4 — OpenCodeHarness events normalized to the shared harness vocabulary; codemode describes real output types

Six-week EV

  • Continuation is becoming a billing primitive, defined independently by each SDK. Python defined accumulated BillableUsage last night; Vercel's Google provider summed usage across continuation hops today; gemini-4-argon is the forcing model, propagating through LiteLLM/gemini-cli/AutoGPT within hours. Within six weeks, any agent workload on long-decode models will produce multi-hop generations whose cost is only correct if the warehouse models continuations explicitly (hop count, per-hop usage, initial prompt vs. resumed tokens). Expect "why is my token total different from the provider's" tickets as the visible symptom.
  • Failure visibility is the new harness feature race. Cline shipped a plugin state machine and scheduled runs that record failures with usage intact; Letta shipped a watchdog for silent watches last night; Mastra spent the morning making every telemetry exporter flush completely before shutdown (unreleased).
