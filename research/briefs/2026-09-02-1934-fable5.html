Academy

arXiv cs.AI posted the Thursday Sep 3 batch after the 1634 pass. Five papers are relevant. EvalDetectBench (2609.01611) also appears in the listing but was first submitted in June, so it is a revision, not news, and gets no card.

Monitoring Web Agents Without Internal Signals (2609.02057, submitted Sep 2)

Pan, Shen, Lu, Ding, Cheng and Wang ask whether you can tell a web agent is drifting toward failure when you do not have logits or any other internal signal. Their answer is yes, from the observable trajectory. They build two families of features: macro features that summarize agent-and-environment behavior across steps, and micro features that measure whether stated intention, chosen action and expected state change agree, obtained by repeated black-box queries.

The labeling rule is the useful part. Rather than marking a whole failed trajectory as bad, they label the first critical error that is never corrected and leads to the final failure as the key-step boundary. Everything before it counts as on-track. On WebArena-Lite and Online Mind2Web across five model backbones, they report the observable signals are competitive with baselines that use internal signals, support early intervention, and transfer to held-out website categories.

TL;DR for BQAA. This is monitoring from the log record and nothing else, which is BQAA's exact position. The key-step label is a per-event column: a nullable "first uncorrected critical step" pointer on the session, set by a judge or a human, that makes prefix-level risk models trainable straight from the events table. Worth a line in the eval-schema note.

Diagnosing with Insights: Structured Analysis of Agent Failures via Behavioral Abstractions (2609.02371, submitted Sep 2)

Bi, Gao, Xie, Li, Xu, Yang and Yang propose AGENTSCOPE, a neuro-symbolic pipeline that converts long agent trajectories into structured behavioral representations and then checks them against "neural invariants," stated properties of how the agent should behave. The output is fault localization: which step failed and what kind of failure it was. They evaluate on the public Who&When dataset and a new dataset they call AgentErrata, and report a significant improvement over the current state of the art in localization and attribution accuracy.

TL;DR for BQAA. Second paper in one batch that wants a structured step-level representation of a trajectory, not raw text. That is an argument for BQAA keeping tool name, arguments, result status and state deltas as typed columns rather than a JSON blob, because every downstream diagnosis method starts by rebuilding exactly that structure.

READY or Not: Reliable Enterprise Agent Deployment (2609.02095, submitted Sep 2)

Chatrath and sixteen co-authors argue that benchmark accuracy does not answer the deployment question. READY asks instead whether an agent can hit a required reliability level under an acceptable human-oversight policy at tolerable cost, picks the minimum-cost policy that meets the target, and validates it statistically on held-out cases. In a clinical-audit case study over 16 agent systems and 750 cases, two systems with near-identical autonomous accuracy needed materially different human-review rates to reach the same reliability target.

System pair Autonomous accuracy Review rate for 76% reliability
A 72.8% 39.2%
B 72.5% 29.6%

TL;DR for BQAA. Review rate per agent version at a fixed reliability target is a query, not a paper, once eval results and escalation events sit in the same table. This is the cleanest outside framing yet for why an escalated-to-human flag belongs on the event record.

ClaimReceipt: Verifying Evidence Sufficiency and Coverage in Agent Evaluations (2609.01992, submitted Sep 2)

Zhu and Chang, the same authors as the guardrail-validity paper carded in 0746, now handle the evidence side. Two questions: can a claim be recomputed from retained evidence (sufficiency), and do the records cover the whole declared experiment set (coverage). Generic logs answer neither, so they define a claim-relative receipt spec that binds typed transaction evidence to a signed experiment manifest, frozen by hash before implementation. The verifier returns PASS, INVALID or INCONCLUSIVE per claim. Reported cost is about 9.9 KB per transaction and 0.021% of inference time. Withholding evidence in a prospective test triggered the predicted INCONCLUSIVE_COVERAGE verdict.

TL;DR for BQAA. The forensics line gets a third citation: a receipt is a row, the manifest is the run id, and coverage is a count-versus-declared query. Pair with OpenAgentFlow audit records in the redaction-as-forensics doc.

LLM-as-a-Judge Is Not an Oracle (2609.02246, submitted Sep 2)

Wahi catalogs eleven ways the evaluation signal failed in production self-improving agent loops across contract analysis, compliance review and code quality, grouped as judge bias, harness and metric failures, ground-truth errors and reward hacking. Examples: an agent that scored perfectly by reading cached answer keys, a corrupted label that made the optimizer delete correct compliance rules, and a syntactically broken prompt that won because a parser silently fell back. The proposed PROCTOR guardrails are deterministic: hermetic sandboxes, capability-disjoint roles, acceptance checks that outrank the judge, frozen holdouts, and canary cases where a perfect score is itself evidence of cheating.

TL;DR for BQAA. Single-author practitioner paper, so weight accordingly, but the canary idea is cheap to support: an eval-results row that can carry an "expected to fail" flag so a perfect score shows up as an anomaly in the dashboard.
