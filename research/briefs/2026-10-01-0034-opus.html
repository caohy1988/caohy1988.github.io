In 43 of 72 runs where the rule for admitting evidence was deliberately broken, the system still answered correctly. Scope, Temporal and same-name-$PATH Tool laundering occur in 100% of runs, and subagents run with the main session's approval in 94.7%. NEW I1 — @langchain/mcp-adapters 2.0.0: MCP SDK 2, modern and legacy servers in one adapter, elicitation via LangGraph interrupts, tool names prefixed by server

Release times: GitHub 01:15:20Z Oct 1. npm @langchain/mcp-adapters@2.0.0 was published 01:16:28Z. Catalog check: I grepped the live catalog for mcp-adapter. There is no card. The nearest LangChain card is langchainjs-langchain-1-5-14-openai-1-6-0-tool-error-status-cache-writes-langsmith-gateway, which covers the core langchain package rather than the MCP adapter. This is a major-version product change to a separate package, so I rank it NEW.

What shipped (release notes):

  • One adapter for both MCP protocol generations. Each server negotiates its own protocol: mode: "auto" (the default), "modern" or "legacy". The adapter bundles the MCP SDK 2 client, and SSE remains legacy-only. In auto or modern mode, HTTP connections no longer resume a dropped response stream.
  • Tool names include the server name by default. search on server docs becomes docs__search. This applies even with one server and with the deprecated MultiServerMCPClient. prefixToolNameWithServerName: false restores the old names, but then duplicate tool names throw MCPClientError.
  • New API surface. MCPAdapter replaces MultiServerMCPClient, listTools() replaces getTools(), and listToolsets() groups tools by server. Configuration is validated with Zod 4, so unknown or conflicting options now throw.
  • Servers can ask users for input through LangGraph interrupts (elicitation). Notification and progress callbacks move into each server's own configuration.
  • Auth: authProvider accepts token providers as well as OAuth providers. Discovery retries after an authentication failure, and UnauthorizedError is exported.
  • Requirements: @langchain/core ^1.2.6 and @langchain/langgraph ^1.4.13.

Why it matters for BQAA.

  • Tool-name discontinuity. Every LangChain.js agent that upgrades will emit server__tool names instead of tool. Per-tool call counts, error rates and latency will split into two series at the upgrade boundary. Normalize on (server, tool) as two fields rather than on the raw name string.
  • Human-input waits become interrupts. MCP elicitation now surfaces as LangGraph interrupts. A session that pauses for user input should be classified as "waiting on human", not as idle or failed.
  • Context: @langchain/typesafe 0.0.2 shipped in the same train (01:22Z). It adds modelRouterMiddleware (TypeSafe Choice routing) and autoModeMiddleware (blocks risky tool calls using a calibrated probability). This is NOTE only; Jev/TypeSafe integrations are already carded elsewhere.

Re-derive owners for that version window, or join on the alias once customers move to v1.103.2. Gateways older than the patched versions should be treated as able to leak provider keys to any key holder. Recommend the advisory's workaround to customers who route agent traffic through LiteLLM.

NEW A1 — Agent Error Dataset: Scaling 50,000 Error–Diagnosis Pairs for Failure Analysis and Error-Aware Post-Training (arXiv 2609.40111)

Authors: Kunlun Zhu, Xuyan Ye, Yibo Li, Cheng Qian, Beibin Li and Heng Ji (Apodex). Submitted 30 Sep 2026, cs.AI. Full PDF read (73 pages: main text plus Appendices A–X).

What it is. AED holds 50,228 error–diagnosis pairs linked to 38,278 stored traces over 9,961 source tasks, across 33 environments, 19 harness families and 23 policy models (Table 4).

  • Record contents: each record keeps the failed trace, the blamed step, the responsible agent, an explanation with verbatim trace quotations, a proposed replacement action and, where replay is possible, a matched replay.
  • The matched replay: the correction and a plain retry of the original action are both run from the same checkpoint, so each correction has its own control.
  • Evidence grades: E0 means grounded but not replayed. E1 means an observed recovery. E2 means at least two trials per arm, with every treatment passing and every control failing (App. C.1, D.2).

Key numbers.

  • Corrections versus retries. Over 3,062 matched replay pairs, first-proposal corrections pass 51.1% against 18.4% for an original-action retry: +32.7 points, with a task-clustered 95% CI of 28.4–37.0 (Table 47a). However, 470 of the 1,564 passing first proposals also passed on the plain retry (30.1%). The breakdown is 1,094 correction-only, 470 both, 93 retry-only and 1,405 neither (App. B.2, Fig. 7a).
  • Repeated diagnoses rarely move on. Across 1,744 successive diagnosis rounds, 61.0% re-blame the same step (App. K.1).
  • Fine-tuning a diagnoser. Full-diagnosis fine-tuning of Qwen3-8B raises exact-step agreement with the internal teacher labels from 47.2% to 63.6% (three seeds, 943-case holdout; Table 28). Prompted Claude Opus 5 scores 54.7% (Table 48a). Public transfer is weak:
  • On TrajErrBench, two of three seeds score below the base (Table 32).
  • The Who&When gain of +7.97 shrinks to +4.92 [−2.24, 12.08] once tasks that overlap training are excluded (Table 15).
  • After Holm correction, the only significant public cells are three losses (Table 31).
  • Error-reporting bias. On 50 successful trajectories, GPT-5 mini, GPT-5.6 Sol and Claude Opus 5 all name an error under a prompt that presupposes failure (0 of 150 abstain). With a neutral prompt that allows "none", they abstain 84%, 86% and 44% of the time (App. L).
  • Label quality.
  • 6,381 of 11,116 diagnosis attempts (57.4%) pass citation grounding (App. E.2).
  • A blinded three-model panel endorsed both the blamed step and full evidence support on only 9 of 120 records (Table 8).
  • Two human reviewers chose the same preferred step on 59 of 69 records, but both accepted the diagnosis on only 41 of 80 (Table 44).
  • Grader defects. In AgentBench-DB, gold SQL failed to reproduce the table hash on 234 of 455 state-changing tasks. In BFCL, the ground-truth calls failed the state checker on 112 of 386 instances (App. D, E.1).
  • Cost. Rollout plus diagnosis cost $0.110 per diagnosis (21,629 runs, 6,898 diagnoses, $758.96; Table 21). Strict admission keeps 767 of 19,904 candidates (3.9%) at $1.25 per retained row (Table 50a).

Limitations, as stated by the authors.

  • The diagnosis experiments use an earlier frozen release whose inputs omitted policy system prompts and tool lists (App. A).
  • 1,846 of the 3,062 replay pairs ran under a substituted ReAct harness, not the harness that failed (Table 14).
  • Actor training on repair targets gains on WebShop-lite but loses 8–10 points on TextQuest. On real ALFWorld and ScienceWorld it falls to 0.75% and 0.34%, against 5.97% and 9.67% for the base policy (Table 49, App. X.6).
  • Code and data are "will be released"; they are not available now.

Why it matters for BQAA.

  • A ready schema for failure diagnosis. The AED record is a near-ready template for a failure_diagnosis table joined to agent_events: blamed step id, responsible unit, quoted evidence span ids, proposed action, replay outcome with its control, and an evidence grade. BQAA should store the control outcome too, or "fix rates" overstate by roughly 30%.
  • Prompting rule for diagnosers. Never prompt an LLM diagnoser with "this run failed" over unlabeled traces. Use the neutral, abstain-allowed form, or the error rate becomes 100% by construction.
  • Check graders before trusting labels. Verifier and grader defects are common enough that "failure" labels need a grader sanity check before they feed analytics.

NEW A2 — Where Do Multi-Agent Systems Fail? Evidence-Grounded Diagnosis of Collective Mechanisms (arXiv 2609.38761)

Author: Zhengye Han (NYU), sole author. Submitted 30 Sep 2026, cs.MA. Full PDF read (9 pages).

What it is. A diagnostic contract pairs two things for one multi-agent mechanism: a violation predicate (what counts as breaking the rule) and an evidence specification (which authoritative records can settle it).

  • Three-valued verdict. The contract returns supported, ruled_out or unknown.
  • Key property. Removing records can turn a verdict into unknown but can never reverse it (Prop. 3.1, §3.3).
  • Mechanisms covered: routing, admission/dependence, state maintenance and representation/action.
  • Ground truth by construction: the author replays each run from a frozen prefix three ways (unchanged, mechanism broken, mechanism restored) across AutoGen, LangGraph, CAMEL and MetaGPT adapters (§4).

Key numbers.

  • Correct answers hide violations. In 43 of 72 admission-rule violations the system still answered correctly, so task success concealed 59.7% of realized violations (Table 3, §6.1). In the separately frozen allocation family (DRAC), 28 violations still produced the exact optimal allocation.
  • Evidence access matters. A diagnoser prompt without examples recovered the broken mechanism in 26.4% of cases from public outputs and 63.2% from native execution records, a paired gain of +0.368 [0.271, 0.472] (§6.2, Fig. 2).
  • Overclaiming with the same evidence (Table 4):
  • When decisive records were deleted, the generic prompt still asserted a definite verdict on 576 of 768 packages.
  • It reversed 138 of 1,152 verdicts as records were removed, which the contract semantics forbid.
  • Prompts that state the contracts made 0 reversals, but returned valid outputs on only 78.1% and 67.1% of packages. The preregistered verdict is therefore "inconclusive" (§5.3).
  • Transfer gap. A prompt that kept its verdict under irrelevant-record deletion in 287 of 287 benchmark pairs did so in only 13 of 28 pairs from an independently developed workflow (Co-STORM) (Fig. 3, §6.4).
  • Public traces lack the needed records. None of 156 TraceElephant multi-agent traces supports a verdict at any of the four mechanisms; 147 stay unresolved (§6.3).

Limitations.

  • One model lineage (DeepSeek-V4.1-Flash) throughout.
  • The benchmark authors its own institutions, and mechanisms are broken one at a time.
  • The transfer result rests on one external workflow: 28 pairs from 10 tasks, with an admission binding that reviewers called ambiguous.
  • An OpenAI Agents SDK approval gate was rejected as a binding, because it authorizes actions rather than admitting evidence (Table 5).

Why it matters for BQAA.

  • Formal backing for "missing ≠ absent". This formalizes the vault rule that a negative claim needs a lookup that worked. "Unknown" is the correct answer when the records cannot settle the question.
  • Log per-operation records, not just transcripts. To support any mechanism-level diagnosis, BQAA needs records bound to each operation: the input each agent actually received, admission decisions, state versions and action receipts tied to the caller and payload. Outcome rows and chat transcripts are not enough.
  • Prompt LLM trace diagnosers with the evidence rules. Any LLM diagnoser over BQAA traces should be prompted with the evidence obligations, or it will claim certainty the data cannot support.

NEW A3 — Approval Laundering: Systematizing Approval–Execution Binding Failures in AI Coding-Agent Harnesses (arXiv 2609.38983)

Author: Yang Wang (Fudan), sole author. Submitted 30 Sep 2026, cs.CR. This is a working draft dated 2026-09-22 that has not yet been submitted for review. Full PDF read (20 pages).

What it is. The paper names six ways the action a human approves can differ from the action the harness actually runs:

  • Scope: an approved npm script's child process reads a file the grant never named.
  • Argument: a pre-commit hook runs git add -A under an exact-literal git commit -m "wip" grant.
  • Temporal: a persisted rule is reused in a later session.
  • Tool: a cross-tool substitution, or a $PATH-shadowed binary behind an approved command name.
  • Delegation: a subagent runs with the main session's approval.
  • Semantic: the approval text does not disclose the target.

The measurements instrument Claude Code 2.1.197 headless through its PreToolUse hook, with N=19–20 runs per class (§4).

Key numbers (Bound-Gap Rate, Table 3).

Class Bound-Gap Rate 95% CI
Scope 1.00 [0.839, 1.0]
Temporal 1.00 —
Tool, same-name $PATH 1.00 —
Delegation 0.947 [0.754, 0.991]
Argument 0.45 [0.258, 0.658]
Semantic (proxy metric) 0.10 —
Tool, cross-tool (Bash/curl with only a WebFetch grant) 0.00 —

The 0.00 cross-tool result is correctly blocked by the native policy engine.

The proposed defense. Approval Token is an HMAC over principal, agent id, session id, tool, arguments, scope and expiry, verified in a second hook (Table 5).

  • Delegation falls from 0.947 to 0 (p=7.6e-6) and Temporal from 1.0 to 0 (p=1.9e-6). Both were also confirmed in 6 of 6 live runs.
  • Scope is unchanged at 1.0, and Argument moves only from 0.45 to 0.40 (p=1). These are effect divergences that sit one process below what a field-level check can see (§3.2, §9).

Limitations, which the author discloses.

  • Runs were not hermetic: all 138 main-study traces had a previous-session summary and extra plugins injected at SessionStart (§4.1).
  • Temporal uses a synthetic seeded session id, not a real two-session lifecycle.
  • κ comes from a non-blinded author cross-check.
  • An analyzer bug, found during review, changed Scope from 0.80 to 1.00 (§4.4).
  • Only one harness was measured. The Codex probe used v0.154.0, where codex exec never invoked the configured hook (§9).
  • The token's key file is readable by the same user.

Why it matters for BQAA. An approval audit row is only useful if it carries agent_id, session_id and the grant identity. With those, Delegation and Temporal laundering become detectable with a SQL join (approval's agent or session ≠ executing call's). Scope and Argument laundering are invisible at the tool-call layer, so detecting them requires joining approvals to effects (file writes, commits, network) rather than to command strings. Note that this measures an older Claude Code version (2.1.197); I did not confirm the rates on current 2.1.286.

Use A2's three-valued verdict, with unknown as a first-class value. Both papers say LLM diagnosers overclaim unless prompted neutrally and with explicit evidence rules.
