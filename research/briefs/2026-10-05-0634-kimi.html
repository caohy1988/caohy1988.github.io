NEW — 2610.00972 — VeriHarness: the generator's own model as an agentic verifier — resolve disagreement with evidence, challenge consensus (34% of unanimous values are wrong), and keep a claim-level verification record

Full PDF read (method §2–3, results §4/Table 2, self-evolution §5/Fig 4, analysis §6/Fig 5, ablation App F/Table 4, cost App K/Fig 8, limitations). Cambridge + Google Cloud AI Research (Zhang, Han, Wang, CuiZhu, Collier, Pfister, Lee). v1 1 Oct 2026. Code: github.com/google-research/veriharness; ~26k released rollouts (HF caiqizh/veriharness), >$100k generation cost.

The motivating measurement (Fig 2, App A; ten-rollout pools of Claude Opus 4.8 on APEX-Agents, 434 tasks / 1,692 claims): 34% of consensus values are judged incorrect, while disputed claims contain a correct candidate 74% of the time and the most-frequent value is correct only 47%. Voting and pool-reading judges structurally cannot fix the first number; that is the paper's wedge.

The system: the verifier is the same model as the generator, given a workspace (each rollout's artifact, final state and trace as files, mounted read-only), evidence tools, and a library of 18 verification skills (Table 6). A disagreement resolver traces disputed claims to sources/recomputations and eliminates contradicted candidates; a consensus challenger proposes how shared values/readings/omissions could fail and tests those against the environment; adjudication in a fresh context emits a base rollout + evidence-backed revision plan + unresolved list, and delivery returns the artifact with a verification record linking every claim → check → evidence → verdict (§3.4).

Results (Table 2; five workspace benchmarks — APEX-Agents, Workspace-Bench Lite, WorkBuddy, SpreadsheetBench 2, JobBench; Gemini 3.5 Flash and Claude Opus 4.8, N=10 rollouts, three seeds): VeriHarness-select beats every selection baseline in all 10 model×benchmark settings (+4.4/+4.1 avg over single rollout); with revision, +6.2 (Flash) / +6.4 (Opus), e.g. APEX-Agents 35.8→47.5 with Opus. The agentic-verifier-with-tools-but-no-protocol baseline recovers only ~half the gain — access alone is insufficient. The protocol ports into Gemini CLI / Claude Code / Codex with most of the gain intact (weaker on JobBench/SB-2 with Opus — host runtime matters, App G). Ablations (Table 4, Opus): resolver-only 54.3, challenger-only 52.6, no-skills 53.8, single-context 55.3, full 56.1 — the two investigations are complementary and earn their separate contexts. Selection gain is concentrated where the pool disagrees: +0.6 on unanimous pools vs +6.1 on disputed ones (Fig 5). The challenger's blind spot is named (Table 7): in ~70% of surviving shared errors it verified an intermediate value while the error sat downstream. Self-evolution (§5): skill libraries evolved from failure feedback beat the human-authored library on held-out tasks (empty→evolved +11.0 on APEX vs empty; evolving from human-authored adds +6.8). Cost (App K): selection $1.44/task (Flash) / $3.92 (Opus) — on the cost-gain frontier, ~half the price of the prior-best LLM-as-a-Verifier at higher gain; 86–91% of input tokens are cache-served.

Limitations (stated): N=10 pool cost is the entry fee; no per-rollout scalar score (claim-level verdicts only); same-model setting only; multi-turn latency; CLI deployment costs 2–3×.

Why it ranks. The cleanest demonstration yet that consensus is not correctness for agent artifacts — and a working pattern (claim-level evidence records) that agent-observability products can ingest directly. Pairs with 0034's ArrivalBench (re-execute the artifact) and Sentry (verify recovery before admitting lessons): the week's Academy line keeps saying the same thing — grade against the environment, not against the model's own outputs.

NEW — 2610.03315 — LiteTrajEval: production trajectory evaluation as ONE rubric-guided judge call over a deterministically budgeted trace — ~6× cheaper than AgentRx with +20–35 pp failure-localization alignment

Full PDF read (design §II, evaluation §III with Tables II–III and the Fig 2 case study, production lessons §IV, conclusion §V). Huawei Ireland Research Center + Shenzhen R&D (Phan, Wang, Wu, Pan, Pang, Zhang). v1 2 Oct 2026.

The problem: multi-call diagnosis pipelines (AgentRx, TRACE, AgentEval) work but are too expensive to run repeatedly against production traffic — and feeding a raw 360k-char trace to a judge degrades attention. LiteTrajEval splits the work: offline, an LLM distills accumulated step outputs into a compact domain rule profile (Jaccard near-duplicate grouping → rule synthesis; a few LLM calls per domain); online is fully deterministic — normalize to a minimal step schema, infer ok/warning/error status from rules, expand suspicious steps into candidate failure regions, then serialize under a fixed 50k-character global budget via tier-based waterfall allocation (error steps get the highest preservation floor; MMR selects within-step evidence units; Algorithm 1, Eqs. 1–3). A single rubric-guided judge call then returns scores, failure steps, categories, root cause and key observations as one structured report.

Results (Table II; AgentRx-derived failed-trajectory sets: 44 Magentic-One-style samples / 78 failure groups, 29 τ-retail / 31 groups): rule-status-only detection is poor (56.8% / 31.0%) — local error messages miss root causes, the paper's motivating point. With a judge, detection matches or trails AgentRx slightly by model (GPT-5-mini 97.7%/89.6% vs 97.7%/86.2%; DeepSeek-v3.2 dips to 72.4% on τ-retail — interaction-heavy traces want reasoning judges), but conditional failure-group alignment beats AgentRx by ~20–35 pp across all four judges on Magentic-One (e.g., @3: 83.1% vs 45.4% with GPT-5-mini) and up to ~23 pp on τ-retail (82.1% vs 59.2%). Cost (Table III, June 2026 prices): $0.4155 vs $2.4628 for the full set under the same GPT-5-mini judge (~6×), $0.1087 with DeepSeek-v4-flash (~22.7×), total wall time 1,840s vs 15,990s (8.7×). The Fig 2 case study is worth reading: AgentRx localizes an unrelated same-message policy violation while LiteTrajEval finds the actual order-level-vs-item-level cancellation failure and its downstream steps. Production (§IV): deployed in Huawei's enterprise platform evaluating an internal SRE RCA agent at hundreds of trajectories/day; small self-hosted judges (DeepSeek-v4-flash, Qwen3.5-35B) suffice; compacting the largest-output steps accounts for most of the trace reduction.

Caveats (mine, stated plainly): the eval sets are small and failed-only (44+29 samples, both derived from one baseline's benchmark), the alignment metric allows ±1/±3 step tolerance, there are no significance tests, and the production evidence is qualitative (no step-level ground truth on real traffic; judge-stability observation is "preliminary manual inspection").

Why it ranks. Small-n aside, this is the first deployed blueprint for trajectory eval as a bounded, repeatable, regression-runnable production job — deterministic preprocessing with status-tiered budgets, one judge call, structured failure output. That is exactly the shape a BQAA-style trajectory-diagnostics feature would take.

Six-week EV

  1. Verification leaves the pool and enters the environment. VeriHarness's 34%-of-consensus-wrong measurement plus LiteTrajEval's evidence-aware budgeted serialization (and 0034's ArrivalBench/Sentry) converge on one design rule: judging agent work by re-reading its own outputs has a hard ceiling; the gains sit in environment evidence, delivery-hazard replay, and claim-level verification records. Expect observability products to ship "evidence-backed eval" modes — and to expose a verification-record schema — within six weeks.
  2. Run durability becomes a shipped, on-by-default product surface. qwen-code v0.25.0 (cold restore, recovery bundles, durable hooks/permissions, takeover) plus Mastra's open durable-run-ownership/fencing PR and letta-code's nested subagents mark the shift: agent runs are becoming durable, ownable, fencable resources. Analytics that key a "run" to a process lifetime will break; expect run-epoch/fencing/restore events to become required span attributes.
  3. Context exposure gets budgeted at every layer. Mastra letting tools read full conversation state (with adapter capability signaling), LiteTrajEval's status-tiered serialization budget, VeriHarness's separate investigation contexts, and 0034's Sentry conditional-exposure rule are the same instinct: what enters a context is a budgeted, auditable decision. Telemetry that records what was visible to each call — not just what was called — becomes the differentiator.

  3. id: arxiv-2610-03315-litetrajeval-budget-bounded-single-call-trajectory-eval-failure-localization - tag: Academy - title: LiteTrajEval: production trajectory evaluation as one rubric-guided judge call over a deterministically budget-serialized trace — ~6× cheaper than AgentRx, +20–35 pp failure-localization alignment - arxiv: 2610.03315 — https://arxiv.org/abs/2610.03315 - card text: Huawei (Ireland + Shenzhen). Offline: LLM distills accumulated step outputs into a domain rule profile. Online is deterministic: normalize steps, infer ok/warning/error, expand suspicious regions, serialize under a fixed 50k-char budget via status-tiered waterfall allocation + MMR evidence selection (Algorithm 1); one judge call returns scores, failure steps, categories, root cause. On AgentRx-derived failed trajectories (44 Magentic-One / 29 τ-retail): rule-only detection is poor (56.8%/31.0%); with a judge, detection ≈ AgentRx but conditional group alignment @3 beats it by ~20–35 pp (83.1% vs 45.4% GPT-5-mini) at ~6× lower cost ($0.42 vs $2.46 per full set) and 8.7× less wall time; $0.11 with DeepSeek-v4-flash (~22.7×). Deployed in Huawei's enterprise platform against an internal SRE RCA agent; small self-hosted judges suffice. Caveats: small failed-only eval sets from one baseline's benchmark, ±1/±3 step tolerance, no significance tests, qualitative production evidence.
