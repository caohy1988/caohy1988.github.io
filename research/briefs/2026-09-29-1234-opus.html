Why this is a card and not a note:

  • A frontier model at this price becomes the default in Codex and a selectable model across Copilot within hours.
  • For an agent-analytics product, that shifts the mix of models in customers' traces immediately. It also brings two metadata facts that break naive cost and overflow logic:
  • Input window vs context window. Inspect's own fallback was 128K, so an unknown-model default underestimates by 7×.
  • No none reasoning. Any "cheap mode" experiment that sets reasoning_effort=none fails with a 400.

What is not claimed here: OpenAI's benchmark numbers (OSWorld 2.0, factual-error rate) are not quoted as fact. openai.com returned HTTP 403 to both fetch paths, so they appear only in Unconfirmed.

TL;DR for BQAA: Add gpt-6.1-sol pricing ($2 / $0.10 / $10) and a separate input-window field (922K) to model metadata. Treat a reasoning_effort=none 400 on this model as a config error, not a model failure. Expect Codex-sourced traces to switch to it at the next Codex stable.

Progress

P1 — LiteLLM #43614 (merged 18:27Z to main; no release yet; PyPI latest 1.103.0). Parent: litellm-1-102-1-jev-routing-compaction-passthrough-stable-backport

  • The bug.
  • Chat per-second pricing added input_cost_per_second and output_cost_per_second.
  • The 28 Bedrock commitment rows set both to the full rate, so those deployments billed 2×.
  • The PR's example: a 2-second call at $0.01/s showed $0.04 instead of $0.02 in x-litellm-response-cost and the logs page.
  • The fix.
  • A new cost_per_second field is charged once for the whole request duration, streaming included. It covers chat, completion, embedding and responses.
  • Legacy fields are now picked in order, never added.
  • Azure chat also stops adding output_cost_per_second × latency on top of token prices.
  • Deliberate behavior change. A config that set two different legacy rates on purpose now bills only the input rate. That underbills.
  • Where it lands. The diff edits both model_prices_and_context_window.json and its backup copy.
  • TL;DR for BQAA: Any LiteLLM-sourced cost for per-second Bedrock commitment or Azure chat deployments before this fix may be 2× or inflated. Flag rather than trust these costs.

P2 — Claude Code v2.1.285 (GitHub 19:27Z). Parent: claude-code-2-1-283-gateway-prompt-id-otel-tool-output-agent-sdk

  • Usage attribution. /cost and the SDK's modelUsage reported a turn under the wrong model when the server answered a refusal with a different fallback model than expected. Fixed.
  • Model switch. Switching models mid-session with set_model (the Agent SDK's setModel) left the new model on the old output-token limit and auto-compact window until restart. Fixed.
  • Governance. A new allowedProviders managed setting limits which API providers a machine may use: Anthropic API, custom endpoint, Bedrock, Mantle, Vertex AI, Foundry, Claude Platform on AWS, or a Cloud gateway.
  • Redaction. Redacted logs and transcripts had shown part of a URL password that contains @, or all of it when @ was written as %40. Fixed.
  • TL;DR for BQAA: Per-model usage from Claude Code refusal-fallback turns before 2.1.285 can be attributed to the wrong model. Also, allowedProviders gives admins a provider allow-list for Claude Code.

P3 — Opik #8411 (merged 17:13Z to main; unreleased, PyPI latest 2.2.85). Parent: opik-2-2-78-jury-votes-33x-experiment-reads-clickhouse-cold-tier

  • The bug.
  • read_and_parse_full_stream() decided a page was short by counting the records it managed to parse.
  • One undecodable record in a full page therefore read as end-of-data. Every remaining page was dropped, with no exception, and the return value looked like a complete read.
  • On the experiment path, an all-unreadable first page surfaced as ExperimentNotFound for an experiment that exists.
  • Reachable from: search_traces, search_spans, search_threads, evaluate_experiment and opik migrate.
  • The fix. The SDK now counts records the backend delivered, and logs one WARNING with the count of dropped records.
  • TL;DR for BQAA: A textbook "short read looks like done" bug. Any export or reconciliation job should compare what the backend delivered against what it parsed.
