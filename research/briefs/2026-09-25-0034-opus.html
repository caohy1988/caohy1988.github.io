PUBLISH: 3 new Industry ranks, 5 new Academy ranks, 3 Industry progress notes, and a short NOTE list.

Theme 1: the typed decision layer went from a model call to a first-class telemetry object in one night, and a paper measured how easily it can be steered.

  • PydanticAI v2.50.0 adds a DecisionModel base class. Every request it sends gets a decide span that records the questions asked, the routes offered, the route taken, per-question confidence and per-option probabilities. It also quietly ignores the old typesafe_tool_call_threshold setting.
  • DSPy 3.4.0 (missed by every pack) makes Jev a normal lm= backend. Its Noul, Choice and Score outputs carry probabilities and confidence, and a new optimizer (ReAnchor) fits decision thresholds against the program's own metric. DSPy also moves its default LM path off LiteLLM onto a native engine.
  • The same probabilities can be pushed around (2609.30243, JevOut). Short, fluent context that leaves the correct answer unchanged redirected Jev on 312 of 508 initially correct decisions (61.4%), 229 of them at ≥0.7 probability on the wrong option.
  • A companion paper found the opposite for injection (2609.28613, read in full, folded into the JevOut card). Classic injection text flipped Jev in only 1.8–3.5% of 510 cases. What decides risk is the decision's margin, not the wording.

Theme 2: what the agent's own record does not show.

  • Cost (2609.28585, Denial-of-Wallet). A tool return that the host keeps in history is billed again on every later call. Cumulative input reached 14,293× the first call's input, and only 71 of 3,830 public MCP repos show any code-visible safeguard against it (token, growth, loop or spend limits).
  • Syscalls (2609.28915, ACE, AWS). App-layer evidence, which is what BQAA sees, scores AUROC 0.586 on "silent exfiltration via logging". The kernel trace scores 0.976 on the same sessions.
  • Approvals (2609.28586, Approval Laundering). 40 of 111 approval records omit an effect class the approved command then exercised, such as a postinstall hook writing a file or an MCP call reaching the network.
  • Cache (2609.28919, Control the Harness). In a harness, the unit to price is the turn, not the request. Corrections are over a third of the bill, and 17–27% of user turns arrive after the 5-minute prompt cache has expired.
  • Telemetry egress (Codex rust-v0.157.0, now npm latest). Under a managed network policy that restricts destinations, Codex refuses every OTLP log, trace and metric export, even to an allowlisted collector. I verified this in the source at the release tag.

What this means for BQAA (as the observer, not the source of truth):

  • Add a decision event to the schema now: question keys, option labels, per-option probabilities, threshold, route taken, hand-off. Store the top-1 minus top-2 margin, because low-margin decisions are the ones that flip.
  • Price turns cache-aware and watch re-billed state: uncached input, cache reads and cache writes per request; the cumulative input amplification (CAF, total session input ÷ first-call input) and per-turn prompt growth; correction turns; cold returns after the cache has expired.
  • Say plainly which failures app-layer telemetry cannot see, and give host evidence (EDR, eBPF) a session join key. Treat "a client went silent" as its own signal, since Codex now goes silent by policy.

NEW 1: PydanticAI v2.50.0: DecisionModel base, decide spans, route-by-name, and the tool-call "lean" removed

GH release at 04:47:15Z; PyPI pydantic-ai at 05:03:21Z and pydantic-ai-slim at 05:03:24Z. I read the release notes and the PR bodies of #8696, #8698, #8733 and #8739.

  • DecisionModel, a base for any Decisions-protocol backend (#8696).
  • It turns an agent's output type and tools into typed questions (noul, choice, score) and maps the answers back. TypeSafeModel becomes a thin adapter on top of it.
  • The PR notes that OpenRouter already serves the same protocol (#8552).
  • Settings are renamed to decision_*; the old typesafe_* names still work but warn.
  • A decide {model} span for every Decisions request (#8698), nested under the chat span.
  • gen_ai.operation.name = "decide". This is a custom value, which semconv allows; it is not a standard operation name.
  • The route and decision attributes are pydantic_ai.decision.{thresholds, questions, state, answers, confidence, route_question, route_options, route_questions, route}. Token counts go in pydantic_ai.decision.usage.*.
  • Hand-offs are errors on the decide span. A pick below decision_route_threshold raises UnsureRoute, and a route the model cannot fill raises UnfillableRoute. With a FallbackModel, the parent chat span ends without an error, so the decide span is the only place the hand-off appears.
  • No gen_ai.usage.* and no cost on decide spans. The chat span already carries the sum, and adding both would double-count.
  • With content capture off, the span keeps numbers and identifiers (question keys, route labels, confidence, probabilities) but drops state text and question text.
  • A fill past the size cutoff produces a sibling decide span. A telemetry failure never fails the request.
  • Nesting is documented for DBOS, Prefect and Temporal, the last as invoke_agent → chat → StartActivity → RunActivity → decide.
  • Compatibility notes:
  • Route by name (#8733). The route question is keyed route, and each route has one label, such as Refund, None or a tool name.
  • ModelSelectionContext (#8737). .messages now ends with the request being routed, and a new .prompt field is added.
  • The tool-call "lean" is removed (#8739). The likeliest route is always taken. The opt-in decision_route_threshold hands unsure picks to a FallbackModel.
  • typesafe_tool_call_threshold (shipped in v2.45–v2.49, default 0.6) is deprecated and ignored. Code that relied on the default now calls the tool Jev picked. The PR's evidence: on 156 labelled support-desk runs, taking the likeliest route scored 156/156 against 154/156 for the lean.
  • Cost and realtime fixes:
  • Anthropic one-hour cache writes are now priced at the one-hour rate instead of the five-minute rate (#8666).
  • Realtime image input is priced at the image rate (#8741), and RequestUsage.audio_seconds is added (#8427).
  • A failed OpenAI realtime response becomes a RealtimeSessionErrorEvent with finish_reason='error' (#8752); before, the error was dropped.
  • wait_for_reply() no longer hangs on a refused send (#8747).
  • RunContext.in_durable_context is added (#8723).
  • Why it ranks as NEW, not progress: it adds a new public API and a new span type compared with the pydantic-ai-v2-49-0-nested-usage-attribution-boolcriteria-typesafe-none card. The catalog followed the same rule for v2.49 vs v2.47.
  • Caveat: decide is not an OTel GenAI semconv operation yet, and the attribute names are PydanticAI's own.
  • TL;DR: count hand-offs from decide-span exceptions, not chat-span errors. Never sum decide usage into session totals. Flag agents whose config still sets typesafe_tool_call_threshold, because their routing changed silently.

NEW 2: DSPy 3.4.0: Jev decision types with probability evidence, ReAnchor calibration, and a native LM engine that bypasses LiteLLM by default

PyPI at 04:04:23Z and GH release at 04:06:22Z. No pack reported it, because DSPy is not on the collectors' watchlist. I read the full release notes and the 3.4.0 migration guide (docs/docs/community/normalized-lm-api-migration.md).

  • Jev through TypeSafe as an ordinary backend (#10463).
  • Configure it with dspy.configure(lm=dspy.experimental.TypeSafe("jev-latest")). Predict translates the signature into Jev decision requests.
  • There are three experimental output types:
    • Noul: .value, .probability, .confidence
    • Choice[...]: .value, per-option .probabilities, .confidence
    • Score[...]: continuous .value, ordinal .level, rubric .probabilities, .confidence
  • Thresholds, score cuts and choice weights are applied locally, not sent to the backend, so identical requests can reuse cached evidence.
  • The notes caveat the confidence values themselves: Noul confidence measures distance from its threshold, not calibration, and a generative LM's confidence is self-reported.
  • ReAnchor (#10475).
  • This experimental optimizer fits Boolean thresholds, score cuts and choice weights against the whole program's metric, without rewriting instructions.
  • A setting must improve the training score and pass a held-out fold check.
  • The notes state there is "no fixed inference budget" guarantee.
  • The native LM engine (lm15) is the new default path.
  • engine="auto" prefers native execution. LiteLLM is chosen only before inference, for requests the native route cannot carry. Auth failures, timeouts and provider errors never switch the backend.
  • engine="litellm" forces the old path, and LiteLLM remains installed.
  • The migration guide says "DSPy owns response caching, retries, candidate fan-out, callbacks and history" on both engines.
  • Accounting semantics that matter for analytics (release notes and migration guide):
  • "Unknown cost remains unknown rather than zero."
  • A setting the native route cannot carry exactly is adapted and recorded in LM history under adaptations (field, action, asked, applied, reason). For example, temperature=1.5 on Anthropic becomes 1.0.
  • Native n answers are n sequential requests, so input tokens are billed more than once.
  • Closing a native Responses stream early can lose final usage.
  • "A network retry can still repeat a request the provider already processed or billed: this is not an exactly-once guarantee."
  • Nested usage trackers now roll into their parent (#10065).
  • GEPA's trace capture no longer misaligns failed examples with their scores (#10305). This fixes an eval-data bug in 3.3.1.
  • Breaking changes: the RLM interpreter_factory= argument is now keyword-only; the experimental 3.3 LM types are removed; legacy lm(messages=[...]) calls and custom BaseLM.forward() are deprecated until the 3.5 cutoff; Pydantic 2.11 or later is required.
  • Why it ranks: it is a major release of a widely used agent/LM-program framework that ships a product capability (typed decisions with probability evidence plus metric-driven calibration). It also changes where LM calls are executed and how cost is recorded.
  • Catalog context:
  • langfuse-4-42-0-decision-model-evaluators-typesafe-jev
  • goose-v1-52-0-decisions-provider-crate-openrouter-jev
  • litellm-1-102-1-jev-routing-compaction-passthrough-stable-backport
  • TL;DR: tracing that depends on LiteLLM being in the call path (LiteLLM callbacks, a LiteLLM-level instrumentor) no longer sees calls DSPy runs natively, so verify DSPy coverage after upgrading. Keep unknown cost as NULL, not 0. Store requested-versus-applied parameters.

1. NEW rank: arXiv 2609.28585: Persistent Billable State: Denial-of-Wallet Attacks and Defenses in Tool-Calling LLM Agents

Zhang, Xia, Wu, Yue, Zhang, Cheng, Tu (Chinese Academy of Sciences IIE / UCAS, Beihang, BUPT). Submitted 23 Sep 2026.

Full PDF read (22 pp): §1–10 and App. C (Tables 4–13, Figs. 9–14).

The idea: once a host keeps a tool's return in history, the provider bills it again on every later call. An admitted malicious or compromised tool can therefore buy recurring, victim-billed processing with a schema-valid, task-plausible return. It needs no credentials, and cumulative input grows as O(N²).

What they did:

  • DOW-BENCH: six attack vectors (Table 1): direct recursion, polymorphic mutation, cross-tool chaining, stealth escalation, weaponized output and adaptive threshold-hugging.
  • 243 core executions across six model families: GPT-4o, GPT-4o-mini, Mistral-Large, Llama-3.3-70B, Nemotron-120B and Qwen-3-235B.
  • Metric: CAF, the cumulative input tokens of a session divided by its first call's input tokens, computed from provider-reported usage.

Numbers:

  • Exposure (Tables 3–4). Maximum CAF was 14,293× (Mistral-Large, direct vector). 51 of 69 priced attack sessions crossed $0.10, and the largest reached $3.404, against $0.025 for the largest benign session.
  • Run length is not a safeguard (§6.1). CAF's coefficient of variation reached 3.08 (V1 on Llama-3.3-70B), so "the agent will stop on its own" cannot serve as a budget.
  • Turn survival drives exposure (§6.2). CAF tracks mean turns (ρ = 0.79) and tool calls (ρ = 0.81).
  • Retention policy (§6.3, Table 13). Keeping raw tool history raised mean effective cost by 21.2–35.9%. Deterministic compression kept 10/12 and 11/12 history-dependent tasks successful; deletion kept 2/12.
  • Their fix: four host-side checks before each later call (§7–8). D1 caps prompt tokens, D2 flags prompt growth, D3 caps recursion, and D4 is a cost circuit breaker.
  • They contained all 123 replay evaluations (41 recurring attacks × 3 presets).
  • The moderate growth check (D2) fired on 2 of 1,050 benign runs (0.19%).
  • Median decision time was 3.3–4.4 µs.
  • A progress-authorized budget completed 22/24 workflows, against 13/24 under a fixed $0.10 cap (McNemar p = 0.0039).
  • Ecosystem (Fig. 14). Only 71 of 3,830 public MCP server and transport repos have any code-visible safeguard (1.9%), and none cover all four check families.

Caveats I'd flag:

  • It is a paper-only release: no code, data or attack material.
  • The models are mostly 2025-era, and the priced cohort is small (78 sessions; V2 and V4 have 3 priced sessions each).
  • The archived manifests omit temperature, max-turn and cache-policy fields.
  • Prices are nominal list rates.
  • The ecosystem scan is lexical.
  • Disclosure to providers is still under review.
  • It comes from the same team as 2609.28586 below, so the two are not independent confirmations.

Why it ranks: it turns "retained tool output" into a measurable cost-security object, and every metric it uses (CAF, per-turn Δp, priced exposure) can be computed from per-call usage telemetry that BQAA already stores.   • Ship per-session CAF and per-turn prompt-growth (Δp) views. The paper's moderate rule is Δp > 10k, or Δp/p₁ > 3 with Δp > 2k.

2. NEW rank: arXiv 2609.28915: On the Effectiveness of Kernel-Level Evidence for Agent Security (ACE)

King (U. Georgia); Zhang, Kuznetsov, Liu, Coskun, Ding (AWS). Submitted 24 Sep 2026.

What they did:

  • ACE corpus: 4,047 paired sessions, 17 threat models, six delivery vectors (31 real third-party MCP servers with hand-authored patches; file, web, memory, retrieval and user-direct injection), 12 attack mechanics, and 14 of 25 OWASP LLM/agentic categories.

Numbers:

  • Kernel evidence works alone (Fig. 2). Held-out-family AUROC was 0.750 for XGBoost, 0.725–0.775 for the LLM judges, and above 0.88 for every LoRA SLM. The best overall was 0.922 (Llama-3.1-8B LoRA, kernel only).

  • App-layer blind spots (Table 2, mean over 10 detectors):
Mechanic App-View AUROC Kernel-View AUROC
Silent exfiltration via logging 0.586 0.976
Audit-log poisoning 0.608 0.932
Retrieval reference injection 0.906 0.703

Retrieval reference injection is the reverse case: the app layer catches it and the kernel does not. Preference manipulation clears 0.75 only with Cross-View (0.834).

  • Default rules fail on agents (App. L).
  • Falco's default rules fire on every session, benign or malicious. Their rule-count AUROC is 0.565–0.572.
  • The Cisco MCP scanner catches 15.9% of tampered-MCP attacks at a 16.3% false-positive rate.
  • Runtime transfer (App. M). On 592 sessions captured with a different agent (Devstral 2 123B in a ReAct scaffold), XGBoost reached 0.842 and a Qwen3-80B judge 0.998. TabPFN fell to 0.662 because a single /tmp-path count differs between the two runtimes.

  • There is one primary runtime (Claude Code with Haiku 4.5) plus one alternate.
  • The network is sinkholed, so connect/send shapes differ from a real deployment.
  • tools/list is captured once per session.
  • Attribution is per session, not per tool call.
  • By construction, the design cannot see tool-return content manipulation, timing channels or whitespace steganography.
  • The corpus is released only on acceptance.

Why it ranks: it is the first paired measurement of how much signal the application layer carries compared with the kernel. It quantifies exactly the evidence class BQAA is built on. TL;DR for BQAA:

  • Document which mechanics app-layer telemetry cannot detect (silent exfiltration via logging, audit-log poisoning).
  • Emit a session join key (container ID, PID namespace or cgroup) so EDR and eBPF evidence can be joined per session.
  • Baseline agent sessions separately. Server-calibrated rules fire on every agent session.

3. NEW rank: arXiv 2609.28586: Agent Approval Laundering: Transitive Effects Beyond the Approved Invocation

Zhang, Xia, Wu, Yue, Zhang, Cheng, Tu (the same CAS IIE group as #1). Submitted 23 Sep 2026.

Full PDF read (19 pp): §I–IX, App. A–B (Tables IV–X).

The idea: an approval record faithfully names the command the human approved, but not what that command's workflow then does. For example, pnpm install runs a postinstall hook that writes files, and a named MCP documentation tool also reaches the network.

What they did:

  • They define "closure-bound approval": the approval's recorded effects must cover every effect the launched workflow can reach. They track six effect classes: process, file, environment, network, container and MCP.
  • Lemma 1: if two runs look identical to the policy but need different decisions, no record-only policy, deterministic or randomized, can get both right.
  • They measure the gap at three levels of information: the explicit approval fields, fields plus generic command semantics, and fields plus metadata that was available at decision time.

Numbers:

  • Controlled benchmark (Table IV). Across 111 approval/trace pairs, records that omitted an effect the run exercised fell from 40 (explicit fields) to 17 (command semantics) to 13 (metadata). All nine mechanism classes show at least one explicit-field gap.
  • Real repositories (Table II). Across 11 executions on 8 pinned repos (webpack, vite, pip, flask, ripgrep, vscode devcontainer, awesome-compose, MCP servers), gaps fell from 10 → 2 → 0. The two gaps left under command semantics are MCP remote calls that also used the network (M → M,N).
  • Across products. The same gaps recur in Claude Code, GitHub Copilot CLI and Qwen Code.
  • Predicting effects before approval (§VI, Table III). A frozen metadata parser, tested on 17 holdout workflows, reached macro recall 0.926, precision 0.941, and exact effect sets in 13/17 cases. The command-only baseline scored 0.770, 0.941 and 9/17.
  • Effect-bound records raised coverage from 0.755 to 0.922 and cut missed effect instances from 10 to 3.
  • The cost is prompt volume: the policy asked for extra approval in 17/18 cases, and 9 of those runs had no added effect.
  • A Claude Code PreToolUse hook ran the check with a p95 of 98 ms.

Caveats I'd flag:

  • The samples are small (17 holdout cases).
  • The six effect classes are coarse, and the environment class was not measured in the holdout.
  • It is a paper-only release, and its authors are the same team as #1.
  • Frequent extra approval prompts carry an approval-fatigue cost.

Why it ranks: it defines a measurable coverage gap ("the effects the run exercised minus the effects the approval recorded") for the approval events that harnesses and ADK tool confirmation already log. It extends the catalog's arxiv-2609-26529-from-approval-to-execution-reconstruction-aware card: that paper shows the approved action can be rebuilt before it runs, and this one shows the action's side effects fall outside the record.

TL;DR for BQAA:

  • Log each approval with the effect classes it predicts.
  • Join it to the effects the run actually produced (file delta, network, child processes, containers).
  • Report the uncovered effects per approval as a first-class metric.

4. NEW rank: arXiv 2609.30243: JevOut: Natural Context Can Flip Decision Models (with 2609.28613 Decision Hijacking as its companion)

JevOut: Zixiang Xu (USC), submitted 24 Sep 2026, code released. Decision Hijacking: Wu, Lim (NTU Singapore), submitted 23 Sep 2026.

Full PDFs read: JevOut (32 pp: §1–5, App. A, D, L–O; data tables H–K skimmed) and Decision Hijacking (18 pp: §1–7 and limitations).

JevOut: what they did:

  • The main target is hosted jev-1.13.0, plus OpenSourceJev, Von and a plain Qwen scorer.
  • Tasks: 700 held-out items from seven datasets (MMLU-Pro, SuperGPQA, MuSR, ToMBench, LAR-ECHR, SATA-Bench, BFCL V4 tool routing).
  • For each item the model initially answered correctly, they fixed a wrong target option. They then added short, fluent sentences that keep the question, the options and the correct answer unchanged, and let the model's own option probabilities guide the search (at most 64 target queries per item).

JevOut numbers:

  • Targeted flips (Table 1). Jev chose the fixed wrong option on 312 of 508 initially correct decisions (61.4%, 95% CI 57.1–65.5%). It put at least 0.7 probability on the wrong option in 229 of them (45.1%), and at least 0.9 in 91.
  • One target-aware sentence alone flipped 16.9%; one neutral sentence flipped 2.2%.
  • The other systems flipped at 64.9–73.2%.
  • By task (Fig. 2). From 40.0% on legal reasoning to 85.7% on tool routing (BFCL V4).
  • Small additions (Fig. 3). The median successful context adds 31 words, and 51.9% of successes use one sentence.
  • Probabilities are the attacker's signal (§4.3). Allocating the search by probability beat label-only feedback by +7.1 points (63.6% vs 56.4%, paired CI 2.1–12.9).
  • Transfer (Fig. 5). Contexts frozen after optimization redirected other systems 21–48% of the time; Jev → Von was 25.4%.

Decision Hijacking, the contrast:

  • They rebuilt 510 InjecAgent cases as typed Jev decisions and made 54,060 calls.
  • The original injection text selected the attacker's tool in 1.8% of cases. Adding "ignore all previous instructions" lowered the attacker's probability (−0.032).
  • Twenty-four score-guided queries raised validated success to only 3.5%.
  • Success tracked the initial margin (Fig. 3). Near-boundary embedded cases (margin ≤ 0.1) were hijacked 12 of 12 times; far-boundary embedded cases 1 of 468.

Caveats I'd flag:

  • JevOut's optimizer needs repeated probability-returning queries.
  • Answer preservation is checked by a Gemma4-12B judge, not by humans.
  • Both papers use benchmark tasks, not deployment streams, and test one Jev version.
  • Decision Hijacking uses a three-option action space.

Why it ranks: Industry just made these probabilities first-class (the PydanticAI decide spans and DSPy's Choice.probabilities), and this fleet runs Jev as its shadow routing layer. The two papers together say the risk variable is the decision margin, and that exposed probabilities are an optimization oracle. They qualify the catalog's arxiv-2609-29769-jev-vs-llm-rubric-judges-correlated-errors and arxiv-2609-26758-type-safe-is-not-error-free-option-name-flip cards.

TL;DR for BQAA:

  • On decision events, store the top-1 minus top-2 margin and the provenance of each context segment (trusted vs tool- or retrieval-derived).
  • Alert on low-margin picks, and on picks that flip when context grows.
  • Restrict who can read per-option probabilities.

5. NEW rank: arXiv 2609.28919: Control the Harness, Control the Cost: Routing and Governing AI Coding Agents in the Enterprise

Abbasi, Aqrawi, Kwartler (Accenture; Harvard Extension). Submitted 24 Sep 2026.

Full PDF read (32 pp): §1–9 including the limitations. I skimmed App. A–D (taxonomy, cost model, the table of 20 harnesses).

What they did:

  • Derived a cost model for agentic turns under prompt caching that belongs to one model.
  • Repriced about 10,000 real Claude Code sessions from two public corpora (TraceLab, SWE-chat).
  • Built a router in which Jev labels every prompt against a four-axis taxonomy supplied by the enterprise. It moves work only where no running conversation has to rebuild its cache: at session start, in side lanes, and at subagent launch.
  • Emulated a 10,000-seat enterprise.

Numbers:

  • Payback rule (Eq. 1). A mid-task model switch pays back only after the cheaper model has served enough requests to repay the cache rebuild. From Fable 5.1 to Sonnet 5 that is 291 requests with a return and 46 without; from Opus 5 to Sonnet 5, 27 and 8.
  • Crossover (Table 2, Fig. 3; the paper's list prices of 21 Sep 2026).
  • The top model reads cache at half the next tier's price ($0.25/M vs $0.50/M), so per warm turn it becomes cheaper above 65k context at 18 tool steps (211k at 6 steps).
  • Of the real sessions costing $100 or more, 51% (TraceLab) and 80% (SWE-chat) are cheaper on the top model.
  • The top 1% of sessions carry 31–53% of all spend.
  • Savings (Table 3, Fig. 7). The router recovers 13.8% of spend with today's labels and 21.1% with perfect labels ($3.3M–$5.0M a year on $23.7M). Three quarters of that comes from the crossover.
  • Classifier (§5.3). Jev got the action right 74% of the time, the domain 80%, the complexity 63% and history-dependence 82%. Of the turns moved, 12.5% were moved to too weak a model, and 42% of the turns that could have moved were held.
  • Corrections and pauses (§5.3–5.4, Table 4).
  • Corrections are more than a third of the bill ($1.26M without them vs $1.97M).
  • 17–27% of user turns follow a pause longer than 5 minutes, which expires the cache. The saving ranges from 24% with no such pauses to 7.4% with TraceLab-like pausing. A one-hour cache lifts it to 17.1%.
  • Standing prompt overhead (Table 5). A measured 55k-token power-user setup (skills, tool schemas, plugins) costs 3–4× the lean default per session.
  • Governance (§3.5). There is deliberately no productivity axis, and only aggregates are reported. The authors cite EU AI Act employee-monitoring rules and German works-council co-determination.

Caveats I'd flag:

  • The scenarios are synthetic: 46 conversations and 109 turns, written and tagged by the authors.
  • The taxonomy has no inter-rater agreement yet.
  • The crossover share rests on 102 + 30 sessions.
  • Prices are list prices from one vendor on one date; under uniform 0.1× cache pricing the saving falls to 5.2%.
  • The simulator is not released, and the enforcement point was not built.

Why it ranks: it gives agent cost analytics a correct unit (the turn, priced with cache reads and writes) and names the drivers most dashboards miss: cold returns after the cache expires, correction chains, and the always-loaded prompt prefix. Its aggregate-only rule is directly relevant to how BQAA should report cost per user.

TL;DR for BQAA:

  • Break every request into uncached input, cache read and cache write, and price the turn.
  • Tag cold returns (a gap longer than the cache TTL) and correction turns.
  • Report cost per verified task by team or harness configuration, never per person.
