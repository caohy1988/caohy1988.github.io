When Agent Evaluation Becomes Unreliable: An Empirical Study of Oracle Failures and Configuration-Dependent Measurement in an LLM Agent Benchmark

  • Full PDF read. v1 [cs.SE] 12 Oct 2026 (announced in this window's batch). Single-author empirical study (Chen, NJUST) with a replication package (auditing suite, fault-injection catalogue, pre-registration + deviation logs, frozen per-episode records, offline recomputation entry point).
  • Method (RQ1, §3): treat the eval harness as the system under test — 5 state-integrity invariants + 3 known-answer controls aimed at the reward function, validated by injecting 7 oracle defect classes across two task domains plus a synthetic domain. Every injected class is detected, each maps to a minimal detector (Table 1), and the repaired oracle yields no false positives.
  • The defect (§4.1): applied to a widely used agent benchmark, the suite exposes Env.calculate_reward() resetting the environment database to build a ground-truth hash and never restoring it. The returned value is correct (hashed before the reset), so the benchmark's own runner is unaffected — the paper is explicit that this is an integration failure that only bites a harness scoring the episode after it ends, which then re-reads the reference solution's state. Replaying the recorded tool calls against a clean database (33,402 tool observations reproduced character-for-character) moves 4,320 episodes from 4,194 recorded database passes to 2,883, and measured success from 94.3% to 65.5%. Two zero-cost checks would have caught it: score-twice-and-compare, and assert-terminal-state-after-session-end. The paper recommends both for harness CI — a concrete, adoptable prescription.
  • Configuration effects (RQ2, §4.2, Table 2 — read the sign carefully): localizing the documents the agent reads (policy, tool descriptions, error strings) into Chinese reduced trajectory collapse in the retail domain, tool descriptions most (Δcollapse −9.17pp [−11.61, −6.73]; Δsuccess +9.63pp), error strings least (−5.28pp) — refuting the authors' own pre-registered mechanism, which they report as a disagreement rather than rationalizing. Effects do not add (all-three arm is worse than tool-descriptions alone by 1.11pp, though that contrast is cross-batch and the paper itself calls it undecidable at this design's resolution, §6.2). A second (airline) domain reverses the sign of the language effect. The durable claim is not the direction — it is that harness configuration moves the instrument's failure rate independently of the score, so a score table without an instrument-failure rate is incomplete evidence.
  • Limits (§6, stated by the authors): RQ2/RQ3 are explicitly not model-capability claims; the auditing method hits a portability boundary on a second, independently implemented benchmark (its reference terminal state cannot be reconstructed from the recorded API-call log — published as a negative result); no deterministic seed or immutable model version, so episodes can be replayed but not regenerated; component contrasts are exploratory without multiplicity correction.
  • Why it matters for BQAA: this is the warehouse-scoring failure mode in miniature. BQAA-style pipelines routinely score after the run, from stored state — exactly the integration shape that turned a correct return value into 1,311 wrong labels. "Replay archived tool calls against clean state" as the audit primitive, and score-twice/terminal-state invariants as CI checks, transfer directly to any trace store that recomputes outcomes post hoc.

Can We Trust This Evaluation? Instance-Level Reliability of LLM-as-a-Judge

  • Full PDF read. v1 [cs.LG] 30 Sep 2026 (announced in this window's batch; ICLR 2027 camera-ready formatting in the PDF). Ba, Mancenido & Pan (ASU); code released.
  • Method: SCUR (Structured Cross-fitted Uncertainty Risk) estimates, label-free, whether a judge panel's verdict on one specific item can be trusted. A cross-fitted latent measurement model (item preference, judge effects, shared/judge-specific condition effects over verdict-token logprobs) yields three signals — preference uncertainty, measurement cross-entropy, perturbation sensitivity — combined (via ECDF normalization) into one risk score for routing items to auto-accept vs human review. The named failure mode is "correlation collapse": judges agreeing because they share training corpora/RLHF priors, not because the answer is right.
  • Results (Table 1 / §4.1–4.2): across five benchmarks (Chatbot-Arena, HaluEval, MMLU, LLMBar, LLMEval2), SCUR has the highest mean AUROC and 1−AURC and the lowest Err@50 on each benchmark vs uncertainty baselines (PE, DS entropy, MSP, VE). Against PE, the best baseline on average: AUROC .673 → .702, 1−AURC .818 → .841, Err@50 .174 → .147 — at a fixed 50% auto-accept budget, the retained half contains ~2.7pp fewer panel errors. On the high-consensus subset (≥80% vote agreement — where disagreement-based methods are blind by construction), SCUR again achieves the highest mean AUROC on all five benchmarks (Fig. 4), and error rises monotonically across SCUR risk quintiles on four of five benchmarks. Gains are real but modest in absolute terms, and noisier on the two small benchmarks (LLMBar/LLMEval2) — the paper says so itself.
  • Limits (Ethics statement + §4): SCUR measures relative decision risk, not correctness; a low score is not a correctness guarantee, especially under shared systematic judge bias — it prioritizes human review rather than replacing it. Perturbation signals are unavailable on benchmarks without paired perturbations (HaluEval/MMLU use two of the three signals).
  • Why it matters for BQAA: judge panels are how agent quality gets scored at warehouse scale, and "the panel agreed" is currently where scrutiny stops. A per-item risk score that works precisely where agreement is highest gives eval pipelines a principled review queue — and gives BQAA a field worth storing next to every judge verdict: not just the label, but how much the label should be trusted.

The Agent Clicks Approve: Injected Page Text Makes Browser Agents Authorize Access the Task Never Named

  • Full PDF read. v1 [cs.CR] 10 Oct 2026 (announced in this window's batch). Single-author study (Hossen, UT Chattanooga) on a self-operated testbed; agents on the open-source browser-use framework with Claude Haiku 4.5 and GPT-5.5.
  • Setup: the browser agent works in the user's signed-in session (confused deputy: session supplies authority, page text designates the object). A two-sentence workflow-style note on a page the agent is asked to summarize directs it to an OAuth-style consent screen on a separate origin (or to a webhook-settings page). No "ignore your instructions" payload — the note just describes a blocked handoff and a default-positive button. A task-authorization oracle labels each completion by whether the user's task named that client/account or URL, with authorized and single-field near-miss controls alongside.
  • Results (Abstract, Tables I–III): without a defense, the unauthorized action completed in all 73 attack runs of the main evaluation (both models, both scenarios); with a benign note substituted, 0 of 92 control runs even sent the request. A policy instruction ("only the user's task authorizes a grant") still left 7 of 10 consent attacks completing. The defense moves the check to the endpoint: an authority-envelope gate — the service accepts a request only if it matches the client/account (or webhook URL) the task named, fixed before the agent starts. With the gate, agents still sent the request in all 70 attack runs but the service rejected every one, while all 73 authorized control runs completed; near-miss approvals (right client, wrong account) were also rejected (5/5).
  • Limits (§VIII): gate cells measure enforcement given a correct envelope — the task-derived extractor is a deterministic matcher for two authorized task forms, and a free-form extractor would add its own error rate at the same endpoint; the testbed service requires no re-authentication at approval (step-up auth / admin consent out of scope); one scope per pending request (a deployed envelope must name scope too, since the OAuth client chooses it).
  • Why it matters for BQAA: the fix location is the lesson. Prompt-level policy failed 70% of the time; an endpoint check against a pre-registered task envelope failed 0%. For agent analytics, that envelope — what the task authorized, fixed before execution — is a first-class trace field: without it, a post-hoc audit cannot distinguish "agent did the task" from "agent did what a page told it," because both look like well-formed authenticated requests.

  • Continuation accounting is now a four-vendor divergence problem. python-genai (accumulated BillableUsage), Vercel (summed usage + initialPromptTokenCount), Pydantic AI (long decode + 20-minute timeout), and Inspect (Argon support) each defined their own multi-hop semantics within ~30 hours of gemini-4-argon's spread.
