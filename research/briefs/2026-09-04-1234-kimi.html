Academy

3. SWE-Gate: Passing Functional Tests Is Not Enough for Software Engineering Agents (cs.SE cross-list, new today). abs/2609.04167 (PDF available, submitted Sep 3, 2026, 463 KB; not in catalog). The benchmark derives "review constraints" from real pull-request review comments and builds 303 repository-level repair instances across 75 Python repos, each with separate functional tests and constraint tests plus non-compliant and gold patches. The headline finding: across four LLM backends under a common scaffold, of 644 repairs that pass functional tests, 221 fail the review constraints — functional-only evaluation overestimates real acceptability by roughly a third on this corpus. Constraints and correctness are scored separately, so the failure mode is measurable rather than anecdotal. This is directly analogous to the gap between "task success" and "acceptable output" in production agent analytics. TL;DR for BQAA: pass/fail metrics systematically overstate quality; evaluation pipelines should carry a separate compliance/acceptance axis, and analytics surfaces should report the gap, not just the pass rate.

4. Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments (cs.AI, new today). abs/2609.04148 (PDF available, submitted Sep 3, 2026, 484 KB; not in catalog). The core observation: the tool-execution history inside recorded trajectories exposes enough of the original environment to reconstruct it — replay file operations to restore pre-edit state, then a completion agent fills missing files and dependencies. Applied to public terminal-agent trajectories this yields 37.3k task-sufficient environments, with task synthesis along breadth (cross-workspace queries via dependency mining) and depth (multi-round sessions with a user agent) axes. SFT of Qwen3.5-27B on the corpus gains +11.9 on Terminal-Bench 2.1 single-round and +13.8 on EvoCode-Bench v2 MT@4. It reframes trajectory stores from passive logs into regenerable training/eval assets. TL;DR for BQAA: trace/trajectory archives have direct reuse value as environment generators — a retention and indexing decision made today determines whether tomorrow's eval environments are free or unrecoverable.

5. DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics for Long-Horizon Agent Training (cs.AI, new today). abs/2609.04094 (PDF available, submitted Sep 3, 2026, 1.8 MB; not in catalog). Targets the outcome-blind setting where no programmatic checker exists: rubrics are generated dynamically during training to track the policy's current capability, scored once per completed trajectory, then that trajectory-level judgment is redistributed in closed form over the steps the rubric items annotate, producing per-step advantages in GRPO without a trained attribution module. On AppWorld it beats the base model by 15.9 points and GRPO-with-sparse-ground-truth by 5.3 despite using no verifiers; on out-of-domain Tau-Bench it gains 5.3 over base without a frontier judge. The rubric-to-step attribution is the analytically interesting piece: it is a structured mapping from evaluation text to trajectory steps. TL;DR for BQAA: rubric annotations mapped to specific steps are emerging as the unit of agent credit assignment — score schemas that carry step-level attribution will interoperate with this training lineage.
