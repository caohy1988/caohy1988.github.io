Epistemic Guard: out-of-process MCP receipt proxying, post-turn prose supervision, and provenance-gated memory — arXiv:2611.27095

Full PDF read (every part, including methods, results and limitations).

The paper names three runtime verification gaps for MCP tool-using agents: post-tool prose that narrates side effects which failed, timed out or never ran; unverified model prose or web text entering durable memory beside executed tool outputs; and mirrored web pages counted as independent corroboration. epistemic-guard v0.5.2 answers with an out-of-process stdio MCP receipt proxy that keeps Ed25519 signing keys out of the agent and child-server environments, a CPU INT8 post-turn supervisor that matches state-mutating prose claims to verified receipts and concrete targets, a provenance-gated SQLite store that refuses narration/untrusted-content writes at the database boundary, and shingle/SimHash collapsing of wire-syndicated mirrors before source counting (§§2–3, Table 1).

Measured results: deterministic conformance rejects 200/200 mutated Merkle receipts, passes 58/58 AER-1 ingestion vectors and 50/50 reference-verified exports, verifies 40/40 fault-injected wire calls across its four execution states with 0 child-environment key leaks, and blocks 100/100 unauthorized memory writes (§4.1, Table 2). On N=250 frozen traces the supervisor reaches 93.2% accuracy at 17.9 ms warm median CPU latency with 0 GPU VRAM, ahead of two 12B–14B GPU judges by 6.4 and 6.8 points (p=0.0259, p=0.0095); on N=60 live proxy traces it catches 96.15% of hazards at 76.67% accuracy but a 38.24% false-positive rate, +18.34 points over its no-receipt ablation (p=0.001) (§4.2, Table 3).

Limits that bound adoption (§5): English replies on one workstation; supervision labels come from author rubrics and blinded LLM raters, not a multi-human agreement study; the proxy mediates stdio MCP only, so remote HTTP/SSE servers need a bridge; a malicious or buggy server returning ok=true still yields a validly signed false receipt; and mirror collapsing holds for verbatim/lightly edited copy (100%) but falls to 0% on moderate or heavy rewrites (§4.1). For BQAA/ADK the transferable contract is the separation itself: executed=false (rejected before execution) must never ground completion prose, memory admission needs a provenance domain a narration cannot sign for, and any receipt export to traces should carry the target binding, not only a success bit — with the live-trace false-positive rate budgeted as retry cost, not ignored.

ProbeAgent: principled diagnosis of agent failures in verifiable environments — arXiv:2611.26897

Full PDF read (every part, including methods, results, appendices and limitations/audits).

ProbeAgent connects three stages: build and validate executable probes from benchmark tasks (reference must pass, inaction must fail, checker source read, and an independent read-only review); explain each failed trajectory as an erroneous/omitted action, its task stage, its trigger and a corrective action; then construct sibling tasks that preserve the trigger while changing domain, data, tools, naming or format, and rerun the same agent to test whether the error recurs. Failures are then grouped by cause under a density constraint and given descriptions that must cover the group and exclude its nearest non-members (§3, Definitions 1–5).

Across 22 agent configurations, 10 benchmarks and 347 generated environments it collects 1,244 explained failures and 536 failure-mode descriptions (§4.2, Table 2). Human annotators (2 annotators, 30 failures, 60 pairs each) accept 90.0% of assigned descriptions and correctly reject 83.3% of similar alternatives (§4.3, Appendix C.5). Probe validation is the load-bearing result for eval builders: over 1,451 build rounds execution controls reject 349 candidates and semantic review rejects a further 638 that passed execution, most commonly a rewarded shortcut that bypasses the intended work (565 rounds) (§4.4, Table 3; Appendix E, Table 7). Sibling testing then disciplines the explanations: of 119 tested explanations, 40.3% recur in no sibling (task-specific), 16.8% meet the agent-behavior criterion and 21.8% recur weakly (§4.5, Figure 6). Removing the group density constraint collapses 505 groups to 23 and drops held-out agreement from 91.8% to 78.0% (§4.6, Figure 8).

Caveats (§§4–5, Appendices C–E): 63.9% of induced groups are singletons (Table 6); held-out agreement uses a model-based pairwise reference, with the small human study as the independent check; matched replay uses only 18 trials per configuration with wide intervals (Figure 7, Appendix D); and a manual audit of 20 environments finds 30% with a wrong expected value or a format ambiguity (Table 8), so probe corpora still need audit sampling. For BQAA the reusable discipline is: a failure cluster is not a product defect until its trigger survives context change, and a generated eval task is not admitted by execution alone — it needs checker/instruction consistency review plus a null control.

Know Your Context Bank: repairing inconsistency and measuring generalization in context-aware text-to-SQL — arXiv:2611.26775

Full PDF read (every part, including methods, results, appendices and limitations).

The paper studies context banks — curated example queries, metric definitions and domain knowledge that tell a text-to-SQL model how an organization writes queries — and names "context bank rot": entries that each pass per-entry review yet resolve the same underspecified decision (distinct count vs. row count, tie handling, which table defines a concept) in opposite ways. It decomposes each query into licensed semantic units, scores every same-database pair with an align–conflict–novel profile from a scorer distilled from human-calibrated dual judges, aggregates a Bank Health Index, and repairs banks with a two-track protocol (per-entry audit plus rulebook adjudication of conflicting pairs) (§§2–4). The same pairwise distance generates CAT test questions at controlled distance from a bank (§6).

Measured results: public banks score BHI 86.8 (BIRD-train, 5.3% of overlapping pairs conflicting), 88.6 (BIRD-dev), 87.4 (a Spider-train subset) and 66.1 (LiveSQLBench, 18.7% conflicts) (Table 1). The scorer reaches alignment MAE 0.020, Spearman 0.970 and conflict AUC 0.982 on held-out BIRD-dev pairs, lower on real pairs alone (0.855 / 0.872) (§3.2, Table 5). Cleaning removes 1,332 of 6,980 BIRD-train entries; 92.4% of removals overlapping an independent expert audit had their SQL corrected there, against 45.6% of audited entries overall (§4.2). Fine-tuning on the cleaned bank beats a same-size random subset at every epoch by 2.6 points on average (Table 2), and with every entry defensible, in-context examples following the gold convention beat the opposite convention by 13.3 points (p=0.0004) while a mixed bank is barely better than none (§5.2, Table 3). On CAT-BIRD, retrieval gains decay from +22.2 points on rephrases to +3.0 once about three quarters of the logic is new, fine-tuning decays similarly, and training hard enough to reproduce the bank can cost accuracy on uncovered databases (§6.2, Table 4).

Limits (§7, Appendix H): the scorer is trained mostly on SQLite and thresholds may need per-dialect calibration; cleaning and CAT gold labels rely on LLM referees (mitigated by execution checks, abstention and the expert-audit agreement); the training experiment measures cleaning as a whole, not consistency alone; CAT's flat no-context baseline is imposed by selection, its far-distance group is small (n=100), its probes were generated by two of the evaluated retrieval models, and each configuration uses one seed. For BQAA data agents this is the most directly transferable Academy item this slot: example/semantic banks need a pairwise health metric, an explicit convention rulebook with a per-entry removal ledger, and distance-stratified evals — a single aggregate text-to-SQL accuracy cannot distinguish memorizing the bank from generalizing its conventions.

Six-week EV

  • Receipt-bound trace shadow (high EV, 2–4 weeks). For two MCP/ADK tool paths, record execution state (executed, ok, error class), argument digest and concrete targets outside the model prose, then replay traces to count completion claims with no matching successful receipt, rejected-before-execution calls narrated as done, and memory writes whose provenance is narration or untrusted tool text. Report false-block/retry cost separately; the Academy live-trace false-positive rate (38.24%) is the planning prior until BQAA traffic says otherwise.
  • Sibling-test gate for failure clusters (high EV, 2–5 weeks). Before promoting any recurring-failure label from trace mining into a fix or eval, generate at least three validated siblings that keep the suspected trigger and change the surrounding task, with reference-pass + null-fail + checker/instruction review admission. Promote only labels that recur in at least two of three siblings; file the rest as task-specific, mirroring the 40.3% non-recurrence observed.
  • Context-bank health for data agents (high EV, 3–6 weeks). Inventory one production example/metric bank, decompose entries into decision units, compute pairwise conflict/duplicate rates on overlapping pairs, and adjudicate conflicts against an explicit, editable convention rulebook with a per-entry ledger. Add distance-stratified text-to-SQL evals (rephrase → ~25% → ~50% → ~75% new logic → uncovered database) so bank changes report a decay curve, not one blended accuracy.

TL;DRs for BQAA

  • Epistemic Guard: a tool span that says "done" is not evidence — require a signed, target-bound receipt with executed separated from ok, and refuse durable writes that only narration can sign for.
  • ProbeAgent: failure explanations are hypotheses; sibling tasks that keep the trigger and change everything else are the experiment, and most single-trace explanations should be expected not to recur.
  • Context Bank: per-entry correctness cannot see opposite conventions; measure bank health pairwise, record the chosen convention, and expect bank value to fade to ~zero at ~75% new question logic.
