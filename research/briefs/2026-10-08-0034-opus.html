NEW — Loud Failures, Quiet Failures: Fault Detection and Recovery in Tool-Using Language Model Agents — https://arxiv.org/abs/2610.10062

Kraishan (Texas Tech), cs.AI, submitted Oct 7. Accepted at IEEE CogMI 2026. Full PDF read (8 pp.).

  • Setup (§III):
    • 24 tasks from the BFCL multi-turn split, run as stateful local Python environments.
    • A wrapper injects one fault per trial at about the midpoint of the trajectory:
      • timeout, missing tool and schema drift return an error ("loud");
      • silent corruption returns a value of the right type and shape with wrong content ("quiet").
    • Six models in three matched reasoning/instruct pairs: Claude Haiku 4.5 ± thinking, DeepSeek R1/V3, Qwen3 thinking/instruct.
    • 1,920 trials; 1,694 analysed (faults that never fired are excluded; Table II).
    • Recovery is scored against the same model's independent clean run.
  • Detection follows the error channel, not the content (Table IV):
    • loud 91.3% [88.3, 94.1], n=936; quiet 58.8% [45.7, 71.2], n=374;
    • no-fault baseline 26.8% [17.8, 36.5].
    • Timeout and corruption fire at the same median step, yet detection differs by 91.6% vs 58.8%.
    • Under corruption, 39% of trials show no reaction at all: the agent carries the wrong value forward (Fig. 1).
  • Reasoning variants notice less and act more (Table V):
    • Pooled over 450 pairs: detection −9.3 points (p<.001), replanning +10.4 (p<.001), recovery −2.4 (p=.512).
    • The detection drop is clearest for Qwen (−16.6) and holds for Claude only on matched pairs.
  • Cost of one fault (Table VI):
    • Two clean runs of the same task agree on end state only 63.3% of the time.
    • Against that baseline, only a missing tool clearly lowers recovery (39.9%).
    • After a fault, agents call the same tool three or more times in a row in 12.5–22.2% of trials. Exactly identical repeats are rare (0.8–1.8%).
    • The 15-call cap ends 24.8–31.7% of fault trials.
  • Prompting does not fix it (§IV-D): adding "after every tool call, briefly check whether the result is what you expected" moved detection +0.6 and +2.5 points (n.s.).
  • Limitations (§VI):
    • one simulated benchmark family and four chosen fault types;
    • detection is coded by an LLM judge from what the agent wrote, validated on 92 trials against one author (κ=.69);
    • three model pairs, with DeepSeek-R1 sometimes writing tool calls as text;
    • the prompt arm covers one family only.
  • Why it matters for BQAA: a dashboard built on the tool-error rate is blind exactly where agents are blind. The paper's first recommendation is to validate tool outputs at the point they enter context. The signal you need is the tool result next to what the task implies. Its second point: any fault-effect claim needs a repeated clean baseline (63% agreement), not a single reference run.

NEW — Correct Answers, Unsupported Findings: Evidence Binding in Forensic Reconstruction of LLM Agent Logs — https://arxiv.org/abs/2610.09581

Yun, Kim, Kim, Seo, Hur, Min (Sungkyunkwan University), cs.CR, submitted Oct 7. Full PDF read (11 pp.).

  • Setup:
    • Corpus: 694 saved AgentDojo Banking (v1.2.2) executions by GPT-5.4-mini, Haiku 4.5 and Gemini 3.8 Flash. Each action carries a generated paragraph, a Note and a "Basis" array of local input IDs. A fixed rule selects 64 mechanically checkable cases (13 tasks).
    • Three questions:
      • Q1: is the value in the authentic user request?
      • Q2: which earlier records contain it?
      • Q3: which of those records does the saved Basis cite, through a recorded ID→record binding?
    • Readers: gpt-5.6-luna and claude-sonnet-4-6, plus a deterministic packet-only comparator.
    • Scoring: reference agreement (W), grounded correctness (G, where justified abstention counts as correct) and unsupported assertions (U) are reported separately.
  • The binding is the evidence (Table 5, mapping-required stratum, n=28):
    • Without the ID→record table: Sonnet abstains in 2 cases and makes 26 unsupported assertions, 22 of which match the complete reference. Luna makes 21, 12 matching.
    • With the table: supported definite answers rise to 24/28 (Sonnet) and 21/28 (Luna).
  • Over all 64 cases (Table 6):
    • Q3 grounded correctness goes 26 → 49 (Sonnet) and 38 → 49 (Luna) once the table is supplied.
    • Reference agreement barely moves (46 → 49; 43 → 49). Most of the change is previously correct guesses becoming supported.
    • Task-equal gains: +31.5 pp (Sonnet), +14.4 pp (Luna) (Table 7).
  • Other findings:
    • Renaming IDs to opaque labels alone gives no consistent remedy.
    • Sonnet retrieves every Q2 literal location correctly, so the failure is the citation-to-record relation, not retrieval.
    • Both readers share reference-matching but unsupported answers in 11 cases. Agreement between readers is not support.
    • The deterministic comparator is grounded-correct on all 64 cases in every condition (Table 3).
    • With complete tables, readers still give 12–16 non-grounded Q3 answers. Preserving the binding and reading it correctly are separate problems.
  • Limitations (paper):
    • one simulated environment, 64 cases from 13 tasks;
    • Sonnet was added after Luna's results were seen;
    • one response per condition;
    • no investigator study;
    • Sonnet shares a model family with the Haiku actor in 17 cases.
  • Why it matters for BQAA: this is a direct argument for storing execution-scoped ID bindings (citation ID → span or record locator) next to the content. A "which input did the agent act on" query is then a join, not a model's inference. It also argues for scoring LLM-generated trace explanations on support, with abstention allowed, not on agreement.

NEW — Know the Shape, Find the Fault: Topology-Conditioned Diagnosis of Multi-Agent LLM Failures (MAScope) — https://arxiv.org/abs/2610.10126

Liu, Pan, Zhu, Zhang, Liu, Wo (Beihang University), cs.MA, submitted Oct 7. Full PDF read (10 pp.).

  • Claim (§3.3): a system's communication topology predicts its failure mix. MAST failure codes against four topologies (Layered, Centralized, Decentralized, Shared Message Pool) on 851 MAST-clean traces give χ²=409.9, p=1.2×10⁻⁷⁰ (Fig. 2).
    • Layered pipelines lose information between stages.
    • Centralized hubs drift on verification.
    • Shared-pool systems show semantic drift.
  • Method (§4):
    • TSE compacts a heterogeneous trace to ~4k tokens of evidence spans and extracts at most 24 typed relations (control/use/feedback/pool_read/independent), each citing a span. It validates them with rules (at most one repair call) and assigns a topology label. Adapters cover LangGraph, AutoGen, CrewAI, ChatDev, MetaGPT and Magentic.
    • TC-Judge adds the label, a frozen per-topology prior over the 14 failure codes (estimated on a disjoint 400-trace slice) and a short failure signature to a zero-shot judge prompt.
  • Results:
    • Topology recovery (Table 4): 93.8% on MAST-clean. In the framework-controlled LangGraph corpus it is 76.5%, with Shared Message Pool hardest at 56.9%.
    • Diagnosis (Table 2): gpt-mini 0.173 → 0.350 Macro-F1 with true topology and 0.346 with predicted topology (§5.6). gpt-5.4 rises 0.372 → 0.399.
    • Cost (Fig. 6): $0.52 vs $8.73 for gpt-5.4 on trace alone over 851 traces (~6%). The gpt-mini cost is estimated from normalized token counts.
    • Transfer: supervised baselines collapse when a framework is held out (Flat-GBM 0.490 → 0.226; Fig. 5). On the injected-fault corpus, gains are smaller: gpt-mini 0.304 → 0.321, gpt-5.4 0.320 → 0.356.
  • Caveats:
    • absolute Macro-F1 stays ≤0.40;
    • in MAST-clean each framework maps to exactly one topology, so topology and framework are confounded there (LG-Ctrl is the control);
    • the paper has no separate limitations section.
  • Why it matters for BQAA: topology is a per-deployment constant you can extract once and attach to every trace as a dimension. A diagnosis view can then condition on it, at small-model cost. "Each relation cites an evidence span" is the same discipline as 2610.09581.

NEW — Not Every Call Needs a Frontier Model: Per-Call-Site Evaluation of Small Language Models in a Deployed Agentic Home-Automation System — https://arxiv.org/abs/2610.09021

Kasnesis, Chatzigeorgiou, Toumanidis, Contiero Syropoulou (Univ. of West Attica / Waldiez), cs.AI, submitted Oct 6. NeurIPS 2026 SLM-for-Agents workshop. Full PDF read (17 pp. incl. appendices).

  • Setup (§3):
    • The deployed Wactorz home-automation agent makes five kinds of call: intent, HA-action classification, grounded actuation, pipeline planning and code generation.
    • The first three are evaluated with the production prompts unmodified.
    • 280 cases over two real Home Assistant installations; 9 models (Qwen3.5 0.8B–4B, Gemma4 E2B–26B, Claude Haiku 4.5, Claude Sonnet 5); 2,520 scored calls.
  • Per-site results (Tables 1–2):
    • No model wins every site, and size is not monotone: Qwen3.5 4B is below 2B on actuation.
    • The best local model (Gemma4 26B) is statistically indistinguishable from both hosted models on four of five sites. Only codegen separates them (p=.002 vs Sonnet 5, p=.039 vs Haiku 4.5), and the gap concentrates in callback and lifecycle API shapes (Table 8).
  • Where the money goes (Table 11):
    • The actuator prompt carries the full entity registry, about 28k input tokens, and takes 81% of hosted spend.
    • It is the site a local 12B model already serves at 95.7%.
  • Routing (Table 3):
    • Hosting only planner and codegen: 93.9% vs 95.4% all-hosted, at 82% lower spend.
    • All-local, best model per site: 91.8% at $0.
  • Live check (Table 4, one installation, n=46):
    • Generation-only hosting = all-hosted at 39/43, for $0.70 vs $2.47 (28%).
    • Actuation moved local costs exactly the one case in 26 that the offline table predicted.
  • Aggregate accuracy hides actuation safety (App. B):
    • Gemma4 E2B actuates on 87.2% of requests for devices the site does not own.
    • Qwen3.5 0.8B "refuses" everything by emitting a constant empty array.
    • Of 70 service calls emitted on impossible requests, 53 named a real but wrong device, so constrained decoding would not have blocked them.
  • Limitations (§6):
    • one pass at temperature 0;
    • two installations;
    • a single unblinded rater for the live run;
    • some answer keys revised after inspecting outputs (disclosed, with both key sets released);
    • accuracy weighted by case count, not traffic.
  • Why it matters for BQAA: this is the analysis a per-call-site cost/quality view should make easy: group spend and accuracy by call site, not by model. The most expensive call is often not the hardest one. Pairs with last slot's Haiku 5.5 tiered pricing, where prompt length decides price.

Six-week EV

  • Output-content validation becomes the next telemetry ask. 2610.10062 shows the error rate misses about 41% of corrupted results, and agents don't catch them either. Expect observability vendors to pitch "result anomaly" checks. The cheap first step is to log tool results with enough structure to compare them against task expectations.
  • Binding-preserving trace export. 2610.09581 and MAScope both require every inferred relation to cite a stored record or span. Trace schemas that keep execution-scoped ID→locator maps (citation IDs, input IDs, parent links) will support "supported vs guessed" scoring. Schemas that flatten them will not.
  • Per-call-site cost accounting. Haiku 5.5's prompt-length pricing (last slot) plus 2610.09021's 81%-on-one-site result make "spend by call site × prompt-length tier" the question the next cost dashboards will be asked.
  • Decision spans get heavier. Vercel now writes base64 file bytes into OTel state attributes. Any pipeline ingesting AI SDK decision spans needs size caps and redaction before warehouse load.

TL;DRs for BQAA

  • 2610.10062 Loud/Quiet failures: agents catch 91% of errored tool calls but 59% of plausible-wrong results. Reasoning tiers notice less. Alert on result content, and use repeated clean runs as the baseline.
  • 2610.09581 Evidence binding: without ID→record bindings, a reader states the right source in 22 of 28 cases with no support. Store the binding; score support and abstention, not just agreement.
  • 2610.10126 MAScope: topology extracted once per deployment doubles a cheap judge's diagnosis score (0.173 → 0.346) at ~6% of a frontier judge's cost. Topology is a dimension worth storing.
  • 2610.09021 Per-call-site eval: one call site took 81% of hosted spend and didn't need the frontier model. Group cost and accuracy by call site.
  • Vercel ai@7.0.133: decision spans now carry base64 file bytes on two span levels, and harness turn usage was under-counted before 1.0.143. Check ingest size limits and back-filled totals.
  • AutoGPT v0.8.3: approvals go to Slack/Teams buttons, and turns are cursor-resumable with stream-vs-persisted drift reported. Approval events now arrive from chat channels.
  • Letta Code v0.34.5: always-on secret redaction in tool returns. Redaction now happens before the trace sees the value.
  • Claude Code v2.1.294: instruction-style policy hooks were failing open; the fix is on npm next only. Hook "allow" outcomes from older builds may be wrong.
