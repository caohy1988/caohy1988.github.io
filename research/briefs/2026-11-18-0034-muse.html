Read this first

All three papers this slot study the checkers, not the checked — and each finds the fashionable checker weaker than its reputation.

The rubric-verifier study (2611.22841) builds the first human-judged meta-evaluation for rubric-graded agent environments (2,464 criteria, two bankers per criterion, κ=0.82, §3) and shows verifiers differ mainly in what evidence they can reach: a reactive in-environment judge (Gandalf) matches the strongest serialize-then-grade baseline's UNMET F1 at one-fifth the cost (0.864 at $9.81/pass vs 0.852 at $46.73, §7.1), while domain guidance and MCP tools resolve no F1 effect at all (Table 2a) — guidance only makes the judge stricter. AgentFaultBench (2611.20711, reserve promotion) runs the control most recovery papers skip: against a neutral "take one more turn" message, recovery advice reduced full success by 8.33pp for GPT-4o mini in the 1,944-run primary (Table 2) — all 20 losses are rate-limit cases where the guided agent received the advice, called no further tool, and reported incomplete (§5). FCP (2611.21679) removes the artifact's own checks from the evidence entirely: on ten code tasks, three models' code passed its own tests (18–745 per suite) and violated the request every time; trusting those tests certified all 33 violations, FCP certified 3 — all on one task where both independent formal readings and all three models misread the same flagged phrase alike (§7.6, §7.8).

NEW 1 — Verifying Agents in Rubric-Graded Environments — abs

Full PDF read (31 pages via pdftotext in chunks: abstract, §§1–10, Tables 1–4, Figure 1, references, Appendices A–F incl. dataset provenance, taxonomy construction, the RewardKit matched comparison and over-acceptance/over-rejection analysis; methods/results/limitations included). New-listing paper. Not in live catalog (grep 2611.22841 / gandalf: 0 hits).

Dücker et al. (Handshake AI Research) treat the verifier — not the agent — as the object of study. BankerVerifierBench (BVB) has 2,464 binary rubric criteria over 24 investment-banking tasks (67–128 criteria each), one rollout per task, every criterion judged independently by two practicing bankers (92.1% raw agreement, Cohen's κ 0.82) and adjudicated; 66.3% are met, so they score UNMET F1, which an always-"met" verifier scores 0 on (§3, §7). A three-stage pipeline derives nine verifier capabilities from the rubric corpus itself (largest: recompute a derived figure, 21.2%; Table 1), distilled into three design principles — reactive verification, environment alignment (judge runs read-only inside the rollout's own environment), domain guidance — implemented as Gandalf (§§4–6). Results (§7.1, Fig. 1): Gandalf/Gemini 3 Flash reaches F1 0.864 at $9.81 per dataset pass vs Archipelago's 0.852 at $46.73; with GPT-5.4 it leads by 0.127 F1 (0.892 vs 0.765) at one-third the cost, paired 95% intervals excluding zero. The honest debits are the useful part: toggling MCP tools and guidance moves F1 by at most 0.008 with all CIs including zero — guidance only shifts the operating point (UNMET predicted +2.2pp, precision −0.030, recall +0.024; Table 2a) — and the concurrent RewardKit verifier matches Gandalf at matched models while costing 24–44% less (App. D, Table A4), so most of the win is the shared reactive in-environment design, not the extras. Per-capability errors track evidence access exactly as predicted: trajectory-only grading fails where the criterion depends on the rendered deliverable (17.0% error on visual presentation), serialized snapshots collapse on stateful-tool evidence in the second environment (36.7% vs 10.0% on cross-component linkage; §8.2, Table 4), and no verifier solves tracing a value across files (14.1–28.8% error for all). Stated limits (§10): one rollout per task, 24 tasks per environment, the second dataset is internal and not reproducible, whole-system comparisons do not isolate principles, and verifier F1 was never tied to better RL-trained agents.

BQAA read: BQAA's judges should be meta-evaluated like this before their scores drive decisions: human-adjudicated per-criterion labels, UNMET-class F1 (not accuracy on a 66%-met corpus), cost per pass next to F1, and over-acceptance vs over-rejection reported separately (App. E) — verifiers with near-identical F1 differ by 44.7 over-rejections per pass, and the backing model alone can swing FN/FP from 1.03 to 0.08. Budget note: guidance text and extra tool access are not free accuracy; measure them or drop them.

NEW 2 — AgentFaultBench: State-Verified Evaluation of Tool-Fault Recovery — abs

Full PDF read (63 pages via pdftotext in chunks: abstract, §§1–7, Tables 1–5, Limitations and Ethics, references, Appendices A–Y incl. fault catalogue, per-model counts, intervention texts, delivery audits, sensitivity analyses and the later operational/Sol/new-instance campaigns; methods/results/limitations included). Reserve promotion from 2026-11-17-1234. Not in live catalog (grep 2611.20711: 0 hits).

Gupta asks whether recovery advice helps an agent finish after a tool fails — against the right control. LangGraph/CrewAI agents execute specified GitLab incident tasks (expected issue/report text supplied, so execution and procedure are tested, not content generation) under injected faults (429 cooldowns, forged verification, 503 bursts, post-commit permission revocation; Table 1). Scoring separates correct final state from full success (state + required reads + genuine verification + valid final JSON), and a separately written standard-library checker agrees on all 1,879 observed primary outcomes and 241 constructed cases (§4). Primary result (1,944 planned runs, Table 2): guided feedback vs a neutral "take one more ordinary turn" reminder changes full success by −8.33pp (GPT-4o mini; 2 wins/20 losses/194 ties, no missing outcomes), 0.00pp (GPT-4.1 mini) and +1.06pp (GPT-4.1), the latter two inconclusive under missing-data bounds. The mechanism is visible: all 20 first-model losses are rate-limit cases where the guided agent demonstrably received the advice (325/325 guided messages bound into returned model calls), still had six tools, called none of them, and reported incomplete citing the rate limit — the advice bundles pending steps, prohibitions and "if any required step remains blocked, report incomplete" (§5, App. O/P). State/process separation also bites the other way: 318 runs reach the correct state but fail full requirements (311 missing required reads), and GPT-4.1 neutral completes state on all 32 clean cases but full success on only 17. Later campaigns: a revised policy (execution information + next-step advice, incl. restoring executor-held issue IDs the agent never saw) gains +9.90–10.42pp on six unused related instances for GPT-4o mini (161 vs 142 of 192), while stronger baselines already solve every recoverable case (all ties); removing the issue IDs changes 47/48 vs 46/48, so information-restoration and wording remain confounded (Apps. V–Y). Stated limits: small constructed tasks in three incident families on one workflow, no human validation of semantic flags, no retry arm in the primary study, code/records not public with the submission.

BQAA read: this is the evaluation template for every "recovery hint / self-healing prompt" claim: same-trigger neutral-continuation control, delivery verified separately from effect, state vs procedure scored apart, missing outcomes kept as bounds instead of dropped. The failure mode transfers directly to production harnesses — a well-meant "report incomplete if blocked" clause inside recovery guidance can convert a retryable 429 into a voluntary stop; BQAA trace views should flag runs that end immediately after a guidance injection with tools unused.

NEW 3 — FCP: Formal Context Protocol for Verifying LLM-Generated Artifacts — abs

Full PDF read (26 pages via pdftotext in chunks: abstract, §§1–11, Tables 1–8, Figures 1–5, references, Appendices A–E incl. Lean-checked proofs, the property language, and per-study details; methods/results/limitations included). New-listing paper. Not in live catalog (grep 2611.21679 / formal context: 0 hits).

FCP verifies an AI-generated artifact against the request itself, never against the artifact's own tests. It splits conformance (artifact vs a formal reading; decided by model checkers/SMT) from fidelity (reading vs prose meaning; undecidable, refutable by one behavior two independent readings judge differently), and gives each of eight false-assurance situations — vacuity, unreceptive assumptions, fidelity, conflict, under-determination, weak properties, black-box dependence, engine error — a mechanical witness, with only fidelity ending as a concrete question to the request's author (Table 1, §§2–4). Adapters put hardware, text, agents (scaffold as circuit, model output unconstrained; every rule classified enforced/delegated/broken) and code (exhaustive request-derived scope, plus translation-validated proofs beyond it) on the same engines (§§5–6). The numbers are stark. Hardware: trusting AI-written assertions certified 56/244 (23%) of violated requirements; FCP certified 0/244, and all 45 disagreements between two isolated formalizers were real errors (Table 4) — though only 44/98 well-formed formalizations matched intent at all. Code (§7.5–7.6, Tables 6–7): on ten tasks each with a planted conflict, three models' implementations passed their own suites (18–745 tests) and violated the request in every case; in nine tasks all three resolved the conflict identically, in eight answering every scope call (up to 3.6M) identically — agreement across models signaled a shared misreading, not correctness. Self-checks certified all 33 violations; FCP found 9 of 10 conflicts before any code existed and certified 3 violations, all on the gift-card task where both formalizers and all three models resolved one flagged ambiguity alike; a variant reading per flagged answer removes them (§7.8). Proofs beyond the scope decided 2,245/2,263 verdicts for all inputs and caught 7 failures the exhaustive scope missed (§7.7, Table 8). Debits are stated (§10): small planted-defect corpus, all models from one family, gold readings model-assisted (mechanically validated, fidelity still a judgment), assurance bought with an author review queue (8–27 decisions per hardware reading), and an LLM judge baseline on the prompt study marked all 33 checklist items PASS on a literally unsatisfiable prompt (§7.3) — which FCP instead returned as a question with its witness.

BQAA read: two portable rules. First, never let an artifact's own generated tests, or cross-model agreement, count as verification evidence in BQAA quality gates — both failed 30/30 implementations here; log them as generation metadata, not assurance. Second, the enforced/delegated/broken split is exactly the right analytics primitive for agent scaffolds: BQAA should report, per guardrail rule, whether the harness enforces it for every model output or merely relies on the model complying — six of eight planted scaffold bugs were invisible until the model deviated, which is precisely the prompt-injection condition.
