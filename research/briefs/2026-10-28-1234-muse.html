Progress

1. Mastra @mastra/core 1.80.0 — span aggregation becomes a served, stored capability. Parent: mastra-core-1-72-0-trace-aggregate-plans-lease-fenced-background-tasks-cyber-refusal-retry. npm 2026-10-28T13:39Z; GitHub release published 2026-10-28T15:23Z (stable, not prerelease). Release.

Context matters for why this is Progress and not a re-note of last week: 1.79.0 (already Progressed 2026-10-21) added only the aggregateSpans() storage contract — adapters could implement it and advertise a feature flag. The 1.80.0 notes ship the usable surface: a new POST /observability/spans/aggregate endpoint plus aggregateSpans() implementations in the ClickHouse, Postgres and DuckDB stores for grouped counts, latency, error rate, tokens and cost over agent runs, tools and workflows. Span records also gain nine native columns (externalParentSpanId, resumedFromSpanId, model, provider, outcome, stopReason, stopReasonContext, timeToFirstTokenMs, errorCount; unset stored as null — "this release only adds the fields; later releases fill them in"), agent-run and model-step spans now show configured vs actually-called model/provider, stored span previews preserve intentionally empty strings via a new buildSpanPreviews(), dataset experiments accept a per-experiment agentModel recorded in experiment and trace metadata so cross-model runs stay separable, and provider errors get one persisted classification (classifyProviderError and helpers) carried in streams so a reloaded thread classifies like a live one. Judged as one monorepo release on its substantive notes. The BQAA-relevant core is the aggregation endpoint over warehouse-class stores: grouped span metrics as a first-class server query, not a client-side trace scan. Breaking changes noted in the release (thread rows drop model/provider, page limit capped at 100) do not change the judgment.

2. Inspect AI 0.3.286 — sentinel steps replay from the log; log handling hardened. Parent: inspect-ai-0-3-280-agent-bridge-attribution-response-headers-sandbox-mounts. PyPI 2026-10-28T14:25Z; GitHub release 2026-10-28T14:22Z. Release.

The evaluation-evidence features are the Progress substance: a live sentinel now follows the span a bridged agent's event sink gives each generate; a sample's sentinel steps can be rebuilt from its log with a single step builder shared by live execution and replay; the log records where each model call was made and generate steps keep their ids in replay; and the Terminals tab shows all of a sample's terminals together on one shared clock (extending the recorded-terminal browsing Progressed at 0.3.285). Two deliberate breaking hardenings ship alongside: recomputing, editing or recovering a log no longer imports files or builds models the log names, and Docker sandbox file reads now run as the container's default execution user instead of a privileged copy path (explicit-user reads are rejected until a provider supports them; the notes name the symlink-privilege reason and the Kubernetes terminal-recording caveat). Remaining items are fixes (cache-expiry readback, transcript-recording bypass prevention, large-integer dataframe handling, proxy streaming). For BQAA the pattern to borrow is live/replay parity from one builder plus call-site recording in the log itself: an evaluation artifact that can be re-derived without trusting or executing what it names.

3. Braintrust JS braintrust 3.41.0 — MCP server tracing. Parent: braintrust-js-3-39-0-application-logs-console-capture-trace-correlation. npm 2026-10-28T16:19Z; GitHub release published 2026-10-28T16:14Z. Release.

The minor adds automatic tracing for MCP servers (protocol v1 and v2) covering tool calls, prompt retrievals and resource reads, with a wrapMCPServer() entry point for existing servers. Per the linked change description read this slot, traces record inputs, outputs and session/request IDs for correlation; a tool result flagged as an error counts as a failure even when the handler does not throw; response metadata and inline media bytes stay out of traces, with images and resource blobs captured as attachments only when enabled and audio/video bytes always omitted. The same release adds compressed voice recordings via a new companion audio package and per-direction call-recording flags for voice-agent integrations, plus fixes (including finishing recording uploads before session close resolves so recordings are not lost at process exit). The Progress rests on the MCP tracing surface: the tool-server side of an agent trace becomes instrumentable with the same failure semantics as the client side, which is the missing half in most MCP deployments BQAA would be asked to analyze.

Six-week EV

  • Span aggregation as a server query is now table stakes in open frameworks (0–6 weeks). Mastra's contract-to-endpoint two-step (1.79 contract, 1.80 served endpoint + three warehouse-class stores + native metric columns) is the shape BQAA competes with directly: grouped latency/error/token/cost over spans answered by the store, not exported elsewhere. Expect feature comparisons to ask whether aggregation runs where the traces already live; BigQuery-native aggregation is BQAA's structural answer, and first-class span columns (outcome, stop reason, time-to-first-token, error count) are the schema checklist to match.
  • MCP server-side tracing closes the trace's missing half (2–6 weeks). Client-side tool-call spans alone cannot attribute server-internal failures or correlate sessions; automatic server tracing with error-flag semantics and attachment discipline sets the expectation. Any BQAA MCP guidance should assume both sides emit and join on session/request IDs — and should budget for media-attachment policy questions (what bytes enter the trace store) arriving with it.
  • Evaluation logs converge on replay-without-trust (ongoing). Inspect rebuilding sentinel steps from the log with the live builder, preserving step ids, and refusing to import code a log names during recomputation is the same direction as the catalog's evidence-certificate and regrade-provenance papers: the artifact must be re-derivable and safe to open. Eval-evidence stores that require executing artifact-named code to re-score will read as liabilities in review.
  • Release-train velocity keeps rising; judgment cost follows (process, ongoing). Four Opik stable releases inside eight hours and weekly Mastra minors mean per-version carding would drown signal. The train-as-one-item and contract-vs-delivery distinctions used this slot are the sustainable filter: rank the delivered capability once, note the rest.
