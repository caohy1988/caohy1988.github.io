Academy

NEW — τ^τ-Bench: An Environment for End-To-End, Realistic Agent Construction — https://arxiv.org/abs/2609.04611

Quan Shi, Keshav Dhandhania, Karthik Narasimhan, and Victor Barres; Sierra and Princeton. Full 41-page v1 PDF read, including appendices.

Across 53 construction tasks in four domains, builders recover requirements from business artifacts and client interaction, implement agents, and face service evaluation with a budget-overage penalty. The strongest reported overall score is 23.9; the expert-authored oracle reference is 82.2. These are budget-adjusted task means, with 35 banking tasks dominating the aggregate, and one construction trial per configuration/task. The reference authors have ground-truth access and model assistance; it is not average human performance. PDF, §§3–5, Table 2.

The actionable evidence is the failure analysis: self-written tests can miss requirements, and API failures can require clarification about commitment or idempotency. “Retry” can be the wrong repair. Scope remains simulated service delivery: selected pilot variants expose a sample of traffic retained in scoring, and the suite does not establish long-term deployment performance. Clarification correlations do not prove a universal asking policy. PDF, §6 and appendices.

BQAA TL;DR — inference: connect each consequential requirement to its source or clarification, an acceptance check, and the resulting behavior. A convincing build trace and passing self-tests can coexist with an agent that violates the business contract. An ADK fixture with ambiguous API commitment and one client-only rule would test this cheaply.

Why new: this concerns recovering and fulfilling the client's service contract; HarnessDev's previously covered held-out harness selection does not cover that evidence chain.

NEW — Harbor Adapters and Harbor-Index: Infrastructure and a Curated Meta-Dataset for Large-Scale Agentic Evaluation — https://arxiv.org/abs/2609.04298

Lin Shi, Haowei Lin, and collaborators. Full 88-page v1 PDF read, including benchmark adaptation and audit appendices.

The broad study covers 54 benchmarks and 6,627 tasks, eight models in two harness conditions, with three trials. Harbor-Index is a separate, deliberately difficult 82-task selection audited from that pool; its nine-model/two-harness evaluation comprises 1,476 rollouts. Approximately one-third of the hard candidates reviewed were broken—not one-third of all benchmark tasks. Audit examples include unreachable simulation triggers, lost input modalities, and hidden or incorrect verifier requirements. Reproducing an original score therefore does not establish task validity. PDF, §§3–4 and adaptation/audit appendices.

GPT-5.5 scores 28.0% with Codex versus 19.5% with Terminus-2 on the selected Index. This does not establish a universal capability ceiling or a harness effect independent of model family. The larger public archive includes additional trials; it should not be conflated with the main experimental corpus. Appendix judge denominators are inconsistent enough that their failure-category percentages are not used here. PDF, Table 1 and judging appendices.

BQAA TL;DR — inference: attach an evaluation result to the original task, adapted task, verifier/oracle, resource budget, and rerun disposition. Audit whether an apparent agent failure was possible to avoid before attributing it to reasoning. The SQL adaptation examples also caution against assuming equivalent database environments.

Why new: this is task and verifier provenance, beyond the Phoenix/Braintrust Harbor telemetry integrations already cataloged.

NEW — EVOHARNESSBENCH: Can Your Agents Keep Pace with an Evolving Harness? — https://arxiv.org/abs/2609.04280

Zixuan Ke and collaborators, Salesforce AI Research and academic collaborators. Full 32-page v1 PDF read, including appendices.

The benchmark follows 17 streams of cumulative tool, skill, or specialist-agent additions. It separates fixed-model deployment from memory, prompt, or code adaptation, and checks older tasks under expanded harnesses. Its scope is additions; removal and replacement are not tested. PDF, §3.

More tools sometimes help: on EOG, the full-catalog deployment baseline passes 30.2% versus 26.0% with task-specific tools, while aggregate token use rises from 27.2M to 75.8M. MemToolAgent reaches 38.6% on EOG but trails the deployment baseline on ALE, 10.1% versus 12.2%. Improved aggregate performance can coexist with regressions on older tasks. Skill-verifier heuristics and inconsistent appendix descriptions limit stronger claims about skill use; backward-transfer definitions also require care before treating a reported number as percentage points. PDF, Table 1, §4 and appendices.

BQAA TL;DR — inference: preserve the exposed tool/skill/agent manifest, including capabilities never invoked. Compare old-task retention and new-task performance at each harness version, with cost and adaptation state alongside them. Otherwise a release can look better because its task mix changed while established workflows regressed.

Why new: external harness growth and version-to-version regression differ from HarnessDev's optimizer-selection problem. The paper supports measuring both benefit and interference; it does not justify always pruning tools.

NEW — Same Request, Different Answer: Quantization Amplifies Cache-Induced Divergence in LLM Serving — https://arxiv.org/abs/2609.04748

Aditi Patodiya, independent researcher. Full 13-page v1 PDF read, including controls and limitations.

Ten small-model serving configurations each run 80 agent episodes per arm. The headline 75% is cross-arm trajectory disagreement for Qwen2.5-7B Q4 under llama.cpp. Same-arm repetition is a separate measurement. In a second-host control, repeated cache-enabled divergence falls from 31/80 to 1/80 when the server prompt cache is disabled while prefix caching remains enabled. Cache layers and execution order matter. PDF, §§III–IV, Tables 1–2.

Response telemetry can misidentify exposure: the tested vLLM endpoint reports zero cached tokens despite engine logs confirming cache hits. Scope is local 7–14B models on an RTX 4090; SGLang was excluded and hosted production serving was not tested. Low agent-task success prevents a strong outcome conclusion. Across 1,300 unique arithmetic items, 20 correctness flips favor both directions; the aggregate directional test is inconclusive. PDF, Table 3 and limitations.

BQAA TL;DR — inference: before diagnosing an unexplained replay difference as a prompt or model regression, record the server build, relevant cache modes, verified exposure, and execution order. A cold/warm repeat fixture can distinguish changed trajectories from changed correctness. Missing cache telemetry must remain distinguishable from a confirmed zero.

Why new: this identifies a serving-state confound in reproducibility, beyond existing model/judge snapshot identity. It does not establish a need to flush every cache or predict production error rates.

Full-PDF evaluations retained as holds

These are screening dispositions, not new cards or catalog progress entries.

  • Tanveer, reviewer capability — HELD. 2609.04270; full 6-page PDF. On 100 numeric mathematics problems, accuracy is 52% unreviewed, 58% self-reviewed, and 64% with the stronger cross-family reviewer. The direct 64-versus-58 comparison has p=0.238. Capability and family are confounded; malformed reviewer output defaults to acceptance in one condition, and the reviewer sees truncated solutions. BQAA TL;DR: measure false alarms, repair, harm, and parse failures separately. Reopen with matched reviewer comparisons and a realistic SQL/code workload; do not prescribe cross-family reviewing from this pilot. PDF.

  • David Dylan et al., At Equal Inference Cost — HELD. 2609.04217; full 14-page PDF. One frozen Qwen model and one planner/executor/critic topology yield 0.769 versus 0.754 for a single agent, p=0.80. This is not an equivalence test. The “iso-call” setting concerns search budgets, with unequal realized calls and tokens; deployment also takes more calls. The title's equal-cost framing is broader than the controls support. BQAA TL;DR: retain complete generation and deployment accounting; this does not justify a blanket single-agent preference. Reopen with matched total cost, repeated runs, and more than one topology. PDF.

  • Yao et al., Forgetting Without Restarting — STRONG WATCH / HELD. 2609.04875; full 8-page PDF. Selective execution-state removal is tested on 280 scripted episodes. Exact counterfactual claims require controlled randomness, recoverable state, and compatible downstream observations. Strong selective-reuse benefits rely on oracle independence attribution; the reported token advantage narrows substantially against a prefix-cached reset. Committed external effects cannot be undone by deleting model state. BQAA TL;DR: track which derived memory and actions depend on withdrawn evidence. Reopen on non-oracle dependency tracking and realistic rollback boundaries; current results do not certify erasure for ADK or hosted APIs. PDF.

  • Zheng and Yang, CONTINUITY — HELD. 2609.05269; full 20-page PDF. The conformance suite uses a Python reference implementation, mock atomic world, trusted issuers, and complete mediation. Its zero attack successes are results against modeled fault classes, with no LLM in the harness. Reported millisecond overhead excludes real external policy and network/storage costs. BQAA TL;DR: revocation and authority-change cases are useful negative tests. Reopen with real integrations, durable state, and incomplete-observation failures; conformance does not establish production attack resistance. PDF.

  • Grotov and Malykh, draft-model gate — HELD. 2609.05274; full 11-page PDF. Table 2 reports SWE-Bench execution errors falling 21%→15% and tokens falling 14%, while task success falls 49%→44%. DACode moves 64%→63% task success. The gate targets execution validity, draft inference is treated as free in the cost accounting, and the task results have no uncertainty intervals. BQAA TL;DR: judge gates by cost per correct task and harmful vetoes, including draft overhead. Reopen on downstream success recovery and complete costs; fewer exceptions alone is insufficient. PDF.

  • Ben Amor et al., RefactorPlatform — HELD. 2609.04898; full 9-page PDF. AST retrieval and structured diagnostics are useful engineering evidence. However, the delegated setup is exercised on only 81 of 100 Python tasks, and an important Java feedback comparison uses different task subsets. These comparisons cannot cleanly attribute their full gains to the advertised interventions. BQAA TL;DR: distinguish the intended configuration from whether it actually ran, and compare identical task manifests. Reopen on matched cohorts and stronger behavior checks; this remains adjacent to existing harness evidence. PDF.

  • Sun, Yang et al., Trace2Tower — STRONG WATCH / HELD. 2609.05261; full 13-page PDF. The trace-derived skill hierarchy is promising on ALFWorld; its WebShop margin over SkillX is small relative to reported variability. Key graph ablations use one run versus the main three-run averages. Mid-level retrieval happens at episode initialization from a rewritten plan, rather than continuous per-step refresh; Appendix E.2 leaves the exact embedding model unidentified. BQAA TL;DR: trace-to-skill evidence links are useful, but transfer across enterprise tasks and harness versions remains open. Reopen with an identifiable retrieval manifest, repeated ablations, and transfer evidence. PDF.
