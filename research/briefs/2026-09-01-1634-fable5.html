Industry

1. OTel GenAI: execution state-change event proposal, with ADK as a reference producer (Sep 1, 3:02 PM PT)

PR #483 on semantic-conventions-genai was opened as a draft on Aug 30 evening PT and moved to ready-for-review today at 3:02 PM PT. It adds one event and three attributes, all Development status:

  • gen_ai.execution.state.changed, recorded in the context of the internal workflow or agent span that observes a non-empty, runtime-owned state delta.
  • gen_ai.execution.state.changed_key.count (required). Must come from the runtime's own delta, never from diffing two full state payloads.
  • gen_ai.execution.state.changed_keys (opt-in). Only bounded, schema-defined key names. If keys are dynamic or could carry user identifiers, content, tool arguments, or secrets, leave it unset and record the count alone.
  • gen_ai.execution.state.version (conditionally required). Only when the runtime exposes a version. Must not be synthesized from content, timestamps, span IDs, or hashes, and must not be used in metric dimensions, span names, or sampling.

The event must not carry state values, transition payloads, tool arguments or results, idempotency data, or hidden reasoning. The accompanying guidance page draws the boundaries hard: checkpoint writes belong to storage instrumentation, an unchanged checkpoint is not a state change, replays must not report an external effect as re-executed unless it actually ran again, tool spans do not prove an external system was mutated or deduplicated, and compensation must not be inferred from tool names or trace proximity. Relationship types for resume, retry, delegation, fan-out, and compensation are explicitly deferred.

The ADK reference scenario is the part to read. It runs a confirmation-gated tool, resumes the same ADK invocation with the confirmed function response, checks Event.invocation_id matches the original execution without emitting it, and when event.actions.state_delta is non-empty it emits one event with the key count and the sorted key names. The LangGraph producer is a real instrumentation PR (opentelemetry-python-genai #507), also open, also by the same author.

Context that has not been in any brief: issue #462 (Aug 19) frames the whole area as durable agentic runtimes that persist state, pause, resume, delegate, retry, and compensate, and asks which execution work belongs to, whether a workflow resumed from persisted state, and which transition led to an action. PR #445 (Aug 9) proposed gen_ai.agent.paused, checkpointed, resumed, and pause.resolved events with a flat resumed-from pointer. On Aug 31 its author accepted a reviewer's critique that it modeled one durability pattern as the whole design space, converted it to draft, and committed to prototyping over LangGraph (identified checkpoints), CrewAI (dual mechanism, tree), and ADK, which the author characterized as "append-only event log, nothing to point at." The author also conceded a flat resumed-from pointer fails because LangGraph checkpoints form a tree.

State of play, verified: #483 has two bot reviews and no maintainer comment. #445 is draft. #462 is open discussion. Nothing here is spec.

The wrong belief to kill: OTel GenAI has no opinion on agent state, pause, or resume, so the state columns in an ADK event schema are free design space. The opinions are forming now, in public, with ADK as one of the two runtimes being read at source.

TL;DR for BQAA. The proposal's privacy stance is a forensics statement we can adopt verbatim: on the row that carries a state change, record how many keys changed and, where the key names are bounded, which ones, and keep values out by default. ADK's invocation ID across a pause and resume is exactly the "something to point at" the #445 author says ADK lacks, and rows sharing it in a warehouse is a named-loop story worth one paragraph in the producer contract. Watch #483 for a maintainer response; no action until then.

2. OTel GenAI: skill-usage proposal, prototyped on ADK, ready for review (Sep 1, 4:42 AM PT)

PR #463 (opened Aug 20) went ready-for-review at 4:42 AM PT today and took another commit at 12:17 PM PT. Its changelog fragment: add gen_ai.skill.* attributes and skill metrics for agents that use Agent Skills. Skill loads, resource reads, and script runs are recorded on the execute_tool span. The skills whose instructions are in an invocation's context, and whether each one is compacted, are recorded on the invoke-agent span as gen_ai.skills. New metrics count loads and script runs and report how many distinct skills a single agent or workflow invocation activated. The PR body says the changes are prototyped on Google ADK and Microsoft's Agent Framework, and that "there is ongoing work in bringing these changes into ADK as an experimental feature." The ADK reference scenario adds about 530 lines and two sample skills.

Fourteen review comments, still open. Not spec.

TL;DR for BQAA. If ADK grows skill telemetry, skill loads land on tool events and the active-skill list lands on the agent event. Both fit as attributes on existing rows rather than a new event type. One line in the coverage matrix, nothing to build.
