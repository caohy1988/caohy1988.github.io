Industry

LangChain: "What Is Eval-Driven Development? How to Improve AI Agents"

Divya Santhanam, LangChain blog, 2026-11-09. Source: https://www.langchain.com/blog/what-is-eval-driven-development

What it is. A how-to modeled on test-driven development: evals become the definition of success and the agent is built toward them.

The method.

  1. Spec. For one behavior at a time, write when it should happen, what the agent should and should not do, and what must keep working, precisely enough to score pass or fail.
  2. Eval before build. Build a dataset, with real agent runs as one of the best sources. Use a code evaluator for deterministic checks and an LLM judge otherwise. Run a baseline before changing anything.
  3. Compare experiments. Each change gets its own experiment, compared with the last. Read the failing trace for the cause, and keep a held-out set, since tuning until everything passes can overfit.

Then CI + production. Fast code checks can block a bad merge, slower LLM-judge suites run nightly or before a release, and production failures become new dataset examples.

LangSmith surfaces named. Datasets from real runs; experiments with a side-by-side comparison view; tracing; scoring of a step, a tool-call sequence or a multi-turn thread; pytest and Vitest integrations; online evaluators on sampled live traces; annotation queues; dashboards for eval scores, feedback, cost and latency; Insights, which clusters production traces; and LangSmith Engine, which turns issue clusters into dataset examples with assertions for review. For environment-changing agents it points to Harbor (per-task sandbox; a test script grades the end state).

Common mistakes. Defining success too loosely; writing the eval after the fix; checking only the average score; adding evals not tied to a specific change; trusting an LLM judge before comparing it with human scores.

Why it matters for BQAA/ADK. Writer's reading: traces sit at both ends of this loop. Real runs seed the dataset, a failing trace explains a regression, and production traces are scored, clustered and fed back as examples. Three analytics questions follow: can two agent versions be compared example by example, can tool choice be checked from recorded tool calls, and can judge scores be checked against human review. It is vendor guidance: a recommended workflow, not a measured result.
