NEW — LangGraph 1.2.13 (Python): the checkpoint/replay state-integrity train — fork-before-replay, branch-scoped update_state, DeltaChannel corrections, get_state stops reporting answered interrupts

Primary: https://github.com/langchain-ai/langgraph/releases/tag/1.2.13 (2026-10-05T17:51:32Z = 10:51 PT, prerelease=false). PyPI langgraph==1.2.13 uploaded 17:51:20Z — installable artifact confirmed.

Why NEW and why now. The catalog has a LangGraph.js card (1.4.19, Saturday 1234) but no Python LangGraph card (live catalog grep: zero langgraph-1-2 / python-langgraph items). 1.2.13 is a patch release, but its entire content is durable-state integrity on the checkpoint store — the same class of fix that carded the JS line, and the surface that durable-agent analytics reads. All seven substantive changes (release notes):

  • Fork before replay when the thread moved past the checkpoint being updated (#9170) — replaying an update_state no longer mutates a checkpoint the thread has already advanced beyond; the update forks instead.
  • update_state on an older checkpoint stays out of its other branches (#9165) — cross-branch state leakage on stale-checkpoint writes is closed.
  • DeltaChannel counters kept on every update_state path (#9142), no history walk for a DeltaChannel that was never written (#9141), no replay of an abandoned branch into a DeltaChannel fork (#8548) — three accumulator/replay corrections for interrupted multi-branch runs.
  • Subgraph delta channels hydrate with the caller-resolved saver (#8538) — subgraph state rehydration uses the right checkpointer.
  • get_state stops reporting answered interrupts (#9103) — the state API no longer surfaces interrupts that were already answered as pending.

BQAA read. If your trace model keys "pending interrupt" or "branch state" off get_state/checkpoint reads, pre-1.2.13 LangGraph could hand you answered interrupts as pending and stale-checkpoint writes as live branch state — silent wrong-state telemetry, not an error. This is the Python twin of Saturday's JS card: durable-execution state surfaces are being corrected to report what actually happened, which is exactly what run-epoch/restore analytics depends on (see 0634's qwen-code v0.25.0 and the Mastra durable-run WATCH).

NEW — 2610.02808 — ROUTEAUDIT: contract-conditioned identification for budgeted multi-verifier routing — matched static equals the cascade; the apparent +0.1797/+0.1250 gains were the verifier-set edge; ship an attribution certificate before any route claim

Full PDF read (method §3 with the C1–C6 contract and the lattice/tape/bounds constructions, experiments §4 with Tables 4–7, robustness §4.6, limitations §5, and appendices A–J including the mutation suite Table 28, blind semantic audit Table 30, error taxonomy Table 31, and RLVR binding Table 37). U. Chinese Academy of Sciences + Institute of Information Engineering CAS (Hu, Hu, Guo, Wang, Wang, Fu, Zha, Xiao). v1 2 Oct 2026.

The problem: adaptive multi-verifier routing (cheap verifier first, escalate conditionally) is routinely compared through endpoint quality–cost gaps where the verifier catalog, availability, accounting, information filtration, or scorer changes with the policy — so the "route effect" mixes the policy change with a changed measurement contract. ROUTEAUDIT makes the contract itself the object: K = (request support, verifier catalog, availability schedule, prices/accounting, online filtration, post-trace scorer), and a legitimate route claim requires the matched contrast Δroute that changes only the policy coordinate (Eqs. 1–3). On top it adds (§3.3): a contract lattice that averages coordinate increments over all admissible bridge orders (Shapley allocation on the full factorial) and reports path sensitivity Ωj; a policy-independent response tape indexed by (request, verifier, call index) so adaptive policies couple to the same provider realization instead of two independent draws; sharp partial-identification bounds for incomplete matching that strictly refine complete-case analysis; and a machine-verifiable identification certificate returning IDENTIFIED / PARTIALLY-IDENTIFIED / NOT-IDENTIFIED before any aggregate claim.

The headline measurement (Table 5, Table 7, Table 17; two held-out raw-tail caches, n=128 and n=32): full static (SF+SA+LF, 3 calls/10 units) scores 0.7656 / 0.8438 while the cascade (SF→SA, 2 calls/6 units) scores 0.9453 / 0.9688 — an apparent adaptive gain of +0.1797 / +0.1250. But matched static SF+SA at the same 2-call/6-unit budget scores identically to the cascade on every record (route Δ = 0.0000, McNemar p = 1.0): the entire apparent gain is the verifier-set edge (adding LF hurts), not routing. The negative-control gate (§3.8, §4.4) makes this structural: mixed-path operating points that lose quality (−0.0625 on calibration) fail the predeclared gate; quality parity occurs exactly at the fixed two-call endpoint.

The learned-policy stress test (Tables 4, 9–11, 13; 1,319 held-out GSM8K-style requests, Qwen2.5-7B/32B generators, 5 seeds, 7 serving seeds) runs under the same contract: RLVR router reaches quality 0.9553 vs matched static 0.9484 — paired +0.0068, request-paired interval [0.0015, 0.0122], training-seed-by-request hierarchical interval [0.0006, 0.0131] — at 1.4466 mean calls and 0.680 normalized cost; the learned router's interval straddles zero ([−0.0003, 0.0079]); expanding the verifier catalog yields route–catalog interaction ΓV = −0.0027 (Table 6). Integrity machinery: controlled attribution recovery reaches route MAE 0.0011 / endpoint reconstruction error 0.0004; the trace checker detects 2,025 of 2,028 mutations with zero clean false positives (misses: one availability-field and two reason-field mutations, §4.6/Table 28); the full contract's false-attribution rate is 0.0000 vs 0.0498 MAE under controlled violations.

Limitations (stated, §5): identification is conditional on the declared contract; the task study is a short routing horizon; interaction/path-sensitivity values are specific to the measured factorial cells; pairing and retraining are separate uncertainty sources (hence two intervals); RLVR is an application of the contract, not a universally superior optimizer claim.

Why it ranks. This is the eval-integrity paper for the verifier-routing wave: it shows a canonical-looking cascade win evaporating under a matched control, and turns "did you measure the route or the contract?" into a machine-checkable certificate with an explicit NOT-IDENTIFIED verdict. It pairs directly with 0634's VeriHarness (verify against environment evidence) and LiteTrajEval (budgeted trace serialization), and with 0034's ArrivalBench (replay invariance): the week's Academy line is that agent-eval claims need declared contracts, paired identification, and replayable traces — all ingestible as product checks.
