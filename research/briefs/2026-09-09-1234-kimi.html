Grepr Agent Sessions — NEW RANK: reconstruct coding-agent sessions from disjoint OTLP signals, honestly labeled

New item, kind rank. Grepr opened an early-access preview of Agent Sessions, announced in-window (collector receipt: @grepr_ai, 08:32:20 PT) and independently verified against the primary blog post and pipeline documentation.

What survives review. The docs state that coding agents (Claude Code, Codex, OpenCode emitters listed) emit conversation as OTLP log events and execution as OTLP spans, and that an agent-sessions pipeline "reads both from the same integration and joins them into a session." The session record lands "in your own S3 buckets rather than a shared store." Verified capabilities: transcript view with per-turn model calls, tool calls and tool results; a timing waterfall; a summary bar with turns, tool calls, errors, duration, token counts and cost; token cost broken into uncached input, output, cache read and cache write "when the harness provides it"; embedding-based intent clustering of sessions (via a customer-selected OpenAI or Gemini integration); direct SQL query over the session data; and sync of some or all session data to any OTLP-compatible destination.

Honesty mechanism worth carding by name: the documentation commits to labeling capture gaps — "a session names the content its harness never sent, and marks content the harness shortened as a truncated capture" — rather than silently dropping or fabricating telemetry.

Qualifications. (1) Gated preview: "Agent Sessions are enabled for each organization individually." (2) Clock: the blog metadata declares datePublished: 2026-09-08, dateModified: 2026-09-09T15:24:25Z (08:24 PT, in-window). Consistent with the Formo/Neon corrections, do not present this as a product that first existed today; the in-window, collector-receipted event is the public launch announcement. (3) The launch tweet itself was not independently re-fetched here; the X timestamp remains collector-reported. (4) Cost breakdowns depend on harness reporting; intent clustering routes session content through a customer-chosen third-party model. No measurement of analytics quality is claimed by the vendor or established here.

BQAA TL;DR — inference: two design rules transfer directly. First, when the conversational signal and the execution signal travel on different channels, the join key and the reconstruction step are part of the product, not an implementation detail — a BQAA session view must say which spans and messages were actually joined. Second, make incompleteness a first-class value: "harness never sent this" and "capture truncated" are more useful than a silently partial trace. The S3-residency model is also the shape enterprise customers will expect for agent telemetry.

ReCite: Agentic Reasoning for Faithful Citation — arXiv:2609.09156

NEW Academy rank, narrowly scoped: an agentic verify-and-retry pattern for claim-evidence checking, with fine-tuned-vs-zero-shot and judge-validation limits. Yuyang Huang, Bobo Li, Jiajia Song, Yuzhe Ding, Chong Teng, Fei Li and Donghong Ji (Wuhan University; National University of Singapore). Primary history: September 8 v1, 17:59:50 UTC, no revisions, cs.CL. The complete PDF was read (PDF route plus ar5iv HTML for the image-embedded tables). Full PDF · Project page.

What survives review. The paper decomposes citation failure into fabrication (claimed largely solved by retrieval) and misattribution — real, topically relevant papers that do not logically support the specific claim. Three decoupled fine-tuned Qwen3-4B modules run in an observe-think-act loop: CiteLocator predicts where citations are needed (with Mandatory/Optional necessity labels); QueryPlanner generates reasoning plus keywords per position (SFT then GRPO, G=4); a Master Brain queries the Semantic Scholar API (top-k=8), checks candidate metadata against the inferred intent, and on failure attributes the failure and re-retrieves with refined keywords. The collector's three-phase description is accurate; two overstatements are corrected below.

Evidence and limits from the PDF:

  • End-to-end on 200 test paragraphs (50 each from CVPR'25/EMNLP'24/ICCV'23/NeurIPS'25; 1,023 unique target papers; zero train/test paper overlap): ReCite-SFT(CAP-8) reaches Strict F1 39.15 / Lenient F1 55.14 / Position-only F1 89.71, versus DeepSeek-V4-Flash 33.10/36.57/77.26, DeepSeek-V4-Pro 31.77/35.79, and general agents (Claude Code, Hermes, OpenClaw — all forced onto a Mimo-V2.5-Pro engine) at 21.49/25.87/30.92 and below.
  • The headline comparison is fine-tuned on tens of thousands of in-domain examples versus zero-shot baselines on the same retrieval backend. That conflates training with architecture, and the general-agent rows do not run those agents on their native models. Absolute Strict F1 of 39.15 is low; the practical claim is relative, not "solved."
  • The Lenient metric is judged by an unspecified "advanced LLM" with no human validation or agreement statistics; the CAP-8 lenient jump (47.10→55.14) is exactly where a judge can inflate. All supervision (reasoning traces, keywords, necessity labels, reflection) is DeepSeek-V3-generated, much of it with posterior access to the target paper's metadata — QueryPlanner's token-overlap scores measure agreement with that synthetic ground truth, not correctness.
  • Internal inconsistencies: Table 3's "Qwen3.6-27B" is "Qwen3.5-27B" in §5.3/Table 4; the "w/o Master Brain" ablation row (36.33/42.76) is numerically identical to Table 3's undefined "ReCite-Base" row; the prose's "15.99% gain in Lenient F1" is the same model's Strict→Lenient gap mislabeled as a gain. Small N throughout (200 paragraphs; module tests N=3,112 and N=300) with no significance testing. Scope: CS-venue introduction paragraphs, text-only, Semantic Scholar title/abstract metadata as the entire evidence base — no full-text verification.

Collector corrections: "claim-level logical entailment checking" overstates the mechanism — the verifier is a 4B LLM cross-checking candidate title/abstract against inferred intent, and the paper itself contrasts its approach with NLI/theorem-prover verification. "Replacing semantic-similarity citation matching" also overstates — retrieval remains keyword search over Semantic Scholar; the reasoning layer sits on top of, not instead of, similarity retrieval.

Why admit a narrow rank: the design pattern — locate where evidence is required, plan an intent-conditioned query, verify the candidate against the claim, and on mismatch attribute the failure and re-retrieve — is a concrete, falsifiable template for agent retrieval evaluation, with honest ablations (removing CiteLocator collapses Strict F1 to 2.75; removing the Master Brain's verification loop costs ~10 lenient points). It is one of the first closed-loop verify-and-retry citation agents with a released intent taxonomy (CAP-8) and trajectory data. The evidence does not justify adopting its numbers as a benchmark of frontier-model citation ability, treating its verifier as entailment, or importing its LLM-judged Lenient metric without human validation.

BQAA TL;DR — proposed application: the misattribution framing maps directly onto schema/term retrieval in a conversational analytics agent: a retrieved table or definition can be topically adjacent yet fail to support the specific question. A bounded local experiment: for a fixed set of BQAA questions with known-correct table/column ground truth, add a verify step that checks each retrieved schema element against the question's intent before SQL generation, attributes retrieval failures (wrong table vs wrong column vs missing definition), and re-retrieves once. Measure whether verified re-retrieval improves first-pass SQL correctness at fixed latency — not whether the verifier's self-reported confidence rises. Keep human spot-checks on any LLM-judged "support" label.
