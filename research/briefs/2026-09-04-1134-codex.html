Industry

1. Langfuse v4.29.0 and v4.30.0 make baseline-regression review a first-class experiment workflow (September 4)

GitHub timestamps v4.29.0 at 2026-09-04 14:59 UTC / 07:59 PT and v4.30.0 at 16:02 UTC / 09:02 PT. v4.29.0 replaces the experiment chart grid with a compact metric strip, removes an empty Analytics tab, explains empty windows, and makes comparison runs selectable, grouped, and preselected. v4.30.0 then rebuilds the results grid around score columns and adds a “worse than comparison” filter. Its score-by-run matrix places dataset items on one axis and experiment runs on the other, turning the same scores into a cross-run regression view. The current evaluation concepts describe dataset items, experiment runs, scores, and run comparison as the underlying model. Score columns alone appeared in v4.28.1 and were correctly held below bar; comparison selection plus a regression filter plus the matrix now constitutes a coherent shipped review workflow. Both tags predate the morning briefs, so this is a corrected catch-up, not an 11 AM launch.

TL;DR for BQAA. Make the SQL/eval-table story support stable dataset_item_id, candidate and comparator run_id, evaluator/version identity, score direction, and explicit missing-score behavior. A “worse than baseline” view is easy only when those semantics survive ingestion; write the schema/query note, but do not start a bespoke UI.

2. Gemini Enterprise Workflow Builder GA composes published ADK and A2A agents as live steps (September 3)

The September 3 Gemini Enterprise release note declares Workflow Builder—formerly Agent Designer—generally available for manually triggered, scheduled, and @mention-triggered multi-step workflows. It also says customers can import existing ADK and A2A agents for centralized management, sharing, governance, and reuse. The Workflow Builder overview, last updated 2026-09-03 UTC, describes deterministic and nondeterministic workflows, integrated preview/simulation, publishing, sharing, scheduling, and human intervention. The existing-agent step documentation, also last updated 2026-09-03 UTC, narrows the contract: the picker uses published shared agents, passes workflow inputs and outputs through the selected agent, and keeps a dynamic reference that automatically follows the latest live version of the source agent. A2A input-required and ADK RequestInput pause the workflow for a human response before execution resumes. During that clarification loop, the child receives only its own interaction history and initial prompt; other workflow outputs or variables arrive only when explicitly referenced in the step prompt. The dynamic version binding means two executions of an unchanged workflow can invoke different child-agent versions. This GA item sat beside the already-carded Gemini agent-observability views, but its ADK/A2A composition, context, and version semantics are distinct content absent from the catalog.

TL;DR for BQAA. Record the configured child-agent reference, resolved resource/version, and explicitly bound upstream inputs for every invocation; model input-required/request-input as typed pause and resume events rather than unexplained wall-clock latency. ADK should verify parent/child trace correlation and context isolation across that GA path; this is an interop test and documentation note, not a new feature commitment.
