Read this first

  1. Claude Managed Agents can now run "dynamic workflows" (beta, Oct 9). The agent writes a program that runs up to 1,000 agents in phases. The server runs it in the background as a workflow run, and the session's event stream reports it through seven workflow_run.* event types. For analytics, the shape is run → phase → thread. Two gaps matter: a run has no cost of its own (you sum thread usage by workflow_run_id), and no event or field says which phase a thread worked in. → NEW Industry.
  2. TRACE (2610.11678, Prime Intellect) shows that a score change is often a measurement change. Renaming tools cut a scripted agent's score by 0.250 with identical behavior, and rescoring the same trajectories closed the whole gap. On τ²-bench, identical reruns flip 15–36% of outcomes. Two frontier judges disagree on 57% of the same records because one grades procedure. → NEW Academy.
  3. Typed decision models make weak guardrails (2610.12292, USC). This is the model family behind the Decisions/Jev cards. Renaming only the "allow" option drives fail-open to 93–100% on four of six models. Six lines of irrelevant log text raise fail-open from 0% to 63%. An attack-reversed decision is no less confident than the original, so escalating low-margin decisions does not catch attacks. → NEW Academy.

    • Where Do the Tokens Go? (2610.11602, HUST): token cost attributed by activity stage, plus auxiliary-model billing that hides net cost.

NEW

Claude Managed Agents: dynamic workflows (beta). The agent writes a program that runs up to 1,000 agents in phases, reported through workflow_run.* events

Source: https://platform.claude.com/docs/en/release-notes/overview (entry dated Oct 9, 2026), with https://platform.claude.com/docs/en/managed-agents/workflow-runs and https://platform.claude.com/docs/en/managed-agents/multiagent-orchestration (both marked beta, header managed-agents-2026-04-01). SDK types shipped the same day: anthropic-sdk-python v1.13.0 (PyPI 15:29Z) and TS sdk-v0.133.0 (15:35Z), "add workflows, multiagent configuration and thread status filtering to Managed Agents".

  • What shipped:
    • You turn the feature on with multiagent: {"type": "multiagent_20261001", "workflows": {"type": "enabled"}}. The same block also covers subagents, an advisor model, and predefined vs inline agents.
    • The agent writes a workflow: a program that runs agents in named phases, passes results between them, and can repeat steps. The server runs it in the background as a workflow run.
    • Only the agent can start a run. No client event ends one, but archiving the session can.
  • Events (the analytics surface):
    • workflow_run.created carries workflow_run_id (wrun_…), the run's name and description, and the declared phases;
    • status_running, status_idle (paused, for example at the session budget; the event does not say why), phase_started and phase_ended (each with workflow_run_phase_id; the end event also has phase_started_id);
    • status_ended, with a result of completed / stopped / error;
    • workflow_run.error, with error types such as program_error, thread_limit_error, timeout_error and max_workflow_runs_error.
      Each run thread's session.thread_created carries the run's workflow_run_id.
  • Limits and billing:
    • 1,000 agents per run over its whole life, 10 open runs per session by default, and a 24h default run lifetime.
    • A run has "no price of its own". To get one run's usage, list the session's threads and add up usage for the threads with that workflow_run_id. Summing list_cost instead leaves out session runtime.
    • At the session budget, every open run pauses. A run can pass the budget by one request for each working thread.
  • Documented gaps:
    • "No endpoint lists runs." Run state has to be rebuilt by listing past events with a types filter, because the stream does not replay missed events.
    • "No event or field says which phase a thread works in." Threads of one run can share an agent_name.
    • The API "doesn't guarantee" that phases run in order or only once.
  • Context: Claude Code has had a dynamic-workflows feature since May 28, 2026 (claude.com blog). What is new is a server-run version in the Managed Agents API with a documented event contract.
  • Why it matters for BQAA: this is a first-party, documented trace shape for orchestrated multi-agent work: session → run → phase → thread. The vendor itself leaves out per-run cost and phase-to-thread attribution, so an analytics layer that ingests this stream has to compute both.
    • Key thread usage by workflow_run_id.
    • Derive phase membership from timing, and label that attribution as inferred.

NEW — TRACE: Diagnosing Verifier Brittleness in Agentic Evaluation — https://arxiv.org/abs/2610.11678

Gaonkar (Prime Intellect), cs.CL, Oct 8; AI Measurement Science Workshop @ COLM 2026. Full PDF read.

  • Method: run the same task twice, once with a targeted change, and compare scores. Then inspect whether behavior changed, and rescore the unchanged trajectory with a corrected scoring rule (§2, Fig. 1). This separates whole-system sensitivity from evaluator sensitivity.
  • Results:
    • Controlled suite (25 tasks, 1,575 records):
      • tool renaming lowers a scripted "careful" agent's score by 0.250 with identical operations. Alias-normalized rescoring takes the gap to 0.000, while the same mutation exposes a real behavioral failure in a second agent (Fig. 2, §3.1);
      • the "shortcut" policy has the smallest gap (0.006) because it fails in both conditions (Table 2).
    • τ²-bench Study 3 (88 new tasks, 3 runs per condition, analysis fixed in advance):
      • renaming or reformatting is equivalent within ±0.10 for 7 of 8 agent–change pairs;
      • misleading names (the positive control) cut reward by 0.196–0.437 for all four agents (Table 6);
      • identical reruns flip 14.7–16.3% of outcomes, and 35.6% for one agent (§5);
      • Study 2's one significant effect (+0.267) did not replicate.
    • Judges (Table 8): GPT-6.1 Sol and Claude Opus 5.5 are stable under presentation changes, but disagree on 57% of the same records. Opus agrees with native reward on 95% (κ = 0.89) and Sol on 38% (κ = 0.09). In 163 of 201 disagreements, Sol objects only to procedure.
  • Limits:
    • single author;
    • synthetic suite with scripted agents;
    • two presentation changes and four agents;
    • native reward is partly LLM-graded and treated as a reference, not ground truth (§7).
  • For BQAA: store repeat-run IDs and treat the identical-rerun flip rate as a baseline metric. A pass-rate change smaller than that rate is noise. Keep judge identity and rubric with every verdict, because two consistent judges can measure different constructs.

NEW — One Word Opens the Gate: The Option-Channel Attack on Typed Decision Models as Agent Guardrails — https://arxiv.org/abs/2610.12292

Azizi, Baghaei Potraghloo, Pedram (USC), cs.AI, Oct 8. Full PDF read.

  • Setup:
    • Seven open-weight models: five typed decision models (151M–421M parameters, reimplementations of the Jev-style interface) plus a Qwen2.5 baseline at two sizes.
    • GuardBench: synthetic agent tool calls under six policies, with computed ground truth (Table 1).
    • Three public screening sets.
    • Fail-open and fail-closed are always reported separately.
  • Results:
    • Clean accuracy is 36–72% against 50% chance. A low error in one direction only reflects the model's default answer (Table 2).
    • Six lines of routine server log text raise fail-open on a policy the gate otherwise gets right from 0% to 63% (Fig. 3).
    • Option channel: renaming only the permissive label, with definitions and input untouched, takes fail-open to 93–100% on the four models that feed the label into the network (Table 4). The strongest gate (Qwen2.5-7B) goes from 5% to 100% with the label remediate.
    • Correct blocks sit near 0.5 (median P(block) 0.57, §6.4). Reversed decisions are no less confident: margin 0.149 before vs 0.151 after. A 10% review budget only lowers attacked fail-open from 60% to 54% (Table 8).
    • Defenses: every defense is beaten by an adaptive attacker (Tables 10, 12, 13). A deterministic rule over parsed fields is 100% correct on GuardBench (Table 11).
  • Limits:
    • open-weight models only; the commercial Jev model is not measured;
    • GuardBench is synthetic, and a rule solves it by construction;
    • attacks use fixed pools, so the rates are lower bounds (§10).
  • For BQAA: decision events used as gates should log the full typed question (labels and definitions), the label source, and both error directions. The returned probability should not be presented as a confidence or escalation signal.

NEW — OnTrack: Real-Time Monitoring and Intervention in LLM Agent Trajectories via Streaming Structure-Aware Optimal Transport — https://arxiv.org/abs/2610.12375

Barazandeh, Swanson, Kulkarni, Mungel (Cribl AI Research Lab), cs.AI, Oct 8. Full PDF read.

  • Method:
    • Streams each step into a growing dependency DAG and aligns it against recorded successful runs with warm-started unbalanced fused Gromov–Wasserstein, at ~1 ms/step (p50 0.85 ms at t = m = 40, §4.6).
    • Per-step verdicts: OK, EXPLORING, WARN, LOOP, STALLED, CAUSAL INVERSION, OFF TRACK, BLOCK.
    • Three layers: L1 vital signs need no references; L2 alignment needs references; L3 is a pre-execution gate for irreversible tools and needs schemas.
  • Results:
    • SWE-agent traces (2,288): at the first 8 steps, AUROC is 0.631 vs 0.574 for cosine (+0.057, CI [.033, .080]). The advantage is gone by k = 15 (Table 5).
    • Abort policy: severe-flag density stops 23.3% of failing runs at a 20.7% false-stop rate, saving 17.9% of compute on the failed population at ~83% deployment precision (Table 6).
    • Cost-limit detection: AUROC 0.979, equal to trace length (0.978, Table 7).
  • Limits (stated plainly by the authors):
    • On real traces, the structure term changes the operating point (13/40 vs 29–32/40 benign false alarms), not recall (Table 4).
    • In-distribution hallucinations and splices sit near the detection floor (AUC ≈ 0.54).
    • Once length is controlled, no task-generic signal predicts outcome (§6.6).
    • Only five reference instances; the abort threshold was chosen after the sweep.
  • For BQAA: "recorded successful runs" is a warehouse query. A trace store that marks resolved runs and records step-level produce/consume artifacts can serve as the reference set for in-flight monitors. The honest result is loop and stall detection plus cost-overrun early warning, not hallucination detection.

NEW — Safe Actions Alone Do Not Ensure Safe Agents: Identifying Unfulfilled Obligations with Guard Models — https://arxiv.org/abs/2610.11773

Feng, Zhang, Liu, Li (Tsinghua), cs.AI, Oct 8. Full PDF read.

  • Claim: on SusVibes, 56.92% of GLM-5.3 trajectories leave a required safety action undone (an obligation), vs 30.00% that take a forbidden action (Table 1). Those labels were assigned by GPT-5.6-Sol, not by humans.
  • ObligationBench: 240 expert-validated trajectories (120 positive with 2.83 obligations each on average, 120 hard negatives) from SWE-Bench Pro, FeatureBench and Terminal-Bench 2.0. Experts agreed on 82.2% of obligation sets before adjudication (§3).
  • Results:
    • The best existing model reaches recall 48.97% and exact match 10.00%. The three guard models reach ≤5.60% recall, and Llama-Guard-3 returns nothing (Table 2).
    • Recall falls from 42.8% to 25.5% as more actions follow the obligation, and EM falls to 0% at five coexisting obligations (Fig. 6).
    • ObligationGuard (Qwen3-8B fine-tuned on 40K synthetic trajectories) reaches recall 57.52% and EM 21.67%. As agent guidance it raises SecPass from 6.5% to 15.1% with FuncPass flat (Table 4).
    • Benchmark recall tracks the safety gain (ρ = 0.94).
  • Limits:
    • a GPT-5.6-Sol judge matches obligations (95% human agreement on a 400-pair audit, §7.1);
    • one guidance round;
    • one agent model for the guidance experiment.
  • For BQAA: compliance analytics that only flag forbidden tool calls miss the larger class. You need end-of-trace state checks (created secret not deleted, session not invalidated, inspector not disabled) that compare what was opened during a run with what was closed.

NEW — Where Do the Tokens Go? Understanding and Reducing Costs in LLM Agents for Vulnerability Discovery — https://arxiv.org/abs/2610.11602

Lu, Zhao, Chen, Wang (HUST), cs.CR, Oct 8. Full PDF read.

  • Method:
    • 200 CyberGym traces: four agents (Codex, OpenCode, Cybench, EnIGMA) × baseline plus four efficiency methods.
    • 32,924 turns open-coded into nine activity stages: rule labels, LLM review, then a blinded human audit with κ 0.83/0.85 and 94–96% agreement (§2.5).
    • Costs are reconciled against provider usage records, with auxiliary-model billing kept separate.
  • Results:
    • 776.6M tokens in total; 7.0% are auxiliary-model tokens.
    • Code localization (43.1%) and vulnerability reasoning (17.3%) take 60.4% of tokens and 68.7% of failure weight (§3.2).
    • Only 24.4% of method-vs-baseline pairs keep success at lower cost (Fig. 3).
    • Auxiliary billing reverses savings: Codex+Revelio's main-model cost is 0.61× baseline, but its total is 1.15× (Fig. 5). Codex+AgentDiet is 0.74× across all tasks but 1.10× on tasks both runs solved.
    • Their AVRI interface cuts total cost 18.0% (Codex) and 23.7% (OpenCode) without lowering success (Table 3).
  • Limits:
    • one run per configuration, so run-to-run variance is not separated;
    • failure and mechanism codes come from a single coder;
    • one benchmark family (C/C++);
    • no ablations (§6).
  • For BQAA: cost dashboards need per-turn stage labels and an auxiliary-model cost line next to the main-model line. "Cost per success" must be compared on tasks both arms solved, or savings will be overstated.

Six-week EV

  • Run → phase → thread becomes a vendor trace shape. Claude Managed Agents workflows (and Claude Code's local version) produce hundreds of threads per run. The vendor documents that runs have no cost of their own and threads carry no phase. Customers ingesting this stream will ask for per-run cost and per-phase rollups. BQAA should define workflow_run_id / phase columns and an "inferred" flag for phase attribution now.
  • Variance becomes a reported metric. TRACE's 15–36% identical-rerun flip rate and 57% judge disagreement mean single-run eval deltas are not reportable. Expect eval products to add repeat-run baselines. BQAA eval tables need a repeat_index and judge-identity dimensions.
  • Decision-model gates need input-side logging. The option-channel result lands just as the Decisions API spreads (Pydantic AI 2.55.0 this window; LiteLLM, LangChain and promptfoo last window). Logging only the chosen option and probability will not support a security review. The labels, definitions, label source and both error directions must be stored.
  • Absence-type failures. ObligationBench (and last window's CAP omission result) shows the costly failures are omissions. Analytics needs open/close pairing of resources created during a run (secrets, sessions, inspectors), not only per-action policy checks.
  • Approximate vendor analytics. Anthropic's own Cowork distinct counts are HyperLogLog-approximate in date-range mode. Reconciliation against vendor numbers must allow ~2% tolerance on distinct counts and exact match on non-distinct counts.

TL;DRs for BQAA

  • Claude Managed Agents dynamic workflows: up to 1,000 agents per run with workflow_run.* events. No per-run cost and no phase on threads, so sum thread usage by workflow_run_id yourself.
  • Anthropic SDK 1.13.0 analytics: new chat_cowork_unified product. Distinct counts are HLL-approximate (<2%), so reconcile with tolerance.
  • Claude Code 2.1.296: OTel tool_result keeps git_commit_id, Sonnet 5.5 cache-read cost is fixed in cost figures, and adaptive-thinking token counts are corrected.
  • Pydantic AI 2.55.0: every failed fallback attempt is a usage record, cache-health span attributes are added, and there is an OpenAIDecisionsModel.
  • LangSmith SDK 0.14.5: runs carry revision_id from the environment, and sandbox IDs land in tracing metadata.
  • Inspect AI 0.3.278: task/sample descriptions are in eval logs, handoffs go through tool review, and the compaction double-count is fixed.
  • Cloudflare Agents 0.28.0: lifecycle, scheduler, state and MCP client are stable; browser and web_fetch tools are added.
  • 2610.11678 TRACE: tool renaming cost 0.250 with identical behavior, and reruns flip 15–36%. Store repeat runs and rescore before believing a delta.
  • 2610.12292 Option channel: one renamed label gives 93–100% fail-open on decision-model gates, and attacked decisions look just as confident. Log labels and definitions.
  • 2610.12375 OnTrack: a ~1 ms/step monitor against recorded successful runs saves ~18% of compute on failing runs. It catches loops and stalls, not hallucinations.
  • 2610.11773 ObligationBench: unfulfilled obligations exceed forbidden actions (56.9% vs 30.0%). Pair opens with closes in trace analytics.
  • 2610.11602 Where Do the Tokens Go: auxiliary-model billing turned a 0.61× main-model cost into 1.15× total. Show auxiliary cost and compare on jointly solved tasks.
