  • What shipped: five stable Python releases (v3.32.0 2026-10-16T20:17:26Z, v3.33.0 2026-10-17T00:29:04Z, v3.34.0 2026-10-17T20:34:04Z, v3.35.0 2026-10-17T23:13:52Z, v3.35.1 2026-10-18T01:05:46Z) and four stable Node releases (v7.35.0 2026-10-16T20:16:58Z, v7.36.0 2026-10-17T00:28:22Z, v7.37.0 2026-10-17T20:34:08Z, v7.38.0 2026-10-17T23:13:58Z) — all nine bodies read by me via gh api; PyPI openai latest = 3.35.1 re-read by me. Prior card is openai-sdk-node-7-33-0-python-3-31-0-browser-computer-toolsets; this train ranks NEW as one card on the Live/Realtime surface expansion, following the same train-consolidation precedent.
  • The Live surface is the story. v3.35.0/v7.38.0 add typed Live sideband events (Python #4099, Node #2964) — Live sessions gain a typed out-of-band event channel alongside the media path, so session-adjacent signals stop being untyped payloads parsers must guess at. v3.34.0 adds Realtime Translation WebSocket sessions as a named session type (Python #4095; Node v7.37.0 moves onto generated Translation bindings, #2961). The train opens with Decisions inside Live sessions, audio fixture playback in Live, cache settings/key options, prompt-based voice creation, regional processing residency options, and response error diagnostics with model notices (v3.32.0/v7.35.0). Read together, "Live" is becoming a session family — voice, decisions, translation — with its own event typing, not a single realtime socket.
  • The Agents tier name matters for analytics even before its semantics are public. Python v3.35.0's body lists, verbatim, "add ultrafast service tier for Agents" (#4101). I claim only what the release establishes: a new service-tier value named for Agents traffic now exists in the Python SDK's API surface. The Node v7.38.0 body lists only the sideband feature — the collector-reported Node ultrafast merge (#2966) is not in the v7.38.0 body I read, so Node shipment of the tier is recorded under Unconfirmed, not claimed here. v3.35.1 is a one-line Realtime byte-read fix on websockets 13 (#4102), included in the train, not a rank reason. GPT-4-alias shutdown notices (Node v7.37.0, #2959) are noted without weight.
  • Why it matters for BQAA: three new dimensions will start appearing in OpenAI-originated traces and usage rows: session family (Live vs Realtime Translation vs classic Realtime), sideband event types, and service tier including ultrafast. If tier and session-type fields are flattened into free-form attributes at ingest, the first "what did ultrafast Agents traffic cost/latency?" question becomes a backfill. Preserve them first-class now, while volume is zero-to-small. The residency options (v3.32.0) similarly foreshadow region as a queryable field on requests that previously carried none.

LiteLLM v1.106.0 — stdio MCP servers disabled by default (breaking); one-command Docker quickstart; Lens learns Claude Agent SDK traces

  • What shipped: GH Release v1.106.0 published 2026-10-18T05:53:32Z (stable; body read by me via gh api, including its v1.105.0...v1.106.0 compare line); PyPI litellm latest = 1.106.0 re-read by me via curl. Prior card is litellm-1-105-0-stable-lens-beta-agent-trace-investigations-otlp-ingest-clickhouse. The in-window v1.103.5 (2026-10-17T17:02:19Z, body read by me) is a two-fix stable-branch backport (#46949) and is a mention, not part of this rank; v1.107.0-rc.1 is a prerelease and NOTE-only (see mentions).
  • The breaking default is the headline: feat(mcp)!: disable stdio MCP servers by default (#44066). A gateway that silently spawned local stdio MCP servers on configuration now refuses unless explicitly enabled — the safe direction for a proxy that increasingly runs multi-tenant, and an upgrade-breaker for anyone who relied on the implicit behaviour. For an analytics audience the immediate effect is a population change: MCP tool-call traffic through LiteLLM gateways will step down (or error) at this version boundary wherever stdio servers were implicit, and that step will look like a usage drop unless version is joined in.
  • The rest of the minor, judged honestly: a one-command Docker quickstart starting gateway + Postgres + admin UI (#43673) lowers the self-host on-ramp; auto_register_map_existing_key maps a JWT to the user's existing virtual key (#42375), tightening the identity-to-spend join; Lens gains Claude Agent SDK trace support with agent name/logo/chat content (#44248), typed trace queries aligned with log visibility (#44228), and investigation briefs carrying problem/goal/outcome/test-cases (#44311); background interaction billing gets durable cross-pod settlement (#41955) — spend records for async work are exactly where double-counts and drops hide, so durability here is an analytics-correctness feature; ROI reporting adds GitLab sources with branch cost attribution (#44324). The long fix tail (Bedrock/Responses bridging, pricing stamps, guardrails on image edits) is recorded as tail, not rank weight.
  • Why it matters for BQAA: LiteLLM is the gateway most likely to sit between BQAA-adjacent agent traffic and its warehouse copy. This minor changes three joins at once — MCP traffic population (stdio default), identity mapping (JWT→existing key), and async spend settlement (cross-pod durable) — so cost and tool-call series spanning the 1.106 boundary need a version annotation before anyone trends them.
