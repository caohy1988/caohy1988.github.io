Academy

1. FERN: Cross-Benchmark Table Retrieval for Text-to-SQL with Frozen Retrievers and Learned Ranking — reserve promotion, full PDF read

Full PDF read: yes — pdftotext of the complete v1 PDF (20 pp. incl. appendices), read in full including methods (§4), protocol (§5), results (§6, Tables 5–11), discussion (§7), limitations (§8) and Appendices A–B. SAP authors; cs.IR, 10 Nov 2026. Not in catalog (grep: 0 hits). Promoted from the Nov 11 reserve queue because the Thursday batch had not listed (see Unconfirmed).

What it does: three frozen retrievers (BM25, Qwen3-Embedding-0.6B, BGE-large) fuse into a 100-table candidate pool over pooled multi-database catalogs (no target database given); each candidate gets up to 120 hand-built features (retrieval scores/agreement, database support, lexical overlap, value matches, join-graph, question type); LightGBM lambdarank rankers fitted once on 9,394 BIRD training questions order the pool. Zero generative-model calls per question (Table 2).

Key numbers (Table 5, vs RASL's published LLM-linking recall; point differences only — RASL per-question data unavailable, no interval on the gap):

  • Spider (never fitted on, cleanest comparison): recall@5 96.7 vs RASL 97.0 (−0.3); @15 99.1 vs 98.0 (+1.1). The frozen pool alone already hits 98.0 @15; the ranker's real contribution is complete table sets at small budgets — complete@5 83.9% → 95.6% (Table 6).
  • BIRD with evidence hints: @5 96.6 vs 97.5 (−0.9). Without evidence: 89.3, i.e. −8.2 @5 — the question-only row is the deployment-relevant one (§6.1).
  • BEAVER enterprise (121 real log questions, no BEAVER fitting): recall@15 82.1 sits between two BEAVER-trained retrievers (80.8, 84.5), but complete@15 49.6 trails both (54.5, 62.0) — with ~4 gold tables/question, recall flatters; complete-set recovery is the metric that decides whether the SQL can be right (Table 8, §6.2).
  • Fiben (opaque run-together names, single DB): @15 54.2 vs RASL 69.2 on different question sets (298 vs 279; bounded 51.1–57.9 either way) — both candidate retrieval and small-budget ranking break (§7).
  • Cost: median 208 ms/question on one A100, indexes precomputed, no hosted calls, schema never leaves the system (Table 11, §6.4). Feature ablation: non-retrieval features add +7.7 complete@5 over retrieval signals alone on BIRD-ev (Table 9); only database-support and join-graph families individually clear zero (Table 10).

Why BQAA cares: (1) BQAA's table-retrieval stage can treat "LLM picks the tables" as the fallback, not the default — a local ranker is auditable, deterministic (the paper re-ran its pipeline and reproduced every number exactly), and keeps customer schema on-prem. (2) Report complete@k next to recall@k in BQAA retrieval evals; FERN's BEAVER split is the cautionary example that recall hides missing-table failures. (3) The evidence-hint delta (7.3 points @5) prices what curated column/value descriptions and query hints are worth — a direct input to metadata-enrichment ROI.

Limits the authors state themselves (§8): comparison is against published numbers, not a RASL re-run; 9,394 labeled BIRD questions is far more supervision than RASL's 200/question-set calibration — FERN avoids target-domain fitting, not supervision; BIRD dev and BEAVER each informed one documented design exception (§5), so Spider is the only fully clean transfer; retrieval only, no end-to-end SQL accuracy; code/rankers promised on journal publication, not yet released.
