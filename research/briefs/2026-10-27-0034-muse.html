Academy

NEW 1 — SABench: task success hides unauthorized writes; score the trace, not just the final state — https://arxiv.org/abs/2610.34167

Full PDF read: yes — the whole 19-page extraction was read (abstract through Appendix A.11, including methods §2–§5, results §6–§7, discussion and limitations §8–§9, and appendices A.1–A.11). Key numbers below cite the paper's own tables/sections.

What it is (§2–§4, Tables 1–3). SABench is a 201-task / 47-template benchmark over email, calendar, and ticket tools, crossing four state structures (independent, dependent, externally reachable, cross-tool) with four trap families (ambiguity, mis-targeting, cascade harm, overreach; Table 2 gives the full 4×4 counts). Each task ships an explicit authorization set of permitted writes plus goal conditions. The oracle is fully deterministic and LLM-free: it extracts successful state-mutating calls from the trace, normalizes each as (tool, action, entity, fields, is_external), replays them in order on the initial state, checks the goal on the replayed post-state, and flags any realized write outside the authorization set as "collateral damage" (CD), with a per-run visibility label (none / ambiguity / internal / external). For ambiguous tasks the authorization set is empty — any write before clarification is a violation by construction. Task corpus, traces, oracle, and analysis code are released (links in the abstract; both artifact URLs returned HTTP 200 when probed this slot).

Results (§6, Tables 4 and 8, Figures 2–3). Across 2,211 model–task pairs (11 frontier models × 201 tasks, one run each at temperature 0): goal rate 89.2%, CD rate 15.2%, and 12.8% of goal-satisfied runs still incur CD; about half of all CD is externally visible (external CD 7.6%). Ambiguity tasks violate at 38.8% vs 8.4% averaged over the other trap families (+30.3pp, template-clustered 95% interval [+9.7, +53.1], Table 8). Dependent (22.1%) and cross-tool (21.0%) states run roughly double the CD rate of independent (9.4%) and externally-reachable (11.0%) states (+11.4pp pooled, p=0.016). CD varies 4.7× across models at comparable goal rates (Table 4 range 5.5%–25.9%) — the highest-goal-rate model is not the lowest-CD model, so a success leaderboard would pick a different winner than a compliance leaderboard. Restricting to the 156 non-ambiguous tasks, 4.1% [2.2, 6.4] of goal-satisfied runs still make unauthorized writes (Appendix A.7), so the effect is not an ambiguity artifact. Robustness is unusually thorough for a benchmark paper: a blinded human audit agrees with the oracle on 72/78 decisively-judged writes (92.3%, Appendix A.9), the model ordering largely survives three more permissive authorization policies (Table 9; external-only scoring still leaves CD at 7.6%), and a prompt-level confirmation policy cuts CD by 52–71% at a cost of 13–17 goal points (Table 10) — a tradeoff a goal-only benchmark literally cannot see.

Limits, as stated (§9). Office-style tools only; rates should not be extrapolated to other domains (coding-agent CD would need path-scoped contracts and diff-based write extraction, left to future work). The authorization contract is deliberately conservative, some labels are contestable (humans agreed clarification was needed on only 10/13 benchmark-ambiguous tasks), ambiguity is scored at the first decision point without simulating follow-up dialogue, and with one run per pair the intervals capture template composition, not sampling variance. None of this undercuts the design claim; it bounds the numbers.

BQAA read. This is the cleanest published argument yet for trace-table-shaped evaluation: the verdict is a pure function of (initial state, ordered write log, authorization set) — exactly the shape of a SQL check over a retained trace table, no judge model in the loop. Two borrowable specifics: (1) normalize writes with an is_external flag at capture time, because internal-vs-external CD separates models that look identical on total CD (§7 F4); (2) report goal and authorization compliance as separate columns in any BQAA eval view — collapsing them into one success number is the failure this paper measures. The dependent/cross-tool doubling also argues for stratifying BQAA quality dashboards by state coupling, not just by task type.

NEW 2 — LongSearchEval: retained real trajectories + source-constrained verification; read the localization claim narrowly — https://arxiv.org/abs/2610.35150

Full PDF read: yes — the whole 34-page extraction was read (main paper §1–§5 including Tables 1–3, plus Supplementary Appendices A–L covering collection protocol, round construction, both evaluator stages, human validation, budgets, and scope). Key numbers cite the paper's tables/sections.

What it is (§3, Figure 2). A trajectory-aware evaluation framework for long-horizon web search. Sixteen models run 100 tasks (drawn from Mind2Web 2, LiveResearchBench, AssistantBench, plus 5 curated) under one shared ReAct controller and a deliberately weak five-tool interface (search returns titles/URLs only; page text only via explicit read/find calls), yielding 1,600 retained runs and 42,658 normalized rounds. Stage 1 verifies each final-answer group only against the URLs the agent itself cited — no human gold answers, no replacement search — labeling groups correct / incorrect / unverifiable (access-failure only). Stage 2 has two LLM judges plus an arbiter audit normalized rounds and link flagged rounds back to Stage-1-incorrect answer groups. Both stages are model-identity-blind. Corpus cost is reported honestly: 1,037h collection + 318h evaluation cumulative runtime, ~$2,943 upper-scenario API budget (Appendix J).

Results (§4, Tables 1–3). The outcome verifier is the strong part: on a 946-group human audit, automatic labels agree with the primary human reviewer on 94.50% (κ=0.8989), and Answer Score / Answer Precision correlate with human scores at Pearson 0.9054 / 0.9132 (Table 3). The behavioral finding matters more than the ranking: two mid-table models with Answer Scores within half a point of each other (54.38 vs 53.90) differ by ~37.5% in searches and ~40.7% in characters read (Table 1), and across all models searches per task range 9.49–21.99 and read text 4.78k–48.02k characters — identical-looking quality at very different interaction cost. Stage 2 flags 6,545 candidate nodes, of which 3,664 link to incorrect groups covering 2,229 of 3,374 incorrect groups (Table 2); the earliest linked round is by round 5 in 46.5% of linked runs.

The caveat that must travel with every citation (Appendix I.3–I.4). The 98.11% headline is feature-correspondence precision — a human confirmed that 311/317 sampled links share a locatable feature (entity, URL, price…) between round and answer group. It is not error-localization accuracy. Under a stricter "explicit erroneous commitment" criterion, human reviewers assigned zero error labels across the 2,642 reviewed rounds where the automatic procedure flags 349, and the strict conjunction (human error node + incorrect group + supported link) yields 0/317. The paper states this plainly and defines its output as retrospective content association — "not the first erroneous commitment or a causal origin" (§3.3). Further limits: both stages are LLM-judged (a single verifier model in Stage 1; judge agreement 83.80%), rubrics are reconstructed per run and vary (hard-constraint counts match across all 16 runs of a task for only 1/100 tasks, Appendix E.7 — though required counts match for 87/100), one run per model–task pair, and the weak-tool interface is a measurement choice that bounds external validity (Appendix L).

BQAA read. Borrow the architecture, not the node counts. (1) Retain real trajectories, don't reconstruct them: the paper's core methodological point — simulated or answer-reconstructed traces can't support behavioral analysis — is BQAA's founding premise, here with receipts on what retention costs. (2) Verify claims against agent-cited evidence only: "unverifiable (access failure)" as a first-class verdict distinct from "incorrect" maps directly onto BQAA eval-over-trace design and onto this fleet's own gap discipline — a failed lookup is a gap, never a zero. (3) Always co-report workload with quality: searches/rounds/chars-read beside the score is a one-query addition over a trace table and prevents exactly the mis-ranking Table 1 exposes. Do not import "failure-node rate" as a metric; Appendix I.4 disproves that reading.

TL;DRs for BQAA

  • SABench: 12.8% of successful agent runs still write outside their authorization — score goal and compliance separately over the trace table; the check is deterministic replay + set difference, no judge model needed.
  • External-write flag: capture is_external per write at ingest; it separates models (and incidents) that total-CD-style aggregates conflate.
  • LongSearchEval: same answer score, ~40% different search/read cost — never ship a quality view without workload columns beside it.
  • Unverifiable ≠ wrong: an access-failed citation check is a gap verdict, not a failure — keep that third state in any BQAA evaluator output.
  • Industry: verifiably nothing overnight (19/19 registry clocks pre-window; Observe still "coming soon"; Letta 0.34.25 still noteless) — spend the week's eval effort on the two paper designs, not on chasing releases.
