1. NEW rank: An Empirical Study of Harness Design for Coding Agents — 176 matched settings across 4 models × 2 benchmarks: context management is worth +35.7pp at 32k windows but +2.7pp at 128k (it's mostly overflow prevention), planning flips from +11.6pp accuracy on weak models to −30% cost on strong ones, and "lossless" recall tools go unused 56% of the time

Run-Ze Fan, Zihao Zhang (equal contribution), Simin Ma, Yebowen Hu, Shouju Wang, Kaiqiang Song, Fei Liu, Hamed Zamani, Xiaoyang Wang (UMass Amherst / Emory / UNC Charlotte; Zoom internship). v1 2026-09-17; cs.AI (cross cs.CL, cs.LG, cs.SE); 43 pages. Full text read incl. limitations + appendices 7–9. (PDF)

  • Design: a lightweight ReAct-loop harness (LangGraph + Harbor containers) with a fixed execution loop, independently varying planning, action space (predefined tools vs bash-only), and context management (5 tiers T0–T4, none → staged elision→recall→summarization). 176 settings = 22 per model–benchmark pair (T0–T4 × 32k/64k/96k/128k + 2 ablations at T4/128k) across Nemotron-3 30B/120B/550B (within-family scale) + Mistral-Medium-3.5-128B (cross-family), on SWE-Bench Verified (500) + Terminal-Bench 2.1 (89). Paired exact McNemar + Benjamini–Hochberg FDR 0.05; trajectory phase-labels by GPT-5.5 judge validated against 3 humans (94.2% agreement, κ=0.929).
  • Headline results: the value of context management (managed − T0) shrinks with budget: +35.7pp at 32k → +2.7pp at 128k on SWE-Bench (+9.5 → +2.8pp on Terminal-Bench) — because T0 overflow deaths fall 78.7%→8.7% as the window grows, and managed tiers never overflow. T4 (elision before summarization) is the lowest-cost tier at every budget with comparable accuracy. Null result: the lossless recall_event tool goes uncalled in 56.3% of T2/T4 settings and adds nothing (T2 vs T1 mean −0.36pp). Planning: +11.6pp success for the 30B model on SWE; for 550B/Mistral it instead cuts cost ~30–32% at −2.0/−0.4pp success. Bash-only action space: the 30B model collapses (66% of Terminal-Bench runs die emitting unresolvable out-of-interface calls); the 550B gains +3.6pp SWE / +5.6pp TB at −53%/−30% cost; Mistral splits by task type (+23.2pp tools on SWE, +6.7pp bash on TB).

Mandatory qualifications (authors' own): single planning instantiation and one threshold policy; the action-space ablation is a bundled interface change (tools + prompts + diagnostics confounded); planning/action-space ablated only at T4/128k (no full factorial); one run per task; Terminal-Bench n=89 leaves many contrasts underpowered (conclusions rest on directional consistency); SWE-Bench is Python-only; model size is an imperfect capability proxy; crossover points need revalidation before transfer.

TL;DR for BQAA: (1) Track context overflow as a first-class failure class — most of context management's "accuracy gain" is preventing truncation deaths; attribute failures to overflow vs reasoning before crediting model quality. (2) Instrument out-of-interface tool-call emission rate — 66% of weak-model bash-only trajectories died on unresolvable calls; this cheap metric predicts collapse better than success-rate deltas. (3) Eval hygiene worth copying: paired McNemar + BH-FDR per comparison family, LLM-judge phase labels human-validated (κ≈0.93) before scaling behavioral claims, and cost reported beside accuracy since planning/tools routinely trade one for the other. (4) The recall-tool null is a warning for any "give the agent more memory" proposal: unused affordances are not improvements.

2. NEW rank: How Do Agent Harnesses Create Value? Planning Information and Release Control in Stateful LLM Agents — Fixed plans beat word-count-matched Sham plans by only +7.17pp verified success (90% CI [1.15, 13.36]); a sub-cent read-only terminal verifier rejects 61% of oracle-invalid episodes and captures ~97% of the full harness's avoided false-pass at ~1/12 the cost

Yukun Zhang (CUHK), Kemu Xu (U. Edinburgh), Yishen Chen (CUHK Shenzhen). v1 2026-09-17; cs.AI; 56 pages. Full text read incl. §5–7, Table 5, appendices. (PDF)

  • Design: decomposes harness value into planning information and terminal release control, priced against success, false-pass, and cost. Key methodological novelty: a word-count-matched Sham control — shuffled policy vocabulary in the same <task_plan> wrapper — isolating plan content from merely adding context. τ²-bench Retail + Airline; the primary Fixed−Sham sample is 265 model–task–replication matched cells (Retail planner block: 1,227 trajectories, 5 models, 24 tasks, Minimal/Fixed/Sham/Self); 90% task-clustered bootstrap (5,000 draws). Verifier = same model as executor, read-only, last ≤8 messages truncated, no DB access.
  • Headline results: Fixed−Sham = +7.17pp verified success (90% CI [1.15, 13.36]); high-complexity split +13.01pp vs low +2.11pp (exploratory, single partition). Sham−Minimal placebo +1.89pp, CI crosses zero. Heterogeneity is stark: Qwen +13.33pp vs Kimi −1.45pp at near-identical baselines; no per-model effect survives Holm correction. The verifier is the workhorse: rejects 83/137 (61%) of oracle-invalid episodes, withholds 16/92 (17%) correct; false-pass rate 57.21% → 20.96% at $0.0079/episode. Verifier-only captures 48.38pp of Full Fixed's 49.82pp avoided false-pass at ~1/12 the incremental cost — and Full Fixed has a negative success delta (−4.11pp) in the high-risk stratum. Capability probes (PF/TCC/FDS) predict nothing (ΔR² +0.002).

Mandatory qualifications (authors' own + adjudication): sample selected on Minimal success ≥0.05 and mutation status; 213 missing cells; Airline is a 6-task pilot; public benchmark (training-contamination risk); plans manually authored with unrecorded information access (only substring leak-guards); Sham is word salad, not a coherent-but-useless plan; no preregistration; hosted-endpoint revisions unlogged; no public repo at v1; 90% (not 95%) intervals; most secondary contrasts cross zero.

TL;DR for BQAA: (1) Adopt the Fixed–Sham placebo pattern for any BQAA harness-feature eval (prompt packs, plan injection): control for token count and wrapper, or "planning gains" may be context effects. (2) Log oracle correctness (Z), agent-claimed-done (S), and verifier rejection (R) as separate trace fields — false-pass = S·(1−R)·(1−Z) is directly implementable in an eval schema, and conflating them is how bad agents look good. (3) Cheap terminal verifiers are high-ROI guardrails — ~$0.008/episode bought a 36pp false-pass reduction — but budget the 17% false-rejection cost, and note the full harness stack was worse per dollar than the verifier alone.

3. NEW rank: Chronicle: Cut-Point Replay for Regression Testing of LLM Agents — records runs at non-deterministic boundaries as immutable envelopes (23 µs/crossing); cut-point replay serves a subset from record and executes the rest live, turning a production incident into a $0, bit-stable CI regression test — killing 62% of behavior-changing mutants where a stub-everything baseline kills 0%

Tisha Chawla, Susheem Koul (equal contribution; Microsoft). v1 2026-09-17; cs.CL (cross cs.AI); 6 pages. Code: github.com/theagentplane/chronicle. Full text read incl. §5 Table 2. (PDF)

  • Design: agent failures can't be reproduced by re-running (non-bitwise-reproducible inference, drifting tool state, multi-step trajectories). Chronicle records each run at annotated non-deterministic boundaries (model calls, tool calls, routing decisions) as immutable input/output envelopes; cut-point replay serves a chosen subset of crossings from the record while executing the complementary subset live under new code — so a recorded incident plus an assertion becomes a deterministic regression test of a candidate fix. A per-name call-count check on stubbed crossings keeps fixtures honest as the agent evolves.
  • Evidence: 6 recorded incidents (refund sizing, currency mismatch, notional-vs-quantity trade, over-broad email audience, payout-account injection, prod file deletion), 18 boundary sites. Recording overhead 23 µs/crossing median, store ≤1.44 KB/crossing; against a real local model (Qwen3.5 4B, 50 interleaved calls/arm) the mean diff is +91 ms with CI crossing zero. Full replay: 0 model calls, 0 divergences across 20 repetitions; 1,000 replays = $0.00. Fault detection 6/6 expected verdicts; tolerates 30 benign rewordings. Mutation study (192 first-order mutants of guarded tools): cut-point replay kills 51; the stub-everything baseline kills 0. 110 survivors are provably unkillable from these recordings; among behavior-changing mutants on the recorded input, 51/82 (62%) killed; no surviving mutant lets the recorded unsafe action through.

Mandatory qualifications (authors' own): small (n=6), self-constructed benchmark; 3-step incidents without loops/retries/multi-agent routing; model boundaries are simulated/deterministic — no reproduction measured against a live provider; incidents/guards/assertions co-written (validates the mechanism, not general fault detection); no streaming or concurrent tool calls; recorded exceptions not re-raised; count-preserving reorderings escape the check; envelopes miss hidden internal state; the shipped LLM-as-judge is not evaluated.

TL;DR for BQAA: (1) Record at boundaries, not just traces — immutable input/output envelopes per model/tool/router crossing make warehouse-stored incidents replayable test assets; BQAA's OTel spans are already 90% of this. (2) Per-name call-count checks are a cheap fixture-freshness guard — when a stubbed boundary's crossing count changes, fail loudly and re-record rather than silently pass. (3) Stub-everything baselines are vacuous — 0/192 mutants killed means full-mock tests cannot exercise tool-gate logic; cut-point replay is the minimal design that actually tests guardrail changes against real recorded arguments.

NEW rank: AgentPProf: Semantic Profiler for Long Horizon AI Agents — pprof-style flame graphs for agent trajectories: 0.764 B³ F1 against human task segmentation, up to +0.117 MAP on fault localization, failed runs spend 44.6% of steps in "recover interaction" vs 12.0% for successes, and one profile-guided one-line fix cut agent tokens 19%

Code: github.com/eunomia-bpf/agentsight. From the AgentSight eBPF-observability group. Full text read incl. §5 tables. (PDF)

  • Thesis: existing agent observability is per-execution debugging/tracing, not cross-run aggregate profiling. AgentPProf adapts systems profiling (pprof/flame graphs) to trajectories: all activities (prompts, LLM calls, tool invocations, system effects) become uniform "operations"; a query-time "operation stack" replaces the runtime call stack for hierarchical cost attribution; "recursive operation segmentation" (an LLM agent cutting trajectories at responsibility transitions, naming intervals verb-first — "diagnose authentication") supplies the stable identifiers that fold across sessions. Output is standard pprof protobuf readable by go tool pprof.
  • Evidence: segmentation vs human stages 0.764 B³ F1 (+0.101 over the best automatic baseline); fault localization beats each benchmark's own diagnostic by +0.031 / +0.107 / +0.117 MAP (all significant; the abstract's "up to 56%" is the relative gain). Failure differential: failed web-agent runs spend 44.6% of steps in "recover interaction" vs 12.0% for successes (matches expert looping labels, AP .634 vs .398 random). One profile-guided one-line fix: −19.0% agent tokens at fixed quality on 23 held-out ToolSandbox scenarios. Scale: 405 trajectories segmented in 37 min; profile construction sub-second (1.16 s for 27,765 ops, +1.14% memory). Data: 41 real long-horizon coding sessions + a 42-session developer history (1,252 prompts, 1.38B tokens) + 440 AgentRewardBench + 405 CodeTraceBench trajectories; ground truth hidden from methods until outputs frozen.

Mandatory qualifications (adjudication; no dedicated limitations section): benchmark trajectories average 8–52 ops (short/medium — long-horizon coverage rests on 42 workstation sessions); the Git-deployment case is n=3; segmentation depends on a frontier LLM (a small-model segmenter degrades to 0.448 B³ F1 on OSWorld-Human); residual error is over-segmentation; the token repair is a single one-line fix; adaptive triggering/runtime control are future work.

TL;DR for BQAA: (1) Adopt the uniform-operation + query-time-stack schema — one record type for prompts/LLM calls/tools/system effects with additive measures enables warehouse-side re-aggregation by task/session/action without re-ingesting traces; it maps cleanly onto folded-stack tables in BigQuery. (2) Differential profiles (failed minus successful runs per task) are a cheap, high-signal artifact — the 44.6% vs 12.0% recovery-loop gap is the kind of number a harness should emit automatically per task. (3) Their eval hygiene is worth copying: ground truth hidden from the LLM segmenter until outputs are frozen. (4) Profiling complements, not replaces, per-trace debugging (+0.03–0.12 MAP as a tie-breaker, not a landslide).

NEW rank: Silence Is Endorsement: Verification-Status Laundering in LLM Agent Pipelines — handoffs preserve "authorized" while losing "never verified": removing one (UNVERIFIED) tag rockets risky-action approval 5%→60% (Llama-3.1-8B) and 9%→98% (Qwen2.5-14B); memory compression launders status in up to 90% of hops; re-adding the tag recovers only 15–27pp

Yibo Hu (sole author; Jetstream2/Indiana U. ACCESS + Chameleon testbed acknowledged). v1 per abs-page submission history 2026-07-25 (surfaced in the September listing above the prior ceiling); cs.CR (cross cs.MA); 22 pages. Code/data: github.com/yibo-hu-lab/verification-status-laundering. Full text read through Appendix K. (PDF)

  • The failure mode: safety monitors judge actions from rewritten handoffs, not original evidence. Handoffs preserve the claim "this action is authorized" while dropping the "(UNVERIFIED)" provenance attached to it — verification-status laundering. Unlike prompt injection, nothing is inserted; the exposure is status loss in ordinary summarization/memory steps.
  • Evidence: controlled probe (n=56 hand-authored items, 40 risky + 16 safe controls; 4 conditions: no-claim / marker-visible / marker-lost / explicitly-verified; paired bootstrap CIs): Llama-3.1-8B approval 0.052 → 0.601 (Δ +0.549 [0.450, 0.640]); Qwen2.5-14B 0.089 → 0.975; DeepSeek-V4-Flash 0.060 → 0.985; GPT-4o-mini 0.480 → 0.995; CI excludes zero on 7/9 open-weight monitors. Null result that matters: Qwen2.5-3B, Mistral-7B, Gemma-2-9B approve the marked unverified claim anyway (Mistral Δ=0.000) — the marker only helps already-cautious monitors. External validation: Δclaim +.143 on WildGuard (754 harmful/971 benign), +.205 on ATBench. Memory is the worst channel: semantic status loss 0.36–0.90 across 5 compressors vs 0.10–0.13 for summarizers. End-to-end proposer→summarizer→memory→monitor pipeline: risky approval 0.57–0.81 vs ≈0.00 marker-visible; re-adding a trailing tag recovers only 15–27pp. Fidelity control: status wording survives 0.59→0.98 of hops yet risky approval stays 0.42–0.48 — lexical survival ≠ bound status. Policy-instruction fix is inconsistent (fixes Qwen2.5-14B/7B, backfires on 1.5B, Llama-3.1-8B over-refuses verified-safe).

Mandatory qualifications (authors' own + adjudication): hand-authored small probe (n=56); model-annotator audits (Claude Opus 4.8 + GPT-5.5, κ=0.79–0.87) with no human gold labels; reinsert/placement ablations on n=15 (n=4 bindable) are directional; forced-choice single-token logprob estimator; smaller open-weight judges proven unreliable as annotators (κ≈0.09); deployed systems "may differ in prompts, thresholds, action spaces"; no complete provenance architecture implemented — the structured-state fix is proposed, not built.

TL;DR for BQAA: (1) Trace provenance must be structured state bound to each claim, not prose — summarizers and memory compressors strip it even when the words survive; any BQAA pipeline that rewrites spans before a judge sees them is a laundering candidate. (2) The 4-condition Δstatus probe (none / visible / lost / verified) is a cheap, high-signal regression test for monitor evals — directly runnable in harness CI. (3) Don't ship "instruct the monitor to reject unverified" as the fix — it trades vulnerability for over-refusal inconsistently across models. (4) Pairs with the 0034 implicit-trust card: per-channel scoring blind (then), per-handoff status loss blind (now) — both argue for cross-hop provenance as a first-class telemetry dimension.
