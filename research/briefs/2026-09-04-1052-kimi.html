Industry

1. Mastra 1.64.0: feedback review workflow in the observability API, evals as Vitest tests (tagged Sep 4, 06:14 PT — missed at 0946)

Verified from the full release notes. The observability-relevant changes:

  • Feedback review workflow. Feedback records now carry a reviewStatus (needs-review | reviewed, defaulting to needs-review, settable at creation). listFeedback accepts a reviewStatus filter, there is a new updateFeedbackReviewStatus storage method, and a PATCH /api/observability/feedback/:feedbackId/review-status server endpoint (gated on observability:write) is exposed through @mastra/client-js. This is the triage loop for human/agent feedback over traces: queue the unreviewed, drain the queue.
  • @mastra/evals/vitest. A new test-runner integration that runs runEvals as Vitest tests with expectEvals/expectEval matchers and a reporter printing per-test scores — eval results as a CI gate rather than a dashboard.

The rest of the release is agent-runtime plumbing (reusable E2B sandbox templates, unified workingDirectory across sandbox providers, client-tool toModelOutput, a breaking sandbox-factory change) — off-beat, as with the Sep 3 Sandbox Lifecycle Controls post ruled off-beat at 2134. Carded under the same precedent as the existing mastra-feedback-redaction-multiturn-evals-token-cost-control card: Mastra minor releases that touch feedback/evals are in-beat.

TL;DR for BQAA. Two column notes, nothing to build. First, review status is becoming a standard field on feedback/score rows: Mastra now stores needs-review/reviewed on the feedback record itself, Braintrust shipped blind-review independence settings, Langfuse has annotation queues — three vendors converging on "human review state is data in the store, queryable like any other column." BQAA's feedback/score table should carry a review-state column (plus reviewer identity and timestamp) so "show me unreviewed negative feedback this week" is a WHERE clause. Second, the vitest runner is a vocabulary note: evals-as-CI-tests keeps spreading (LangWatch's testing v2 already carded); BQAA's docs story for CI is "assert against a SQL query," which stays simpler — one sentence in positioning, no feature.
