NEW — Vercel CLI budget-alert history makes spend-control configuration inspectable

Primary: October 23 announcement, timestamped 21:44 UTC / 14:44 PT in the official feed; stable functionality documented in the CLI reference.

The useful new surface is vercel budgets alerts: a chronological record of budget thresholds, spend, budget amount and configured actions, with time filters, pagination and JSON output. Budget viewing, setting and removal share the team's dashboard configuration. Access requires the Owner or Billing role; availability covers Pro and Enterprise Flexible Commitment teams.

Timing qualification: the base budgets command dates to CLI 59.23.0, and alert history requires 65.2.0. npm dates those distributions to September 18 and October 22 23:33:51 UTC, respectively. This card admits the in-window product announcement and its newly documented alert-history workflow; it does not claim either binary first shipped in this window.

The alert's actions column records configuration, not action completion. Spend is checked every few minutes, so threshold crossing and intervention can differ in time. Pausing affects production deployments; AI Gateway API-key usage, v0 usage and retained-storage charges can continue. Setting an amount alone does not stop usage. These limits are explicit in the Spend Management documentation.

BQAA inference: distinguish budget configuration, observed threshold, requested intervention and observed enforcement. Preserve team and billing-cycle scope. A threshold alert is neither an execution receipt nor a hard cap on total agent spend.

Progress — Pydantic AI 2.61.0 carries structured citations through supported history and UI paths

Target catalog item id: pydantic-ai-v2-57-0-approval-reviewer-mcp-apps-service-tier-pricing.

Primary: v2.61.0, stable, October 24 03:13:40 UTC / October 23 20:13:40 PT; PyPI 03:55:19 UTC, unyanked.

TextPart.citations gives supported providers a common source-and-anchor representation while retaining provider-specific citation data. Positions that cannot be validated receive no normalized anchor rather than a guessed one. Citations attach to text, not arbitrary structured tool-output fields. Released citation design.

History replay is deliberately narrower than storage: eligible web-search citations and Responses URL/file annotations return only to the originating provider under documented identity and text checks. Document-position citations fall back to plain text because trimming or rearranging history can make the same index identify a different document. Same-length text edits are not reliably detectable; callers must clear citations when editing. Released replay behavior.

The Vercel adapter preserves citations in text metadata and exposes web sources, but merged text can make a citation ineligible for replay. Late-arriving citations after a text part has ended are retained in dumped messages rather than guaranteed in the streamed UI path. Adapter scope.

BQAA inference: retain source identity, answer anchor, provider, transformation history and replay eligibility separately. Citation presence is provenance supplied by a model/provider, not an independent factuality score. This is one release update, not separate cards for its component changes.

Primary: 1.8.9 release, stable, October 24 02:35:39 UTC / October 23 19:35:39 PT; PyPI 02:32:37 UTC, unyanked.

A custom llm_node can attach attributes to the provider's llm_request span through telemetry.gen_ai.set_llm_request_attributes. This enables prompt-name/version attribution at the generation that backends consume. Attributes apply to actual provider attempts, including failed and serving fallback attempts, while background recovery probes do not inherit them. They are scoped to the node's calls rather than leaking into the next node. Released attribution behavior.

SessionReport.duration now falls back to session elapsed time when no audio-based duration exists. Audio-recorded sessions retain the existing audio-based measurement. Consumers should preserve the duration basis: this repairs missing values but does not make the two clocks identical. Released duration behavior.

BQAA inference: distinguish user-serving attempts, failed attempts and recovery probes when joining prompt versions to outcomes. Record whether duration means session elapsed time or recording duration, and stop coercing a missing duration to zero. Gateway decision-client availability remains qualified in Unconfirmed.

NEW — EpiSEM-Bench: Evaluating Safety and Evidence Recovery in LLM Agents under Missing Evidence — arXiv:2610.31650

Full PDF read — 29 pages. The benchmark pairs 300 prohibited/permissible tasks across six domains. It removes annotated facts from every ordinary-tool exposure while retaining the complete world for an executable oracle. A valid recovery query returns all omitted facts; the agent must choose to query and then choose the appropriate action (§§3.1–3.4).

The measurement distinction is the contribution: unsafe-commit rate counts tasks with any unsafe execution, whereas omission-failure frequency averages tested conditions within tasks. For the evaluated GPT-6-Luna configuration, those are 21.0% versus 7.9% (Table 8). Paired Useful Recovery requires evidence acquisition followed by restraint in the prohibited world and completion in its safe twin. It is 30.5% for that configuration and 58.4% for the evaluated DeepSeek-V4.1-Flash configuration (Table 1); this is not a general model recommendation.

Recovery's benefit must use aligned masks. Table 9 reports fewer affected unsafe tasks for all ten configurations, but one loses safe-world completion, and individual tasks can regress. Adaptive coverage differs by model and setting (Table 7). There is one rollout per condition, requested temperature zero and a 12-step budget (Appendix E); the minimum observed failure boundary is not a probabilistic safety guarantee. Deterministic, complete recovery is an easier evidence service than many production systems provide.

BQAA inference: store the missing-fact mask, recovery attempt/result, action order and both permitted/prohibited outcomes. Pair safety with legitimate completion; count a tool query, evidence delivery and useful recovery separately. Compare recovery overhead on matched conditions, not unequal aggregate populations.

NEW — What the Specification Did Not Say: Specification-Oracle Gaps in Test-Graded Coding-Agent Benchmarks — arXiv:2610.30635

Full PDF read — 13 pages. A static audit separates dependencies supplied by the task/base code from hidden names, paths and literals demanded by reference tests. On SWE-Milestone, 25 of 98 graded milestones contain a hard hidden name/path dependency, although only 0.6% of required tests are at risk overall (Table 2). A few hidden dependencies can block a whole compilation/collection unit.

Affected units fail in 80.6% of observed unit/run pairs versus 48.4% for comparison units containing new tests within the same milestones (§6.2). That comparison is observational. A separate Go-only counterfactual renames one hidden identifier in reference code and prevents compilation in 126 of 128 cases, supporting the blocking mechanism without measuring how agents would respond to repaired instructions.

The paper does not overturn the leaderboard: full filtering gives score-ranking Kendall τ 0.984 for its 28 leaderboard runs, and neighboring ranks remain poorly resolved (Table 3, §6.3). Held-out precision is 58/65, while recall is estimated from only 14 positives (§6.4). Lexical matching misses behavioral gaps; cross-benchmark comparisons use different review units; proposed specification addenda were not evaluated with new agent runs (Limitations, Appendix I).

BQAA inference: classify evaluator/specification defects separately from agent failures. Preserve the test's dependency, build-unit blast radius, specification version and grading policy. Re-scoring after removing tests changes the measurement; it is not evidence that the agent became more capable.
