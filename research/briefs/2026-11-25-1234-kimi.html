Read this first

Honeycomb supplies the strongest industry measurement in this slot. Its weekly MCP tool calls grew from tens of thousands in February to more than one million by October, while human-run queries stayed roughly flat. Agents issue dozens of wide, long-range queries in bursts, changing the economics of its retrieval fleet. After a Lambda Managed Instances migration plus months of telemetry-guided performance work, Honeycomb reports cost per hour of customer data queried down about 40% in the US and 56% in Europe from April, while query volume grew about 30%. This is a combined architecture and engineering result, not a claim that flipping the compute service alone produced the savings.

Cloudflare’s Search for Agents turns website indexing and a discoverable retrieval endpoint into a zone-level toggle. It returns retrieved Markdown rather than a generated answer and supports both GET and the proposed HTTP QUERY method. The launch supplies no measured discovery rate or retrieval-quality evaluation; its agent:* metadata is guidance an agent may consume, not authority or evidence of a correct answer.

The Academy reads all attack hidden variance in evaluation. A system-prompt date flips a median 6.6% of test items between correct and incorrect across six models and four benchmarks, yet none of 11 audited evaluation stacks pins it. Repeated runs identify within-task hazard only under explicit independence, selection and cross-section assumptions. Kernel traces test whether coding agents’ stated performance mechanisms actually occurred: among 82 analyzed PRs, 32 ran faster, 28 showed no clear change and 22 ran slower, while 42 changed workload output.

Material Progress lands on Pydantic AI authority gating and usage accounting, Opik’s SQL/guardrail surfaces, LiveKit decision-model fallback and job logs, and Mastra durable experiments. 1. Honeycomb measures agent-driven query growth and cuts retrieval cost after telemetry-guided migration

Primary: https://www.honeycomb.io/blog/outgrowing-lambda-functions-not-lambda (published 2026-11-25T14:39:00Z, in-window).

Honeycomb says weekly MCP tool calls rose from tens of thousands in February to over one million by October, most of them queries; human-run queries were roughly flat from 2024. An investigating agent asks dozens of questions, often wide and long-range, turning formerly spiky retrieval into a steadier baseline while preserving large bursts. Honeycomb moved the bulk of query compute to AWS Lambda Managed Instances, added concurrency attributes to runtime spans, and used execution-environment network statistics and hardware counters to guide optimization.

The final comparison uses cost per hour of customer data queried, indexed to April and public AWS prices with an ordinary one-year Compute Savings Plan. It falls about 40% in the US and 56% in Europe while query volume grows about 30%. The post also reports S3 SlowDown errors falling from 1.31% of requests on Lambda Functions to 0.0001% on LMI. Keep the qualifications beside the numbers: these are vendor-reported, region- and workload-specific results from the migration, capacity tuning, compression, query routing and many code changes together. An earlier denominator change had created a misleading 60% improvement reading, which is why the fixed customer-data-hour denominator matters.

Why it ranks. This is a measured production engineering result directly relevant to agent analytics, not a product-release claim. BQAA should separate interactive human and agent query mixes, record burst width/range and concurrency, and choose cost denominators that the optimization itself cannot move. Do not infer that every LMI deployment saves money or that the 40–56% figures are independent replication. Catalog check: no existing Honeycomb/LMI item; NEW.

2. Cloudflare Search for Agents creates a discoverable site-search endpoint from one zone toggle

Primary: https://blog.cloudflare.com/search-for-agents/ (published 2026-11-25T14:00:00Z, modified 14:00:16Z, in-window).

Search for Agents automatically creates an AI Search instance for a zone, crawls and indexes its content, and advertises /.well-known/search?q={query} through HTML agent:* metadata or Markdown front matter. Agents can use GET or HTTP QUERY with text/JSON bodies; results contain retrieved Markdown and scores, not a generated answer. The feature is available to all customers, including Free with limits, and remains subject to the zone’s bot, AI Crawl Control and WAF settings.

Why it ranks. This is a material data-agent retrieval and discovery surface, not another crawling API. For BQAA, the useful trace unit is endpoint discovery → query → returned documents/scores → downstream answer, with the site’s access policy attached. The launch offers an OpenCode anecdote but no measured agent discovery rate, retrieval quality or task improvement; the advertised instructions must remain untrusted input. 1. The Date You Didn’t Set: The System-Prompt Date as a Hidden Variable in LLM Evaluation — https://arxiv.org/abs/2611.31254

Full PDF read: yes — entire 26-page PDF read via pdftotext in chunks, including the setup, all results and limitations, references, and Appendices A–M. Version note: arXiv v1 is dated 2026-10-17; it appeared in the Wednesday listing and was absent from the live catalog, so this is a newly carded paper, not a claim that October 17 falls inside the industry window.

Problem and method. Six open instruction-tuned models run on four benchmarks with prompts, decoding and configuration fixed except the date rendered into the system preamble (§3). Each cell has disjoint 32 TRAIN / 32 VAL / 96 TEST items. The authors measure per-item correctness churn across plausible 2024–2026 dates, use a grammar-constrained GCG variant to search arbitrary-year dates as a stress test, audit 11 evaluation stacks, and separately test LLM-judge, jailbreak, refusal and activation-monitor outcomes (§§3–8; Tables 1–3).

Results to reuse. Between two plausible dates, a median 6.6% of TEST items switch correctness and a one-day change flips 4.3%, while aggregate accuracy moves a median 2.3 points because flips largely cancel (§4, Figure 1; Appendix I, Table 9). None of the 11 stacks pins the rendered date by default, and none of 16 audited papers using date-inserting models reports that date (Table 1; Appendices A–B). Arbitrary-year optimized dates cost Llama models up to 36.5 held-out points, mostly through refusals; those dates are outside 2024–2026 and the large significant losses are model-specific, not a generic plausible-date result (§5, Table 3; Limitations). Date changes also alter judge verdicts and stored jailbreak survival; the safety analyses do not establish the absence of harmful compliance (§§6–7).

BQAA takeaway. Pin and log the complete rendered prompt, including the date, beside seed, decoding and harness versions. Report per-item churn and refusal/no-final-answer rates, not just aggregate score. A pinned result remains date-conditional, so the date belongs in every replay receipt and safety-eval comparison.

2. Within-task hazards of AI agents: unidentified by time-horizon curves, identified by repeated runs — https://arxiv.org/abs/2611.32415

Full PDF read: yes — entire 16-page PDF read via pdftotext, including mathematical proofs, mechanisms, METR reanalysis, limitations, references, pipeline details and per-model appendices.

Problem and method. The paper shows that a declining horizon curve does not identify a declining within-task hazard: a log-logistic cross-section with slope β≤1 is a mixture of constant hazards, and the same curve is compatible with every within-task Weibull shape k≥β (Propositions 2–3). Under conditionally independent repeated runs, the probability that two runs both succeed is the single-run curve shifted by 1/k on the log2 human-time axis (Proposition 4). A more general direction result still depends on a log-logistic cross-section and explicit frailty/selection assumptions (Proposition 7; Table 1).

Results to reuse. In the TH1.0/TH1.1 METR releases, no eligible 95% interval for 1/k lies entirely above one, so the analysis does not detect a declining hazard; this is not evidence against every declining-hazard model (§5, Result 1). For all five TH1.0 frontier models, cross-batch intervals lie below one; for TH1.1, three of five estimable frontier models do, while baseline-timed and estimated-time subsets give zero (Table 2, Appendix Table 3). Under the stated assumptions and prefix interpretation, those intervals reject a non-increasing average hazard; they do not prove that hazard rises everywhere. Independence, rerun selection, task composition, human-time error, low-power correlation tests and missing multiplicity corrections are material limitations (§§5–6).

BQAA takeaway. Store repeated-run joint outcomes, batch identity and task family, then report pass² as well as pass@1 and cross-batch comparisons. Do not turn a time-horizon curve into a claim about compounding within-task failure without these assumptions; a direct experiment that observes the same task at several lengths is still needed.

3. Below the Stopwatch: Checking the Performance Claims of Coding Agents in the Kernel — https://arxiv.org/abs/2611.31460

Full PDF read: yes — entire 5-page PDF read via pdftotext, including the claim taxonomy, blind-build harness, measurement protocol, all results, threats to validity and references; there is no separate appendix.

Problem and method. BELOW maps 28 claimed optimization mechanisms to kernel/hardware signals that must move, hides the PR claim from the build agent, and compares base/head/base-again with timing, counters and LTTng traces (§II, Figure 1). From 1,343 runtime-performance PRs, the authors select 82 measured PRs for mechanism analysis. A speed result requires at least a 5% median wall-time reduction with every head run faster than every base run; a claimed signal must move at least 10% with the same separation.

Results to reuse. Across the 1,343 PRs, 57.3% offer reasoning only or no evidence and 31.4% state an effect size (§III.A). Among the 82, 32 are faster, 28 show no clear change and 22 are slower; the claimed mechanism holds in 34, including 20 using kernel-trace signals alone (Table II). Kernel-trace signals move about 1.7 times as often for faster PRs’ claimed mechanisms as for unclaimed ones, versus 1.15 for instruction count; 42 PRs change workload output (§III.C). The sample is small and early, workloads are agent-written and may miss the claimed path, labels/workloads use the same model family as one evaluated agent, and each PR is measured on one machine (§IV).

BQAA takeaway. A latency delta is not mechanism evidence. Attach workload identity, output equality, syscall/I/O/scheduling signals and hidden resource regressions to performance claims. Kernel evidence supports the stated mechanism; it does not prove production generalization or correctness when output changes.
