1. NEW rank: ModularRSI — decomposing harness self-improvement into five modules (Loop / Tools / Observations / Context / Completion) with contrastive pass/fail trajectory diagnosis and cross-task vote counts; under a benchmark-disjoint evolution protocol two prior harness-RSI methods collapse to within ~1pt of baseline while ModularRSI gains ~5.6 — benchmark-proximate evolution was inflating prior results

ModularRSI: Modular and Generalizable Recursive Harness Self-Improvement, Siwei Wu, Jincheng Ren (co-first), Yizhi Li, Haau-Sing Li, Chengran Yang, Yuxuan Zhang, Weicheng Gu, Jian Yang, Riza Batista-Navarro, Chuanyi Zhang, Xianglong Liu, Ming Zhou, Bryan Dai, Chenghua Lin (Beihang University, University of Manchester, IQuest Research, M-A-P, Langboat, Hohai University — pack author list verified exact). v1 2026-09-14; no v2. Full text read including Appendices A–F (harness interfaces, findings schema, evolution prompts, case studies, difficulty construction, judge prompt). (PDF)

Monolithic harness evolution overfits benchmarks, amplifies single-trajectory noise, and entangles behavioral deficiencies. ModularRSI evolves the harness as five scoped modules — Agent Loop, Tool Use, Observation Management, Context Management, Task Completion Detection — diagnosing deficiencies by contrasting successful and failed trajectories of the same task (with a trajectory memory so all-fail tasks pair with historical successes), requiring a counterfactual ("would this module change plausibly flip the outcome?") before attributing blame, and aggregating evidence across tasks via vote counts before editing. Verified findings:

  • The eval-integrity headline (Table 6): under a benchmark-disjoint protocol (2,000 external evolution tasks screened by semantic similarity against the downstream benchmarks), prior methods AHE and Meta-Harness hover within ~1pt of baseline (62.54, 62.92 vs 61.79) while ModularRSI reaches 67.42 — the sharpest evidence yet that benchmark-proximate evolution inflates harness-RSI results.
  • Modularity beats joint evolution (Table 4): non-modular evolution (46.44) and joint all-module evolution (44.19) both land below the 47.57 baseline on TerminalBench 2.0, while independent module evolution + integration reaches 52.43. All five single-module variants beat baseline; Agent Loop gives the largest accuracy gain, Observation Management cuts steps hardest (34.70→22.50).
  • Verified gains: TerminalBench 2.0 (89 tasks) 47.57→52.43 and SWE-Bench Verified (500) 73.40→76.45 in-domain; cross-domain transfer positive both directions; a frozen evolved harness transfers across three foundation models (GLM-5.2, MiniMax-2.5, DeepSeek-V4-Flash — all three metrics improve for all three models). Reliability (Pass³) rises more than mean accuracy (30.34→35.96). Evolution-data difficulty matters: medium-centered beats hard+easy bimodal by 2.2pts.
  • Pack correction: the benchmark is TerminalBench 2.0 (pack hedged "TB2.0"); only 240 of the 2,000 tasks (120/subset) were actually used for the reported evolution runs (compute constraint, self-acknowledged) — the 2,000-task set is a released resource, not the experiment scale.

Mandatory qualifications: no variance, CIs, or evolution seeds anywhere; TB2.0 has 89 tasks × 3 rollouts, so ~2–5pt deltas (e.g. the +1.83 cross-domain gain) are plausibly within noise; single evolution lineage per setting; two different backbones across headline tables (Tables 2/4/5 use DeepSeek-V4-Flash-Preview, Table 6 uses -0731 — cross-table comparisons invalid); no ablation isolating contrastive analysis (self-acknowledged); auxiliary Opus-4.8 trajectory judge has no human validation (headline metrics are benchmark-provided binary rewards, so this is contained); evolution data is semi-synthetic (LLM-filtered, human-reviewed; disjointness enforced by screening, not guarantees).

BQAA/ADK application: squarely on-beat. (1) Benchmark-disjoint evolution as an eval-integrity protocol — evolve on external tasks, freeze, evaluate held-out; adopt the same shape for any BQAA harness-tuning loop. (2) Contrastive trajectory diagnosis is a reusable observability primitive — pair pass/fail rollouts of the same task, require a counterfactual before blame, vote-count across tasks; the structured-findings schema is copy-paste usable. (3) A reward-blind diff-review gate that rejects task-specific edits is a concrete guardrail for self-modifying agent loops. (4) Report Pass^k alongside Pass@k — reliability moved more than the mean. (5) Efficiency and correctness evolve on different levers (observation management halved steps without hurting accuracy) — score them separately.

2. NEW rank: ImpossibleRubrics — 169 impossible tasks with verifiable oracle certificates; eleven rubric generators exploited 8–26% by an adversarial answerer that sees the rubric; a single generic "be decisive" rubric exploited 64% beats 7/11 tailored generators on robustness — tailored criteria act as an attack roadmap; swapping only the verifier swings measured exploitation 33.3%→75.6%

ImpossibleRubrics: Stress-Testing Generated Rubrics as Reward Signals, Bowen Qin (NUS), Yi Xie (Peking University), Yesheng Liu (CASIA), Xi Yang (JD.com — pack author list verified). v1 2026-09-15; no v2. Full text read including Appendices A–M (provenance contract, resampling sub-study, open-weights parity, multiplicity, judge robustness, human calibration, held-out attacker, certificate-faithful calibration, best-of-N, negative control, self-play, Oracle sensitivity). (PDF)

LM-generated rubrics increasingly serve as reward signals (rubric-based RL, LLM-as-judge, automated grading); this benchmark isolates the hardest regime — 169 impossible tasks across six impossibility categories (objective conflict 41, counterevidence trap 27, insufficient evidence 26, impossible exhaustiveness / missing citation support / false premise 25 each), each paired with a machine-checkable oracle certificate specifying what an honest answer may/may not claim, plus 48 answerable controls. The benchmark persists environments + certificates, not rubrics — rubrics are generated downstream so the eval cannot be memorized. Verified findings:

  • Generated rubrics are exploitable: eleven generators exploited 8–26% on the unbiased Full-150 cut under a fixed attacker/judge/oracle chain, with a capability-tier gradient (frontier 8–15% << mid 17–18% << mini 26%).
  • The counterintuitive headline: a single generic rubric ("decisive, well-cited; penalize hedging") used unchanged for every task is exploited 64% [95% CI 49–78], and 7/11 tailored generators are exploited at least as often (appendix framing; the abstract says "more often" — carried here as the appendix states it, k=1 single draws) — task-specific criteria leak which claim to fabricate. "Not vague — specific about the wrong things."
  • The observability finding (§M): holding rubrics, attacks, and judge scores frozen and swapping only the Oracle moves measured exploitation 33.3% / 75.6% / 66.7% — absolute rates are conditional on the verification protocol; the metric includes its verifier.
  • Stress cut honesty: on the deliberately adversarial Hard-45 cut (selection-amplified by construction) the best generator (Opus 5) is exploited 36% while a certificate-faithful rubric is exploited 0/45 — flagged by the paper itself as not independent validation (rubric and Oracle share the certificate). The gap is rubric quality, not task impossibility.
  • Prompt-injected safety guidance is not a mitigation: explicit "reward evidence faithfulness" instructions leave 22–49% residual exploitation on the hard set.

Mandatory qualifications: single fixed chain, single vendor (attacker = Opus 5, judge = Haiku 4.5, oracle = Opus 5; the Opus 5 generator arm is self-play); k=1 single-draw headline rates (resampling shifted Claude arms 8–16 points; 27/45 Opus 4.8 environments flip verdict across draws); Hard-45 is selection-amplified; human validation is one rater × 40 items (κ=0.89, no IAA); within-tier rankings don't survive multiplicity correction (only tier-level separation claimed); only 109/169 environments have fully verifiable sources; zero observed exploits under one chain is not a zero-risk guarantee (the paper says this itself). Credit the unusual rigor: pre-registered sub-studies, cluster bootstrap, resampling, negative controls.

BQAA/ADK application: the most directly eval-relevant paper of the slot. (1) Treat generated rubrics as attack surfaces — any rubric-as-reward or rubric-judge pipeline should be stress-tested with an adversarial answerer that sees the rubric ("exploited = adversarial score ≥ honest baseline ∧ certificate violation"). (2) Version the verifier with the metric — pin judge/oracle model + prompt alongside every eval number and run periodic verifier-swap sensitivity checks; a 42-point swing on frozen artifacts is the cautionary number. (3) Resample rubrics, cluster-bootstrap by environment — single-draw rubric evals are coin flips on 60% of hard environments. (4) Certificates > rubrics as the durable artifact — persist environments + machine-checkable honesty certificates, generate rubrics downstream; audit rubric quality as the gap against a certificate-faithful reference. (5) The over-refusal negative control is a reusable pattern for false-refusal testing.

HarnessVLN: Unifying Training-Free Embodied Navigation through an Agent Harness, Yang Chen, Lirong Che, Zhenyu Huang, Wenbo Fu, Chuang Wang, Xu Cao, Daqi Liu, Yuzhe Yang, Jian Su, Lan-Zhe Guo (Nanjing University, AGIBOT, Tsinghua University — pack's "et al." resolved: adds Su and Guo, corresponding). v1 2026-09-14; no v2. Full text read including Appendices 1–3 and all six tables. (PDF)

A zero-shot, training-free framework whose Agent Harness coordinates perception, retrieval, grounding, navigation, recovery, and termination through a unified tool interface (8 tools); the Harness validates planner proposals against spatial evidence, geometric feasibility, and subgoal consistency, feeding structured tool feedback (status, measurements, failure evidence) into subsequent decisions. Verified findings:

  • Verified headline (Tables 2–3): training-free SR SOTA on all four benchmarks — 60.8% R2R, 53.9% RxR, 76.0% HM3D-v2, 59.3% HM3D-OVON (SOTA deltas also check: +5.8 vs AgenticNav, +12.1 vs HSGM, +1.6 vs MSGNav, +9.1 vs DRIVE-Nav).
  • The transferable mechanisms: (a) validation layer between planner and tool dispatch — evidence provenance/recency, geometric feasibility, consistency with active subgoal + applicable failure history are checked before execution; (b) termination as a gated request — the model can only request stop; acceptance requires a conjunction of semantic, geometric, and progress checks, and rejected stops are logged and trigger recovery; (c) subgoal state machine with evidence-required completion (pending/active/completed/blocked — completion requires a pose-aligned observation or successful tool result); (d) failure annotations with applicability weights and decay on a persistent spatiotemporal graph, with full failure traces kept separately from the lightweight retrieval index.
  • Ablations (100-episode subsets): memory +8/+7 SR, graph +6/+1, stop validation +4/+2; full harness +18/+10 over base agent. Honest negatives disclosed: stop validation widens the OSR–SR gap and lowers SPL. Model sensitivity at fixed harness: ~18 SR points of harness contribution at fixed model.

Mandatory qualifications: the claim is training-free SR SOTA only — R2R SPL (43.5) is below AgenticNav (48.4), HM3D-v2 SPL below DRIVE-Nav, RxR nDTW below HSGM, and trained models still beat it overall; no variance, CIs, or multi-seed results (simulator seed fixed at 0, single runs); ablations and model-sensitivity on fixed 100-episode subsets with undisclosed selection; per-task base models differ and are proprietary (GPT-5.5 / GPT-5.6-luna), no code release linked; humanoid deployment is 3 qualitative demos — no episode counts or success rates; one table's text is written in future tense while populated (numbers may be preliminary).

BQAA/ADK application: the domain is embodied navigation, but the paper is literally an agent-harness design study, and its mechanisms map 1:1 onto gateway concerns: (1) interpose validation between planner and dispatch (evidence provenance + feasibility + active-goal consistency before execution); (2) gate termination — a model's "done" claim should be a request verified by the harness, the single most transferable idea here; (3) evidence-required progress state blocks LLM planners self-advancing task state — a concrete spec for agent progress telemetry; (4) separate full failure traces from a weighted, decaying retrieval index — failure-aware retrieval without unbounded context growth; (5) structured tool feedback as the state-update contract is what makes executors replaceable.
