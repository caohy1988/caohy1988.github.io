Read this first

The useful industry shift is from agent activity to agent outcome evidence. LangSmith now attributes coding-agent spend to pull requests while keeping non-PR work visible; Qodo reviews an agent's whole cross-repository session and guards automatic approvals; Foundry connects production traces, expert annotation and optimizer candidates; CrowdStrike connects agent intent to downstream endpoint execution. Sashiko's production data is equally useful because it separates association from causation: clean reviews correlate with fewer follow-up fixes, but the vendor does not claim its system caused the release-wide improvement.

Academy supplies the measurement controls those products need. VFM makes thousand-rule verification cheap enough for runtime escalation, but its real-call false passes rule out standalone enforcement. Context Has a Price shows that shorter prompts and fewer searches can still cost more once cache reuse and behavioral responses are counted. Done, But Still Working shows that a twice-passed stop rule saves 22.8% in its replication, yet its preregistered test does not establish quality non-inferiority. Cost savings are not quality evidence in any of the three.

NEW 1 — LangSmith for Coding Agents: spend attributed to pull-request outcomes

Published 2026-11-18T15:00Z; public beta on LangSmith Cloud. Not in live catalog (URL / track spend by outcome: 0 hits).

LangSmith's new coding-agent overview automatically attributes trace spend to the pull requests each agent contributed to, including one thread opening several PRs and several threads finishing one PR. It rolls cost up by PR state (open, closed, merged), model, conversation length, work type and skill, and links every aggregate back to the underlying threads. Claude Code, Codex, Cursor, GitHub Copilot in VS Code and Deep Agents are supported through plugins plus a GitHub connection.

The crucial accounting choice is that unattributed spend remains visible. Investigation and code review may be valuable without producing a PR; LangSmith separates that spend rather than pretending every session should end in code. Teams can define off-topic work for their own use case and compare cost per merged PR before and after a model or skill change. A merged PR is an outcome proxy, not proof of patch quality — the post explicitly preserves that distinction.

BQAA read: this is a concrete schema for outcome-aware agent analytics: many-to-many session/work-item attribution, cost by outcome state, separate non-outcome work, and drill-down from every KPI to raw evidence. BQAA should add quality signals beside the outcome proxy rather than optimize cost per merged artifact alone.

NEW 2 — Qodo: guarded Auto Approval Workflows and session-level agent review

Published 2026-11-18T09:52:34Z; Auto Approval Workflows in Beta, Agent Session Review in Research Preview. Not in live catalog (qodo / agent session review: 0 hits).

Auto Approval Workflows can approve a PR, or merely label it, after Qodo's review meets configurable thresholds for findings, blast radius and team rules. Repository, path and author guards keep sensitive changes with a person; required reviewers and code owners still apply. Every new commit triggers re-evaluation, and Qodo withdraws an approval that no longer qualifies. This is not automatic merge authority.

Agent Session Review changes the unit of review from an isolated diff to the coding agent's whole session. Its Agentic Toolbox gathers PRs across repositories, the plan and the agent's decisions into a work package with deviations, merge order, interacting contracts, a guided reading path, evidence-linked risks and unresolved questions. The reviewer can inspect decisions one by one instead of reconstructing the feature from independent diffs.

BQAA read: store session-level plan deviations and cross-repository dependencies as first-class evaluation objects, and model approvals as revocable state transitions tied to the exact reviewed commit. A passing review is not durable evidence after the diff changes.

NEW 3 — Sashiko: production evidence for specialist code review with independent proof

Published 2026-11-18T17:00Z in the Google Cloud feed; new production/evaluation evidence, not a new Sashiko launch. Not in live catalog (sashiko: 0 hits).

Sashiko separates up to seven specialist bug-finding passes from a triage verifier and per-bug deep checks. Both a claimed bug and a dismissal require concrete code proof; shaky self-dismissals are investigated rather than accepted. Every prompt, tool call, reasoning step and ruled-out concern is public. The team also built a benchmark of nearly 1,000 real Linux kernel bugs that had passed human review; the post reports 75.8% detection with the new model at high thinking level.

The production evidence needs equally careful reading. Across 21,500 tracked mainline commits, patches with a clean Sashiko review needed a follow-up fix within 60 days 0.9% of the time, versus 7.6% for patches merged despite a critical warning — an association the post also reports as 6.3× after patch-size adjustment. Separately, the release-wide 60-day fix rate fell from a 3.4% historical baseline to 2.2% in Linux 7.2 (35% relative reduction), but the authors explicitly say other factors prevent crediting Sashiko for the whole drop. The post reports roughly 241,000 reviews and 1,200 reviews/day, not an independently controlled production A/B.

BQAA read: mine historical escaped defects into a regression set, split specialist discovery from evidence-backed verification, and require ruled-out concerns to carry proof too. Preserve the clean/warning association as a useful signal, never as a causal estimate of prevented incidents.

NEW 4 — Falcon Complete for Falcon Guardian GA: agent intent linked to endpoint execution

Published/effective 2026-11-18T14:10:36Z; Falcon Complete for Falcon Guardian now generally available. Not in live catalog (falcon guardian: 0 hits; the existing Fiddler/Falcon Observe card is a different product line).

Falcon Guardian captures human prompts, AI system instructions, MCP connections, tools, skills and agent activity at the operating-system level. CrowdStrike Agent Graph connects those upstream instructions to downstream endpoint execution, while Falcon Complete analysts and Adversary OverWatch hunters correlate that evidence with identity, cloud and SaaS telemetry to investigate and respond to suspected agent misuse. The managed response can include removing a malicious skill or containing an affected endpoint.

The launch is evidence of a product capability, not proof of detection efficacy. Its value for agent analytics is the causal chain it makes inspectable: requested outcome → instructions and skills → agent action → OS effect → broader enterprise impact.

BQAA read: a trace that stops at the model or MCP boundary cannot distinguish a benign tool call from a harmful outcome. Preserve intent and instruction provenance beside host and cloud effects so reviewers can investigate deviation from the user's actual request.

NEW 1 — Runtime Verification of Multiple Natural Language Criteria for Agent Governance — abs

Full PDF read (27 pages via pdftotext in chunks: abstract, §§1–5, Tables 1–21, Figures 1–2, references, Appendices A–D including data construction, audits, benchmark protocols, latency, violation metrics and the deployment-rule decomposition; methods/results/limitations included). Reserve promotion. Not in live catalog (2611.23074: 0 hits).

Pitis et al. build a verifier that encodes the shared context/target once and branches independent criteria through a tree-attention mask, returning YES / NO / N/A for each. CriteriaBank contains 393,531 tuples and 321,419 distinct criterion strings (Table 2), all model-labeled with a two-judge panel plus adjudicator. On one H100, the 4B model evaluates 1,000 criteria against a ~4K-token prefix in 1.807 s at 10.5 GB VRAM (Table 6, §4.5). That is an unoptimized HuggingFace measurement; an optimized vLLM prefix cache changes the latency comparison, so the tree mask is not itself a serving moat (App. C.3).

DynaBench shows the useful operating pattern. VFM-4B reaches 0.885 FAIL F1, above DynaGuard-4B/8B at 0.720/0.731 but below the larger raw-rule Gemma judge at 0.922; passing only VFM's top-three suspected rules to that judge reaches 0.946 (Table 5, §4.3). The violated rule ranks first on 97.6% of failing traces and in the top three on all of them (App. C.10). On synthetic governance, VFM-4B scores 88.8% accuracy versus GPT-5.4's 83.9%, and 77.7% versus 75.5% on held-out regulations (Table 3), but the set is small and LLM-built, with only a 75-item co-author human audit.

The limitations decide the card. On 50 real insurance calls, Direct-FT slightly leads VFM, and finetuned 4B variants label 19–26% of gold violations as satisfied, mostly with high confidence; reviewing the most uncertain 30% raises violating-call coverage only from 84.7% to 87.4% (§4.2, App. C.9). CriteriaBank pretraining mainly helps low-data transfer (macro AULC 0.789 vs 0.736 for Direct-FT), not full-data dominance (§4.4). The authors therefore recommend monitoring and escalation, not standalone enforcement (§5).

BQAA read: a per-criterion compliance record with explicit N/A and rule-level escalation is a strong runtime primitive. Report false-pass rate beside latency and F1, keep a larger judge or human path for suspected violations and confident all-clear cases, and treat the natural-language-to-atomic-rule translation as a separately evaluated dependency.

NEW 2 — Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching — abs

Full PDF read (25 pages via pdftotext in chunks: abstract, §§1–8, Tables 1–7, Figures 1–10, references, Appendices A–R including preregistration, methods, fixed-action replay, price maps, measurement biases and official-report coverage; methods/results/limitations included). Reserve promotion. Not in live catalog (2611.22238: 0 hits).

Across more than 20,000 runs, Yang et al. price uncached input, cached input and output separately (Eq. 1) and test both retrieval and removal. The evidence package cuts read/search commands by 18–34%, while raising cost by 33–42% when cached input costs one tenth of fresh input, without an established resolution gain (§4, Table 4). Replacing the large package with an index pays in 91–97% of runs and saves about a quarter; small candidate-only evidence is much less attractive. Retrieval is more effective as a localization complement: appending its ranking to the agent's answer raises function Acc@10 by 14–20 points for three models (§4).

Rolling observation masking flips sign with cache price: +116% / +87% cost at c=0.1 for two Qwen models, versus −19% / −25% at c=1 (§5, Fig. 3). Break-even masking halves that premium but still costs 2.8%/1.8% more than no masking at the cheap-cache point, failing the 5% non-inferiority margin; at c≥0.25 the same runs save 10–26%. None of 33 method/model/scaffold combinations is cheaper throughout the tested current API price region (§§5–6, App. P). Fixed-action replay is not sufficient evidence: agents re-fetch masked content and take more steps, and behavioral effects account for much of the premium (§5, Apps. J, Q).

The measurement warning is directly reusable. Concurrent conditions warm one another's prefixes; excluding sibling-supplied hits changes the Verified evidence-package premium from +8% to +36%, with +29% in an isolated run (§2, App. K). Quality results also retain patch-definition and incomplete official-report caveats (§8, App. R), so small resolution deltas should not be overread.

BQAA read: store the three token streams and their prices, attribute cache hits only to the run's own previous requests, and evaluate a context intervention's later actions as well as its immediate prompt delta. Report cost and quality over a price map, isolate paired conditions, and never translate fewer search calls or shorter prompts directly into savings.

NEW 3 — Done, But Still Working: Anytime Evaluation of When Coding Agents Should Stop — abs

Full PDF read (22 pages via pdftotext in chunks: abstract, §§1–7, Tables 1–8, Figures 1–6, Impact Statement, references, Appendices A–T including preregistration, stopping rules, distillation, precision analysis, patch-definition audit and official-result coverage; methods/results/limitations included). Reserve promotion. Not in live catalog (2611.22901: 0 hits).

The paper replays recorded commands, reconstructs intermediate patches, scores them with hidden tests and aligns each with cumulative cost. This permits paired evaluation of policies that only stop or select an earlier patch, provided policy-relevant states are preserved (Proposition 1). Replay or snapshots match the recorded final tracked-file patch in 4,009 of 4,012 runs, an end-state check rather than proof that every intermediate state matches (§2). Pairing reduces standard error by 2–8×, worth 4–60× as many tasks for the tested comparisons (Table 1, §4.2).

Across about 6,000 runs of eight open models in two scaffolds, hindsight savings at passing self-tests range from under 1% to 57% by model/scaffold (Fig. 4, §4.3). The practical result is narrower: stopping after the same patch passes twice saves 22.8% in the preregistered 386-run replication with a 1.0-point resolution decrease, and the preregistered test does not establish non-inferiority at the 2-point margin (Table 2). First-pass stopping saves 30.5% but loses 1.8 points in that replication. The corrected patch accounting changes earlier quality verdicts and withdraws the previous last-pass gain (App. R).

Stop distillation is promising but not settled: six training seeds save 30.0% at −1.2 points on 256 tasks, with quality ranging from −3.1 to +1.2 by seed (§4.5, App. N, Table 4). Prompting to stop early saves only 8.4%, and asking the agent whether to submit yields SUBMIT in just 6–7% of 439 cases (§4.5, App. H). Hidden tests fail in about 30% of runs where the detected self-test fires (§7), and the decomposition into firing rate, later patch changes and net repair explains why one rule cannot be ported blindly across models or scaffolds (§4.4).

BQAA read: build per-step patch-and-cost ledgers and evaluate stop/selection policies against hidden tests on the same runs. Ship no early-stop policy on token savings alone: require a preregistered quality margin, preserve the exact patch definition, and run fresh trajectories for interventions such as distillation that change later behavior.

Six-week EV

  • Outcome-attributed analytics (high EV, 2–3 weeks). Implement many-to-many session/work-item attribution with PR/outcome state, unattributed work and trace drill-down. Compare models and skills on cost and independently checked outcome quality; do not optimize merged-artifact count alone.
  • Session review and revocable approvals (high EV, 2 weeks). Add a session-level review package for cross-repository work: plan deviations, contract interactions, evidence-linked risks and unresolved questions. Bind approvals to the reviewed commit and emit withdrawal events on every subsequent change.
  • Verifier escalation telemetry (high EV, 2 weeks). Evaluate per-criterion monitors with false-pass rate, N/A rate, escalation rate and judge cost beside F1/latency. Include a random sample of confident all-clear runs in the escalation path, not only flagged cases.
  • Cache-aware cost ledger (high EV, 1–2 weeks). Record uncached/cached/output tokens and price vectors per run, reject sibling-cache credit in experiments, and evaluate context policies on both direct cache effects and subsequent actions. Publish cost-quality maps instead of one-token-count winner claims.
  • Anytime stop evaluation (high EV, 3–4 weeks). Snapshot each distinct patch, score it offline and compare stop rules against a preregistered hidden-test quality margin. Keep early-stop behavior off production defaults until replication establishes non-inferiority; use new runs for distilled or prompted behavior changes.
  • Production improvement loop (medium-high EV, 4–6 weeks). Prototype recurring-issue clusters → expert trace annotation → versioned evaluation set → optimizer candidate → gated deployment. Mine historical escaped defects into a code-review regression set and require both findings and dismissals to carry evidence.
