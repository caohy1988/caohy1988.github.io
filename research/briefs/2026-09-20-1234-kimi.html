1. NEW rank: Semantic Layer Induction from Raw Telemetry via Hierarchical LLM and RAG Abstraction — raw tracking-event logs → a deterministic two-level Feature→Node semantic layer with SQL-like rules: human score 82.3 vs 51.6 for its own no-RAG/no-filter ablation, business coverage 62%→98%, embedding retrieval is the single biggest lever (−24.5 when removed) — but one e-commerce dataset, a strawman baseline, and a rubric-free 0–100 expert score

Yuanzhe Jia (U. Sydney), Ali Anaissi (U. Sydney / UTS). v1 2026-09-17; cs.CL; 11 pages. Code: github.com/yuanzhe-jia/semantic-layer. Full text read incl. Tables 1–3. (PDF)

  • Method: induce a canonical, platform-agnostic semantic layer from heterogeneous event streams (event name + key-value params) with no labeled training data: (1) LLM scores each metadata column for business importance and drops low scorers; enumeration values are entropy/LLM-screened so random IDs (UUIDs, session tokens) are masked to *; (2) LLM generates coarse business features (Signin, Search, Cart, Checkout…) from a stratified sample, conditioned on a curated industry prior, with a post-hoc quality gate; (3) the RAG step — each key-value condition is embedded into Milvus and hybrid dense+BM25 retrieval pulls semantically aligned condition subsets per feature, translated into SQL-like predicates; (4) hard filters then per-rule LLM relevance judgments (74% of candidate rules eliminated); (5) LLM clustering + canonical [noun]+[verb] naming. Output is deterministic (temperature 0, fixed seeds, JSON-constrained): a machine-readable layer new KPI queries run against.
  • Numbers (paper's own): blind human assessment (100 sampled mappings, 5 experts, 100-pt scale): 82.3 (σ=9.7) vs 51.6 (σ=14.2), p<0.01; Business Coverage 62%→98%, Name Consistency 59%→96%. Manual effort 10 h/week → ~2 h/week; new-metric query 4 h → <25 min. LLM-judge vs humans on a 500-mapping golden set: κ=0.87. Ablation from 82.3: no BM25-dense hybrid retrieval −24.5 (biggest), no feature identification −18.2, no enumeration normalization −16.3, no column-importance scoring −7.8, hard-filter-only −6.4.

Mandatory qualifications (adjudication — the paper has no limitations section): the only comparator is the authors' own weakened initial pipeline (no external baseline — no Drain/LogParser-class system, no hand-built dbt-style layer); the headline 82.3 is a rubric-free subjective score with no inter-rater agreement reported for the humans (ironic beside κ=0.87 for the judge); single dataset, single domain (the public Synerise e-commerce clickstream — the multi-platform fragmentation that motivates the paper is never tested); effort numbers come from a loosely described 5-expert exercise with no protocol; "no labeled data" is oversold (hand-curated industry priors + a hand-annotated 500-mapping golden set); several thresholds unreported/unswept. Treat every number as directional.

TL;DR for BQAA: (1) This is the most on-mission Academy paper in the window — raw event telemetry → canonical semantic layer → self-service metric querying is the BQAA thesis stated as a pipeline, with a runnable artifact. (2) Retrieval over conditions (not whole events) is the load-bearing step (−24.5 ablation) — if BQAA prototypes telemetry semantics, index key-value conditions, not event blobs. (3) Random-ID masking before retrieval (UUID/session-token → *) is a cheap, stealable normalization that keeps the embedding space honest. (4) The evaluation is exactly how not to validate such a system — any BQAA version needs a rubric, inter-rater stats, and an external baseline before claiming quality.

2. NEW rank: Coding Agents with an Obstacle-Aware Harness for Safe Robot Manipulation (system name: SafeHarness) — the constraint is stated in the prompt, restated in the plan, and still violated at step ~300: skills-only GPT-6 avoids collisions 59.0% of the time; adding two verifier-tool harnesses (no prompt change, no training) reaches 87.5% — "instructions to a language-model planner are not constraints"

Bingxin Xu (USC), Yuzhang Shang (UCF), Zhen Dong (UCSB), Emilio Ferrara (USC). v1 2026-09-17; cs.RO (cross cs.AI, cs.CL, cs.CV); 13 pages. Full text read incl. Tables 1–2 and §3.4/§4.4. Corrections to pack/abs claims: the title carries no "SafeHarness:" prefix (SafeHarness is the system name), and the abstract's "+6.5pp/+27.0pp vs SOTA" is internally inconsistent with the paper's own Table 1 — actual deltas vs AEGIS are +4.4pp TSR / +18.6pp CAR. (PDF)

  • Design: on SafeLIBERO (32 tasks × 10 seeds, simulation), a coding agent (GPT-5.5 / GPT-6) writes controller programs over perception skills + a frozen π0.5 VLA. Each task is cut at contact events into route + contact phases, each guarded by a harness: obstacle-aware route planning — target and obstacle grounded as bounding boxes (SAM-3), the model proposes a waypoint polyline, and a verifier outside the LLM rejects obstacle-crossing routes and forces replanning before any motion is issued (plus a mid-execution replan trigger); obstacle-aware contact execution — grasp/place side chosen farthest from the obstacle, or tangent reorientation when no clear side exists. No training, no prompt change — safety lives entirely in tools.
  • Numbers (Table 1/2, corrected): SafeHarness-GPT-6 71.9% task success / 87.5% collision avoidance vs AEGIS 67.5/68.9 (+4.4pp / +18.6pp) and vs the same agent without harnesses 31.0/59.0 (2.3× / 1.5×; conclusion's +40.9pp/+28.5pp checks out). Per-suite caveat the abstract hides: AEGIS still beats it on Goal TSR (82.8 vs 75.0), and it still collides in ~1 episode in 8.
  • The transferable finding: the unharnessed agent acknowledges the obstacle in its reasoning trace, restates the constraint in its plan, and drives straight through the bottle anyway — the paper attributes this to long-horizon constraint decay (step-0 instruction vs step-~300 action) and shows model scale does not fix it (skills-only GPT-6's gains concentrate at local contact decisions; route safety barely moves). Only the external verifier closes the gap (≥85% avoidance at both levels, both planners). Their words: "For an invariant that must persist across a long episode, the tool interface is a more reliable carrier than the prompt."

Mandatory qualifications (authors' own + adjudication): simulation-only, no real-robot eval; single benchmark, single obstacle per scene (one axis-aligned box), single embodiment; collision proxy is obstacle displacement >11 mm; the trace-level diagnosis is one characterized rollout plus prose — no systematic quantification of acknowledge-then-violate across episodes; 3-day-old v1 preprint. The abstract's SOTA-delta numbers do not match its own tables.

TL;DR for BQAA: (1) Adjudicated KEEP despite the robotics surface — the harness-constraint thread from 1134 (verification-status laundering, Sham-controlled release control) continues here in its starkest form: a constraint the agent verbalizes is not a constraint the agent executes. Any BQAA safety guardrail that lives only in the system prompt is, per this paper's ablation, worth ~59% adherence — the tool-enforced verifier is the fix. (2) Budget guardrails as stateless verification tools applied at the action boundary, not as prose — the same shape as the 0034/1134 provenance cards, from an independent lab and domain. (3) Cite it with the corrected numbers (+4.4/+18.6 vs AEGIS) and the sim-only flag; the abstract oversells.
