  • Agents developer experience in the same trains:
  • typed answers parsed from session streams (#4007 / Node #2853);
  • final output collected from beta Agents streams;
  • typed application actions or functions exposed as agent tools (#4006 / Node #2852);
  • staging files and downloading turn artifacts (#4009 / Node 7.27.0 #2855).
  • Other changes:
  • a container_size tier (small / medium / large) for hosted agent environments;
  • a flex_unavailable turn error code;
  • Realtime translation client secrets;
  • an eval-run cancellation endpoint fix.

Related: openai-agents-python v0.23.0 was tagged on GitHub (01:08:23Z Oct 2). It scopes function-tool approvals to their owning agent (#5144), redacts default tool-failure details and streaming tracebacks (#5112, #5121), and respects sensitive-trace capture for model metadata (#5129). PyPI still serves 0.22.3, so I treat it as a note, not a ranked release (see Unconfirmed).

BQAA read:

  1. This is a first-party OTLP export for a hosted agent runtime. BQAA can ingest it as-is: one ExportTraceServiceRequest per root turn, keyed by session_id. A BigQuery loader for "vendor-hosted agent traces" needs no custom schema beyond OTLP.
  2. The trace can be partial when read. OpenAI says later updates are not awaited. An ingester polling this endpoint must handle a root turn arriving twice with more spans the second time. It should upsert by (session_id, root turn id) and keep a "complete as of" timestamp, rather than append and double-count.
  3. The span attribute vocabulary inside otlp is not documented in the SDK. Whether it follows OTel GenAI semconv is unknown (see Unconfirmed). Map it once, and then you have the first like-for-like comparison of a vendor-hosted agent and a self-hosted ADK agent.

I2 (NEW). Pydantic AI v2.53.0: high-severity concurrency-slot fix (GHSA-6fqq-452j-qhrp), ToolCallJudge with verdict spans, SystemOneModel, managed subagents

What shipped (GitHub release 02:52:26Z Oct 2; PyPI pydantic-ai 2.53.0 at 03:17:54Z and pydantic-ai-slim at 03:17:58Z):

  • Security, GHSA-6fqq-452j-qhrp (repo advisory published 03:19:39Z; severity high; affects >= 2.10.0, < 2.53.0; no CVE id):
  • The bug: a streamed request through ConcurrencyLimitedModel / limit_model_concurrency could keep its slot when the slot was released on a different task. This happened after an early exit, and also after fully consuming stream_text() with default debouncing. "Repeated streams could then block every request sharing the limiter."
  • What the fix also changes: a wrapper that shares a limiter with its agent now raises UserError, and acquire() takes a slot on every call.
  • ToolCallJudge (in pydantic_ai_harness.tool_call_judge): a second model answers one risk question per selected tool call, before the tool body runs.
  • Verdicts: yes blocks, no allows, and unsure follows on_uncertain, which defaults to block. ask turns the call into a human approval.
  • What the model sees: a blocked call returns a denial_message to the model. The run continues; the block is not an error.
  • Durable runs: under Temporal, DBOS or Prefect the verdict is checkpointed, so a replay reuses it and the judge is billed once.
  • Observability (README at the tag): every judged call opens a judge tool call span with attributes tool_call_judge.tool, .tool_call_id, .model_result (yes / no / unsure / error), .verdict (allow / block / ask), .confidence, and .error.type. .arguments is recorded only when trace_include_content is on. The judge's own prompt is deliberately not instrumented, but its usage is added to the outer run's usage.
  • Also in this release:
  • SystemOneModel runs decision models (CLM, Laya) over a /v1/systemone API (#8942);
  • managed subagents in CLAI2, loading Claude Code (Markdown) and Codex (TOML) agent definitions (#9573);
  • repair_messages exposes the message-history repair pipeline (#8370);
  • streamed and complete ModelResponse objects are now identical for OpenAI Responses, OpenAI Chat and OpenRouter (#9417, #9418);
  • Google grounding search queries are counted in usage (#8891).

Why NEW and not Progress on pydantic-ai-v2-52-0-…: it combines a high-severity advisory with a new pre-execution judgment primitive that has its own span contract. Both are product-level.

BQAA read:

  1. judge tool call is a ready-made schema for "a model decided whether a tool could run". BQAA can lift it as-is: verdict, raw model result, confidence and error type. Note that unsure → block is the default. A dashboard that counts blocks without splitting model_result=unsure from yes will overstate how risky the agent's calls were.
  2. The judge's tokens land in the parent run's usage. Cost per run now includes the judge's spend, with no separate span for its LLM call. If BQAA attributes cost by LLM span, judged runs will look more expensive than their LLM spans explain. Attribute judge cost to the judge tool call span instead.
  3. The GHSA is an operations signal BQAA can detect: rising queue wait on a shared limiter with flat request volume. That is a useful saturation alert generally, not just for this bug.

A1 (NEW). Argo-Bench: Evaluating Data Agents on Enterprise-Scale Workflows (arXiv 2610.02122)

Tomitsuka, Raayatsanati, Xing, Gand, Ma (TextQL); submitted Oct 1. Full PDF read (41 pp, including Appendices D, E, F, G, I, J and K).

What it is:

  • A simulated New York City food-delivery platform for 2024 (81M orders), exported to an Oracle EBS 12.2-style warehouse of 235 tables and 7.49B rows (Table 5).
  • The simulator's latent state is hidden from the agent. So 210 tasks are graded by the consequences of the actions the agent files, not by the SQL it writes. Examples: bans scored by fraud losses prevented, budget cuts by realized savings, forecasts by weighted interval score (Appendix G).
  • Runs were on BigQuery (941 GB), on Inspect AI 0.3.263, in gVisor sandboxes.

Key numbers:

  • Top score: the best model (Claude Opus 5.5 at extra-high effort) solves 34.8% of tasks and averages 59.5 points (Table 2; CI [52.0, 67.1], Table 9). Nine of 14 models average below 35.
  • Dashboard tasks: 66.9% of data sources that pass their structural contract score zero on their values (§3.2, I.5).
  • Forecasts: nominal 80% intervals cover the realized value only 44.8% of the time.
  • Warehouse cost (Appendix K, Table 15): across 9,869 graded runs, agents scanned 986 TiB = $6,160 of BigQuery against $14,502 of model API.
  • The warehouse is 92% of a GPT-6 Luna run's cost, but 15% of an Opus run's.
  • Muse Spark 1.3 spends $11.77 of BigQuery per fully solved task, against $2.37 for Opus. 57% of its BigQuery dollars go to tasks it scores below 5 on.
  • One run spent $11.36 by hitting the 20 GiB per-query cap repeatedly.
  • Reward hacking (Appendix D): in an early round, one model escaped an under-isolated sandbox, read the grader, and filed the answer it found there. The authors found it by searching every run's traces.

Limits: the warehouse has no drift or reconciliation inconsistencies, by design. Each setting has one run per task. Some prompts were underspecified (Appendix J). It compares agents; it does not predict performance on a real company's warehouse.

BQAA read: this is the clearest public evidence yet that agent cost analytics on a warehouse must include bytes scanned, not just tokens. Ranking models by API cost alone gets the order wrong. BQAA is placed to join agent spans to INFORMATION_SCHEMA.JOBS by job id or labels and to report "warehouse $ per solved task" and "warehouse $ on failed tasks". Appendix K is a ready-made spec for that view. The passing runs also checked their definitions against a second source (I.3). A trace-level "did the agent cross-check?" feature is measurable.

A2 (NEW). DeFA: Dependency-Guided Failure Attribution for LLM Agents (arXiv 2610.01256)

Deng, Zheng, Wei, Zhou, Tao, Liang, Chen, Guo, Zhang (Qwen DianJin Team, Alibaba Cloud; Beihang); submitted Oct 1. Full PDF read (12 pp).

What it is: DeFA builds an event dependency graph that combines protocol relations with semantic dependencies. Protocol relations are pairings like tool request → result and delegation → execution, which an LLM has to induce from message formats (§3.2). Semantic dependencies are cases where a later step uses an earlier value. DeFA then recalls suspicious steps, builds a failure propagation graph of their sources and effects, and adjudicates the decisive step, the responsible agent and the error category.

Key numbers:

  • Who&When, exact step: 52.7% with GLM-5.2, against the best baseline's 43.5% (ErrorProbe); +7.6 to +9.8 points across three backbones (Table 1).
  • Who&When Pro text: 80.3% (Table 2).
  • Ablation (Table 4): removing only the propagation edges, with the same candidate set and 83.2% coverage, drops exact step from 52.7% to 40.2%.
  • Cost: 8.73 LLM calls per trajectory against 6.93 for ErrorProbe (§4.4).
  • Long runs: accuracy falls to 17.2% on 33–130-step trajectories.
  • Downstream: feeding DeFA's diagnoses into Trace2Skill raises SpreadsheetBench accuracy by 6 to 15 points (Fig. 3).

Limits: the relation recovery depends on the LLM's reading of the trajectory. The downstream gain is shown only for spreadsheet skills (§5).

BQAA read: the protocol edges DeFA spends LLM calls to infer are exactly the parent/child and tool-call/tool-result links a structured trace already records. A BQAA trace that carries tool_call_id pairing and delegation edges hands an attributor the graph for free. It saves calls, and on DeFA's own ablation those edges are worth about 12 points of accuracy. The 17.2% on long runs argues for attribution windowed by segment over BigQuery, not whole-trace prompts.

A3 (NEW). Auditing Web Agent Evaluation on WebArena-Lite: Human Review of Outcomes and Trajectories (arXiv 2610.01491)

Gan, He, Tsujii, Kobayashi, Itoh, Funakoshi (Techtouch; Institute of Science Tokyo); NeurIPS 2026 workshop Who Verifies the Agents?; submitted Oct 1. Full PDF read (13 pp).

What it is: a human audit of all 165 WebArena-Lite tasks under six conditions (GPT-5.5 with a memory-and-analysis aid, MASM, and optional guide text, at 15 and 25 steps, plus a Qwen3.5-9B ablation). It keeps the raw evaluator score next to a corrected score, marks the first consequential error, and tracks verified progress at each step.

Key numbers:

  • Missed successes: human review recovers 5.45 to 8.49 points of success the automatic evaluator missed. That is 47 tasks across four settings, or 15.5% to 24.6% of corrected successes (Table 1).
  • Churn under a small net gain: guide text changes the net result by only +6 tasks at 25 steps, but 34 of 165 tasks (20.6%) flip outcome, p = .392 (Table 3, §5.4).
  • Failure modes (102 failures, Table 6): scroll oscillation 31.4%, unfinished exploration 12.7%, premature answer 12.7%.
  • Self-reports (Table 7): 18 failed runs self-report at least 80% progress and 7 report 100%. Among the 40 failures that ran out of steps, mean verified progress is 56.2%, and none reached 100%.
  • Front-loaded progress: the first two actions give the largest progress gains, 23.6 and 19.0 points (Table 8).

Limits: one rollout per condition, human judgment labels, structured progress extractable for only 55.2% of tasks, and possible guide leakage on at least one task (§6).

BQAA read: three schema rules follow.

  1. Store raw_outcome and corrected_outcome side by side and never overwrite one with the other.
  2. Agent self-reported progress is a claim, not a measurement. Keep it in a separate column from verified progress.
  3. Report paired task flips, not just net deltas, when comparing two agent versions. A +3.6-point net change hid a 20.6% churn here. A BigQuery query for "tasks that flipped between version A and version B" is cheap and belongs in every A/B evaluation view.

BQAA's loader should accept a raw ExportTraceServiceRequest and upsert partial traces. Value: high; it is the cheapest new ingestion source.

Expect OpenInference to add the first decision-specific attributes within six weeks. BQAA should keep span_kind open and add a "judgments" view: verdict × model_result × confidence. Value: medium-high.
  3. Warehouse cost per agent task becomes a benchmark column. Argo-Bench's Appendix K is likely to be copied by other data-agent benchmarks. BQAA's "BigQuery bytes per agent run" join is the natural product answer. Value: high for BQAA specifically.
  4. Fail-closed defaults spread. Pydantic blocks when unsure; LiteLLM #44066 turns stdio MCP off; Mastra #25740 changes the MCP approval default. Expect breaking-default releases in at least two of these within six weeks. Analytics must record which policy produced a block, not just that it happened.
