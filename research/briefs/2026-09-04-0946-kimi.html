Industry

1. MLflow 3.16.0: span links, session grouping by default, and Assistant-built Custom Trace Views (Sep 4)

Verified from the v3.16.0 release notes, tagged 2026-09-04T08:30 UTC, after the 2134 baseline. Three major features:

  • Span Links. "Spans rarely stand alone. MLflow 3.16.0 adds first-class span links so relationships between spans — a retrieval step, a tool call, a downstream trace — are captured and navigable. Record links in your SDK and the trace explorer surfaces them in a dedicated Links tab to jump straight to the destination span." TypeScript SDK support landed in the same release, and the trace explorer normalizes span links arriving over OTLP.
  • Redesigned Trace Experience, now default. Rebuilt trace explorer with tighter row density, reorderable columns, configurable custom columns from any trace tag or metadata field, and session grouping to "find multi-turn conversations inline." The experiment Sessions tab is deprecated in favor of Traces session grouping.
  • Custom Trace Views. "Design your own trace UI in plain English — describe the view you want and the MLflow Assistant builds it for you, laying out exactly the fields you care about with no config files or custom code. Save, name, and reuse views per experiment so your whole team shares the same lens on your traces."

Also in the release, product-level and on-beat: an Assistant analyze action on evaluation runs; logFeedback and typed trace assessments in the TypeScript SDK; per-user budget policies in the AI Gateway; built-in judges can use UC model services; make_judge exposes generate_rationale_first; the OpenCode tracing plugin now includes reasoning/thinking content in spans; the Claude Code plugin gains workspace support; and a docs fix for the online evaluator skipping long-running traces (a completion buffer).

TL;DR for BQAA. Three reads. First, span links are the shippable form of the edge schema the academy thread keeps asking for (AgentEval: "attribution works when the schema records the edges"): MLflow now records span-to-span and span-to-trace relationships as data, not as parent-child inference. BQAA's event/step table should carry a links field (target span/trace id plus a typed relationship) rather than reconstructing causality from ordering — column note, not a feature. Second, session grouping displacing a dedicated Sessions tab is a second vendor (after Laminar's session timeline) deciding the session is a lens over the trace table, not a separate object — that is exactly BQAA's session-row-over-event-table shape, and the docs can now cite MLflow and Laminar as prior art. Third, Custom Trace Views plus the Sep 3 Langfuse entry below make five vendors shipping "assistant does analysis over the trace store" (Laminar Agent SQL, Phoenix AI Query, Braintrust Loop, Langfuse Assistant, MLflow Assistant). The differentiation sentence for BQAA gets sharper: the assistants are bound to each vendor's store; BQAA's store is the customer's BigQuery, where the same questions are plain SQL the customer already owns.

2. Langfuse: the Assistant now builds datasets and dashboards and runs code over thousands of observations in a sandbox (changelog Sep 3, missed at baseline) — plus multimodal LLM-as-a-Judge (Sep 1, missed)

Verified from the dated entry pages. The Sep 3 entry (link): ask the Langfuse Assistant to build a dataset ("create a dataset from the failed generations of last week"), build a dashboard ("error rate and p95 latency for the last 7 days"), or run code over thousands of observations in a sandbox rather than loading payloads into model context ("cluster the main error types across the failed observations of the last 7 days," "find what the slowest 100 traces from yesterday have in common"). Runs continue in the background with completion notifications; anything that changes data or configuration waits for approval, with a per-tool "Always approve" escape. This entry was live before the 2134 baseline ran, but 2134 checked only Langfuse's GitHub tags (v4.28.1), so it was never carded; it post-dates the Sep 2 evaluator-alerts card. This morning's v4.29.0 (14:59 UTC) and v4.30.0 (16:02 UTC) tags are the packaging for it.

The Sep 1 entry (link), also missed: LLM-as-a-Judge evaluators now support multi-message prompts (system criteria, user content, assistant example) and multi-modal inputs — judges can evaluate images, audio, video, PDFs or text files captured in observations, with LANGFUSE_EVALUATOR_MEDIA_* env controls for self-hosters.

TL;DR for BQAA. The sandboxed-analysis half is the fourth citation this week that the read path over a trace store is an agent loop with code execution, and Langfuse's approval-gating wording ("anything that changes data or configuration still waits for your approval") is the governance line BQAA's own assistant story should copy verbatim. Note the division of labor Langfuse chose: the assistant writes into datasets and dashboards, i.e. into the same store it reads — the BQAA analog is the assistant materializing BigQuery tables and Looker views, which is a docs example, not a feature. The multimodal-judge half is a column note: if judges consume image/audio/PDF payloads, the eval event needs the judged content's modality and a media reference, or score comparisons across modalities are meaningless. Both are notes; nothing to start.

Six-week EV

Ranking unchanged from 2134. What moved:

  • Span links as a recorded edge field (schema note, strengthened to shipped-primitive status by item 1). MLflow 3.16.0 records span-to-span and span-to-trace relationships (retrieval, tool call, downstream trace) as first-class SDK data with a Links tab — the second vendor after Langfuse's v4 graph work to ship edges as data. BQAA's step/event table should carry a nullable links field (target id + relationship type) so attribution queries don't reconstruct causality from timestamps. Companion to AgentEval's "the schema records the edges" and the source-event-references note; still a column note, not a roadmap row.
  • Assistant-over-trace-store is table stakes (positioning note, strengthened by items 1 and 2). Five vendors now ship it: Laminar Agent (SQL), Phoenix AI Query, Braintrust Loop, Langfuse Assistant (sandboxed code over observations, approval-gated writes), MLflow Assistant (plain-English trace views, analyze action on eval runs). All five are bound to the vendor's own store. BQAA's wedge sentence: the store is the customer's BigQuery, the assistant's outputs are tables and views the customer keeps, and the read path is governed SQL the customer can audit. Belongs in the docs' positioning section; no feature.
  • Judged-content modality on eval events (new column note, from item 2). Langfuse judges now consume image/audio/video/PDF payloads captured in observations. Any aggregation of judge scores needs the judged content's modality (and a media reference) on the eval row, or cross-modality score comparisons are noise. Same family as the judge instrument metadata note from 1934.
  • Session as a lens over the trace table (vocabulary note, strengthened by item 1). MLflow deprecated its dedicated Sessions tab in favor of session grouping inside the trace explorer; Laminar made a session one timeline of runs, evals and notes. Two vendors now implement BQAA's session-row-over-event-table shape; cite both in the schema docs.
  • Per-action instability floor, typed refusal events, mechanism-plane gate events, source-event references, failure-step pointer with outcome stratum, judge instrument metadata, task-key baseline, repeatability-is-not-correctness: unchanged from 2134.
