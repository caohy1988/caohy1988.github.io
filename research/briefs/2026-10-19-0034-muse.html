2. Vercel AI Gateway logs — Sessions view groups requests by session affinity (cache, cost, provider path per session)

  • Primary: https://vercel.com/changelog/ai-gateway-logs-now-show-session-affinity (published Oct 18, 2026; changelog Atom 2026-10-18T20:03:00Z; page re-read in full by me). Fresh F05. Window note: collectors labeled this "pre-window CARRY" against their per-pack windows; against this brief's window (opens 19:34Z Oct 18) 20:03Z is in-window, and the 1234 brief had already started when Agy 1232 carded it, so it was never consumed. Judged here on that basis.
  • What shipped, per the changelog: AI Gateway logs gain a Sessions view grouping requests into sessions; each row shows the coding agent or app (e.g. Claude Code, Codex, Cursor), session cost, models, providers, and cached-input share across turns. A session detail shows cache hit rate, duration, and the per-turn path with the serving provider and any earlier providers. Sessions are keyed by an explicit sessionId in providerOptions.gateway or x-session-id header when sent; otherwise requests are grouped by a fingerprint of the conversation opening and shown as fingerprinted sessions. Session affinity (route each turn to the prior turn's provider) runs by default on text and chat requests. Single-turn sessions are hidden until the minimum-turns filter is cleared.
  • Why it ranks: session becomes a first-class, costed unit in a major gateway's own observability — with two identity qualities (client-asserted vs gateway-fingerprinted) in the same stream, and a default-on routing policy (affinity) that itself changes cache-hit and provider distributions. For BQAA the transferable rules are: store session-identity source as a dimension; expect fingerprinted sessions to mis-merge or split at some rate (unquantified by the vendor); and treat any cache-hit-rate improvement after affinity defaults on as a routing effect before reading it as workload change.

NEW — 2610.22466 Harness-Delta Attribution: Dissecting Gains From Harness Evolution

Full PDF read (20 pp., pdftotext of the complete PDF; abstract, method (§§2–4), Results (§5), Table 1, Figures 1–5, conclusion (§7), and appendices B/C/G read). Wenxuan Ding et al. (Amazon / NYU), v1 15 Oct 2026.

  • Method: HDA decomposes an evolved harness's search-set gain ΔS into three measured parts: an overfitting component O (score recovered by an artifact-neutralized copy of the evolved harness — a lower bound on detected overfitting), a test-time-scaling component T (score of a compute-matched baseline harness — the gain reproducible just by spending more inference compute), and a residual G explicitly framed as an upper bound on generalizable improvement. Held-out transfer is measured separately. Settings without a statistically significant ΔS get no attribution.
  • Results (Table 1, 25 settings; 11 executor models × Meta-Harness / SkillOpt / AHE across ALFWorld, LiveMath, CREATE, SWE-bench Verified): in the 21 settings with significant gains, O explains 54% and T 14% of the gain on average; O+T exceeds 50% in 14 of 21 (§5). On ALFWorld, all five Meta-Harness executors reach 100% search-set success while HDA attributes 98% of the gain to overfitting, and the small-model (0.8B/2B) evolved harnesses become rule-based controllers that make no LLM calls (§5; Appendix D). On LiveMath a single recurring meta-option artifact is independently discovered by different frameworks: test accuracy 100% (53/53) on questions containing the artifact vs 31% (22/71) on the rest, so a positive held-out gain can be an artifact shared across splits (§5). CREATE is test-time-scaling-dominated (compute-matched baseline recovers 49% for Haiku 4.5 under Meta-Harness and outperforms the evolved Qwen3.6-35B-A3B harness; 75% T share under AHE). SWE-bench Verified is the benchmark where residual-dominated rows actually appear (several G = 94–100% rows in Table 1; Appendix G contrasts a benchmark-fitted patch heuristic with a reusable guardrail).
  • Limits (my assessment from the text): no standalone Limitations section; the interpretive bounds are stated with the method — O is a lower bound (undetected overfitting hides inside G), G an upper bound — and the protocol is semi-automated, retaining human review at exactly the two judgment calls, compute-matching and overfitting neutralization (Figure 6 / Appendix B–C). So HDA numbers are analyst-assisted measurements, not a fully automatic metric; and the evolved artifacts are small-benchmark objects (LiveMath, ALFWorld) in most overfitting-dominated rows, with SWE-bench the main counterweight.
  • BQAA read: this is the evaluation-side counterpart of cost accounting. Any "new harness version scores X better" claim BQAA stores should carry, at minimum, the inference budget, a compute-matched baseline delta, and an artifact check — otherwise the warehouse will faithfully record overfitting and extra sampling as capability. It also gives ADK a concrete protocol shape for separating the three before a harness change is promoted.

NEW — 2610.22987 From Approval to Abuse: Privilege Escalation Attacks on Harness-Protected Coding Agents

Full PDF read (18 pp., pdftotext of the complete PDF; abstract, threat model (§2), two-stage framework (§3), Results (§4, Tables 1–2, Figure 4), mechanistic insights (§5, Tables 3–4), conclusion and ethics statements read). Yechao Zhang et al. (NTU / NUS / Ant Group), v1 16 Oct 2026.

  • Claim and setup: harness approval systems (Claude Code, Codex CLI) let users persist agent-proposed allow-rules to reduce approval fatigue. The paper plants adversarial context in a repository so that, during a routine task, the agent requests a plausibly justified but over-broad reusable rule; conditional on the user approving it, later harmful actions matching the rule execute with no further prompt (§2.1: 25 cases per configuration, synthetic isolated workstations, mocked credentials).
  • Stage I — permission acquisition (Table 1): goal-reachable over-broad rules elicited in 17/25 (Codex gpt-5.6-luna), 18/25 (Codex gpt-5.6-sol), 14/25 (Claude Haiku 4.5), 9/25 (Claude Sonnet 5) — 58/100 overall, vs Direct Request's 7/18/6/1; benign control 0/25 everywhere. Mean permission-capability coverage (PCC) of acquired rules: 0.48–0.61 per configuration.
  • Stage II — authority reuse (Table 2): on the shared 58 eligible checkpoints, verified silent goal completion 47/58 (81.0%), vs IssueTrojanBench-adapted 20/58 and Direct Injection 1/58; most successes are prefix-attributed (the malicious action matched the Stage I-acquired rule prefix). Figure 4: no consistent fall-off from Ordinary to Critical sensitivity tiers.
  • Mechanism (§5): the two harnesses generalize rules along different axes — Codex over workflow history, Claude Code over command syntax (Table 3); agents exercise granted authority when the target op is made a dataflow/control-flow dependency of the benign task (3/3 in the Table 4 ablation) rather than when it is merely narrated (0/3 base instruction); stronger agents route around roadblocks that do not causally dominate the execution graph.
  • Limits: everything in Stage II is conditional on approval — the paper measures consequences given approval, and does not measure how real users rate-limit broad rules (it cites Anthropic's figure that 49.5% of active Claude Code users have configured a Bash allow rule as motivation, not as an approval-rate measurement). N is small (25/configuration), environments are synthetic, and only two production harnesses are tested. The defense direction named in-text is an immutable authority ceiling set before untrusted context is read (§6, citing CapScope) — the paper itself proposes no deployed fix.
  • BQAA read: approval events are privilege state transitions. A trace store for coding agents should record proposed rule text/scope, its generalization basis, approver, and persistence lifetime, and should be able to answer "which later actions executed under a rule acquired in an earlier, differently-tasked session." Without that, post-hoc audits see allowed actions with no visible reason they stopped prompting.

Six-week EV

  • Era becomes a trace dimension, not a version footnote. The MCP reference servers now answer two spec eras from one binary (v2.0.0, this window), on a new SDK major and a new Node floor. Expect client SDKs and gateways to surface the negotiated era inconsistently during the transition; within six weeks the judgeable question is whether era/protocol-version shows up as a standard session field or has to be inferred per vendor. Schema should carry it now, nullable, rather than backfill later.
  • "Harness improved" claims will increasingly need an attribution split. HDA (2610.22466, this window) gives harness-evolution marketing a decomposition to be measured against: overfitting, extra compute, residual. Frameworks that auto-evolve prompts/skills (Qwen's pinned catalogs into hosted runtimes, this window, is the shipped-management side of the same trend) will produce versioned harness artifacts whose benchmark deltas are uninterpretable without budget and artifact controls. Six-week watch: whether any major framework ships HDA-style reporting (compute-matched baseline, artifact neutralization) as a built-in eval feature.
  • Approval state is joining traces as audit surface. The allow-rule escalation results (2610.22987, this window) plus another window where approval-adjacent fixes shipped quietly (Letta Code OTID-after-rejection preservation; Qwen approval-policy selection in managed sessions) point the same way: the interesting forensic object is no longer only what the agent did, but what standing permission let it do it without asking. Expect harness vendors to add rule-scope surfacing or ceilings; until they do, rule proposals/approvals belong in the event model.
  • Session identity quality diverges across vendors. Vercel's asserted-vs-fingerprinted sessions (this window) is the latest instance of the pattern from prior briefs (gateway session affinity, per-vendor skill ids): the grouping key exists everywhere, its reliability varies, and nobody publishes the error rate. Within six weeks, anticipate more session-level cost/cache products; BQAA's defensible position is storing identity source and keying method per session so cross-vendor session aggregates stay honest.
  • Script-wrapped tool use will distort flat tool metrics. Letta CodeMode (this window) collapses arbitrary tool combinations into one script invocation with background completion. Other CLIs have the same pressure (fewer round-trips). If this spreads, tool-call counts and per-tool latency series break comparability at each adoption boundary unless inner calls are recorded as children — worth a schema convention before it is common.

  • MCP servers v2.0.0: reference servers are dual-era (modern + legacy) on TS SDK v2 / Node 24 — add negotiated era/protocol version to the session record; server version no longer determines it.
