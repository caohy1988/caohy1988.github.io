1. Routed — local skill selection with inspectable ranking and correction history

New product capability, September 6. Routed accepts a task description and selects instructions from an indexed skill collection through a CLI or MCP interface. Its official release records place MCP support in v1.1.0 at 07:08:59 PDT and adaptive history weighting in v1.3.0 at 12:01:21 PDT, both within this slot. These dates were retrieved from GitHub's release API; they are not inferred from social-post timestamps.

The tagged implementation makes the capability concrete. route_skill returns matched skill IDs, paths, instructions, scores, and optional component signals; it can also return no match. A separate feedback operation records a preferred skill for a normalized query pattern. On the hybrid-scoring path, repeated corrections can increase that skill's history contribution, with a 21-day decay half-life. Strong exact matches can bypass the hybrid path. This is a stateful selection mechanism, not a fixed ranking determined solely by the prompt. MCP implementation, router, correction store.

Evidence limits: release notes and selected tagged source files were inspected; no installation, benchmark reproduction, or cross-host test was performed. The advertised sub-20-ms latency and token savings remain author claims. Returning skill instructions still consumes downstream context. The semantic engine permits model downloads and falls back to a different vector-generation path when inference is unavailable; the inspected code does not establish guaranteed zero egress, equal routing quality across modes, or calibrated success probabilities. Tagged README, semantic engine, scorer.

Why this clears dedupe: no matching product, repository, title, or capability entry was found in catalog items, nested progress, or prior briefs. Existing otel-genai-skills-proposal coverage concerns recording skill activity; this supplies a released selection interface and an inspectable feedback mechanism. It is an emerging implementation to compare, not evidence of enterprise deployment maturity.

BQAA TL;DR — analyzer inference: preserve the skill/index revision, routing mode, candidate scores, selected instruction revision, and correction-state timestamp when investigating a choice. Distinguish selected → loaded → followed → useful. Test correction persistence and downstream outcomes separately: an accepted preference is not proof that the preferred skill improved the task. Keep this within existing feedback-correction and memory-use evaluation.
