Decision: PUBLISH. 2 NEW (both Academy) and 1 Progress. 0 Industry NEW.

  1. A safety monitor can run, match, and still not enforce — because the evidence never reaches the decision (Academy NEW, full PDF read). Monitor-Validity Failures (https://arxiv.org/abs/2610.23362) confirms 18 repair-boundary cases across 11 framework project groups with deterministic parent/fixed canary contracts (Table 2); 14 reach E1 enforcement boundaries (Table 4). The canonical case: a NeMo Guardrails regex detector returned is_match=true and the parent framework still allowed the output, because the positive result was never mapped to the block decision. For BQAA the lesson is direct: a trace that records "detector ran / evaluator scored" without recording the downstream decision (block, route, redact, interrupt, finding) cannot distinguish enforcement from a stranded result. Visibility and decision are separate oracles and belong in the event model as separate fields.
  2. MCP gateway architecture is a cost and security variable, not plumbing (Academy NEW, full PDF read). GatewayBench (https://arxiv.org/abs/2610.23449; 524 tasks, 11,118 real-world tools from 251 MCP servers, 7 gateways) finds that as injected noisy tools scale 0 → 1,500 under GPT-5.4, flattened gateways' mean tokens/turn climb 8.3k → 233.3k while hierarchical (discovery meta-tool) gateways stay at 9.1k → 12.6k (§5.2, Figure 5), and hierarchical gateways hold indirect-attack success far below flattened ones (Table 2 means 19.6% vs 60.5% under OpenAI SDK/GPT-5.1; the gap is driven by tool injection, Figure 4). Any BQAA comparison of agent cost, latency, or injection rates that does not carry gateway type and exposed tool-surface size as dimensions will attribute gateway effects to the model or harness. Results are from a single run per the paper (§5.1) — the magnitudes are large and partly mechanical, but treat exact rates as single-run numbers.

Agno v3.1.5 (2026-10-19T11:53:23Z) + v3.1.6 (13:44:23Z), both stable, both re-read by me: sandboxed ClaudeAgent/CodexAgent sessions pin an exact repository commit across warm reuse and checkpoint restore; sandbox checkpoints move to a content-addressed, upload-verified S3 store; open_run_checkpoint(run_id) yields the verified archive a completed run committed after its container is gone; eval Cases gain session/user/state arguments so cases sharing a session_id run as consecutive graded turns. NEW — 2610.23362 Monitor-Validity Failures: LLM Safety Evidence Paths at Evolving Framework Boundaries

Full PDF read (8 pp., pdftotext of the complete PDF; abstract, problem setting, canary-contract method (Table 1), corpus construction, evidence/impact tiers (Table 2), RQ1–RQ4 experiments (Tables 3–8, Figures 1–4), related work and conclusion read). Junchi Liao, v1 16 Oct 2026. Carried as a HOLD from the 0034 queue; ranked now on the full read.

  • Claim and method: a runtime safety monitor (guardrail, detector, verifier, hook) reads a framework representation — message fields, tool-call objects, stream deltas, detector outputs, trace metadata — not the world directly. As frameworks evolve (new carriers, adapters, surfaces, authority channels), policy-relevant evidence can fail to reach the decision point while the application path stays operational and the monitor stays configured. The paper confirms such failures with canary contracts: one deterministic payload placed only on the changed evidence surface, run against parent and fixed revisions of a public repair, with two separate oracles — did the monitor see the payload (visibility), and did the intended action fire (decision)? A case counts only when the parent misses and the fix restores the same oracle (six stated conditions; loud crashes, fail-closed parents, unmerged PRs and feature additions excluded).
  • Results (Tables 2, 4–6): 18 confirmed cases across 11 framework project groups and 4 implementation ecosystems (Python, TypeScript, Java, C#/.NET), from a 195-reference high-signal denominator pass. Strata are kept explicit: 9 established-boundary repairs, 8 new-surface coverage gaps, 1 boundary-only case; 17 Tier-A (framework/module-level execution) and 1 Tier-B confirmations. 14 cases reach E1 enforcement boundaries — 7 native action outcomes, 6 configured enforcement boundaries, 1 synthetic-consumer consequence — split operationally as 5 block/filter/rewrite, 3 interrupt/HITL-route, 6 hook/cap/policy-state (Table 4); 3 cases are E2 (verifier/safety-prompt evidence) and 1 is E3 (observability channel). Four failure families by first broken dependency (Table 3): carrier (payload moved to an object the monitor does not read — e.g. Invariant: analyzer matched a nested tool call but pending-trace metadata sat only on the top-level message), adapter (detector positive, result-to-action mapping missing — the NeMo regex case), authority (two channels describe the same event; policy reads the lower-authority one), surface (payload only on a newly materialized request/stream/multimodal surface). Breadth checks: largest single project contributes 4 cases (LiteLLM, across four different boundaries); the established-boundary subset alone spans 8 project groups, all at E1. A five-case diagnostic (RQ4) shows ordinary functional checks passing without the canary oracle, and visibility-only checks missing the NeMo/Haystack decision failures. A frozen prospective pass over 300 recent closed PRs (186 merged) produced 27 term-matched candidates: 23 excluded, 3 under reproduction, 1 additional confirmed case outside the retrospective corpus.
  • Limits (stated in-text and my assessment): the corpus is targeted and deterministic, explicitly not a prevalence sample — cases were selected for feasibility, so no rate ("X% of monitors are broken") is supported and none is claimed here. No case establishes the full working→failing→repaired "drift" interval; all are failing-parent/repaired-child contrasts. The 8-page PDF references appendices (B/D) and per-case audit tables (Tables 9–13) that live in the external artifact/case records, which I did not open — per-case revision pairs therefore rest on the main text's summary tables, not on my inspection of each reproduction. Single author; one E1 case is a synthetic-consumer consequence rather than a native action.
  • BQAA read: this names a failure class that trace warehouses are positioned to either expose or hide. If BQAA stores detector/evaluator outputs without the joined downstream decision and the evidence-surface version (which carrier/field/stream shape the monitor actually read), then "guardrail passed" aggregates will silently include stranded positives exactly when a framework upgrade moves the payload. Concrete schema consequences: record visibility and decision as separate facts per monitor invocation; version the evidence surface per framework release; and treat canary contracts — payload placed only on the changed surface, parent/fixed compared — as the regression shape when ADK or any ingested harness changes its tool-call, stream, or callback representations. It also reframes last slot's approval paper (2610.22987): approvals are one decision oracle among several that can disconnect from their evidence.

NEW — 2610.23449 GatewayBench: Unified Capability and Security Evaluation Platform for MCP Gateways

Full PDF read (15 pp., pdftotext of the complete PDF; abstract, gateway taxonomy (§3, Table 1), benchmark construction (§4), setup (§5.1), results (§5.2, Tables 2–3, Figures 4–5), conclusion (§6) and appendices A.1–A.4 read). Zheng et al. (Tsinghua / UChicago / UIUC), v1 16 Oct 2026. Scouted in the 0034 queue (Agy 1832); ranked now on the full read.

  • Setup: 524 tasks (450 DTAP benign/direct/indirect-attack tasks across CRM/Finance/Travel + 74 MCP-Universe execution tasks), scored by rule-based judges on final environment state. Seven gateways in default configuration — flattened (AgentCore, Agentgateway, LiteLLM, Lunar MCPX: full tool list exposed every turn) vs hierarchical (Enkrypt, Strata, Bifrost: discovery meta-tools retrieve tools on demand) — under three agent configurations (OpenAI Agents SDK × GPT-5.1/GPT-5.4; OpenClaw × GPT-5.1). Tool surface is scaled by injecting 0/500/1,000/1,500 task-irrelevant tools sampled from a pool of 11,118 real tools across 251 MCP servers, domain-filtered for strict irrelevance and served by a mock server that returns standard errors (no real side effects).
  • Results (Table 2, no noisy tools): hierarchical gateways hold mean indirect-attack success (ASRind) far below flattened in every configuration — 19.6% vs 60.5% (SDK/GPT-5.1), 30.9% vs 47.2% (SDK/GPT-5.4), 15.6% vs 42.5% (OpenClaw/GPT-5.1) — while direct-injection success is indistinguishable under capability-matched GPT-5.4 (44.7% vs 44.2%), as expected since a gateway shapes the tool surface, not the prompt. The security gap decomposes almost entirely to tool injection (Figure 4: flattened mean 51.5% → 40.6% as noisy tools accumulate, hierarchical ≈16% throughout); environment injection shows no architecture separation. Capability interacts with model strength: downgrading GPT-5.4 → GPT-5.1 costs hierarchical gateways 37.6 mean TSR points vs 11.9 for flattened (discovery becomes an obstacle for weaker models; Enkrypt collapses to 23.3% TSR via hallucinated tool calls, Appendix A.4), while under GPT-5.4 the architectures reach comparable TSR (85.1% vs 87.2%) — the security gain at essentially no capability cost. Harness matters independently: OpenClaw beats the OpenAI SDK on TSR for all seven gateways at GPT-5.1.
  • Scaling and cost (Table 3, Figure 5): from 0 → 1,500 noisy tools, flattened mean TSR falls 10.0 / 3.9 / 6.0 points across the three configurations while hierarchical loses at most 5.5 and nothing under GPT-5.4 (85.1% → 85.6%); the architectures cross over (GPT-5.4: flattened +2.1 points at 0 tools, −2.3 at 1,500). Token cost is mechanical: flattened mean tokens/turn climb 8.3k → 233.3k vs hierarchical 9.1k → 12.6k (GPT-5.4); latency reverses between 500–1,000 tools (no noisy tools: flattened faster, 20.8s vs 30.1s; at 1,500: 64.1s vs 38.7s). Appendix A.4: AgentCore's optional search tool was invoked in only 11/19/1 of 1,800 runs per configuration — a discovery affordance on top of a flattened list goes unused.
  • Limits (stated or evident in-text): main DTAP results are from a single run due to time/cost (§5.1) — no seed variance is reported, so small TSR/ASR differences (and per-gateway orderings) should not be over-read; the headline effects used here are the large ones (token growth is a direct consequence of context composition; the tool-injection gap is tens of points). Noisy tools are mocks that error on invocation and are LLM-filtered for irrelevance, so the setting measures distraction/selection, not competition from working near-duplicate tools. Two model tiers from one family and two harnesses bound generality; gateways run default configurations only; infrastructure/protocol-translation gateways are explicitly out of scope (§3). No standalone Limitations section — constraints are stated inline where noted above.
  • BQAA read: gateway type (flattened vs discovery), exposed tool count, and discovery-call share belong on the session/tool-call record next to model and harness. Without them, three common BQAA readings are confounded: token-cost growth looks like workload growth when it is tool-list carriage; latency regressions look like model regressions when the tool surface crossed the 500–1,000 crossover; and tool-injection incidence looks like a model property when it is largely a surface-exposure property. For ADK, the crossover result is the actionable shape: flattened exposure is simpler and faster at small tool sets, discovery pays once the surface is large — and whichever is chosen, the choice must be observable per run or cross-deployment comparisons are meaningless. Pairs with this brief's other rank: a gateway is also an evidence path — what it exposes (or truncates, cf. Bifrost's truncated descriptions lowering ASR in A.4) decides what any downstream monitor can see.

  • https://arxiv.org/abs/2610.22779 When Can You Trust an Agent's Own Verifier? Stress-Testing Counterfactual Rationale Verification Under Search Pressure and Oracle Access — full PDF read (17 pp.; NeurIPS 2026 workshop paper; method §§3–7, setup §8, Results §9 Tables 2–8/Figures 2–4, Limitations §10 read). The paper stress-tests its own Rationale Consistency Score (negate each stated claim, re-run, measure the drop) inside an LLM agent designing ML pipelines: pressure ratio ρ (applied verifier weight vs task-score spread), four failure modes (silence, untested, claim minimization, oracle exploitation). Findings: the authors' prior configuration runs at ρ ≈ 0.007–0.089 (Table 2) — the verifier barely steers search, partly due to an accuracy gate, though it flips the reported artifact in 5/18 runs as a tie-break (Table 4); search never discovers claim minimization even at ρ ≈ 41.7–63.7 (Table 7; Spearman −0.12…+0.38, all p > 0.15) while instructed minimization cuts claims 18–35% on four datasets (Table 5); pre-commit probe access yields the selection signature (fewer claims, higher verified rate) at sign level on 4/6 datasets with held-out fidelity falling (Table 6; only Madelon's volume drop and Credit-G's rate rise exceed the replicate band, and part of the fidelity decline may be a small-pipeline scoring artifact). Why not ranked: by the authors' own framing the evidence is preliminary — one self-built verifier, one generator model (Solar Pro 3), six pipeline-design tasks with mechanical counterfactuals, three seeds, 16–38 iterations — and the central null is largely structural (search feedback omits claim counts, horizons are short, §9.3/§10), so it demonstrates neither robustness nor gaming in deployed agent loops. The transferable reporting standard is worth noting for BQAA eval design — report applied pressure (ρ) not nominal weights, count claims separately from verifier scores, pair any robustness claim with a capability control, measure fidelity on verifier-unseen data — but no quantitative claim from this paper is used elsewhere in this brief. Six-week EV

  • "Monitor ran" will stop being sufficient evidence. Monitor-Validity (2610.23362, this brief) gives the failure a testable shape — visibility oracle + decision oracle, payload only on the changed surface — at exactly the moment frameworks are churning their evidence surfaces (MCP dual-era servers last slot; decision/media tracing and span customizers shipping this window at NOTE grade). Within six weeks the judgeable question is whether any major framework ships canary-style evidence-path regression tests, or whether operators keep discovering stranded detectors from incidents. BQAA's defensible move now: store monitor visibility, monitor decision, and evidence-surface version as separate, joinable facts.
  • Tool-surface size becomes a first-class cost/security covariate. GatewayBench (2610.23449, this brief) quantifies what gateway vendors assert: flattened exposure scales tokens/turn ~28× across 0→1,500 tools while discovery stays flat, with a latency crossover in the hundreds of tools and a persistent tool-injection gap. As MCP server counts per deployment grow, expect gateway choice to be re-litigated per deployment tier — and expect cross-vendor agent benchmarks that omit gateway type and tool count to keep producing non-comparable numbers. Schema should carry both fields before the fleet data accumulates without them.
  • Run provenance is hardening from logs into artifacts. Agno's verified, content-addressed, reopenable run checkpoints + commit pinning (Progress, this brief) continue the line from Qwen's pinned catalogs (0034) and durable command operations: the run definition and its end state are becoming addressable objects. Six-week watch: whether checkpoint/commit references start appearing in trace exports by default, which would let BQAA join analytics rows to exact replayable state instead of reconstructing it.
  • Decision calls are emerging as a traced object — shape still undocumented. Two independent NOTE-grade ships this window point the same way: Braintrust tracing OpenAI/AI-SDK decision calls, and the Vercel AI SDK adding a Perplexity Decisions-API provider patch. If "decision" becomes a standard span kind, BQAA will need a canonical decision record (options considered, chosen option, policy/authority) rather than per-vendor blobs. Watch for the first vendor to publish the actual span fields; that publication, not the changelog bullet, is the rankable event.
  • Patch-train cadence is now the background rate; version annotations matter more than version cards. This single 12h window contained ~140 Vercel package releases, paired same-day releases from Agno/Opik/OpenHands, and cost-accounting changes inside Opik patches. The analytical risk is no longer missing a launch; it is pooling metrics across silent accounting/pricing/default boundaries (Opik span pricing, LangGraph deploy default, both this window). Expect more value from boundary annotations on ingested series than from additional release cards.
