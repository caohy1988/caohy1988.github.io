1. NEW rank: EvoOntology: A Self-Evolving Ontology Layer for Data Agents — an agent-facing ontology (Terms/Mappings/Constraints/Evidence) exposed as MCP browse/resolve tools and self-evolved from failure trajectories through typed, paired-validation-gated edits: +17.8 avg Traj-Wise on DDR-Bench across six backbones, +7.4 EX on BIRD — while injecting the same ontology statically into the prompt hurts strong backbones by up to −15.0

Shaolei Zhang (corresponding), Ju Fan, Xiaoyong Du (Renmin University of China; github.com/ruc-datalab/EvoOntology). v1 2026-09-14 (HF-trending pointer via DSH 2032/Agy 2132; not a fresh abs — carded on full-text merit). Full text read incl. Tables 1/3/4/5/7/8 and Fig 5. (PDF)

  • Method: ontology = typed semantic graph (Terms, Mappings, Constraints, Evidence) + two MCP tools (browse(q,k,n), resolve(I,c)) + a compact session manifest (the only prompt injection). Builder agent proposes concepts from the training workload and commits only probe-verified entries (executable probes against raw sources, no gold answers). Evolution loop: cluster failure/success signatures from historical trajectories → attribute to Content/Tool/Schema level → propose a single-level typed patch → accept only if paired validation-set score improves by margin τ; rejections logged. Eval: reciprocal two-fold split-and-swap (70% build/evolve, 30% paired validation, frozen ontology tested on the held-out fold, reversed and averaged).
  • Numbers (paper's own, Tables 1–8): DDR-Bench 10-K: Traj-Wise gains +4.8 to +26.7 (avg +17.8 over six backbones; best GPT-5.6-sol 93.5 vs 68.5 baseline). BIRD Oracle Knowledge: EX avg +7.4, VES +8.6 (positive on all six backbones; Claude-Opus-4.8 78.3 EX). InsightBench: mean +1.9 (authors admit saturation). Ablations: removing the acceptance gate costs −11.2 (biggest single loss); Tool-level edits carry 57% of accepted gain; masking Mappings costs −13.4. Cost: evolved ontology cuts turns/task 14.6→8.4 and tokens 52.6K→42.0K (~20% below baseline) while Traj-Wise rises 69.5→89.5. Cross-backbone transfer drops ≥6.6pts (Jaccard overlap of accepted Terms ≤0.62 — evolved stores are backbone-specific).

Mandatory qualifications + claim-check corrections (adjudication): (1) the abstract says "four LLM backbones"; the experiments use six (Tables 1/3/4 all have six rows; "four" is only an analysis subset — sloppy but conservative direction). (2) "Consistently outperforms semantic-layer approaches" does not strictly hold on InsightBench — the GPT-5.5 row is numerically identical to Baseline+SL and Opus-4.8 ties; holds on all six backbones on DDR and BIRD. (3) Table 4's comparison to CHESS/MAC-SQL is apples-to-oranges (non-Oracle BIRD numbers vs EvoOntology's Oracle-Knowledge rows) — do not quote "beats CHESS by 13pts". (4) Baseline+SL is the authors' own builder output injected statically — no external semantic-layer system benchmarked; no error bars or significance tests; big gains concentrate on DDR-Bench; evolution requires benchmark-like workloads with scorable validation sets; repo release claimed, not independently verified.

TL;DR for BQAA: (1) Semantic layer as queryable tools, not prompt injection — the same ontology content that hurt agents when prepended (−15.0 worst case) helped via browse/resolve (+20.0), while cutting tokens ~20%: direct evidence for how BQAA should surface schema/metric semantics to agents. (2) Telemetry → typed semantic-layer patches with a paired-eval gate — their evolution loop is production trace mining formalized (attribute failures to content/tool/schema; single-level edits; accept only on paired validation), and the gate is the load-bearing piece (−11.2 without it): a template for safely auto-maintaining a BigQuery semantic layer from agent traces. (3) Semantic layers are backbone-specific (cross-backbone transfer −6.6 to −10.9pts) — one shared induced layer will underperform per-model stores if BQAA serves multiple model generations; the evolutionary, tool-exposed counterpart to the 1234-carded Semantic Layer Induction.

2. NEW rank: RecreationWorld: Scalable and Verifiable Environments for Hybrid Computer-Use Agents — 250 tasks across five platforms where agents must discover a running reference app's behavior via GUI exploration and re-implement it in code, scored by hidden oracle-derived programmatic + visual test suites: GPT-6 Astra leads at 58.1% but passes all programmatic tests on just 2.8% of tasks — and only 23.6–47.5% of trajectories re-run and inspect the artifact after the final edit

Shuai Bai, Jiayong Deng, Yikun Fu, … Zhihui Xie, … Bowen Zhou (32 authors; Alibaba Qwen team per in-text evidence). v1 2026-09-18. Full text read incl. Tables 2/3, Figs 3/5/9/17, App A. Claim-check: clean — every abstract number (58.1%, 2.8%, 250 tasks, five OOD benchmarks) matches the body. (PDF)

  • Method: hybrid computer-use task — given only a running reference (source withheld on desktop/Android), the agent interleaves GUI exploration, implementation, and visual/behavioral self-verification; deliverable is a runnable build (median 282.5 top-level tool calls, 20h budget — genuinely long-horizon). Evaluation: hidden frozen suites of programmatic assertions (AT-SPI/AX/UIA/UiAutomator) + VLM-judged visual assertions, every case validated on the reference and human-reviewed before freezing. Training-data engine: 35k verified recreation trajectories (7k/platform, verifiers as reward). Integrity: permission/network isolation + evaluation-hacking attempt detectors + exact-line overlap audit vs references (median 0.014–0.088%).
  • Numbers: GPT-6 Astra 58.1% overall; full programmatic coverage only 2.8% (≤0.8% all others); 90%-coverage 17.6% vs ≤5.5%. Transfer from recreation training: up to +17.9pp on five OOD benchmarks (hedged by the authors as exploratory). REPL-runtime study (Windows, 39 valid pairs): composing tool calls in a persistent REPL+SDK vs per-primitive MCP round-trips — tool-result text −65.5%, input tokens −40.7%, cost $90.50→$41.58/task, similar quality. Trajectory telemetry: strict final edit→relaunch→inspect closure only 23.6–47.5% across models; same-field controlled input probing in 13.4–17.0% of trajectories; recreations smaller than references in 89.4% of cases (median LOC ratio 16.9%).

Mandatory qualifications (adjudication): transfer training entirely in-house (trajectories by Qwen3.8-Max, scored by authors' own verifiers, SFT on Qwen-family inits, one trial/task/checkpoint, no external replication); VLM judge is the authors' own Qwen3.7-Plus; 44/50 Web tasks are benchmark-authored synthetic sites and Web can't enforce the source-blind boundary (mitigated by a 0.10 score cap on detected reference replay); n=10 frontier models; the +17.9pp transfer figure rests on first-vs-last-checkpoint comparisons with acknowledged harness-revision differences — treat as soft.

TL;DR for BQAA: (1) Oracle-derived hidden tests beat spec-authored tests — freeze behavioral assertions validated against a running golden reference before scoring any candidate; directly portable to data-agent evals (execute golden SQL/pipelines, replay candidates, freeze the denominator so agents can't move their own metric). (2) Measure loop closure, not just outcomes — only 23.6–47.5% of trajectories re-run and inspect the artifact after the final edit; one case scored 100% visual / 55.1% programmatic. Final-unchecked-edit rate is a trace-level metric BQAA can compute today. (3) Persistent-runtime composition cuts eval cost ~54%/task at similar quality — a concrete lever for long-horizon agent harnesses; their evaluation-hacking detector + isolation design is a guardrail-telemetry template.

3. NEW rank: Grounded Skill Synthesis from Code at Scale for Agentic Intelligence — a fully automated pipeline mines 1,006,822 typed skill records (with control rules, invariants, anti-goals, span-level provenance) from 19,769 GitHub repos, verifies them by source-body-blind LLM round-trip reconstruction, and the resulting bank beats trajectory-derived skill banks on all seven shared benchmarks (+6.6 to +13.3pts) with +5.0pts macro-average over no-skill (57 wins / 6 ties / 9 declines of 72 pairs)

Yongqi Tong, Pan Wang, Hang Wang, Jianshe Li, Xin Zhang, Jiang-Ming Yang, Wei Wu (Ant International). v1 2026-09-04 (HF-trending pointer via Muse 1932; older ID resurfacing, not a fresh abs — carded on full-text merit). Full text read incl. Tables 1–3, Figs 2/6/7, App B/D. Claim-check: clean (adjudicator independently recomputed both Table-1 means and recounted all 72 pairs: exactly 57/6/9 — matches). (PDF)

  • Method: repos >500 stars parsed into functions/methods/CLI entry points; LLM tagger selects reusable-intent units; each becomes a typed skill record (atomic op / composite workflow / recurring pattern) with control rules, invariants, anti-goals, span-level provenance. Verification = source-body-blind reconstruction (regenerate code from the record alone) + source-aware LLM judge + adjudicator — explicitly not execution-based. Retrieval: feature tagging + deterministic purpose indexing (750,536 cards). Eval: protocol-matched skill vs no-skill pairs (only skill access varies) across 5 model families × reasoning modes (9 settings) × 8 benchmarks.
  • Numbers: macro-average 42.90 → 47.90 (+5.0pts, +11.66% relative — the abstract's "11.7%" is relative); vs trajectory-derived banks (Trace2Skill/ExpeL/SkillRL-Bank) 49.5 vs best-per-benchmark oracle 40.1, margins 6.6–13.3pts, mean±std over 5 runs. AI-code vs human-code skill banks: 93.50% vs 93.00% on 400 LiveCodeBench tasks (= 2 tasks; paper hedges "does not establish equivalence"). Summary rendering at k=3 cuts rendered skill context 88.9% (6,352→707 chars) with preserved/improved scores. RL integration: post-generation review placement 24%→38% at step 150.

Mandatory qualifications (adjudication): verification is LLM-judge-based (reconstructor/judge/adjudicator share one model config), not execution-grounded — the paper concedes it is "not a substitute for test-based verification"; human spot-check is n=25 per outcome pool; RQ2 baselines built and evaluated with single models; RL result is a single checkpoint, no seeds; no task-paired significance tests in Table 1; no artifact release (no repo/URL for CodeSkillBank or pipeline — reproducibility partial); benchmarks are generic coding/math/terminal — no BI/SQL/data-agent tasks.

TL;DR for BQAA: (1) Mine skills from code, not just trajectories — repository-derived records beat trajectory-derived banks 7/7 under an identical harness; BQAA's internal SQL pipelines, dbt repos, and query-repair code are a pre-trajectory source of reusable procedural knowledge for data agents. (2) Source-body-blind reconstruction is a cheap, stealable verification filter for any auto-generated skill/memory artifact, and span-level provenance lets records be invalidated as source evolves — applicable to a skills store over BigQuery runbooks or NL2SQL examples. (3) Placement and rendering dominate: skills help most at planning/post-generation review, not first-pass prompting, and 88.9% of skill context can be cut via summary rendering without losing utility — a context-cost lever for production agents.

NEW rank: AutoViewMem: Self-Configuring Orthogonal Views for Conversational Long-Term Memory — induce a compact set of complementary extraction "views" from the interaction stream itself (LLM proposals + DPP diversity selection), write structured provenance-tagged memories per view, and plain top-K retrieval then suffices: best overall on LoCoMo (0.837/0.853 judge) and +5.8pts over the strongest baseline on PersonaMem-32k — with retrieval scored at evidence/provenance level so multi-view projections can't inflate recall

Zijie Cao, Xijun Qu, Zhicheng Gu, Xiaoshu Chen, Duanyang Yuan, Yanning Hou, Sihang Zhou, Jianxing Gong, Jian Huang, Yang Mei (National University of Defense Technology). v1 2026-09-18. Full text read incl. Tables 1–3. Claim-check: clean — every body number matches Tables 1–3; "orthogonal" hedged in §3 as "pragmatically low-overlap". (PDF)

  • Method: every N=50 dialogue chunks an LLM proposes 10 candidate views (name + slots + extraction template); a Determinantal Point Process over view embeddings selects K=10 diverse/low-overlap views; each chunk extracted against all active views with view tag + timestamp + provenance span IDs. Offline consolidation: canonical-hash dedup → similarity graph (cos ≥ 0.9, tightened to 0.999 for oversized components) → LLM adjudication merges/splits under Containment/Complementarity/Independence rules, provenance kept so consolidation is auditable/reversible. Query time deliberately boring: single unified index, top-K, evidence-level dedup under token budget. Eval: LoCoMo (1,540 Qs) + PersonaMem-32k (589 MCQs), Qwen3-8B/14B backbones, baselines A-mem/Mem0/MemGAS/MemoryBank + Full-History oracle, shared embeddings, temp 0.
  • Numbers: LoCoMo overall judge 0.837 (8B) / 0.853 (14B) — best overall in both blocks. PersonaMem-32k 69.10% (14B) vs A-mem 63.33 (+5.77) and Full History 55.18 (+13.92). Ablation: full J=0.837 / no-positive-rate 5.14%; single-view 0.774/5.53%; w/o DPP 0.777/7.03%; w/o consolidation 0.801/9.83%.

Mandatory qualifications (adjudication): judge is Qwen3-8B while both backbones are Qwen3 — same-family judge bias possible, no cross-family judge check; only Qwen backbones, only two conversational benchmarks — no data-agent/tool-use workload (authors' own listed limitation); PersonaMem gains concentrate in synthesis-type capabilities — raw fact recall (R-Fact 67.4) loses to MemoryBank (69.0/76.7), not a uniform win; no significance tests; code/prompts "upon acceptance" — not released.

TL;DR for BQAA: (1) Evaluate retrieval at evidence/provenance identity, not item count — dedup retrieved items by source span before scoring so redundant writes can't inflate recall; directly transferable to BQAA trace/artifact retrieval evals where one evidence item fans out into multiple stored records. (2) Move semantic disentanglement to write time — induce schemas from the trace stream and write structured provenance-tagged items per view, then plain top-K suffices: the same design question BQAA faces logging heterogeneous agent events into one store. (3) Consolidation needs adjudication, not just similarity thresholds — graph-cluster + LLM-adjudicate with kept provenance (temporally-versioned conflicts stay separate) is a sane template for compacting agent memory/telemetry without losing auditability.

NEW rank: GraphSkillEvo: Evolutionary Optimization of Graph-Structured Agent Skills — agent skills as graph-structured natural language (step nodes + conditional workflow edges) optimized by population-based evolution (mutation + crossover) instead of LLM self-reflection: +4.01pts over SkillOpt on GPT-5.4-nano at 1.31–1.36× fewer optimizer tokens, and nano-optimized skills transfer upward to beat direct GPT-5.4 optimization on SpreadsheetBench (71.78 vs 69.40)

Rui Sun*, Zhi Zheng* (NUS), Zhenkun Wang (SUSTech), Zhichao Lu (CityU HK). v1 2026-09-18. Code released (github.com/ruisun7/GraphSkillEvo). Full text read incl. Tables 1–7. Claim-check: clean — every abstract number reproduces from Table 1. (PDF)

  • Method: skill = global guidance + reusable step-instruction nodes + M conditional workflow edges; schema validator discards malformed offspring. Population N=4, T=5 generations; 15 training instances/generation, ≤5 failed trajectories as mutation feedback; 4 operators round-robin; top-N selection on full validation. Baselines: no-skill, human skill, one-shot LLM skill, SkillOpt. 5 benchmarks (SearchQA, SpreadsheetBench, DocVQA, LiveMath, ALFWorld), 2 harness settings (none / Codex SDK), GPT-5.4 + GPT-5.4-nano, 3-run averages + separate 5-run significance experiment.
  • Numbers: vs SkillOpt: +4.01 (nano, no-harness avg 60.90 vs 56.89), +1.76 (GPT-5.4, 75.86 vs 74.10), +1.33 (Codex harness, over 4 benchmarks — ALFWorld can't run under Codex). Vs no-skill: +15.37/+21.86/+10.31. Procedural gains: +10.60 SpreadsheetBench; only loss LiveMath nano −0.80 (disclosed). Ablations: w/o graph 64.08 vs full 71.52; removing workflow edges alone costs 0.75–4.52pts across all five benchmarks. Transfer: nano-optimized skill on GPT-5.4 hits 71.78 SpreadsheetBench vs 53.21 transferred SkillOpt and 69.40 direct.

Mandatory qualifications (adjudication): one LLM family (GPT-5.4/nano) — no cross-vendor replication; flagship-model gains modest (+1.76/+1.33), the +4.01 headline is the nano model; significance (5-run Welch, nano only) holds on Spreadsheet (p=0.016) and ALFWorld (0.038) but not SearchQA (0.069) or DocVQA (0.089), and LiveMath is omitted from the significance table (the benchmark where it loses); small test n on LiveMath (124) and ALFWorld (134); single optimization baseline (SkillOpt) — Trace2Skill/SkillX/EvoSkill cited but never benchmarked.

TL;DR for BQAA: (1) Structured artifacts beat flat prompts — factor agent skills/playbooks into graph form (step nodes + conditional workflows); removing the edges alone costs up to 4.5pts: applicable to how BQAA stores/mutates data-agent procedures (e.g. NL2SQL verification loops).
