Read this first

Browser Use 1.0.9 is the most operational industry release: a cloud browser can rotate its exit IP without losing tabs, cookies or logins, and the project reports a 48%→62% pass rate on 11 sites that block cloud browsers. That is a narrow vendor-reported result, not a general web-success claim. The same release repairs Claude prompt-cache routing, making cache usage and cost per solved task important companions to the rotation metric. Instructor 1.18.0 adds typed OpenAI Decisions/Jev calls with validated labels, probabilities and scores; confidence is not correctness, and decision mode does not support streaming, retries, caching or completion hooks.

LangWatch 3.31.0 and Pydantic AI 2.76.0 are material Progress rather than new categories. LangWatch adds content-addressed trace-media reuse and retention-linked deletion, default trace-media storage, 64 MiB exports and organization-owned ClickHouse dashboards. Pydantic AI adds a root conversation id to nested-agent spans, delegated task ids outside durable execution, mid-session realtime tool updates and per-tool UI visibility. These are useful trace and cost-accounting fields, not evidence of better agent quality.

The Academy reads supply the stronger cautions. Agent-as-a-Verifier selects 30/36 mixed Terminal-Bench pools against 24/36 for the same-model text scorer and catches a rewarded-but-invalid implementation, but certification takes tens of minutes per trace and in-loop wall time rises by roughly an order of magnitude. The SkillsBench audit finds that apparent skill-gating gains are larger under permuted labels than in ordinary replay and disappear on held-out trials. Parallel subagents add only 1.2–4.7 points on random ProgramBench tasks at 2.6–3.2× cost; probing and fresh sessions recover parts of the gain in narrower settings, while integration breaks remain visible.

Thanksgiving volume was thin, but this is not a blanket quiet claim: stable GitHub/PyPI/npm releases supplied the industry cards, the unchanged arXiv listing left three carried papers to promote, and primary docs supplied the qualifications. 1. Browser Use 1.0.9 rotates cloud-browser exit IPs without losing session state and broadens Claude prompt caching

Primary: https://github.com/browser-use/browser-use/releases/tag/1.0.9 (stable, 2026-11-26T22:45:43Z; PyPI uploads 23:16:49–23:16:51Z).

rotate_proxy(country=None) assigns a new exit IP to the same Browser Use cloud browser while preserving tabs, cookies and logins. It works over the browser’s own connection without an API key, with the API as fallback; the agent is instructed to invoke it only when a page blocks the current IP, at most once per site, and to choose a country for country-specific sites. The release reports that pass rate on 11 sites that block cloud browsers rose from 48% to 62%. A cloud browser identified by any browser-use.com CDP host is supported, and failure to obtain a new IP now fails explicitly.

Claude prompt caching also works across openrouter:anthropic/..., bedrock: Claude models and ChatOpenAI with an OpenRouter base URL. Previously those routes re-billed the whole prompt at every step because cache_read stayed zero. The release says Bedrock is covered by unit tests only and was not tested live.

Why it ranks. Session-preserving IP rotation is a concrete reliability control for browser agents, and cache routing directly changes repeated-step cost. BQAA should record block reason, rotation attempt/outcome, country, preserved-session identity, cache reads/writes and cost per successful task, then compare against unrotated and uncached controls. The 48%→62% figure is the project’s own 11-site result with no independent rerun or per-site confidence intervals; it does not establish a general bypass rate or a policy-safe automation pattern. 2. Instructor 1.18.0 adds typed OpenAI Decisions/Jev models and opt-in raw-response logging

Primaries: https://github.com/567-labs/instructor/releases/tag/v1.18.0 (stable, 2026-11-26T21:02:33Z; PyPI 21:23:37–21:23:38Z), plus the tagged Decisions guide and logging guide.

Mode.DECISIONS maps Pydantic fields to decision questions across native OpenAI clients, OpenRouter’s Jev route and direct TypeSafe access. Literal/Choices cover classifications, Noul returns a yes/no probability, and Score maps ordered levels to a requested scale. create_with_completion() returns the validated object together with the provider’s original answer distribution, confidence and usage. Unsupported field types, missing instructions, mismatched answers and out-of-range values fail rather than silently receiving defaults.

The release also makes raw provider-response logging opt-in through INSTRUCTOR_LOG_RAW_RESPONSES=1 plus DEBUG on the Instructor logger; provider SDK logging remains separately controlled. The decision guide explicitly says decision mode does not support streaming, retries, caching or completion hooks, that OpenRouter and direct TypeSafe cost metadata differ, and that confidence describes the answer distribution rather than probability of correctness.

Why it ranks. Typed decision calls can make routing, moderation and judge outputs inspectable inside ordinary extraction pipelines, while safer default logging reduces accidental trace-content exposure. BQAA should store the provider route, raw distribution, confidence, usage, validation failure and threshold decision separately, calibrating thresholds on labeled outcomes rather than treating a high-confidence answer as a correct one. The docs’ outputs are illustrative, not live accuracy measurements; there is no decision-quality benchmark in this release. Catalog check: no Instructor card exists; NEW.

1. Agent-as-a-Verifier: From Scores to Evidence for General Verification — https://arxiv.org/abs/2611.34132

Full PDF read: yes — entire 15-page PDF read via pdftotext, including the protocol, offline/online experiments, limitations, references and Appendices A–F. arXiv v1 is dated 2026-11-25; no catalog card exists for this id.

Problem and method. The verifier turns an ordinary agent trace and delivered environment into a claim DAG, independently compiles the task’s acceptance contract, derives obligations, executes checks and preserves a replayable certificate. Six role-separated LLM agents propose and audit the work, but a deterministic orchestrator alone folds evidence into verdicts. Record-only evidence cannot settle a world obligation; failed or unavailable checks cannot become passes, and limited evidence yields SUPPORTED rather than VERIFIED (§3; Appendices A–C).

Results to reuse. On 445 released Terminal-Bench 2.1 traces, certificate selection scores 80/89 overall and 30/36 on pools mixing passing and failing candidates, versus 74/89 and 24/36 for same-model LLM-as-a-Verifier text scoring; pass@5 is 86/89 (Table 1). In one-run-per-task online arms, the same agent improves from 8→11/12 on FrontierMath, 63→73/87 on Terminal-Bench and 37→45/50 on CyberGym (Table 2). The case study finds a numerically unstable 2×2 eigenvector path after testing 4,083 arrays: Harbor rewards it 1.0 while the certificate retains the counterexample and refutes it (§4.4).

Qualifications. The selection study uses one candidate pool, verifier model and configuration; online tasks run once per arm and FrontierMath has only 12 problems. Certification takes tens of minutes per trace against seconds for pairwise text scoring, and in-loop wall-clock time rises by about an order of magnitude (§5.2; Appendix D). Two residual false accepts trust the agent’s own post-task state, two false rejects read a clause too literally, and two pools lack executable checks (§4.2; Appendix F). BQAA should preserve claims, obligations, evidence basis/strength, replay artifacts and abstention beside cost, not translate a VERIFIED label into proof of semantic correctness.

2. What Does Skill Lift Actually Measure? A Source-Code-Level Audit and Noise-Aware Reanalysis of SkillsBench — https://arxiv.org/abs/2611.33943

Full PDF read: yes — entire 9-page PDF read via pdftotext, including the source audit, controlled grader checks, statistical methods/results, threats to validity, data availability and references. arXiv v1 is dated 2026-11-25; no catalog card exists for this id.

Problem and method. The authors audit prompts, reference solutions, graders and skill directories, then reanalyze 7,554 public trials as 1,421 paired configuration–task cells over 83 tasks. Two controlled grader runs and one source-level definition gap identify requirements disclosed only by skills; the paper also separates run noise, baseline constraints and gating-policy evaluation (§II–V).

Results to reuse. Mean skill lift is 18.7 points, while the three instruction–evaluation-gap tasks average +74.6 points across 63 cells (Table II). They account for about 18% of cumulative lift descriptively, but new agent runs with patched prompts were not performed, so the causal share is unknown. Across 100,000 within-cell permutations with Benjamini–Hochberg FDR 10%, 26 tasks show significant positive lift and none shows a significant loss (§IV.B). Zero-baseline cells make a decrease arithmetically impossible in 823/1,421 cells (58%); observed losses number 169 against 327.7 expected under the global zero-effect assignment (Table IV; §IV.C).

Gating is the sharper warning. Baseline/forest gates gain 2–3 points in ordinary replay but 4.5–6.5 points after labels are permuted; on held-out trials, baseline cutoff gains +0.12 points (95% interval −0.67 to +0.93), max-gain forest −0.01 (−0.85 to +0.87), risk-averse forest −0.33 (−1.26 to +0.65), and decision-trial Best-of-two loses 1.61 (−3.01 to −0.16) (Table V). The 17-feature loss detector’s AUC falls from 0.879 over cells to 0.837 over tasks, and to 0.524 among positive-baseline cells over tasks (Table VI). Frozen snapshot differences, at most three runs per condition, retrospective policy choices and single-pair held-out evaluation limit the claim (§VII). BQAA should expose grader contracts, report the subset where a metric can move, group folds by task, and require held-out plus label-shuffled controls before promoting a skill gate.

3. When Are Parallel Subagents Effective for Coding? An Empirical Study on Repository Construction — https://arxiv.org/abs/2611.33893

Full PDF read: yes — entire 50-page PDF read via pdftotext, including RQ1–RQ3, other-product replications, validity discussion, references and Appendices A–H with scoring corrections and case studies. arXiv v1 is dated 2026-11-25; no catalog card exists for this id.

Problem and method. The study compares Single and native parallel-subagent Codex setups on 30 randomly drawn tasks each from NL2Repo and ProgramBench, scoring snapshots over time and list-price cost. It then tests probing and fresh sessions on selected hard ProgramBench tasks, observes modularity, and repeats smaller slices with Opus 5.5 on Claude Code and other models (§2; Appendices A–F).

Results to reuse. With GPT-5.6 Sol, Multi ends at 70.6% versus 67.7% on NL2Repo at $11.56 versus $3.02, and 77.4% versus 76.2% on ProgramBench at $18.32 versus $5.69 (Table 3). Across three ProgramBench model generations, Multi’s mean gain is 1.2–4.7 points at 2.6–3.2× cost; at equal cost, Single matches or leads (Table 4). On 16 hard tasks, Multi’s gain shrinks from +8.8 to +6.0 to +2.8 points across generations; the one-sentence reference probe gains +6.7 points at +50% cost with GPT-5.6 Sol, but only +0.8 at +5% with GPT-6 Sol and −1.5 at −9% with GPT-6.1 Sol (Table 5).

Fresh sessions start faster in all six takeover panels, but finish clearly higher only in the GPT-6.1 Sol delta case; from the same code, new multi-agent sessions cost 1.3–5× the fresh single-agent chains without a consistent equal-cost win (§5.1; Figure 5). Multi writes more modular code, yet that link to score is observational, and integration is not free: multi-agent extended runs have more temporary breaks, and 2/30 end without a build versus 0/38 single-agent runs (§5.2, §8). Most comparisons use only one to three runs, RQ3 selects three tasks, all model generations are priced at GPT-5.6 Sol’s list prices, and many real projects lack a reference executable. BQAA should compare score–time–cost curves, stop reasons, feature coverage, fresh-session resets and build-break rates before enabling subagents by default.

Six-week EV

  • Highest EV — replayable verification receipts (2611.34132): Add independently compiled acceptance contracts, claim dependencies, obligations, evidence basis/strength and abstention to evaluation receipts, with replay artifacts and verifier cost beside the verdict. Pilot on a small mixed-outcome pool and audit authority circularity and over-literal contracts before scaling; do not trade a 30/36 selector for unmeasured order-of-magnitude wall cost by default.
  • High EV — gate evaluation that can falsify itself (2611.33943): For every skill/routing gate, reserve trials from fitting and selection, permute labels inside cells, group generalization folds by task, and report only cells where the outcome can move. Publish grader-enforced conventions and enough repetitions to distinguish a real loss from regression to the mean.
  • High EV — cost-aware subagent allocation (2611.33893): Compare Single and Multi at equal time and equal cost with per-request model/token accounting, snapshot build status, stop reason and feature coverage. Test reference probing and fresh-session resets before paying for parallel agents, and add integration checks with novel inputs because broad stored-input rechecks still miss coupled breaks.
  • Medium-high EV — decision and browser-cost telemetry (Instructor, Browser Use): Persist decision answer distributions, validation outcomes, provider usage, proxy rotations and cache reads/writes beside task success. Calibrate decision confidence on labeled outcomes, and evaluate rotation/caching with matched controls rather than vendor pass rates or cache presence alone.
  • Medium EV — trace lineage and media lifecycle (Pydantic AI, LangWatch): Propagate root conversation and delegated task ids, version conversation-compaction semantics, and record trace-media content hashes, retention class, deletion and export size. Reconcile nested cost and retained-media storage before claiming complete spend or retention enforcement.
