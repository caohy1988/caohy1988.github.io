  • BQAA takeaway. Tonight's items move in two directions. Agent frameworks are adding approval, content-judge and trace-aggregate layers that produce new analyzable events. The research says the numbers those layers produce are easy to misread:
  • a tool result can be wrong while it looks successful;
  • a simulated user can change what is being measured;
  • a judge can agree with humans and still create false findings.
  • Cline's reasoning-token double count and Mastra's cache-write mispricing are two more instances of "valid row, wrong number".

NEW I1 — Mastra @mastra/core 1.72.0 (npm, Sep 30 00:03Z): an aggregate-plan API over trace storage, trace filters by run, session, user and organization, lease-protected background tasks, and a retry for cyber-safeguard refusals

What shipped (from the packages/core CHANGELOG, ## 1.72.0 section; npm time map confirms 1.72.0 at 2026-09-30T00:03:19Z, latest):

  • Trace aggregates (#25124).
  • Storage adapters can declare a trace-aggregate capability next to trace-query.
  • ObservabilityStorage.aggregateTraces() runs a TrustedTraceAggregatePlan and returns a TraceAggregateResponse. The plan is built with parseTraceAggregateRequest → planTraceAggregate, for example measures: ['count'] over a time range.
  • Adapters without the capability throw OBSERVABILITY_STORAGE_AGGREGATE_TRACES_NOT_IMPLEMENTED.
  • Trace-query filters (#24935).
  • Advanced trace queries accept runId, sessionId, userId and organizationId, at trace scope or inside spans.some / spans.none.
  • organizationId "can only narrow the trusted tenant scope".
  • Lease-protected background tasks (#24841).
  • A running task records its owner and when the lease expires. Recovery only reclaims tasks whose lease has expired, and a worker that lost ownership cannot save a result.
  • Conditional storage writes (expectedStatus, expectedOwnerId) are enforced only by storage adapters that support them. Older adapters silently fall back to unprotected writes.
  • CyberRefusalHandler (#25172).
  • Retries once when OpenAI's cyber_policy or Anthropic's cyber classifier refuses mid-run. A second refusal on the same step is treated as genuine.
  • createCodingAgent includes it by default, with maxProcessorRetries: 3.
  • Cost and telemetry fixes:
  • Anthropic 1-hour cache writes are now priced at their real rate instead of the 5-minute rate (#25089).
  • DurableAgent model_generation spans now carry cached-input, cache-write and reasoning tokens (#25392, carded as Progress at 1234).
  • The provider finish reason is added to AgentController error events (#24321).
  • Tool approvals always go to the run that requested them (#24874).
  • Durable-engine transcript transforms now redact stored arguments and results; before, raw values were persisted (#24569).
  • After the release, on main (Sep 30 04:56–06:37Z, unreleased):
  • Evented runs recover before their first step (#25389).
  • A factory guard blocks review verdicts that contradict their own review text (#25494).
  • Recorded traces pick the true root span regardless of span order (#25536).
  • @mastra/teams 0.1.0 was also published to npm (23:57Z). I did not inspect its contents.

Why it matters for BQAA.

  • Mastra now has a planned-aggregate API for trace analytics, where before it had only a row-query API. That is the same layer a BigQuery-backed adapter would implement. The "trusted plan" model is how Mastra keeps tenant scoping out of the caller's hands.
  • The cache-write fix means Mastra-reported Anthropic costs before 1.72.0 understate 1-hour cache writes.
  • The lease fields (owner, lease expiry) give task-level telemetry a way to tell "reclaimed after a crash" from "duplicate execution".

NEW A1 — arXiv:2609.37153 "When Tools Silently Lie: Evaluating and Mitigating Blind Compliance in Tool-Augmented Data Agents" (ToxicBench; Tao & Yin, Tongji)

Full PDF read (28 pp).

  • Setup. A proxy runs the real tool, then edits the returned observation. The source CSVs are left unchanged, so the clean answer is always recoverable.
  • Operators: aggregate scale, rank or label swap, treatment/control flip, column-semantic swap, stale metadata, biased retrieval.
  • Each task is paired clean vs poisoned on the same query, data, model and adapter.
  • Metrics (§3.2, Table 6).
  • BCR (blind compliance): adopting the poisoned answer without detecting or checking anything.
  • VPA: adopting the poisoned answer despite a fresh evidence-producing check.
  • RR (recovery): a clean final answer after detection or validation.
  • Headline results:
  • Degradation (Table 1, GPT, 118 tasks). Clean task success 0.92–0.99 → poisoned drop of 0.26–0.39 across LangGraph, smolagents and AutoGen. BCR was 0.27–0.53.
    • Across models (Table 16), numerical-suite BCR averages GPT 0.62, Qwen 0.40, Claude 0.20.
  • Which operators hurt most (Table 15). Label swaps preserve amounts while changing entities, so magnitude checks miss them. Label swap BCR is 0.55; aggregate scale BCR is 0.62.
  • Retry vs verification (§4.3, Table 18).
    • A plain second attempt beats Base by +0.110 poisoned task success (95% CI [0.056, 0.171]).
    • Explicit verification prompts add nothing beyond that: Guard − Double-pass = −0.025 [−0.054, 0.000].
  • Adoption after checking (§4.3, Table 20). Under repeated poisoning, 101 of 1,572 trajectories adopted the poisoned answer after a qualifying check. 78 of those had only corrupted follow-up checks.
    • In the structured control (App. E.2), full-target corruption gave 0/48 correct for both retry and review, vs 48/48 and 47/48 with clean evidence.
  • Source independence (App. A). 0 of 133 checks were source-independent: every verification re-read the same CSVs.
  • Scorer validity (§4.4, Table 7). The frozen scorer agrees with humans on 96.0% of 200 post-freeze trajectories (precision 1.000, recall 0.957).
  • Limitations (§6).
  • Tiny synthetic tables (4–12 rows) and no production traces.
  • Token billing was unavailable, so cost is latency only: Guard 39.8 s vs Base 16.9 s.
  • 204 of 3,319 historical corruption events were flagged as mis-delivered and are handled with sensitivity analyses.

Why BQAA cares. This is the data-agent failure BigQuery users would hit: a query that "succeeds" with wrong bindings.

  • The paper's split into checked, checked-but-adopted and recovered maps directly onto trace-level metrics BQAA could compute.
  • A tool call followed by a re-query is not evidence of verification. Only a source-independent check is (0/133 here).

NEW A2 — arXiv:2609.38043 "UserProxyBench: Evaluating LLM User Simulators for Agent Benchmarks and Training" (Jain & Sandhu; NeurIPS 2026 workshop)

Full PDF read (8 pp).

  • Setup. An evaluation layer over τ²-bench (commit 8ebb749) that scores the simulated user against its private blueprint.
  • The User Fidelity Score (UFS) is the fraction of episodes where the user proxy passes every applicable criterion.
  • There are 2,141 task-grounded rubric criteria, 5.7 per task.
  • The agent is frozen at GPT-5.5. Seven user proxies each run 375 tasks (Telecom 114, Airline 50, Retail 114, Banking 97).
  • Results:
  • Reward moves with the simulator (§3.2, Table 1). Changing only the simulated user moves mean agent reward from .644 to .796. The per-domain spread reaches .298 on Retail and .280 on Airline.
  • Hidden failures (§3.2). 24.4% of agent-successful episodes fail UFS. On Telecom, 39.7% of all trajectories pass reward but fail UFS.
  • Reward is blind to the commonest failure (§3.3, Fig. 3).
    • Premature disclosure (480 cases) changes agent pass rate by only −.043, with a positive median effect. Goal deviation costs −.515.
    • On Telecom, Sonnet-4-6 and GPT-4.1-mini give the same reward (.947) but UFS .474 vs .737.
  • The trajectory changes, not the reward (§3.4). In successful episodes, over-disclosing users make the agent issue 1.06 fewer tool calls and ask 0.26 fewer questions. Mean agent turns track UFS (r = .955) far better than reward (r = .594).
  • Cheapest adequate simulator (§3.1). At UFS ≥ .84 the cheapest adequate proxy is Gemma-31B (~$0.0175 per simulation). Gemini-3.5-Flash gains 1.9 UFS points at 3.2× the cost.
  • Limitations (§4, App. F).
  • The judge is the same model that wrote the rubrics (Claude Opus 4.8).
  • The manual audit is single-rater and unblinded.
  • One rollout per task and one frozen agent.
  • No measurement of how training against low-UFS proxies affects the resulting policy.

Why BQAA cares. Any eval or RL pipeline that uses simulated users is also measuring the simulator. Tool-call count per successful episode moved by more than one call with reward unchanged, so "agent efficiency" dashboards need the user proxy as a dimension.

NEW A3 — arXiv:2609.35815 "How to Run Statistics over LLM Judges and Trust the Results: Calibrated Inference for Small-Sample AI Evaluation with evalstats" (Arawjo, Université de Montréal)

Full PDF read (39 pp): main text §1–10, plus Appendices A–F for the simulation design, the PPI power-tuning changes and the rank-test constructions.

  • Setup.
  • Monte Carlo sweeps pick CI, p-value and multiple-comparison methods for small evals (N < 100) on binary, [0,1] and Likert scores. They use synthetic data plus real runs from OpenEval and Inspect AI.
  • Nine hypothesis tests are corrected with prediction-powered inference, PPI++ (App. B, C). Wilcoxon, Mann-Whitney U, Friedman and Kruskal-Wallis get what the author calls the first known PPI corrections for rank-based tests.
  • A "bootstrap-adaptive" tweak stabilizes the power-tuning weight with only 15–50 human labels.
  • Results:
  • High agreement does not make raw judge statistics safe (§6.2, Fig. 6, App. F).
    • On Likert data, false-positive risk from testing uncorrected judge scores peaks at quadratic-weighted κ / ICC ≈ 0.80–0.90. It returns to nominal only above 0.99.
    • For binary data, κ = 0.81 still gave ≈37% false positives (fn. 7).
    • The PPI-corrected tests held Type I error near 0.05 across 2,046 null scenarios per test (≈3.68M trials, Fig. 4) and on real judge corpora (Fig. 11).
  • When a judge is worth it (§6.3, Fig. 7).
    • The effective label multiplier is ≈1.5× at ρ² = 0.4 (worst cell 1.36×) and ≈2.3× at ρ² = 0.6.
    • Below ρ² ≈ 0.2 (κ < ~0.41) the judge is not worth using.
  • Small evals (§5, Fig. 2).
    • Bootstrap CIs under-covered nearly everywhere below N = 100; for paired binary data, none reached nominal even at N = 100.
    • Recommended instead: Wilson or logit-t intervals, Bonett–Price for paired binary data, and Wilcoxon / McNemar mid-p tests. Multiple comparisons use Šidák and Shaffer, or Romano–Wolf at n ≥ 30.
  • Worked example (§8.3, real ELLIPSE essays + six-judge ensemble). Raw judge scores gave Kruskal-Wallis p = 1.9×10⁻⁴ at κ = 0.66. The PPI-corrected test gave p = 0.31, matching the human ground truth (p = 0.47).
  • Limitations (§9.6).
  • PPI in compare() needs ≥ 50 judge-scored items, a single factor and no multi-run data.
  • Pairwise CIs for between-subjects designs are not validated.
  • Guarantees assume human labels were sampled at random; paired t, Wilcoxon and RM-ANOVA are the most robust when they were not (Fig. 10).
  • No user study.

Why BQAA cares. Judge-scored agent evals over traces are exactly this setting. The paper gives two concrete rules for any BQAA eval report:

  • report the judge–human ρ² with the effective sample size;
  • never report significance on raw judge scores, however high the agreement.
  • Weave and promptfoo are named (§2) as offering no uncertainty quantification.
