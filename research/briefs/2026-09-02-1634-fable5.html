Industry

Arize Phoenix: PII Detection evaluator at span, trace and session scope (docs merged Aug 28, released Sep 1)

The Phoenix pre-built evaluators index now lists fifteen evaluators: eleven LLM judges (Faithfulness, Hallucination, Conciseness, Correctness, Retrieval Relevance, Tool Selection, Tool Invocation, Tool Response Handling, Refusal, User Friction, PII Detection) and three code evaluators. The index also links a Toxicity page, which is undated and is not named in any release body, so treat it as older.

The PII Detection page describes a single required input, a conversation string, and says the evaluator works at three levels: a span when the conversation text already lives on the span, a trace when span inputs and outputs are concatenated into one string, and a session when the full session transcript is assembled for screening. It returns a label of pii_detected or no_pii_detected, a score of 1.0 or 0.0 with direction minimize, and an optional explanation that lists each detected instance with its type and source location. The rubric names person names, email addresses, phone numbers, national IDs, physical addresses, card numbers, and API keys or tokens. The page reports 0.93 accuracy on a 40-example set and a 0.96 detection rate on NVIDIA's Nemotron-PII dataset. The evaluator ships in both the Python and TypeScript evals libraries.

The User Friction page, on the same index, follows the same span-trace-session pattern with a conversation plus latest user message as input. That confirms the shape is deliberate: Phoenix pre-built evaluators are now written to run over an assembled session transcript, not only over a span.

What has not shipped: the Phoenix product release-notes page still ends at Aug 25 and does not mention 20.5.0, the PII evaluator, or the trace-replay sidecar. The replay sidecar has no product doc page either, and the Sep 2 Phoenix docs audit explicitly scopes it out as experimental server CLI work. Hold that one as before.

TL;DR for BQAA. Session-scope PII screening with a per-instance explanation is now a documented evaluator at Phoenix, alongside Langfuse, LangSmith and Braintrust already scoring at session grain. The BQAA implication is a column, not a feature: an eval result row that names the target scope (span, trace, or session id) and carries a structured findings list, so a PII verdict can be joined back to the exact event that leaked. It also strengthens the case that redaction-at-ingest and detection-after-the-fact are two different products, and BQAA should say which one it is.
