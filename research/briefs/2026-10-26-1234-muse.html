NEW 1 — Snowflake Observe / Agent Observability (dated catch-up; private preview announced, not GA)

Product: Observe by Snowflake (fetched Oct 26, 2026; stable product page). Dated primary source: Improve AI Performance, Quality and Cost with Agent Observability (22 Sep 2026, Hannah Miao; datePublished 2026-09-22 verified in page metadata this slot). Status as verified today: the blog says Agent Observability is "coming soon to private preview," and the product page today still banners "Agent Observability is coming soon" linking to that same blog. Do not upgrade this to GA, public preview, or "launched Oct 22" — the Oct 22 launch event was announced in the blog, but no dated primary source fetched today states post-event availability (see Unconfirmed).

What was announced (blog body, fetched in full this slot). An optional OpenTelemetry-compliant SDK following OTel GenAI semantic conventions, capturing prompts, completions, retrievals, tool calls, token usage and session IDs, with tested support for LangChain and for two named vendor agent SDKs (paraphrased here per house rule on vendor-named titles), or any properly instrumented traces via an OTLP endpoint. An Agent Explorer to search traces, sessions and conversations. Metrics derived from traces (latency, errors, cost). Online LLM-as-judge evaluations on production traffic (hallucinations, guardrail failures, poor-quality responses) with results connected to underlying spans/traces, plus ingestion of offline eval results. Programmatic APIs to query traces, metrics and online evaluation results. Positioning: retain high-fidelity agent telemetry without sampling, then correlate agent behavior with business data on Snowflake.

Platform context (primary sources fetched today). Observe is sold as AI-powered observability unifying logs, metrics and traces on a Snowflake lakehouse with an integrated AI SRE; the product page describes a Telemetry Lakehouse Foundation (compute–storage separation, low-cost storage) and an Observability Context Graph mapping relationships across telemetry to code and business context, with the AI SRE also exposed via CLI and MCP server. Snowflake's intent-to-acquire press release (8 Jan 2026) records a definitive agreement to acquire Observe, framing a unified open-standard architecture on Apache Iceberg and OpenTelemetry for "100% of telemetry data" retention; its "up to 10x faster" resolution line is a vendor claim only and is not carried as a finding. Core Observe pricing is published (pricing page, fetched today): logs from $0.49/GiB (30-day retention), metrics from $0.008/DPM (13-month), traces from $0.59/GiB (30-day), compute included, extended retention $0.01/GiB/month, "no overages," subscription on committed uncompressed ingest. No separate Agent Observability price is published on that page. A redesigned Observe MCP server + CLI reached GA earlier — Snowflake blog datePublished 2026-08-13, verified this slot — so MCP/CLI agent access is not new in this card's Sep 22 announcement; it is pre-existing platform surface the Agent Observability module plugs into.

Cortex AI Gateway governs agent access to models/data; Observe Agent Observability traces and evaluates agent behavior — complementary, distinct products (third-party Oct 22 coverage likewise describes Observe as complementing the Gateway; cited here only for that framing, not as a primary claim). Progressing the Gateway card would misfile the item.

BQAA read. Three concrete comparisons, all developed in depth on today's hub page (smithdb-vs-bqaa): (1) Join-to-business-data is now a competitor pitch, not a BQAA exclusive — Snowflake explicitly sells correlating agent telemetry with business data already in Snowflake, so BQAA messaging needs its BigQuery-native specifics (customer-owned table, SQL/AI.GENERATE in place) rather than the generic warehouse-join claim. (2) Online LLM-as-judge on production traces, linked span-level, is the sharpest capability delta: if Observe ships it as described, "evals as a separate offline step" ages fast; BQAA's answer is evaluators over the trace table itself — worth making that comparison explicit and measured. (3) Published per-GiB telemetry pricing with unlimited users gives Observe a cost story prospects can quote; BQAA's Storage-Write-API-plus-BigQuery cost shape needs an equally quotable worked example. Capture-side, Observe bets on OTel GenAI semantic conventions + OTLP; BQAA bets on one schema via ADK plugin / LangChain handler. Watch which convention customers standardize on — that decides whose ingest is "native" in mixed estates.
