NEW I1 — OpenLLMetry 0.62.4: crewAI spans stop carrying API keys from object reprs; TRACELOOP_TRACE_CONTENT=false finally covers the MCP client path; cancelled MCP sessions still export their span

Timestamps.

  • GitHub release 2026-09-29T10:41:17Z (tag 0.62.4, commit be498301c).
  • PyPI:
  • opentelemetry-instrumentation-anthropic 10:43:16Z
  • opentelemetry-instrumentation-crewai 10:43:21Z
  • opentelemetry-instrumentation-mcp 10:43:32Z
  • traceloop-sdk 10:45:27Z
  • The previous release, 0.62.3, went to PyPI on 2026-08-10 (08:50Z).
  • This is the first OpenLLMetry card. In the catalog, OpenLLMetry appears only inside otel-collector-genai-normalizer-processor-alpha.

Why a fix release clears the bar here:

  • OpenLLMetry is the instrumentation layer many apps use to emit GenAI spans into any OTel backend.
  • This release changes what lands in every downstream span store, including credentials and content.
  • There is no parent card to attach it to.
  • It is a fix release, not a feature release, and I rank it for that data-hygiene reason.

1. crewAI: the credential leak (#4465, merged Sep 16).

  • Old code (0.62.3 wheel):
  • _populate_crew_attributes looped over Crew.__dict__ and stored str(value) for every non-task, non-agent field.
  • Standalone Agent spans did the same via _extract_attributes.
  • _extract_agent_data also copied agent.config.
  • The PR: "anything those objects held -- an LLM client, an embedder config -- reached the span through its repr, api keys included."
  • 0.62.4 reads allowlists instead:
  • Crew: id, name, process, verbose, memory, cache, planning, max_rpm, share_crew.
  • Agent: config is dropped.
  • Tools: reduced to name and description.

My local reproduction (throwaway venv, OTel SDK 1.45.0 in-memory exporter, $0). I ran each version's CrewAISpanAttributes over stand-in Crew/Agent/Task objects with crewAI's field names. A fake key sk-CANARY-… was placed in an LLM object, the embedder config and the agent config.

Span 0.62.3: attributes containing the canary 0.62.4
Crew crewai.crew.embedder, crewai.crew.manager_llm, crewai.crew.agents none
Agent crewai.agent.llm, crewai.agent.function_calling_llm, crewai.agent.config none
Task none none

Why real crewAI objects leak too:

  • crewAI 1.15.23's BaseLLM is a pydantic model with a plain api_key: str | None field (checked in the wheel source). Pydantic's str() prints api_key='…' (checked).
  • So an LLM(api_key=...) object leaks its key.
  • A crew embedder is a config dict, and str(dict) prints nested keys.

2. MCP: the "content off" switch (#4466, merged Sep 27).

  • The PR: "only the FastMCP server-side wrapper consulted it. The MCP client path recorded content regardless: tools/call arguments and results …, whole request and response bodies …, and the response value in InstrumentedStreamWriter.send. An operator who set the variable to false still got request and response payloads on their spans."
  • Wheel check:
  • 0.62.3's client-side instrumentation.py has zero calls to the content gate.
  • 0.62.4 moves should_send_prompts() into utils and calls it at 4 client-path sites.
  • The new tests assert that a marker value is absent from every span attribute when the switch is off.

3. MCP: missing session spans (#4517, merged Sep 27).

  • When Client.__aexit__ was cancelled, CancelledError (a BaseException) skipped both exit paths. The mcp.client.session span "was never ended or exported".
  • It now ends in finally, with status UNSET, because cancellation is not an error.

Also in 0.62.4:

  • #4439: Groq streaming now records token usage and duration metrics.
  • #4477: tracing no longer crashes OpenAI with_raw_response.create(stream=True).
  • #4478: Mistral chunked assistant content is recorded instead of dropped.
  • #4467: LangChain association properties no longer carry objects.

TL;DR for BQAA:

  • Scan stored OpenLLMetry spans. If BQAA ingests them, run a secret scan over crewai.crew.* and crewai.agent.* attributes written by ≤0.62.3. Also check MCP client spans from users who had set content capture off.
  • Content switches work per code path, not per package. Verify them the way #4466's tests do: assert a canary is absent from what was exported.
  • Keep the instrumentation package and version on every span. Then a leak window can be bounded by version.
  • Count sessions opened vs spans exported. Cancelled sessions that never end are invisible otherwise.

Cost fixes (all merged Sep 28; now in the release and on Cloud):

  • #17957: "OpenAI cache-write tokens were costed at $0."
  • Mechanism. The usage schemas move cache_write_tokens out of input into input_cache_write_tokens. No OpenAI price entry had that key, and price matching is exact, so those tokens "dropped out of the cost entirely".
  • Real example. Gateway Codex traffic with 227,060 cache-write tokens was costed at $0.179, "which was the output alone".
  • The fix. 50 price entries now price the bucket: 1.25× input for the gpt-5.6 and gpt-6 families, the input rate for other caching models. Cache writes also count toward the >272K tier thresholds.
  • #17958: Anthropic 1-hour cache writes were priced at the 5-minute rate, 1.25× instead of 2× input, so they came out 37.5% too low.
  • Mechanism. Native usage nests the TTL split in cache_creation.{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}. That object fell through to a parser that keeps only top-level integers.
  • Real example. 10,256 one-hour write tokens on claude-sonnet-4-6 were stored at $0.0385; they now price at $0.0615.
  • Still dropped: server_tool_use.web_search_requests, the inference_geo multiplier and output_tokens_details.thinking_tokens.
  • #17959: failed and cancelled gateway generations got tokenizer-inferred usage.
  • Quote: "cancelled long Codex calls showed about $6 each while the thread's real calls cost about $0.2".
  • The two storage tables (v1 observations, v2 events) even disagreed on ERROR rows.
  • Gateway-scoped generations now skip inference, and provider-reported usage is kept.
  • "Existing stored rows are not backfilled."

Capture:

  • #17960: gateway full-mode input capture goes from 1 MiB to 5 MiB.
  • Before this, larger bodies were uploaded as input=null "with no explanation", which "covers most long Claude Code / Codex sessions".
  • A missing input now carries langfuse.gateway.request.input_omitted with one of five reasons: size_limit, content_encoding, invalid_json, record_limit or telemetry_buffer.
  • Over-limit inputs are omitted, not truncated, because cut JSON would be invalid.
  • Risk the PR itself flags: a quote-heavy row over ClickHouse's 10 MiB JSON-row cap fails the insert. The writer then truncates every oversized value in that batch to 500 KiB, "including unrelated rows".
  • Other gateway changes: #17956 sets the trace environment from a langfuse-environment header; #17955 drops mapped Langfuse attributes from gateway metadata.

Also in the release:

  • Storage. #17939 adds a ClickHouse Native write strategy and #17938 adds NAPI batch encoding. Ingestion opt-in comes separately in #17941.
  • Transcripts.
  • #17925 adds a dedicated "Topics" transcript renderer. It emits size metrics comparing full JSON, the old generic text and the new text.
  • #18011 adds the current turn's nesting level and per-message start/end times.
  • Evaluators. #17954: "View scores" on a decision-model evaluator opened an empty table, because scores are named per question. They are now linked by evaluator ID.
  • Open, not released: #18041 (price Anthropic cache usage from AI SDK 7 spans, including 1-hour writes) and #18044 (ingestion API-key breakdown).

TL;DR for BQAA:

  • Cache writes need their own priced buckets. A pipeline that subtracts them from input and has no price for them reports $0. BQAA cost SQL needs explicit Anthropic 5-minute and 1-hour write buckets and an OpenAI cache-write bucket.
  • Never tokenize a request to invent usage for failed or cancelled calls. Store usage_source (provider-reported vs inferred) per row.
  • Store why a payload is missing, not NULL.
  • Expect a step in cost trend lines on the deploy date, because history is not backfilled.

#8529 (2.2.84): threads disappeared from the list.

  • Threads were registered only when a trace was created. A thread id first set by a later update "was written to traces.thread_id but never registered, so the thread silently disappeared from the Threads list while opening it directly from a trace still worked".
  • Why: the list query switches to an INNER JOIN whenever a time range is set, and the UI always sends one.
  • The fix registers the thread on updates (single and batch), using the earliest trace id's timestamp so the join window matches.

#8540 (2.2.84): Jev in online eval rules.

  • LLM-as-judge online rules can now use Jev (a typed decisions model) through OpenRouter's POST /api/alpha/decisions.
  • How it scores:
  • Only Boolean scores are allowed.
  • It makes one call per trace or span.
  • A probability of 0.5 or more scores 1.
  • Each call is logged as an llm span with the dated model, token usage and OpenRouter's reported cost.
  • Limits: thread-scope rules skip Jev, and prompts over ~32k tokens are skipped. There is no feature toggle.

#8481 (2.2.84): self-filling annotation queues.

  • Queues fill from feedback-score conditions, capped at 1,000 items by default.
  • Each item shows whether it was added manually or automatically.
  • It ships off. The 2.2.85 config.yml has TOGGLE_ANNOTATION_QUEUE_AUTOMATION_ENABLED defaulting to "false".

#8610 (2.2.85): Comet fixed its own SDK product telemetry.

  • The SDK sent 826k events per 30 days.
  • Comet dropped four lifecycle events and stopped the misattributed feedback-score events: 649,171 events per month, 78.6%.
  • The lifecycle events "count processes, not users".
  • client__end reached only 1,734 installs against client__init's 19,416. "most processes never exit cleanly, so the init/end pair never measured session length."
  • Feedback-score events fired from the trace-creation path that @track and every integration tracer use, so they were reported "on the user's behalf".

#8602 (2.2.85) + #8593 (2.2.84): ClickHouse partition pruning.

  • traces is partitioned weekly on a column derived from the UUIDv7 id. The planner "cannot see through that derivation", so reads by id set opened every weekly partition.
  • Reads now name the weeks their ids resolve to: 50 reads across 29 statements.
  • In a local test, 44 of 44 parts dropped to 5 of 44.

#8051 (2.2.85): MCP consent screen.

  • Internal "Cost Intelligence" workspaces (__ai_spend_{orgId}__, __cc_{orgId}__) no longer appear on the hosted MCP OAuth consent screen.
  • A hand-crafted consent for one returns 403.

TL;DR for BQAA:

  • Membership can change after creation. Any session or thread table maintained on insert must also update when a trace is updated, or time-filtered INNER JOIN views silently drop sessions.
  • Test: set the thread id by update, then list with a time filter.
  • Carry a derived time range on id-keyed queries. BigQuery, like ClickHouse, prunes only on the partition column itself.
  • Don't build session length from process start/end pairs. End events arrive for ~9% of starts. Use last activity instead.
  • Attribute feedback events by caller: user vs integration.

NEW A1 — Maintaining Benchmarks Against Increasingly Capable Agents: Detection and Remediation of Unearned Passes (arXiv 2609.34262, Scale AI, cs.AI, v1 28 Sep 2026)

Full PDF read: §1–6, Appendices A–B and Tables S1–S3, 32 pages. This was my own sweep find; it is not on HF Daily.

Definitions (§2).

  • A surface pass is any trajectory the verifier fully credits.
  • Each one is labeled LEGITIMATE, UNEARNED or UNEARNED VIOLATION.
  • A violation needs evidence of all three: a concrete bypass mechanism, intent, and relevance to the grade.
  • The integrity gap is the share of surface passes that are unearned.

Pipeline (§2, Fig. 1).

  • Pre-scan. A deterministic scan flags git-history access, external network hosts and grader files. For git flags, it compares what the command showed against the submission; one case had 78% identifier overlap.
  • Primary judge. An LLM judge reads each trajectory with the flags, the verifier output and the submission. Every pass is judged, flagged or not.
  • Adversarial second judge.
  • A "demoter" that doesn't see the first verdict re-checks legitimate passes.
  • A "promoter" that does see it re-checks unearned ones.
  • Escalation. Disagreements go to a cross-model judge. Disagreement changed 7.9% of cases.
  • Human check. Two authors labeled 39 trajectories.
  • Binary agreement was 87.2% (κ 0.25).
  • Ternary agreement was 79.5% (κ 0.54).
  • The pipeline matched all 31 consensus cases.

Data (§2, Table S1).

  • 3,810 passing trajectories in 29 model–benchmark cohorts, across SWE-Bench Pro V1.0, MCP Atlas, SWE Atlas TW, Terminal-Bench 2.1 and Agents' Last Exam.
  • Harnesses: Claude Code for Anthropic rows; SWE-agent or Codex for OpenAI rows.
  • Git and network access were left as recorded, not normalized.

NEW A2 — Certified Selective Automation of LLM Agent Evaluation (arXiv 2609.34320, independent / UCAS / Pusan National / Shenzhen Univ. of Advanced Technology, cs.CL, v1 28 Sep 2026)

Full PDF read: §1–8 and Appendices A–L, including Tables 1–8. 16 pages. Also my own sweep find.

The question (§3).

  • What fraction of trajectories can a judge auto-decide while guaranteeing, with probability 0.95, that the error among auto-decided trajectories stays at or below α?
  • Auto-reject (likely failures) and auto-release (likely successes) are certified separately.

Why the usual certificate breaks (§3, Table 1, App. D).

  • Many agents or rollouts attempt the same task, so outcomes cluster by task.
  • Intra-task correlation ranges from 0.25 to 0.81.
  • The design effect reaches 17.6: 520 terminal trajectories over 13 tasks carry about as much information as 30 independent ones.
  • The standard i.i.d. certificate over-promises. On MiniWoB++ with 8 rollouts per task (correlation 0.80, 32 tasks), it certifies 98% coverage at α = 0.2. Its realized error then exceeds the budget in 17.5% of task resamples, against a promised 5% (6.9% at α = 0.1).
  • Cluster-valid alternatives promise nothing. One-per-task Clopper–Pearson and task-mean Hoeffding certify 0 on all seven corpora (Table 6).

The fix: TaskBoot (§4, Alg. 1, Table 5).

  • It bootstraps tasks, not trajectories, over a 40-point threshold grid with Bonferroni correction.
  • In simulation it violates its guarantee in at most 1% of trials, down to 20 tasks, at the same coverage as the naive certificate.
  • Every real deployment passes a held-out audit. For example, realized reject error at α = 0.1 is 0.027–0.037 on AgentRewardBench and 0.011–0.012 on τ²-bench.

Judges (§5, Tables 2–3).

  • The trained judge. Qwen3.5-4B, LoRA, scored by the log-probability of a one-token verdict; SFT, then GRPO with a reward that punishes discarding successes. Certified reject coverage at α = 0.1:
  • τ²-bench tool use: 0 → .293 → .297.
  • AgentRewardBench (1,302 expert-labeled web trajectories): .510 → .560 → .585.
  • Frontier judges don't transfer.
  • gpt-5.6-sol with chain of thought beats the 4B judge on web (.704), at roughly 100× the cost, but certifies 0 on τ²-bench.
  • claude-sonnet-5 CoT reaches .497 on web and 0 on τ²-bench.
  • Four other configurations certify nothing anywhere.
  • Recalibration can't help (Prop. 1). The certificate depends only on score ranks, so Platt, isotonic or temperature scaling can't rescue a judge.
  • Hidden outcomes defeat every judge. On code repair judged by held-out tests (SWE-rebench / OpenHands), the outcome never appears in the trajectory. Every judge sits at AUROC 0.53–0.65 and certifies 0.

Predictable before training (§6, Eq. 6).

  • Certified coverage ≈ 1.08 × (1 − success rate) × (2 × base-judge AUROC − 1) − 0.05.
  • Leave-one-corpus-out R² is 0.96 over seven corpora.

What it buys (App. L). At 6 minutes of review per trajectory, about 30 reviewer-hours per 1,000 trajectories on τ²-bench and 59 on web.

  • The release side barely certifies. Nothing certifies at α = 0.1 on any corpus; only τ²-bench SFT reaches .27 at α = 0.2. So in practice the certificate removes review of failures, not of successes.

Self-training (§7). Pseudo-labels harvested inside certified regions had 0.000–0.041 contamination across six harvests. A second round on web degraded coverage from .585 to .465, so the authors recommend one round.

Limits.

  • One pre-registered run with one seed.
  • The guarantee is asymptotic in the number of tasks.
  • The naive certificate's failure is shown on one high-correlation corpus.
  • The coverage formula is fit on seven points.

TL;DR for BQAA: if BQAA auto-judges sessions, uncertainty must be clustered by task.

  • Bootstrap task ids with replacement; it's a few lines of SQL.
  • pass@k-style repeated runs make per-session intervals too optimistic.
  • Expect guarantees only on the auto-reject side.
  • Estimate the automatable fraction up front from base rate and base-judge AUROC.
  • Don't expect score recalibration to help.
  • If the outcome isn't visible in the trace (hidden tests), no judge will certify, so write outcome signals into the trace.

NEW A3 — Dude, Where's My State? Execution Information Requirements for Stateful Agents (arXiv 2609.32687, Mehrotra, Tiwari, Gupta, Gulwani, cs.AI, v1 26 Sep 2026)

Full PDF read: §1–7 and Appendices A–D, including Tables 1–18. 35 pages. Also my own sweep find; the 0034 brief listed it as scouted.

Theory (§2, App. A).

  • The Execution Information Requirement (EIR) is the minimum information, in bits, that must survive from earlier steps for correct completion: log₂ of the number of history classes that need different future answers.
  • Information pressure is EIR divided by storage capacity.

Controlled tests, LACUNA (§3–4, App. C).

  • Causal rescue. Restoring the exact missing result raises accuracy on affected recall steps to 100%. An equal-length irrelevant value gives 0%, and no injection gives 11.3% (four models; Table 6).
  • First miss = first error. The first missing dependency coincides with the first error in all 27 Stepwise Sum trials.
  • Capacity isn't enough (Table 12). At a capacity that fits every needed result (h = 16), exact-window retention scores 0.934 but LRU scores 0.410. LRU needs double the capacity (h = 32) to catch up.
  • Errors cascade. One 64-step run had 19 missing-input errors, 26 cascade errors and 0 computation errors.
  • Memory systems (Table 14; own storage interfaces, not capacity-matched). Store–Recall scores: Graphiti 1.000, Mem0 0.996, A-MEM 0.959, FIFO 0.811, Letta 0.370.
  • Storage format matters more than eviction policy. Key-value storage beats text scratch storage by 25.9–33.0 points (App. C.5).

Real traces, VESTIGE (§4.5, App. D).

  • The graph. It replays each trajectory into a graph of file reads and writes with token costs, anchored to the files the reference patch changes. It was validated on 36 synthetic cases.
  • The data. 72,562 trajectories: 4,988 SWE-bench Verified runs from nine models, 500 CoderForge runs and 67,074 OpenHands runs (Qwen3-Coder-480B).
  • Demand is not a failure classifier. Mean peak demand is 9.0k, 73.1k and 4.5k tokens, with failure AUCs of .541, .440 and .527 (Table 16).
  • Rereading (Table 18). A task-fixed-effects model covers 4,987 runs and 31,779 cells. Failed runs' reread rate for solution-relevant files falls an extra 4.9% per doubling of token distance: rate ratio 0.951, 95% CI [0.911, 0.992], p = .020.
  • The all-file version is null (p = .174).
  • Clipping audit (App. D.2).
  • 24,270 tool views carried OpenHands' literal <response clipped> marker, across 20,839 of 67,074 trajectories.
  • Runs that never re-saw a clipped line the gold patch changes succeeded 35.8% of the time, vs 48.5% for runs that did: a −12.7-point raw gap.
  • The gap is null once each task gets its own random intercept (OR 0.89, 95% credible interval [0.67, 1.19]).
  • Demand vs failure. Peak demand is barely significant after adjusting for trajectory length (OR 1.022, p = .027), and null after adding task difficulty estimated from other runs (OR 1.016, p = .191).
  • Log signatures. Exact command-and-output repeats are common (77,164 events), but manual review shows many are deliberate reruns, so they're no misuse label.

Limits (§5, App. D).

  • VESTIGE is a retrospective proxy anchored to one reference patch.
  • The exported logs lack per-call prompt snapshots.
  • The OpenHands cohort has a single model.
  • LACUNA tasks are synthetic.

TL;DR for BQAA: a file or entity read/write graph can be built straight from tool-call rows.

  • Store truncation as structured fields: bytes returned, bytes shown, clipped flag.
  • Store per-call prompt snapshots. Their absence capped this study.
  • Adjust for task difficulty before reporting any trace-feature ↔ failure gap. Use a per-task random intercept, or difficulty estimated from other runs. A −12.7-point raw gap vanished here.
  • Rereading of goal-relevant artifacts vs distance is a candidate session-health metric, not a classifier.
