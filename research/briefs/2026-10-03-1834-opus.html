NEW 1 — LiteLLM v1.104.0: Langfuse v4 OTel and a master-key gate reach stable, but the dotted-alias $0-spend fix is missing

Primary: https://github.com/BerriAI/litellm/releases/tag/v1.104.0 (GitHub release 2026-10-03 22:50:14Z, prerelease=false; PyPI 1.104.0 uploaded 22:42:59Z, now info.version latest). Full changelog v1.103.0...v1.104.0, 647 entries.

Why it ranks. This is a stable minor that changes what reaches an observability backend and what breaks on upgrade. The parent LiteLLM card has tracked the RC-only Langfuse v4 move since 0634 Sep 28. This is the first stable build where it is the default.

  • Breaking change 1, Langfuse v4 (#36741, merged Sep 25). The langfuse SDK callback moves from Langfuse SDK v2 to v4 and exports generations as OpenTelemetry spans.
  • Pins: the tag's pyproject.toml pins langfuse>=4.7,<5.0 (lines 174 and 229). v1.103.3 pins langfuse>=2.59.7,<3.0.
  • Mapping fixes: OTel v2 mapping onto the Langfuse generation output now covers OCR, completions, images, speech, transcription, moderation, rerank and search (#42267, #42394, #42444).
  • Breaking change 2, master key (#42019). The proxy refuses to boot with an unset, empty, or sk-1234 master key.
  • The check lives in litellm/proxy/auth/master_key_boot_check.py, which is present in the tag and absent in 1.103.3.
  • The escape hatch is LITELLM_DANGEROUSLY_PERMIT_WEAK_OR_UNSET_MASTER_KEY=true. LITELLM_MIGRATE_FROM_MASTER_KEY re-encrypts values stored under the old key.
  • Analytics-relevant additions:
  • error_information.normalized_error (#41715): a stable cluster key such as 429_BUDGET_EXCEEDED or 401_AUTHENTICATION_FAILED, derived from proxy error type, known message shapes, exception class, then status. Existing fields are untouched.
  • $0-cost diagnostics (#42345): one warning per billable request priced at $0, plus the counter litellm_zero_cost_requests_total{requested_model, model, model_id, api_provider, reason}.
    • Reasons are missing_pricing_key, pricing_not_applied and cost_calculation_error.
    • Free models and requests with no usage stay silent.
  • span_type query parameter on /spend/logs/ui and /spend/logs/v2 (#42491), with values llm / agent / mcp / batch, applied in SQL against call_type.
  • Agent access groups (#41634): groups attached to an agent act as a ceiling, intersected with key and team permissions, and fail closed. Forwarded x-litellm-user-id / x-litellm-team-id headers can only narrow access.
  • Also: gen_ai.conversation.id on v2 LLM spans (#42486), the GenAI exception event recorded through the Logs API (#42431), and intercepted web searches kept under the parent request's session and trace (#41711).
  • Missing: the dotted-alias $0-spend fix.
  • The bug: #44341 (merged to main Oct 3 06:44Z) fixes streamed chat through a dotted alias such as claude-opus-4.6 being logged at $0. Its PR marks the bug "Regression in v1.92.0".
  • Not in 1.104.0: the fix adds client_facing_stream_model to litellm/litellm_core_utils/litellm_logging.py. The identifier has 0 hits in the file at v1.104.0, 5 at v1.103.3 and 5 on main. The 1.104.0 release notes do not list #44341 or #44346.
  • Not in the next RC either: v1.105.0-rc.1 (01:41Z, after the window) also has 0 hits.

BQAA read. For a BigQuery spend view that ingests LiteLLM spend logs:

  • Use the new error key: normalized_error gives you a group-by key that does not depend on provider wording.
  • Use the $0 counter: litellm_zero_cost_requests_total can flag rows not to trust.
  • Watch the dotted-alias rows: an upgrade from 1.103.3 to 1.104.0 can quietly bring back $0 rows for dotted-alias streams, and zero_cost_diagnostic may or may not catch them (Unconfirmed).
  • Langfuse is now OTLP: Langfuse-bound telemetry from 1.104.0 proxies is OTLP spans, not SDK-v2 events.

NEW 1 — Deny Without Disabling: authorization-paired evaluation and control for multi-agent systems — https://arxiv.org/abs/2610.00371

Zhang, Lyu, Wang, Ge, Guo, Hamm, Reddy (Tulane, UBC, Virginia Tech), cs.MA, v1 Sep 30, in the Oct 2 listing. Code: github.com/yunbeizhang/FlowReview. Full PDF read (44 pages, including Appendices A–H).

  • Joint metric. Each unit pairs a prohibited use with a task-required authorized use in the same scenario. Selective correctness is C = (1−D)·A, computed per unit (§2.2, Eq. 2). Blocking everything scores D = 0 but A = 0, so "safe" systems that disable the task show up.
  • Composition defeats local review (§4.1, App. B.1). The proposal, artifacts, policy and action boundary are held fixed.
  • Checking each artifact separately commits 413/480 denied uses (86.0%). Checking their union commits 0/480.
  • Authorized supply is 459/480 in both arms.
  • In model-generated composition, 3/60 denied recoveries (all by the Gemma composer) were all blocked by the global reader. Authorized supply there was only 15/60.
  • Lineage written by models vs recorded by the runtime (§4.4, App. D.2 / E.2, Table 24):
  • Complete model-authored lineage: 178/840 graphs in the delegation-depth study; 202/840 under a type-only contract versus 834/840 under an explicit contract.
  • Permission attribution still drifts: at any role, in 676/840 graphs, even under the explicit contract. Correct attribution rose only from 5.5% to 19.5%.
  • Runtime-recorded lineage: moving dependency recording into the runtime gave complete lineage, policy-correct proposals and task completion of 1.0 for all four permission specialists (480 graphs each; drift 0.0021).
  • Detection is not enforcement (§4.2, App. C.4).
  • Model review disclosed in 11/991 episodes even at 0.987 recall. Deterministic deletion: 0/1,009.
  • Class-only review withheld about 88% of denied values but achieved 0 joint successes. Object binding plus enforcement reached C ≈ 0.99–0.998 with 0/2,304 verbatim releases (App. C.2).
  • Ledger vs final state (§4.5, Table 2). On 24 independent AgentDojo-derived Sonnet 4.5 pairs, target commits fell from 21/24 to 0/24 and utility rose from 9/24 to 21/24. The executed-action ledger also caught transient attacks that a later legitimate action overwrote in the final state.
  • Limitations (§6, App. F.4–F.5):
  • The fragment banks are constructed to show mechanisms, not prevalence.
  • The zero-disclosure result is for a registered verbatim matcher. Changing the reader moved denied commits in both directions (22/40 lower, 8/40 higher; App. C.3).
  • AgentDojo confirmation covers Sonnet 4.5 under a relay selected during development. The Qwen replication had too little exposure (1/32) for a confirmatory test.

BQAA read. This paper argues for runtime-written lineage over agent self-report: when models write their own provenance, lineage is incomplete in roughly 3 of 4 graphs and permission attribution drifts in 4 of 5.

  • Record two things separately: what was proposed versus what was executed, and the identity of the object assembled across agents, not just per-message content labels.
  • Report the pair: an eval view should report D and A together, never a deny-only rate.

NEW 2 — HiSentinel: a hindsight-distilled pre-execution sentinel for coding agents — https://arxiv.org/abs/2609.39957

Zhao, Li, Zhang, Du (BUPT, BJUT, Meta), cs.SE, v1 Sep 30. Full PDF read (16 pages, including Appendix A).

  • Logged outcomes become training labels (§3–4). SWE-Intervene has 6,923 action-level decision points drawn from Open-SWE-Traces, SWE-Hero and SWE-Chat.
  • GPT-5.5 labels each point ALLOW / REDIRECT / HARD-PAUSE, and a two-stage human audit rejects 25.3% of intervention candidates (570/2,252; App. A.1.4).
  • A Qwen3-Coder-30B teacher sees the recorded continuation. A 0.6B or 1.7B student sees only the prefix plus the proposed action.
  • Distillation applies only when the future actually helps the teacher (the helpfulness gate, Eq. 7).
  • End-to-end results (Table 2): Qwen3-Coder on SWE-bench Verified Mini goes from 30% to 44% with the 1.7B sentinel; Ask-or-Assume goes from 23% to 33%. Sonnet 4.6 goes from 60% to 66% and from 58% to 61%.
  • Token cost per trajectory is roughly flat for Qwen (0.29M to 0.43M) but rises for Sonnet (0.26M to 0.41M).
  • Quality, not frequency (§5.4.1). Of HiSentinel's 242 interventions, 109 were beneficial, 106 neutral and 27 harmful. Eight rescues and one regression took the resolved count from 15/50 to 22/50.
  • Baselines: SWE-PRM had 3 beneficial interventions out of 284, with 6 regressions. Step-by-step prompting had 1 out of 24.
  • Caching changes decisions (§5.4.2). Cross-step exact-prefix KV caching saved only 22% of processed tokens. Among 896 token-identical routing calls it caused 13 routing flips (3 that changed an effective intervention), and the resolved count fell from 22/50 to 18/50. The authors recompute the full prefix at every step.
  • Transfer and ablations (Table 3, Table 4c). Without being trained on them, it does best on RootSE root-cause localization (T@0 9.80) and R-Judge. Removing distillation drops the resolved rate from 44% to 34%.
  • Limitations:
  • End-to-end results are single runs on 50 SWE-bench tasks and 100 Ask-or-Assume tasks, with no confidence intervals.
  • Labels are LLM-generated with human audit.
  • HARD-PAUSE is evaluated with a proxy-user API, not real humans (App. A.3).

BQAA read. Recorded agent trajectories, joined to their eventual outcome, are the training set for an intervention model. That is a direct downstream use of a trace warehouse.

  • Join outcome to the decision node: the useful record is the decision node (prefix plus proposed action) joined to the realized continuation and the task result.
  • Log the cache state: the KV-cache result is a reminder that a sentinel's decision can depend on serving state, so cache mode belongs in the sentinel's span attributes.

Six-week EV

  1. Stable-line drift is a spend-correctness risk. LiteLLM now has two stable lines shipping hours apart with different spend fixes: 1.103.3 has the dotted-alias fix and 1.104.0 does not. Expect 1.104.1 or a 1.105 backport within weeks. Until then, a BQAA cost view should key "trust this spend row" on version plus alias shape, not on the newest stable version.
  2. Normalized error keys and $0-cost counters are becoming gateway standard. normalized_error and litellm_zero_cost_requests_total give stable group-by keys. BQAA can map them onto its own error and cost-anomaly columns and ask other gateways and frameworks for the same.
  3. Runtime-recorded lineage beats agent self-report. Deny Without Disabling measures what the field has assumed: lineage written by models is incomplete in about 79% of graphs, and permission attribution drifts in about 80% even with an explicit contract. Recording runtime-observable dependencies on every span (artifact id, object id, immediate parent, policy version, source visibility, transform index) is a differentiated BQAA schema position.
  4. Trace warehouses become sentinel training sets. HiSentinel trains a 1.7B pre-execution gate from logged trajectories plus outcomes. Expect "export decision nodes with outcome joins" to become a requested feature. The cache-flip result argues for logging the serving state alongside the decisions.
  5. Harness permission rules are still leaking. Claude Code 2.1.289 closes several deny-rule bypasses, and Mastra #25876 closes a socket-path escape. An analytics view of "deny rule matched / not matched" for each tool call needs the harness version as a dimension.

  • tag: Academy · title: Deny Without Disabling: authorization-paired evaluation, and runtime lineage that agents can't be trusted to write
  • arXiv: 2610.00371 · https://arxiv.org/abs/2610.00371
  • card: Scores multi-agent safety as "block the prohibited use AND complete the authorized one".
    • Composition: with proposals fixed, per-artifact review let 413/480 composed denied commits through and union review 0/480, with authorized supply unchanged (459/480).
    • Lineage: model-written lineage was complete in 178/840 graphs, and permission attribution drifted in 676/840 even with an explicit contract. Runtime-recorded lineage plus an isolated permission specialist reached 1.0.
    • Enforcement: model review leaked 11/991 at 0.987 recall versus 0/1,009 for deterministic deletion (full PDF read).
  1. id: arxiv-2609-39957-hisentinel-hindsight-distilled-pre-execution-sentinel-trajectories-kv-cache-flips
  • tag: Academy · title: HiSentinel: logged coding trajectories train a 1.7B pre-execution sentinel
  • arXiv: 2609.39957 · https://arxiv.org/abs/2609.39957
  • card: A teacher that sees each action's recorded continuation distills ALLOW / REDIRECT / HARD-PAUSE judgments into a 1.7B student that sees only the prefix and the proposed action.
    • Results: Qwen3-Coder rose from 30% to 44% on SWE-bench Verified Mini (15 to 22 of 50) and from 23% to 33% on Ask-or-Assume. 109 of 242 interventions were beneficial and 27 harmful.
    • Caching: cross-step KV caching flipped 13 of 896 token-identical routing calls and cost 4 resolved tasks.
    • Caveat: single runs, no intervals (full PDF read).
