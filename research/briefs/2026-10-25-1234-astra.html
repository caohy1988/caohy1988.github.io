Progress — Inspect 0.3.285 separates terminal inspection from execution timing

Target catalog item id: inspect-ai-0-3-280-agent-bridge-attribution-response-headers-sandbox-mounts.

Primary: Inspect 0.3.285, stable, released October 25 14:27:46 UTC / 07:27:46 PT. PyPI confirms an unyanked distribution at 14:29:08.272158 UTC. The catalog already contains 0.3.283 and 0.3.284 Progress; this update covers the subsequent release only.

A usable overview of existing terminal evidence. Previously, recorded sessions appeared in Metadata and all played automatically. The new Terminals tab starts with paused end-frame previews; selecting a session opens a larger player with speed controls and command navigation. Usage and Metadata move into an Info tab, with redirects for old tab links. This makes a concrete debugging workflow easier without requiring a new log format. Change description.

Two timelines remain visible. The pinned viewer source caps each inter-event gap at two seconds for playback while separately calculating the recording's duration from event timestamps. Command markers navigate this shortened timeline. These are recording and presentation durations, neither a complete task-latency measure nor a spend counter. The implementation also labels sufficiently long idle gaps at markers; it does not establish what work happened during those gaps. Released viewer source, castDuration and castMarkers.

Recording coverage and marker conventions limit the feature. The viewer consumes asciinema:* entries already present in the sample store. Command styling and command-only navigation depend on the recorder's send <terminal>: '<command>' labels; recordings without them retain their existing markers. This viewer change does not add universal terminal capture, repair missing recordings, or change the log format. Admission is grounded in the stable release, its pinned viewer submodule and rebuilt JavaScript bundle, rather than an unreleased PR. Release commit, tagged bundle.

Two accompanying repairs matter when analyzing evaluation failures:

  • Selective .eval reads handle numeric overflow consistently with full reads. A valid JSON literal such as 1e309 could fail when fields were excluded. Both selective readers now fall back to the standard JSON reader for that overflow. The resulting value is inf, not a recovered finite measurement; downstream analytics still needs a non-finite-value policy. Change, tagged readers.
  • The in-process bridge restores the expected beta response types with Anthropic SDK 2.3. It identifies a beta request from the expected response class, replacing dependence on a URL query flag that the SDK removed. This prevents clients reading beta-only usage fields from failing on the wrong response type. The sandbox bridge was outside this bug's scope. Change, paraphrased, tagged bridge.

BQAA inference: retain runner/SDK versions, recording availability, recorder convention, original timestamps and playback settings as separate provenance. Classify reader and bridge failures separately from agent failures. Evaluate the viewer on fixed failure cases before claiming faster diagnosis; no runtime reproduction, deployment test or measured BQAA improvement was performed for this brief.
