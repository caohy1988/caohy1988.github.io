Read this first

  1. Same Query, Different Answer (2610.13823, IBM): rerunning a semantic SQL query at temperature 0 changes the answer often, and BigQuery is not exempt. Across five published SemBench runs, 27% of BigQuery's 64 query cells changed quality, with a maximum range of 1.00. Item flip rates reach 10.2% for gpt-oss-120B and 24.0% on one extraction task. A 4% change in extracted values changed 67% of SQL answers. The fix the paper recommends is cheap: record each operator output (~39 bytes) with its decision margin or reasoning length. → NEW Academy.
  2. SemViews (2610.12768, IBM): reuse earlier LLM labels to decide which rows to check, never to decide what is true, and the precision/recall guarantee survives. It saves 28–45% of oracle calls while missing targets on 0.37% of 145,000 replayed queries. Similarity caches that reuse a "close enough" predicate missed a target 100% of the time when they hit. 56% of the implications an LLM judge asserted between predicates failed on the actual labels. → NEW Academy.
  3. Agreement Without Alignment (2610.13303): editing the rubric clauses that judges disagree on raised inter-judge α by 0.069 on SummEval, with no detectable gain in agreement with experts (τ −0.007). The study was preregistered and used five judges from three providers (129,770 requests). Editing random clauses tended to do better against humans. A provider's batch API silently ignored the JSON schema (0/20 conform). → NEW Academy.
  4. Jev in agent workflows (2610.13092): Jev cuts per-decision cost by 66–78%, yet cost per delivered success rose for one mobile agent (68.70 → 73.97 mUSD). In another, time per success went from 239 s to 378 s. In Reflexion-J, failed recovery consumed 53.3% of all inference spend. → NEW Academy.

  • What shipped: the lmnr-ai/lmnr GitHub release v0.3.0, published 2026-10-11T22:01:00Z (not a prerelease). It is the first tagged release since v0.2.5, so it is the first to carry a batch of September merges to self-hosted users.
  • Signals and clusters in the open-source edition (#2347, #2366, #2474, #2477):
    • each aggregated trace row now holds its signal events (event_id, signal_id, severity, payload) and cluster IDs;
    • a ClickHouse dictionary resolves cluster ancestry;
    • trace views read signals and clusters in a single query instead of three round trips;
    • shared trace pages show signals and clusters;
    • signals can be renamed, and alert emails link to the trace behind a signal event.
      Signals remain a credit-metered feature in Laminar's cloud pricing (#2454, #2471).
  • OpenRouter Broadcast traces (#2369): OpenRouter posts OTLP spans to /v1/traces but does not follow GenAI semantic conventions. Conversations arrive as JSON in gen_ai.prompt / gen_ai.completion, and session and user arrive as bare session.id / user.id. Laminar adds a mapper so that input, output (with the reasoning shown first), session, user and trace name populate correctly. Per-provider "attempt" child spans no longer appear as zero-token generations.
  • PII "dual" mode (#2357–#2361, #2384, #2392):
    • piiMode = off | redact | dual replaces removePii;
    • in dual, raw text is stored once, next to the byte-range masks the redactor returned;
    • ClickHouse views splice [REDACTED_<LABEL>] at read time for members and share-link viewers, while owners and admins see the original;
    • rows the redactor failed on are stamped unchecked and render masked;
    • search indexes only the masked text.
  • Operational caveat: Quickwit 0.9 requires an irreversible Postgres schema migration ("make a backup"). Quickwit also force-commits every batch again (configurable).
  • Why it matters for BQAA: this is another trace store that attaches derived events (signals) and groupings (clusters) to the trace row itself. It also addresses a problem BQAA will face with stored prompts and responses: keep the raw content once and decide redaction per reader at query time, rather than redacting at write time and losing the original. OpenRouter Broadcast is now a second gateway-originated OTLP source with non-standard attribute keys, after LiteLLM's ingestion last brief. Ingestion mappers per emitter are becoming a product feature.

NEW — Same Query, Different Answer: Run-to-Run Variance in Semantic Query Processing — https://arxiv.org/abs/2610.13823

Hassanzadeh, Subramanian (IBM). cs.DB, cross-listed to cs.AI; submitted Oct 9, listed Mon Oct 12. Full PDF read.

  • Setup: the authors re-ran SemBench, LRO-Bench and UDA-Bench through each benchmark's own harness at temperature 0. They logged all 1,219,338 model calls (per-item output, finish reason, tokens, reasoning length and top-5 logprobs where available) on six open-weight deployments plus GPT-4o and Claude Sonnet 5. They also reanalysed SemBench's published five-run results for LOTUS, Palimpzest, ThalamusDB and BigQuery (§4, Table 3).
  • Published results move (§5, Table 4):
    • 21% of the 101 text cells change quality across five runs;
    • BigQuery: 27% of its 64 cells, 8% by ≥0.1, max range 1.00;
    • among cells with deterministic plans (LOTUS outside joins, and BigQuery), 12 of 50 change;
    • 7 of 112 text system comparisons need more than five runs to separate at 95%.
  • Item flip rates at temperature 0 (§6, Tables 5–6):
    • 0.07% (Mistral-24B) to 10.2% (gpt-oss-120B) over five runs;
    • 24.0% on a 24-way diagnosis extraction;
    • GPT-4o 7.5% and Claude Sonnet 5 4.1% on the same filters and maps;
    • rates keep growing with more runs: 5.2% → 10.2% → 13.0% at 2/5/10 runs.
  • Plans amplify item changes (§3, §7, Tables 1, 9): reproduction ≈ e^(−Σδᵢ) when the answer exposes every item. On UDA-Bench, 4.0% of extracted values change but 67% of SQL answers do. LIMIT absorbs changes, and quality metrics hide many: Movie Q1 scores 1.00 in all 10 runs while only 0.53 of run pairs return the same five rows. Averaged over deployments, only 32% of SemBench queries reproduce every operator output and 48% their answer (Fig. 5).
  • Cause (§8, Table 11):
    • Identical requests within one run disagree as often as across runs (6.0% vs 6.1% on gpt-oss-120B).
    • Concurrency, input order, seed and reasoning effort do not remove the variance.
    • The same Llama-3.3-70B on two serving stacks gives deterministically different answers (1.8% of majority outputs), and one stack shifted between campaigns.
    • Changing items are contested items: the first run's decision margin predicts later flips (AUC 0.93), and so does reasoning length (AUC 0.84).
  • Remedies (§9, Tables 12–13):
    • Voting with three samples removes 36% of disagreement at ≤2.13 calls per item, but not all of it.
    • Re-asking only the 20% of items with the longest reasoning gets 64% of that reduction at 1.4 calls per item.
    • A recall-guaranteed cascade keeps its guarantee, but different oracle runs make it return the same rows only 24% of the time.
    • Recording outputs costs ~39 bytes each (348 KB per run).
  • Limitations (§11): text and tabular data only. RQ2–5 rest on open-weight deployments plus two commercial models; Gemini 2.5 Flash, which SemBench used, could not be re-run. The deployment effect rests on one model served by two stacks. Five runs bound the smallest detectable rates. Code and logs: github.com/semviews/sqp-variance-study (not checked).
  • Why it matters for BQAA: BQAA's analysis layer runs LLM judgments in SQL (AI functions, LLM-as-judge over agent_events), and the paper's BigQuery cells are first-party evidence that reruns change answers. Every derived label column needs, per row: model and deployment identity, the run id, and a margin or reasoning-length field. Dashboards should report answer reproduction, not only quality. "Re-run the eval" is not a regression test unless outputs are pinned.

NEW — Semantic Views: Certified Reuse of LLM Labels Across Semantic Queries — https://arxiv.org/abs/2610.12768

Hassanzadeh, Subramanian (IBM). cs.DB; submitted Oct 8, listed Mon Oct 12. Full PDF read, including Appendices A–D.

  • Method (§4, Alg. 1): CertifiedFilter follows one rule: views, helper scores and embeddings may only order the rows.
    1. Fit a logistic score on a 200-row uniform shaping sample, using as features prior predicates' labels (including "unknown"), a helper model's score and a local embedding.
    2. Refine the score on boundary rows for up to 8 rounds.
    3. Split the order into reject, oracle and accept regions.
    4. Certify both outer regions with fresh draws (sampled without replacement, exact hypergeometric bounds).
    5. If needed, close the gap by labelling more rows.
      Theorem 4.1: precision and recall targets hold with probability ≥1−δ for any catalog, including adversarial ones. Views carry provenance (oracle vs derived), and the identity of a view includes the oracle model and prompt version (§3, §5).
  • Results: replayed against 725,000 recorded labels (Llama 3.3 70B oracle; re-labelling 2,000 pairs matched in 99.85% of cases).
    • Accuracy and cost (§7.3–7.4, Table 5): misses a target on 0.37% of 145,000 queries (worst predicate 3.2%) and saves 28–45% of the oracle calls of exact evaluation. BARGAIN needs 1.32–1.71× as many calls.
    • Baselines that skip certification: the LOTUS cascade misses 30.8–65.4%, and SemWeave's entailment-based reuse misses up to 67.8%.
    • Similarity caches: when they hit, they miss a target 100% of the time.
  • Relations between predicates are statistical (§3, §7.2, Table 3, Prop. 3.2):
    • only 92 of 5,280 ordered predicate pairs are 0.1-contained;
    • 56% of implications asserted by an LLM judge fail;
    • containment errors compound along chains by the ratio of the predicates' selectivities.
  • Reworded questions (§7.5, Table 6): a reworded predicate agrees with the original on 76–99.8% of rows, but the positive sets overlap only at Jaccard 0.57–0.95. SemViews uses the twin's view to cut calls by a further 27–36% and misses ≤0.2%.
  • Robustness and scale (§7.6, Tables 7–8, App. B):
    • views from a different oracle still save 18%;
    • unrelated workloads add no measurable cost, and adversarial views do not break validity;
    • cost falls from 60% of exact evaluation at 5,000 rows to 34% at 100,000 on DBpedia.
  • Limitations: filters only (no joins or ranking), and the main tables are 5,000 rows. Two of the four datasets helped tune hyperparameters (App. C). Real analyst or agent sessions were not measured.
  • Why it matters for BQAA: when an analyst or an agent asks "sessions where the user was frustrated", then "…frustrated about billing", BQAA can treat earlier label columns as planning hints and still certify the new answer with a small fresh sample. The paper is also strong evidence against the shortcut of "reuse the label from a similar prompt".

NEW — Agreement Without Alignment: Label-Free Rubric Clarification Increases LLM-Judge Consensus but Not Agreement with Humans — https://arxiv.org/abs/2610.13303

Han, Kim (CEO Business School). cs.CL; submitted Oct 9, listed Mon Oct 12. Full PDF read, including Appendices A–E.

  • Procedure (§3):
    1. Decompose each rubric into sub-criteria.
    2. Five judges probe a development split.
    3. Rank sub-criteria by cross-judge disagreement.
    4. An editor (Claude Opus 5.5) rewrites the top k = min(5, ⌊n/2⌋) contested clauses, adding pass/fail examples where available.
      The stage that moves sub-criteria to code checkers transferred none of the 75.
  • Design (§4, Tables 1–2):
    • judges: Claude Opus 5.5, Sonnet 5.5, Haiku 4.5, GPT-6 Luna and Gemini 3.5 Flash-Lite;
    • data: SummEval, the HealthBench meta-evaluation and USR;
    • six rubric conditions, including a matched control that applies the same edits to random unselected clauses;
    • preregistered under a version-control tag, with a sealed manifest;
    • 129,770 requests at $236.69 (§5.1).
  • Results (Table 3):
    • SummEval: inter-judge α +0.069 (95% CI 0.046–0.092) over the original and +0.074 over the random-clause control. Agreement with experts did not move: τ −0.007 (−0.037 to 0.021).
    • HealthBench and USR: no α effect met the preregistered criteria.
    • Secondary comparison: human agreement after editing contested clauses was below the control on all three datasets in point estimate (all CIs include 0).
    • Repeat runs (Table 6): run-to-run disagreement ranged from ~0 (Haiku at temperature 0) to 0.246 (GPT-6 Luna on SummEval). Clarification raised it for Opus and Sonnet.
  • Practical findings:
    • One provider's batch transport ignored responseJsonSchema: 0/20 outputs conformed, versus 20/20 synchronously (App. C, Table 8).
    • On a negated HealthBench criterion, a judge's explanation identified the failure and then emitted criteria_met = true (App. B).
  • Limitations (§7): three of the five judges are Claude models, and the editor is from the same family. Provider and model size are confounded. The plan changed before evaluation (all changes logged, App. A). No equivalence tests.
  • Why it matters for BQAA: the paper argues against panel consensus as a quality metric for judge configurations. BQAA's eval tables should store per-judge verdicts and their rationales, run-to-run repeat rates and a small human-labelled anchor set. A "rubric v2 raised agreement" claim needs the human anchor. The schema-enforcement failure is a concrete reason to validate the structured output of every judge row at ingestion.

NEW — When Faster Decisions Do Not Make Better Agents: An Empirical Study of Jev in Agent Workflows — https://arxiv.org/abs/2610.13092

Ling, Yu, Chen, Fang (Nanjing U, TU Munich). cs.AI; submitted Oct 9, listed Mon Oct 12. Full PDF read, including Appendices A–C.

  • Setup (§4, Table 1):
    • five agent families: ReAct and Reflexion on ALFWorld (134 tasks); T3A, AutoDroid and FastAgent on AndroidWorld (116 tasks);
    • variants: baseline LLM (gpt-5.6-luna), Jev (jev-1.13.0) for action selection, and on ALFWorld an LLM-Choice control with the same candidate interface;
    • three runs each, 4,500 executions;
    • paired task-cluster bootstrap intervals;
    • two-author trace coding (κ 0.756–1.0).
  • Decision level (§5.2, Fig. 3): per-decision cost −66.1% to −78.4%, time −73.9% to −81.5%, and tokens per decision +53.5% to +134.9%. Jev's lower input price and zero output price (App. A.1) offset the extra tokens.
  • Task success (§5.1, Table 5): ALFWorld drops 1.49 / 1.74 points. AndroidWorld drops 13.22 (T3A), 2.30 (AutoDroid) and 18.10 (FastAgent) points; the intervals for T3A and FastAgent are entirely negative.
  • Delivered outcome (Table 2):
    • T3A: cost per delivered success rises from 68.70 to 73.97 mUSD (+7.7%; the interval spans zero).
    • FastAgent: time per success goes from 239.4 s to 377.8 s.
    • Reflexion-J: 2.0% of executions consume 53.3% of inference spend through unsuccessful recovery (§5.2). First-trial success is higher than the baseline (383/402 vs 376/402), but it recovers only 11/19 initial failures, against 25/26 for the baseline (Table 4).
  • Where savings go (Fig. 4, §5.3, Table 3):
    • auxiliary LLM calls and extra interactions absorb the selection savings;
    • failed recovery (29.1% of coded executions) and ineffective search (24.7%) separate persistent losses;
    • premature completion ends a run early, e.g. clicking a switch labelled "Off" and declaring Wi-Fi enabled.
  • Limitations: text-only observations, three runs with one seed, budgets matched only within a family, and prices fixed at experiment time.
  • Why it matters for BQAA: the right unit for agent cost analytics is cost per delivered success, including failed attempts, split into decision, auxiliary and environment time. Per-call cost is the wrong unit. BQAA dashboards that show only per-span or per-call savings would have reported T3A-J and FastAgent-J as wins. (The same model family sits behind several carded eval-vendor integrations, and behind the fleet's own jev-shadow gate.)

Six-week EV

  • LLM-derived columns need provenance and a reproducibility number. Two independent lines of work now converge: 2610.13823 (variance in semantic operators, including BigQuery cells) and the carded Stochastic Shift paper. Expect buyers who run LLM judgments in SQL to ask "would this dashboard say the same thing tomorrow?". BQAA can answer if it stores per-row model and deployment, run id and margin, and reports answer reproduction.
  • Reuse with certification beats caching. SemViews shows that label reuse across related questions is safe only when a fresh sample certifies it. Agent-driven analytics (agents refining predicates at machine speed) makes this pattern valuable soon; similarity caches will produce silent misses.
  • Judge consensus is not a quality metric. Following last brief's TestJack and SSCBench, this window adds evidence that agreement among judges can rise while agreement with humans does not. Eval tables need a human anchor slice and should keep per-judge rationales.
  • "Cost per delivered success" becomes the agent-cost unit. The Jev agent study shows per-call savings reversing at the task level. Vendors who chart per-span cost will be challenged on this.
  • Trace stores grow per-emitter ingestion mappers and read-time redaction. Laminar (OpenRouter Broadcast) and LiteLLM (OTLP ingestion, last brief) both map non-standard gateway attributes. Laminar's dual-mode PII sets a bar for redaction that depends on who is reading.

TL;DRs for BQAA

  • Laminar v0.3.0: the self-hosted edition gets per-trace signals and clusters, an OpenRouter Broadcast OTLP mapper and read-time PII masking by viewer role. Upgrade needs an irreversible migration.
  • 2610.13823 Same Query, Different Answer: BigQuery's SemBench cells moved in 27% of cases across reruns. Store per-row outputs with model, deployment and margin, and report answer reproduction.
  • 2610.12768 SemViews: reuse old LLM labels only to order rows, and certify each answer with fresh samples. It cut oracle calls 28–45% while staying valid; similarity caches missed every time they hit.
  • 2610.13303 Agreement Without Alignment: rubric edits raised judge consensus (+0.069 α) but not agreement with experts. Keep a human anchor set and validate judge JSON at ingestion.
  • 2610.13092 Jev in agent workflows: per-decision cost fell 66–78%, but cost or time per delivered success rose for two mobile agents. Report cost per success, including failed attempts.
