Microsoft Foundry Insights and BigQuery Agent Analytics: value and comparison

Foundry Insights analyzes traces and organizes recurring behavior into reviewable findings.

Prepared and sources fetched 2026-10-03. This comparison is prepared from the BQAA side, so readers should weigh it accordingly.

This comparison was reviewed by one blind reviewer (Astra) because the second reviewer was unavailable.

01 / What Foundry Insights is

1. What Foundry Insights is

Insights analyzes traces from the Application Insights resource connected to a Foundry project and organizes recurring behavior into reviewable findings (post, 'From trace search to an actionable review queue'). Prerequisites include a GPT-5 or newer GPT deployment, user and managed-identity role assignments, and recent representative traces (Learn, 'Prerequisites'); only GPT models can be the judge (Learn, 'Choose a supported judge model').

An Insight can carry a title; one of eight categories; High, Medium or Low severity; a status; agent version and creation time; an AI-generated likely cause; linked traces; highlighted traces; and a proposed action or fix (Learn, 'Information in an Insight').

The first analysis looks back 7 days; later runs are on demand or scheduled (Learn, 'How Insights in Foundry works'). Developers triage in the portal, checking highlighted traces against healthy ones (Learn, 'Review generated Insights' and 'Validate an Insight'). Foundry MCP's agent_insights_get tool or the Microsoft Foundry Skill gives a local coding agent read-only access to findings (Learn, 'Pull Insights into a local coding agent'). Proposed fixes can be instruction diffs for Prompt agents or source diffs for code-based Hosted agents, otherwise general guidance, and status can be active, resolved or dismissed (Learn, 'Take action on a confirmed Insight').

The only charge either source names is the model deployment, including scheduled runs (Learn, 'Pricing'; post, 'Get started'). The feature is a preview without a service-level agreement, not recommended for production workloads (Learn, opening note), and its supported agents, models, regions, limits and prices can change (Learn, 'Responsible use and limitations').

02 / How Microsoft measured it

2. How Microsoft measured it

Linkage: the same 746 benchmark inputs (653 failure-labeled) ran on September 15, 16, and 17, 2026, across six public research slices (post, 'Labeled evaluation: Do Insights link the right traces?'). Precision was 100.0% on AgentErrorBench and TraceElephant only because every input there is failure-labeled (post, 'Labeled results'). On the mixed AgentRx (Tau-bench retail) slice, with 29 of 102 inputs failure-labeled, mean trace precision was 37.8% and mean trace recall 57.5%, with daily recall of 65.5%, 58.6%, and 48.3% (post, 'What the labeled results show'). The post states: "They do not establish whether an explanation is correct or a proposed action is useful" (same section).

Finding quality: a separate LLM judge scored 40 Insights from 4,496 inputs across five datasets on eight 1-to-5 dimensions (post, 'The eight-dimension judge rubric' and 'Unlabeled results'). Dataset means were 3.53 (PUPA), 3.57 (FailSafeQA), 3.88 (internal monitoring dashboard agent), 2.84 (tau2-bench) and 3.81 (synthetic scenarios). Fix specificity was lowest in four of five snapshots (means 2.00 to 2.64), and tau2-bench's lowest was correctness at 2.25 (post, 'Unlabeled results'). These scores "are not human ratings" (post, 'Unlabeled evaluation: Are the findings grounded and useful?').

Known issues: in the September 23 hosted-agent report, 11 of 12 expected issues were scorable and 10 were detected, and all three scorable healthy baselines had no confirmed unsupported findings. The snapshot is "not a representative product-wide rate" (post, 'Controlled end-to-end tests: Can Insights find known issues?').

03 / Value assessment

3. Value assessment

Methodology worth borrowing

The post separates linkage, finding quality and known-issue detection, reports label prevalence beside precision, keeps datasets separate, scores explanation, importance and fix usefulness apart, and leaves incomplete controlled cases unscored (post, 'Three complementary ways to evaluate Insight quality', 'What the labeled results show', 'Unlabeled results', 'The eight-dimension judge rubric' and 'Controlled end-to-end tests: Can Insights find known issues?').

Judgement: this measurement contract is the release's most transferable part; any trace-to-findings product, BQAA included, can be held to it.

Competitor signal

Microsoft calls discovering "repeated behavior that the team did not know to predefine" the harder problem beyond observability and evaluation (post, 'From trace search to an actionable review queue') and publishes weak results beside strong ones (post, 'What the labeled results show').

Judgement: the competitive bar is moving from storing and querying traces to delivering evidence-linked findings into the coding agent that makes the change, with published measurement in the pitch. Without adoption data in the sources, this signals direction, not traction.

Limits

Preview with no SLA (Learn, opening note); GPT-5-or-newer GPT judge only (Learn, 'Choose a supported judge model'); Application Insights and role setup (Learn, 'Prerequisites'); lookback-window analysis, where Insights "aren't guaranteed to be real time" and the feature "might miss real issues or combine unrelated behavior" (Learn, 'Responsible use and limitations'); no evidence on "longitudinal recurrence or deduplication performance across runs" (post, 'How we track quality over time'); fix specificity lowest-scoring (post, 'Unlabeled results'); benchmark inputs that are "not a representative sample of customer production traffic" (post, 'Labeled evaluation: Do Insights link the right traces?'), plus an internal dataset "compiled from Microsoft employee usage" and synthetic scenarios (post, 'Unlabeled evaluation: Are the findings grounded and useful?').

What is unproven

Diagnosis correctness, fix usefulness and measured improvement after a fix (post, 'What the labeled results show' and 'Unlabeled results'); judge agreement with humans (none reported); category labels, since category agreement is "an exploratory benchmark diagnostic" (post, 'A broader view of quality'); customer-traffic results; and cost per run (no figures given).

Judgement: the labeled results show broad failure coverage but weak discrimination. The mixed slice's failure share is 28.4% (29 of 102, computed), so 37.8% precision beats random linking, yet most linked inputs there had no failure label (the post notes some may hold unlabeled cost or latency issues). On the three mostly-failure slices that include healthy inputs, precision sits within about a point of the failure share (computed shares 75.9%, 96.6% and 94.4%; precision 75.3%, 96.9% and 93.3%). On the mixed slice, daily recall on identical inputs varied; whether the pipeline changed between runs is unstated (NOT VERIFIED), so stability is open. With 40 judged Insights and 11 scorable injected issues, the samples are small.

05 / Bottom line

5. Bottom line

Judgement: Insights is worth more as a product pattern and a measurement standard than as proven diagnosis. It turns traces into an evidence-linked review queue that coding agents can read, but by Microsoft's own numbers it discriminates weakly on the mixed benchmark slice (37.8% precision, 57.5% recall), fix specificity is usually its weakest-judged dimension, and the reviewed Microsoft sources do not establish correct diagnoses or helpful fixes on customer traffic. Insights is in public preview. BQAA is GA in ADK; the pinned SDK 0.5.4 declares an Alpha development status. Whether the ADK GA announcement covers the SDK analysis layer is NOT VERIFIED. The apparent gap in the reviewed SDK is a persisted, evidence-linked, status-tracked findings queue with dedicated read-only retrieval, beyond its agent-callable reporting CLI. A published finding-quality evaluation was not found in the reviewed sources; wider availability is NOT VERIFIED.

06 / What BQAA could borrow

6. What BQAA could borrow

Judgement: each adapts a sourced Microsoft practice.

  1. A persisted finding record (category, severity, status, agent version, linked and highlighted sessions, proposed action) with a verify-before-resolve rule (Learn, 'Information in an Insight' and 'Resolve, dismiss, or monitor recurrence').
  2. A published three-part evaluation of the insights pipeline, per dataset, with base rates beside precision and defect-injection tests that count unsupported and duplicate findings and leave incomplete cases unscored (post, 'Three complementary ways to evaluate Insight quality', 'What the labeled results show' and 'Controlled end-to-end tests: Can Insights find known issues?').
  3. A rubric for findings, not sessions, that scores fix specificity and fix applicability apart from correctness (post, 'The eight-dimension judge rubric'; compare the SDK's session rubric reference).
  4. A read-only, paginated findings tool for coding agents that cannot start analyses or change status (Learn, 'Pull Insights into a local coding agent').
  5. Structured feedback classes for wrong findings (false positive, wrong likely cause, merged or duplicated issues) stored as evaluation data (Learn, 'An Insight appears incorrect').

What this brief did not verify

NOT VERIFIED

  • Application Insights charges, and any Insights fee beyond model charges: Learn 'Pricing' names only model charges; Azure pricing was not checked.
  • Insights regions and subscriptions: Learn 'Troubleshoot Insights in Foundry' says to check availability but lists none.
  • External frameworks Insights can analyze: Learn mentions only registered external agents; its linked "Set up tracing" page was not reviewed.
  • Pipeline changes between the September 15 to 17 runs: the post does not say ('How we track quality over time').
  • Whether BQAA's GA covers the SDK: the release note says only "in the Google Agent Developer Kit"; the BigQuery docs page and SDK README state no SDK launch stage.
  • A published quality evaluation of BQAA findings or judges: none in the SDK README, SDK reference, rubric reference, CHANGELOG, or three design documents listed in Sources. The lab measures skill changes, not finding quality. Papers and blogs were not searched.
  • Evolved-skill gains outside the lab: none found in the job guide, lab README or lab record; the lab's companion blog post and other venues were not reviewed.
  • A BQAA-specific MCP tool or skill for retrieving findings: no "mcp" match in the SDK README, SDK reference or repository file list; BigQuery docs list a general "Use the BigQuery MCP server" page, not reviewed.
  • Cost per Insights run or BQAA insights report: none in the Microsoft sources, SDK reference or README; the lab README prices a demo-size evolution round at "single-digit dollars".
