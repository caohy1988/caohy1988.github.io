The shift

The work is not disappearing. The leverage point is moving.

Coding agents can now hold context, use tools, and carry tasks across many steps. That does not remove engineering discipline—it makes the quality of your operating mechanism more visible.

01 / EXECUTION

Parallel work becomes the default.

Independent research, implementation, and review tracks can run at once. Your attention—not machine time—becomes the scarce resource.

02 / QUALITY

Fast output increases review pressure.

More code is not more progress. Tests, observability, small blast radii, and explicit acceptance criteria become the trust system.

03 / ORG

Every engineer becomes a tech lead.

You direct agent teams the way a TL directs a team—and as spans grow, a manager of managers. How many tracks you can run well becomes a real edge, and org shapes start to bend around it.

What we'll cover

A mechanism, not a magic trick.

The talk moves from a workflow you can try on Monday, to the controls that keep it trustworthy, to the longer-term implications for engineering teams.

Part 01 · Operate

Run a portfolio of agent work

How to split work by independence and reversibility; write spec-style task contracts; run parallel tracks with git worktrees, subagents, and background runs; and engineer context deliberately instead of hoping the model guesses.

Part 02 · Trust

Build a verification system

Where agents predictably fail; cross-model review that catches what a single model misses; tests, evals, and sandboxed permissions as merge gates; and why the engineer stays accountable for the final call.

Part 03 · Learn

Turn context windows into a learning instrument

Million-token contexts change how you ramp up: drop a whole codebase, paper, or unfamiliar stack into an agent and interrogate it. Compressing weeks of onboarding into days—and keeping pace with a field that shifts weekly.

Part 04 · Adapt

Invest in the skills that compound

How the role shifts from producing every artifact to directing systems of work—and what that means for learning, team topology, technical leadership, and career growth.

Tools are examples, not the thesis. The walkthrough uses Claude Code, Codex, and Kimi Code; the operating principles transfer across models, harnesses, and the growing MCP tool ecosystem.

Abstract

For organizers and attendees.

AI coding agents have moved beyond autocomplete: they can inspect repositories, use tools, make changes, and carry work across multiple steps. Run several in parallel and an engineer's role starts to change. The bottleneck is no longer only producing code—it is framing work precisely, allocating attention, and proving that the result is correct.

This talk is a field report from working that way every day. Haiyuan shows how he uses complementary coding agents for implementation, research, and cross-review; the controls he uses to manage their predictable failure modes; and a practical framework for deciding which work to delegate. He also shows how large context windows change learning itself—loading whole codebases and papers into an agent and interrogating them. He then argues that every engineer starts to operate like a tech lead of agent teams—and, as spans grow, a manager of managers—and looks at the skills and org shapes that become more valuable as execution gets cheaper.

The goal is not “AI will do everything.” It is a grounded answer to a more useful question: how should a strong engineer work when capable agents are part of the team?

About the speaker

Building AI systems, then pressure-testing how they change the work.

Before industry, he earned a Ph.D. in theoretical physics and published research in Nature Communications and Physical Review Letters. That research background still shapes his approach: make the hypothesis explicit, design the test, and trust evidence over a convincing story.
