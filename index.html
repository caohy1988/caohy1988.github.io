The shift

The work is not disappearing. The leverage point is moving.

Coding agents can now hold context, use tools, and carry tasks across many steps. That does not remove engineering discipline—it makes the quality of your operating mechanism more visible.

01 / EXECUTION

Parallel work becomes the default.

Independent research, implementation, and review tracks can run at once. Your attention—not machine time—becomes the scarce resource.

02 / QUALITY

Fast output increases review pressure.

More code is not more progress. Tests, observability, small blast radii, and explicit acceptance criteria become the trust system.

03 / SPAN

Every engineer picks up TL mechanics.

Framing work, decomposing it, setting quality bars, reviewing outcomes—daily, at agent speed. That doesn't make everyone a people leader, but it expands every engineer's span of execution. "M2 of agents" is an analogy—and part of the talk is where it breaks.

What we'll cover

A mechanism, not a magic trick.

The talk moves from a workflow you can try on Monday, to the controls that keep it trustworthy, to the longer-term implications for engineering teams.

Part 01 · Operate

Run a manager-led agent team

The pattern I actually use: I talk to one agent manager. It drafts the GitHub issue, fans review out to the team, tracks who has finished, and calls alignment. Underneath: task dependencies, git worktrees, subagents, and deliberate context engineering.

Part 02 · Trust

The agent team is the verification system

Verification organized as an org, not a step: every plan, design, and diff is reviewed by every team member—each a different frontier model, because same-model reviewers share blind spots—with CI as the floor and the human as the final outcome gate.

Part 03 · Learn

Turn context windows into a learning instrument

A safe learning loop for million-token contexts: map the system → ask source-linked questions → form a prediction → run the real code → explain it back → build something. Shown on a real repository, including what the agent first got wrong.

Part 04 · Adapt

Invest in the skills that compound

How the role shifts from producing every artifact to directing systems of work—and what that means for learning, team topology, technical leadership, and career growth.

The team requirement: model diversity at every seat. Each teammate runs on a different frontier model family—GPT 5.6 sol, Fable 5 / Opus 5, Kimi K3—and every seat needs Fable 5-class capability. Diverse models catch each other's blind spots; the operating principles transfer across harnesses and the MCP tool ecosystem.

Collaboration & organization

How collaboration might change—a hypothesis, held loosely.

Agent leverage will change collaboration before it changes org charts. Teams may spend less time coordinating execution and more time sharing context, reviewing evidence, and making customer decisions. Whether organizations actually flatten is still an open question—and accountability and people leadership remain human.

ALREADY HAPPENING

Context becomes the collaboration surface.

Explicit specifications, agent-readable context files, cross-model review, and portfolio-style standups—"which tracks are running, which passed their evidence gates?"—are visible today among power users and small teams.

LIKELY NEXT

Wider scope, fewer handoffs.

Project scope per engineer grows as one person carries research, implementation, and review tracks that used to be split across roles. Execution handoffs—the slowest part of team coordination—get rarer.

STILL UNCERTAIN

Whether org charts actually flatten.

Staffing ratios, management layers, and team sizes are open empirical questions. The honest position: watch the data as it arrives, not the hype. The diagram above is a hypothesis to test, not a prediction to bank on.

INVARIANT

Humans own judgment and consequences.

Customer judgment, prioritization, and accountability stay human. So does people leadership—agents don't need coaching, career growth, motivation, or trust. People do, and someone must still build both.

Operating rules

The rules I actually work by.

Not best practices—scar tissue. Each of these exists because I broke it once and paid for it. The talk gives the story behind each one.

No agent starts without an observable "done."

If I can't state what evidence would prove the task complete, I'm not ready to delegate it.

Second models attack, not rewrite.

Cross-review means asking another model to break the first one's assumptions—not to paraphrase its answer.

A summary is not proof.

I never accept an agent's report of success. The team verifies the diffs and tests; I verify the outcome—the dashboard has to actually work.

Stop parallelizing at the review ceiling.

When the verification queue grows faster than I can clear it, more agents make me slower, not faster.

Irreversible stays human.

Deploys, deletions, and anything outward-facing get human hands and human sign-off. Every time.

Learning ends in an artifact.

A session that produces only an explanation is entertainment. It ends with a prediction, an experiment, or a code change.

Abstract

For organizers and attendees.

AI coding agents have moved beyond autocomplete: they can inspect repositories, use tools, make changes, and carry work across multiple steps. Run several in parallel and an engineer's role starts to change. The bottleneck is no longer only producing code—it is framing work precisely, allocating attention, and proving that the result is correct.

This talk is a field report from working that way every day. Haiyuan walks through the pipeline he runs in his open-source experiment repo: he briefs a single agent manager, which drafts a GitHub issue, fans review out to a team of agents built on different frontier models, drives every plan and design through full cross-review, and calls alignment before he reads the one final plan and says go. Implementation runs in dependency order under the manager's lead, all code review is agent-to-agent with CI as the floor, and his job reduces to two gates: approving the plan and verifying the shipped outcome. He also shows how large context windows change learning itself—loading whole codebases and papers into an agent and interrogating them. He then looks at how the role expands—more TL mechanics practiced daily, wider spans of execution—and closes with a carefully scoped hypothesis about how collaboration and org shapes may change, kept clearly separate from what the evidence already supports.

The goal is not “AI will do everything.” It is a grounded answer to a more useful question: how should a strong engineer work when capable agents are part of the team?
